> **Занятие 53 из 55 · практическая работа №11 · 2 часа.** Прежде чем рисовать красивые экраны, команда договаривается, какие экраны вообще будут и как между ними ходить. Сегодня вы сделаете схему интерфейса веб-приложения «Запись к врачу»: список экранов, переходы и путь пользователя.

## Коротко о теории

На занятии 36 вы делали **карту сайта** — дерево страниц: главная, у неё разделы, у разделов подстраницы. Для сайта-визитки этого достаточно. Но **веб-приложение** (запись к врачу, интернет-банк, электронный дневник) — это не набор страниц, а набор **экранов**, по которым человек проходит, выполняя задачу. Экран может открываться из разных мест, у него бывают состояния, а путь зависит от решений пользователя. Дерево такое не показывает, поэтому рисуют **схему интерфейса** из трёх частей:

| Часть схемы | Что показывает | Вопрос, на который отвечает |
|---|---|---|
| **Карта экранов** | Все экраны и их назначение | Что есть в приложении? |
| **Переходы** | Откуда, по какому действию, куда | Как попасть на каждый экран? |
| **User flow** | Путь по одному сценарию, с развилками | Как пользователь решает свою задачу? |

**User flow** («поток пользователя») — схема шагов, которые человек делает ради одной цели. В нём есть обозначения, которые понимает любая команда:

- прямоугольник — **экран** или шаг;
- ромб — **развилка** (решение): «Есть свободное время?» — да / нет;
- стрелка — **переход**, на ней подписано действие;
- овал — **начало и конец** сценария.

> Частая ошибка: рисовать в user flow всё приложение сразу. Один flow — одна цель одного пользователя. Для «Отменить запись» рисуют отдельный flow.

## Ход работы

### Шаг 1. Список экранов в FigJam

1. Создайте файл FigJam (**New FigJam board**). Назовите его «Схема интерфейса — запись к врачу».
2. Выпишите все экраны приложения. Подумайте о пациенте: что он делает с момента, как открыл сайт? Минимальный список:
   - Главная — ближайшая запись, кнопка «Записаться»;
   - Вход — номер полиса и пароль;
   - Выбор врача — специальности, список врачей, поиск;
   - Выбор времени — дни, свободные слоты;
   - Подтверждение — проверка данных перед записью;
   - Запись создана — номер талона;
   - Мои записи — список с кнопкой «Отменить».
3. Для каждого экрана поставьте **стикер** или **фигуру-прямоугольник** (Shape). В первой строке — название экрана жирным, ниже — назначение одной фразой и 2–3 главных элемента.
4. Расставьте карточки слева направо в порядке основного сценария. Вход и Мои записи — отдельно, сверху или снизу.

### Шаг 2. Переходы

1. Выберите инструмент **Connector** (линия со стрелкой, клавиша X).
2. Протяните стрелку от карточки к карточке для каждого перехода. Например, Главная → Выбор врача.
3. На каждую стрелку двойным щелчком добавьте подпись — **действие пользователя**: «нажимает "Записаться"», «выбирает слот».
4. Проверьте, что:
   - в каждый экран, кроме стартового, ведёт хотя бы одна стрелка (иначе на экран нельзя попасть);
   - из каждого экрана выходит хотя бы одна стрелка (иначе это тупик);
   - у «Запись создана» есть выход: в «Мои записи» или на главную.

> Частая ошибка: стрелки без подписей. Через неделю никто не вспомнит, почему с «Подтверждения» есть стрелка на «Вход». А подпись «не авторизован — просим войти» всё объясняет.

### Шаг 3. User flow с развилкой

1. Ниже карты экранов нарисуйте user flow сценария «Пациент записывается к терапевту».
2. Начало — овал «Пациент хочет к терапевту».
3. Шаги-прямоугольники: Главная → Выбор врача → Выбор времени.
4. Развилка-ромб: «Есть свободное время?».
   - Ветка **Да**: выбирает слот → Подтверждение → Запись создана → овал «Конец: записан».
   - Ветка **Нет**: «Сообщить, когда появится» → возврат на Главную.
5. Сделайте скриншот или экспорт (**Export → PNG**) — его вы покажете преподавателю.

### Шаг 4. Карта экранов в HTML — задание 1 на сайте

Схему удобно хранить и как HTML-документ: его можно открыть в любом браузере, а по ссылкам — переходить между экранами. Каждый экран — карточка `article` с id:

```html
<style>
  .screens { display: grid; grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); gap: 16px; }
  .screen { padding: 12px 16px; border: 2px solid #1f5f8b; border-radius: 12px; }
  .screen h3 { margin: 0 0 4px; }
</style>
<section>
  <h2>Экраны</h2>
  <div class="screens">
    <article class="screen" id="screen-home">
      <h3>Главная</h3>
      <p>Стартовый экран пациента.</p>
      <ul><li>Ближайшая запись</li><li>Кнопка «Записаться»</li></ul>
    </article>
    <article class="screen" id="screen-login">
      <h3>Вход</h3>
      <p>Пациент входит в личный кабинет.</p>
      <ul><li>Номер полиса и пароль</li><li>Кнопка «Войти»</li></ul>
    </article>
  </div>
</section>
```

Две карточки в сетке. Структура заголовков такая же, как в документе: h2 — раздел «Экраны», h3 — каждый экран. id пишем латиницей с приставкой `screen-`: по ним будем ссылаться на экраны.

В задании нужно не меньше шести карточек и сетка mobile first: одна колонка на телефоне, три — на компьютере.

### Шаг 5. Таблица переходов — задание 2 на сайте

Стрелки из FigJam в документе превращаются в таблицу: **откуда, действие, куда**. Названия экранов делаем ссылками на карточки — так по схеме можно «пройти» сценарий.

```html
<style>
  .screen { padding: 8px; border: 2px solid #1f5f8b; margin-bottom: 8px; }
  .screen:target { background-color: #fff3cd; border-color: #8a5a00; }
</style>
<article class="screen" id="screen-a"><h3>Главная</h3></article>
<article class="screen" id="screen-b"><h3>Выбор врача</h3></article>
<table>
  <tr><td><a href="#screen-a">Главная</a></td><td>Нажимает «Записаться»</td><td><a href="#screen-b">Выбор врача</a></td></tr>
</table>
```

Нажмите на ссылку «Выбор врача»: карточка подсветится жёлтым. Это псевдокласс **`:target`** — он срабатывает у элемента, чей id стоит в адресе страницы после `#`.

> **Попробуйте сами.** В примере нажмите по очереди обе ссылки и посмотрите, как подсветка переезжает. Поменяйте цвет в `.screen:target`.

### Шаг 6. User flow в HTML — задание 3 на сайте

Шаги сценария идут по порядку — значит, это нумерованный список `ol`. Развилка — шаг со вложенным списком из двух вариантов. Стрелки между шагами рисуем псевдоэлементом `::after` (занятие 19):

```html
<style>
  .flow { display: flex; flex-wrap: wrap; gap: 12px; padding: 0; list-style: none; }
  .step { padding: 12px; border: 2px solid #1f5f8b; border-radius: 12px; }
  .step:not(:last-child)::after { content: " →"; font-weight: bold; }
  .decision { border-style: dashed; background-color: #fff3cd; }
</style>
<ol class="flow">
  <li class="step">Выбор времени</li>
  <li class="step decision">Есть свободное время?
    <ul><li>Да — выбирает слот</li><li>Нет — «Сообщить, когда появится»</li></ul>
  </li>
  <li class="step">Подтверждение</li>
</ol>
```

Три шага в ряд, развилка с пунктирной рамкой и двумя ветками, после каждого шага, кроме последнего, — стрелка. Селектор `.step:not(:last-child)` выбирает все шаги, кроме последнего: у последнего стрелка не нужна.

> **Попробуйте сами.** Уберите `:not(:last-child)` из селектора — стрелка появится и у последнего шага, ведущая в никуда. Верните.
