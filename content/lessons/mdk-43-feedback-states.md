## Что такое состояние элемента

**Состояние** — то, как элемент выглядит и ведёт себя в конкретный момент. Одна и та же кнопка «Записаться» может быть обычной, под курсором, в фокусе, нажатой, недоступной, загружающейся. Каждое состояние — короткое сообщение пользователю: «на меня можно нажать», «ты на мне», «принято», «сейчас нельзя», «подожди».

В стайлгайде на экзамене кнопки и поля рисуют **во всех состояниях** рядом. В Figma для этого делают компонент с вариантами (подробнее — на занятии 47). А в CSS каждое состояние — это отдельное правило.

| Состояние | Что сообщает | Как в CSS |
|---|---|---|
| Обычное (default) | «я кнопка, на меня можно нажать» | основное правило `.btn` |
| Наведение (hover) | «ты навёл на меня мышь» | `.btn:hover` |
| Фокус (focus) | «ты на мне с клавиатуры» | `.btn:focus-visible` |
| Нажатие (active) | «нажатие принято» | `.btn:active` |
| Недоступно (disabled) | «сейчас нельзя» | `.btn:disabled` |
| Загрузка (loading) | «работаю, подожди» | атрибут `aria-busy`, текст «Отправляем…» |
| Ошибка (error) | «что-то не так» | `[aria-invalid="true"]` у поля |
| Успех (success) | «всё получилось» | класс `.is-valid`, сообщение |

## Наведение, фокус, нажатие

Псевдоклассы `:hover` и `:focus-visible` вы знаете с занятий 14 и 19. Вспомним и добавим новые.

**Наведение** (`:hover`) — курсор над элементом. Обычно кнопка становится чуть темнее. На телефоне наведения нет — поэтому нельзя прятать важное «только по наведению».

**Фокус** (`:focus-visible`) — элемент выбран с клавиатуры клавишей Tab. Для человека, который не пользуется мышью, рамка фокуса — единственный способ понять, где он находится. Правила:

- никогда не убирайте фокус без замены: `outline: none` без другой рамки — грубая ошибка доступности;
- рамка фокуса контрастирует с фоном не меньше чем 3:1;
- `outline-offset` отодвигает рамку от кнопки — так её лучше видно.

**Нажатие** (`:active`) — кнопку нажимают прямо сейчас (мышь зажата или палец на экране). Небольшой сдвиг вниз на 1 пиксель или ещё более тёмный фон дают ощущение «физической» кнопки.

**Недоступное состояние** (`:disabled`) — у кнопки или поля есть атрибут `disabled`. На неё нельзя нажать, и она не получает фокус. Выглядит приглушённо — серый фон, серый текст, курсор `not-allowed` (перечёркнутый круг).

```html
<style>
  .btn { padding: 12px 24px; border: 0; border-radius: 8px; background-color: #1f5fa8; color: #ffffff; font-size: 16px; cursor: pointer; }
  .btn:hover:not(:disabled) { background-color: #174a83; }
  .btn:active:not(:disabled) { background-color: #103660; transform: translateY(1px); }
  .btn:focus-visible { outline: 3px solid #1a1a1a; outline-offset: 2px; }
  .btn:disabled { background-color: #d6d6d6; color: #555555; cursor: not-allowed; }
</style>
<button class="btn" type="button">Пн, 15:00</button>
<button class="btn" type="button" disabled>Пт, 16:00 — мест нет</button>
```

Наведите мышь на первую кнопку — она потемнеет, нажмите и подержите — «вдавится». Нажмите Tab — вокруг появится чёрная рамка. Вторая кнопка серая, курсор над ней перечёркнут, и она не реагирует.

Обратите внимание на **`:not(:disabled)`**: «наведение, но только если кнопка не отключена». Без него серая кнопка темнела бы под мышью, как будто на неё можно нажать.

Частая ошибка с недоступной кнопкой — сделать её текст бледно-серым, «чтобы было видно, что нельзя». Текст всё равно должен читаться: человеку нужно понять, **что** нельзя. `#555555` на `#d6d6d6` даёт контраст больше 5:1 и при этом выглядит приглушённо.

И ещё одна ошибка — отключать кнопку «Отправить», пока форма не заполнена, и не объяснять почему. Человек смотрит на серую кнопку и не понимает, чего от него хотят. Лучше оставить кнопку активной и при нажатии показать, какие поля не заполнены.

> **Попробуйте сами.** В примере выше удалите `:not(:disabled)` из правила наведения и наведите мышь на серую кнопку. Видите, что она «врёт»? Верните как было.

## Загрузка

Если ответ занимает больше секунды, покажите, что работа идёт. Для кнопки отправки формы это делают так:

1. Меняют текст: «Записаться» → «Отправляем…» (многоточие — знак процесса).
2. Отключают кнопку (`disabled`), чтобы человек не нажал второй раз и не отправил две заявки.
3. Ставят атрибут **`aria-busy="true"`** — экранный диктор поймёт, что элемент занят.
4. Иногда добавляют вращающийся значок-индикатор (spinner).

```js
button.disabled = true;
button.textContent = 'Отправляем…';
button.setAttribute('aria-busy', 'true');
```

Когда ответ пришёл — возвращают кнопку в обычное состояние и показывают результат. Если загрузка долгая (загрузка файла, оплата), показывают **прогресс**: «Загружено 40%».

Для целых страниц и списков вместо крутящегося значка часто рисуют **скелетон** — серые прямоугольники на месте будущих карточек. Это тот же эскиз из занятия 40, только «живой»: человек видит, какой формы будет контент, и ожидание кажется короче.

## Ошибки и успех

### Состояние поля

Поле с ошибкой должно отличаться **не только цветом** (помните про людей, которые не различают красный и зелёный):

- красная рамка;
- значок перед текстом ошибки (✕ или !);
- **текст** ошибки сразу под полем;
- атрибут **`aria-invalid="true"`** — диктор скажет «неверное значение»;
- атрибут **`aria-describedby`** со ссылкой на `id` сообщения — диктор прочитает текст ошибки вместе с подписью поля.

В занятии 30 вы уже ставили `aria-invalid` из JavaScript. Сегодня сосредоточимся на том, как такое поле выглядит и что в нём написано.

```html
<style>
  .field { display: flex; flex-direction: column; gap: 8px; max-width: 320px; font-family: Arial, sans-serif; }
  input { padding: 8px; border: 2px solid #767676; border-radius: 4px; font-size: 16px; }
  input[aria-invalid="true"] { border-color: #c62828; }
  .error-text { margin: 0; color: #c62828; }
  .error-text::before { content: "✕ "; }
</style>
<div class="field">
  <label for="email">Электронная почта</label>
  <input id="email" type="email" value="anna.mail.ru" aria-invalid="true" aria-describedby="email-error">
  <p class="error-text" id="email-error">В адресе нет знака @. Пример: anna@mail.ru</p>
</div>
```

Вы увидите поле с красной рамкой и под ним красный текст со значком ✕: «В адресе нет знака @. Пример: anna@mail.ru».

Успех показывают так же, но спокойнее: зелёная рамка, короткое «Логин свободен» или галочка. Не нужно хвалить каждое поле — успех показывают там, где человек сомневался: свободен ли логин, надёжен ли пароль, принята ли заявка.

### Как написать сообщение об ошибке

Хорошее сообщение отвечает на два вопроса: **что случилось** и **как исправить**.

| Плохо | Хорошо |
|---|---|
| «Ошибка» | «Введите номер телефона» |
| «Неверный формат данных» | «В адресе нет знака @. Пример: anna@mail.ru» |
| «Ошибка 422» | «Пароль короче 8 символов. Добавьте ещё 3» |
| «Вы ввели неправильную дату!» | «Выберите дату не раньше сегодняшней» |
| «Поле обязательно» | «Укажите группу, например ИСП-11» |

Правила:

1. **Конкретно.** Не «неверно», а что именно не так.
2. **С подсказкой**, как исправить, лучше с примером.
3. **Без обвинений.** Не «Вы ввели неправильно!», а «Проверьте адрес». Ошибся не человек — интерфейс недостаточно подсказал.
4. **Без технических кодов.** «Ошибка 422» ничего не говорит студенту.
5. **Рядом с полем**, а не только сверху формы. Если ошибок несколько, сверху можно дать список со ссылками на поля.
6. **Вовремя.** Не ругайтесь, пока человек ещё печатает: проверяйте, когда он ушёл из поля или нажал «Отправить».

Частая ошибка — стирать всё, что человек ввёл, после ошибки. Пусть исправит одно поле, а не заполняет форму заново.

## Пустые состояния

**Пустое состояние** — экран, на котором пока нечего показать: список броней пуст, поиск ничего не нашёл, корзина пуста, уведомлений нет. Новички часто оставляют просто пустое место. Пользователь видит белый экран и не понимает: так и должно быть или что-то сломалось?

Хорошее пустое состояние:

- **объясняет**, что здесь будет: «Здесь появятся книги, которые вы забронируете»;
- **говорит, почему пусто**: «Броней пока нет» или «По запросу „HTLM“ ничего не нашлось»;
- **предлагает действие**: кнопка или ссылка «Перейти в каталог», «Проверьте написание: возможно, HTML?».

| Случай | Пример текста | Действие |
|---|---|---|
| Первый вход | «У вас пока нет броней» | «Найти книгу в каталоге» |
| Ничего не найдено | «По запросу „HTLM“ ничего нет» | «Может, вы имели в виду HTML?» |
| Всё сделано | «Все задания сданы!» | «Посмотреть оценки» |
| Ошибка загрузки | «Не удалось загрузить список» | «Попробовать ещё раз» |

Пустое состояние — хорошее место для дружелюбного тона и простой иллюстрации. Но главное в нём — **следующий шаг**.

## Подтверждение опасных действий

**Опасное** (деструктивное) действие — то, что трудно или невозможно отменить: удалить аккаунт, отменить бронь, очистить корзину, отправить деньги. От случайного нажатия защищают тремя способами:

1. **Отмена после действия** («Undo»). Бронь отменена, внизу на 10 секунд появилось «Бронь отменена. Вернуть?». Это лучший способ: не мешает, когда человек уверен, и спасает, когда ошибся.
2. **Подтверждение перед действием.** Окно «Отменить бронь книги „Основы HTML“?» с кнопками «Отменить бронь» и «Оставить».
3. **Ввод для очень опасных действий.** «Чтобы удалить аккаунт, введите слово УДАЛИТЬ».

Правила окна подтверждения:

- **называйте объект**: не «Вы уверены?», а «Отменить бронь книги „Основы HTML“?»;
- **кнопки — глаголами**: «Отменить бронь» / «Оставить», а не «ОК» / «Отмена» (особенно странно выглядит «Отмена» для отмены брони);
- опасную кнопку выделяют красным, но **не делают её кнопкой по умолчанию**;
- не спрашивайте подтверждение на каждый чих: если окно выскакивает постоянно, его перестают читать и жмут «ОК» не глядя.

В браузере есть встроенное окно подтверждения — функция **`confirm()`**. Она показывает вопрос с кнопками «ОК» и «Отмена» и возвращает `true`, если человек согласился, и `false`, если отказался. Кнопки в нём переименовать нельзя, поэтому на настоящих сайтах делают своё окно (`dialog`). Но для учебных задач и прототипов `confirm()` отлично подходит.

Ещё два метода пригодятся сегодня:

- **`элемент.closest('.item')`** — ищет ближайшего **предка** элемента (самого себя, родителя, родителя родителя…), подходящего под селектор. Удобно, чтобы от кнопки «Отменить» добраться до пункта списка, в котором она лежит.
- **`элемент.remove()`** — удаляет элемент со страницы.

```html
<style>
  .list { padding: 0; list-style: none; font-family: Arial, sans-serif; }
  .item { display: flex; justify-content: space-between; gap: 16px; margin-bottom: 8px; padding: 12px; border: 1px solid #d0d7de; border-radius: 8px; }
  .empty { padding: 16px; border: 2px dashed #8c959f; border-radius: 8px; font-family: Arial, sans-serif; }
</style>
<ul class="list">
  <li class="item"><span class="title">«Основы HTML»</span> <button class="cancel" type="button">Отменить бронь</button></li>
</ul>
<p class="empty" hidden>Броней пока нет. <a href="#catalog">Перейти в каталог</a></p>
<script>
  const empty = document.querySelector('.empty');
  const button = document.querySelector('.cancel');
  button.addEventListener('click', () => {
    const item = button.closest('.item');
    const title = item.querySelector('.title').textContent;
    if (confirm('Отменить бронь книги ' + title + '?')) {
      item.remove();
      empty.hidden = false;
    }
  });
</script>
```

Нажмите «Отменить бронь»: браузер спросит «Отменить бронь книги «Основы HTML»?». Нажмёте «Отмена» — ничего не изменится. Нажмёте «ОК» — пункт исчезнет, и появится пустое состояние со ссылкой в каталог.

В задании 3 пунктов будет два, поэтому пустое состояние нужно показывать только тогда, когда их не осталось. Посчитать пункты поможет знакомое `document.querySelectorAll('.item').length`.

> **Попробуйте сами.** Уберите в примере `if (confirm(…))` и оставьте только две строки внутри. Теперь бронь удаляется с одного случайного касания. Представьте, что это книга, которую вы ждали месяц.

## Микротексты

**Микротексты** (microcopy) — короткие тексты интерфейса: подписи кнопок, подсказки под полями, сообщения, пустые состояния, тексты подтверждений. Их мало, но именно они ведут человека по сценарию. Пишет их часто не копирайтер, а дизайнер.

Правила микротекстов:

- **Кнопки — глаголами**, называющими результат: «Забронировать», «Сохранить изменения», «Отменить бронь».
- **Одни и те же слова** для одних и тех же вещей. Если в меню «Брони», не называйте их на другой странице «Заказы» и «Резервирования».
- **Подсказка — до ошибки.** «Пароль — не меньше 8 символов» под полем заранее лучше, чем ошибка после.
- **Плейсхолдер не заменяет подпись.** Серый текст внутри поля исчезает, как только начинаешь печатать, и человек забывает, что вводил. Подпись `label` — всегда.
- **Коротко и по-человечески.** «Бронь сохранена» вместо «Операция бронирования успешно завершена».
- **Один тон** на всём сайте: на «вы» или на «ты», серьёзно или дружелюбно.

| Было | Стало |
|---|---|
| «Submit» / «Отправить» | «Записаться на консультацию» |
| «Операция выполнена успешно» | «Вы записаны на среду, 15:00» |
| «Нет данных» | «Здесь появятся ваши брони» |
| «Вы уверены?» — «ОК» | «Удалить черновик?» — «Удалить» |

## Главное за занятие

- У кнопки есть состояния: обычное, `:hover`, `:focus-visible`, `:active`, `:disabled`, загрузка. Каждое — сообщение пользователю.
- Рамку фокуса не убирают; недоступная кнопка приглушена, но её текст читается; `:not(:disabled)` защищает от «ложного» наведения.
- Загрузка: «Отправляем…», `disabled`, `aria-busy`, чтобы не было двойной отправки.
- Ошибка поля — не только цветом: рамка, значок, текст под полем, `aria-invalid` и `aria-describedby`.
- Сообщение об ошибке говорит, что случилось и как исправить, без обвинений и кодов.
- Пустое состояние объясняет, почему пусто, и предлагает следующий шаг.
- Опасные действия: лучше отмена после, иначе подтверждение с названием объекта и кнопками-глаголами.

## Словарик

- **Состояние элемента** — вид и поведение элемента в конкретный момент.
- **Фокус** — элемент, выбранный с клавиатуры; его показывает рамка.
- **Недоступное состояние (disabled)** — элемент нельзя нажать или изменить.
- **Индикатор загрузки, скелетон** — способы показать, что идёт работа.
- **Пустое состояние** — экран без данных, который объясняет ситуацию и предлагает действие.
- **Деструктивное действие** — действие, которое трудно отменить: удаление, отмена брони.
- **Микротексты** — короткие тексты интерфейса: кнопки, подсказки, сообщения.

## Если осталось время

Возьмите любую форму на сайте, которым вы пользуетесь (запись к врачу, интернет-магазин, госуслуги). Попробуйте отправить её пустой и с ошибками. Выпишите все сообщения об ошибках и оцените каждое: сказано ли, что случилось и как исправить? Перепишите два худших сообщения по правилам из урока.

:::quiz
? Какой псевдокласс показывает рамку, когда кнопку выбрали клавишей Tab?
- [ ] `:hover`
- [x] `:focus-visible`
- [ ] `:active`
> `:focus-visible` срабатывает при навигации с клавиатуры. `:hover` — наведение мыши, `:active` — момент нажатия.

? Зачем в правиле `.btn:hover:not(:disabled)` нужна часть `:not(:disabled)`?
- [ ] Без неё `:hover` не работает
- [x] Чтобы недоступная кнопка не темнела под мышью, будто на неё можно нажать
- [ ] Чтобы кнопка стала недоступной
> Недоступная кнопка не должна реагировать на мышь, иначе она обманывает пользователя.

? Как правильно показать, что форма отправляется?
- [x] Сменить текст на «Отправляем…» и отключить кнопку, чтобы не было повторной отправки
- [ ] Ничего не показывать, сервер ответит быстро
- [ ] Спрятать всю форму без объяснений
> Человек видит, что работа идёт, и не нажимает кнопку второй раз.

? Какое сообщение об ошибке лучше?
- [ ] «Ошибка 422»
- [ ] «Вы ввели неправильный адрес!»
- [x] «В адресе нет знака @. Пример: anna@mail.ru»
> Хорошее сообщение говорит, что случилось и как исправить, без кодов и обвинений.

? Почему ошибку в поле нельзя показывать только красной рамкой?
- [ ] Красный цвет плохо печатается
- [x] Не все различают красный цвет, а диктор не видит рамку — нужен текст и `aria-invalid`
- [ ] Рамка не поддерживается в мобильных браузерах
> Смысл передают несколькими способами: цвет, значок, текст и атрибуты для диктора.

? Что должно быть на пустом экране «Мои брони»?
- [ ] Ничего, раз броней нет
- [ ] Слово «Пусто»
- [x] Объяснение, что здесь появится, и ссылка «Перейти в каталог»
> Пустое состояние объясняет ситуацию и предлагает следующий шаг.

? Какое окно подтверждения отмены брони лучше?
- [ ] «Вы уверены?» — «ОК» / «Отмена»
- [x] «Отменить бронь книги „Основы HTML“?» — «Отменить бронь» / «Оставить»
- [ ] «Внимание!» — «Да» / «Нет»
> Назван объект, кнопки — глаголы: не нужно перечитывать вопрос.

? Что вернёт `confirm('Удалить черновик?')`, если человек нажмёт «Отмена»?
- [ ] Строку `'Отмена'`
- [x] `false`
- [ ] Ничего, страница закроется
> `confirm` возвращает `true` при «ОК» и `false` при «Отмена». По этому значению решают, выполнять ли действие.
:::
