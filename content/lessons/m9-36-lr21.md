## Лекция

**Генеральная репетиция.** Спортсмен перед соревнованиями не учит новые приёмы — он прогоняет программу целиком на время. Сегодня мы делаем то же самое с базой данных. Вы получаете **незнакомый** вариант ТЗ и за 40 минут превращаете его в рабочую базу в phpMyAdmin: от чтения текста до проверенных внешних ключей. Именно так это будет на экзамене: вариант вы узнаете в день экзамена, а база должна появиться в первые полчаса, потому что на ней держится всё остальное.

Хорошая новость: порталы заявок в разных вариантах похожи на 80 %. Отличаются названия и пара полей. Если у вас есть **шаблон в голове**, новый вариант — это замена слов.

**Универсальный шаблон портала заявок:**

| Блок | Таблица | Что меняется от варианта |
|---|---|---|
| Пользователи | `users` | почти никогда: логин, хеш пароля, ФИО, телефон, email, роль |
| Что заказывают | `services` / `courses` / `halls` / `device_types` | название таблицы и, может быть, цена |
| Статусы | `statuses` | названия статусов из ТЗ |
| Способы оплаты | `payment_types` | бывает, что нет вообще |
| Заявка | `requests` / `bookings` / `applications` | 2–4 специфических поля: адрес, кол-во гостей, модель техники, дата начала обучения |

**Алгоритм на 40 минут:**

| Время | Шаг | Результат |
|---|---|---|
| 0–5 мин | Прочитать ТЗ с маркером: подчеркнуть **существительные** (кандидаты в таблицы и поля), обвести **списки выбора** (кандидаты в справочники) и **статусы** | список сущностей на черновике |
| 5–12 мин | Набросать схему на бумаге: 4–5 прямоугольников, поля, стрелки FK | черновая ER-схема |
| 12–30 мин | Написать скрипт по шаблону и выполнить на вкладке SQL (быстрее, чем мышкой). Порядок: база → справочники → `users` → заявки | база создана |
| 30–36 мин | Справочники `INSERT` из ТЗ, `adminka` с хешем | база готова к работе |
| 36–40 мин | Проверка: ломающий `INSERT` (#1452), повторный логин (#1062), Дизайнер, быстрый экспорт | база проверена, дамп сохранён |

Совет: держите у себя свой `lr17.sql` и `lr18_seed.sql` из прошлых работ. На тренировке ими можно пользоваться как шаблоном — вы копируете, переименовываете и дописываете, а не пишете с нуля.

**Как «вытащить» базу из текста ТЗ. Пример.** Фраза: «*Пользователь оформляет бронь: выбирает зал (основной, веранда, банкетный), дату, время, количество гостей от 1 до 10, указывает пожелания и способ оплаты. Администратор подтверждает бронь или отменяет её с указанием причины.*»

- «зал (основной, веранда, банкетный)» — список выбора → справочник `halls`;
- «дату», «время» → `booking_date DATE`, `booking_time TIME`;
- «количество гостей от 1 до 10» → `guests TINYINT UNSIGNED` + `CHECK (guests BETWEEN 1 AND 10)`;
- «пожелания» — необязательный текст → `wishes TEXT NULL`;
- «способ оплаты» → справочник `payment_types`;
- «подтверждает / отменяет» → статусы; «с указанием причины» → `cancel_reason TEXT NULL`.

`CHECK` работает в MySQL с версии 8.0.16 и в MariaDB с 10.2; при нарушении будет ошибка (в MariaDB — `#4025 CONSTRAINT … failed`, в MySQL — `#3819 Check constraint … is violated`). Даже если у вас старая версия, где `CHECK` игнорируется, проверка всё равно будет и в PHP — ограничение в базе это вторая линия защиты.

**Заготовка, которую стоит помнить наизусть.** Шапка скрипта и «неизменяемая» часть одинаковы для любого варианта — их можно написать не думая, пока в голове складывается схема заявки:

```sql
DROP DATABASE IF EXISTS portal;
CREATE DATABASE portal CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE portal;

CREATE TABLE statuses (
    id   INT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(50) NOT NULL UNIQUE
) ENGINE=InnoDB;
-- справочники варианта: копия statuses с другим именем таблицы
-- users: копия из lr17.sql без изменений
-- заявка: id, user_id, <справочники>_id, поля варианта, cancel_reason, created_at, FK
```

Справочник — это всегда `id` + `name` (+ иногда `price`), поэтому его копируют и переименовывают. Таблица `users` переносится из прошлой работы целиком. Думать по-настоящему нужно только над таблицей заявок — и именно на неё стоит потратить сэкономленные минуты.

**Разбор «подводных камней» в тексте ТЗ.** Внимательно ищите слова, которые меняют свойства поля:

- «**необязательно**», «при желании», «если…» → поле `NULL`;
- «**от … до …**», «не более», «не менее» → `CHECK` в базе и проверка в форме;
- «**уникальный**», «не может повторяться» → `UNIQUE`;
- «**администратор указывает**» (стоимость, причину, комментарий) → поле `NULL` при создании заявки: пользователь его не заполняет, оно появляется позже;
- «**по умолчанию**», «новая заявка получает статус…» → `DEFAULT`.

**Правила именования, которые экономят время.** Таблицы — английские существительные во множественном числе. Внешние ключи — `<таблица в единственном числе>_id`. Даты — `..._date`, время — `..._time`. Имена ограничений — `fk_<дочерняя>_<родитель>`. Когда правила одинаковые всегда, не нужно думать над каждым названием.

**Чего не делать на скорость:**

1. Не придумывать лишнего. Если ТЗ не просит «отзывы» и «рейтинг мастеров», их не нужно делать в первые 40 минут.
2. Не создавать таблицы мышкой по одной, если умеете писать SQL: скрипт быстрее и его можно перезапустить.
3. Не пропускать проверку. Пять минут на «ломающие» запросы окупаются: ошибку в структуре дешевле найти сейчас, чем в середине PHP.
4. Не забывать `adminka`. Без администратора не войти в админ-панель, а значит, эксперт не проверит половину функций.

**Типичные ошибки тренировки:**

1. Чтение ТЗ «по диагонали» — пропущено поле (например, количество гостей), и его приходится добавлять через `ALTER TABLE` в конце.
2. Статусы названы не так, как в ТЗ («Отменено» вместо «Отменена»). Эксперт сверяет с текстом задания.
3. Скрипт упал на середине, а студент запускает его повторно — без `DROP DATABASE IF EXISTS` первой строкой получается «таблица уже существует».
4. Справочники созданы, но не заполнены — форма заявки будет с пустым списком.

**Связь с экзаменом.** Эта работа — полная модель первого этапа задания 1. Если за 40 минут база готова, у вас остаётся почти три часа на PHP, дизайн и проверку. Если база заняла полтора часа — на экзамене до админ-панели можно не дойти.

## Задание

**Цель:** спроектировать и создать базу данных портала по незнакомому варианту ТЗ за 40 минут; затем наполнить её и выгрузить дамп.

**Исходные данные.** Преподаватель раздаёт вариант A или B (по рядам). Текст варианта открывается только по команде «Старт».

**Вариант A. Портал бронирования столиков «Свободный столик».**

> Гость регистрируется на портале: логин (латиница и цифры, не менее 6 символов), пароль (не менее 6 символов), ФИО (кириллица и пробелы), телефон в формате +7(XXX)-XXX-XX-XX, email. Логин уникальный. Зарегистрированный гость может забронировать столик: выбрать зал (Основной зал, Веранда, Банкетный зал), дату, время, количество гостей (от 1 до 10), указать контактный телефон, пожелания (необязательно) и способ оплаты (Оплата в ресторане, Предоплата картой). Новая бронь получает статус «Новая». Гость видит свои брони и их статусы. Администратор (логин adminka, пароль password) видит все брони с ФИО и телефоном гостя и меняет статус: «Подтверждена», «Гости пришли», «Отменена». При отмене администратор обязательно указывает причину.

**Вариант B. Портал сервисного центра «Чиним сами».**

> Клиент регистрируется: логин (латиница и цифры, не менее 6 символов), пароль (не менее 6 символов), ФИО (кириллица и пробелы), телефон в формате +7(XXX)-XXX-XX-XX, email. Логин уникальный. Клиент оставляет заявку на ремонт: выбирает тип техники (Смартфон, Ноутбук, Планшет, Бытовая техника), указывает модель устройства, описание неисправности, желаемую дату визита в сервис, способ получения (Самостоятельно в сервисе, Курьером) и, если выбрал курьера, адрес. Новая заявка получает статус «Новая». Клиент видит свои заявки и их статусы. Администратор (логин adminka, пароль password) видит все заявки с ФИО и телефоном клиента, указывает стоимость ремонта и меняет статус: «Диагностика», «В ремонте», «Готово к выдаче», «Отменена». При отмене указывается причина.

**Ход работы.**

*Часть 1 (40 минут, по таймеру на доске):*

1. Прочитайте ТЗ с маркером: существительные, списки выбора, статусы.
2. Нарисуйте на листе черновую схему таблиц со связями (лист сдаётся).

4. Заполните справочники строго по тексту ТЗ, добавьте `adminka` (хеш из ЛР18).

6. Быстрый экспорт. Поднимите руку — преподаватель фиксирует время.

*Часть 2 (оставшееся время):*

9. Сделайте чистовой дамп и скриншот Дизайнера.

**Что сдать:** лист со схемой; `db/lr21_<вариант>.sql` (структура и данные, выполняется на пустом сервере); 3 запроса части 2; дамп; скриншот Дизайнера; время завершения части 1.
