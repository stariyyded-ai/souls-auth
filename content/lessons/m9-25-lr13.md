## Лекция

**Две страницы с данными.** До сих пор мы верстали формы — страницы, где пользователь *вводит* данные. Сегодня страницы, где он их *смотрит*: «Мои заявки» у пользователя и панель администратора, где видны все заявки и можно менять статус. На экзамене это одни из самых «дорогих» страниц: в них сходятся дизайн, данные из БД и логика ролей. Пока данных из базы нет, мы верстаем 3–4 заявки вручную — потом в модуле 5 PHP будет повторять эту разметку в цикле `foreach`. Поэтому главное правило сегодняшней работы: **разметка одной заявки должна быть одинаковой**, меняются только текст и класс статуса.

**Карточка заявки.** На телефоне список заявок удобнее всего показывать карточками — одна заявка, один блок. Что в ней должно быть по образцу экзамена: услуга, дата и время, адрес, тип оплаты, статус и, если заявка отменена, причина отмены.

<section class="requests" aria-label="Список заявок">

**Бейдж статуса.** В ЛР7 вы рисовали бейджи статусов в UI-ките. В коде это один базовый класс и модификаторы — по одному на статус. Цвета берём из переменных, объявленных в ЛР11:

```css
.badge {
  display: inline-block;
  padding: 2px 10px;
  border-radius: 999px;        /* «таблетка» */
  font-size: 0.75rem;
  font-weight: 600;
  white-space: nowrap;         /* «В работе» не рвётся на две строки */
  color: #fff;
}
.badge--new    { background: var(--status-new); }
.badge--work   { background: var(--status-work); color: #1f2937; }
.badge--done   { background: var(--status-done); }
.badge--cancel { background: var(--status-cancel); }
```

Обратите внимание на `.badge--work`: на жёлто-оранжевом фоне белый текст плохо читается, контраст не проходит WCAG — поэтому текст тёмный. Проверяйте контраст каждого бейджа (DevTools показывает коэффициент контраста в подсказке пипетки цвета). И ещё: статус обязательно написан словами, а не только цветом.

**Пустое состояние.** Новый пользователь ещё не создал ни одной заявки. Пустой экран с одним заголовком выглядит как ошибка. Сделайте блок-заглушку с подсказкой и кнопкой:

```html
<div class="empty">
  <p>У вас пока нет заявок</p>
  <a class="btn" href="new-request.html">Создать заявку</a>
</div>
```

В модуле 5 PHP будет выбирать: если заявок ноль — показать `.empty`, иначе — список.

**Админ-панель: таблица.** Администратору нужно видеть *все* заявки с ФИО и контактами клиента и быстро менять статус. Для табличных данных правильный тег — `<table>`. Не делайте таблицу из `div`: так теряется смысл и доступность.

```html
<div class="table-wrap">
  <table class="admin-table">
    <caption>Все заявки</caption>
    <thead>
      <tr>
        <th scope="col">№</th>
        <th scope="col">Клиент</th>
        <th scope="col">Услуга</th>
        <th scope="col">Дата</th>
        <th scope="col">Статус</th>
        <th scope="col">Действие</th>
      </tr>
    </thead>
    <tbody>
      <tr>
        <td data-label="№">17</td>
        <td data-label="Клиент">Петрова Анна Сергеевна<br>+7(912)-345-67-89</td>
        <td data-label="Услуга">Общий клининг</td>
        <td data-label="Дата">12.11.2026 10:00</td>
        <td data-label="Статус"><span class="badge badge--new">Новая</span></td>
        <td data-label="Действие">
          <form class="status-form" action="#" method="post">
            <input type="hidden" name="id" value="17">
            <select class="field__input" name="status" aria-label="Новый статус заявки 17">
              <option value="work">В работе</option>
              <option value="done">Выполнена</option>
              <option value="cancel">Отменена</option>
            </select>
            <textarea class="field__input" name="reason" rows="2"
                      placeholder="Причина отмены"
                      aria-label="Причина отмены заявки 17"></textarea>
            <button class="btn" type="submit">Сохранить</button>
          </form>
        </td>
      </tr>
    </tbody>
  </table>
</div>
```

`<caption>` — название таблицы, `<th scope="col">` — заголовок столбца (диктор прочитает «Статус: Новая»). `<input type="hidden">` невидим, но отправит на сервер номер заявки — так PHP поймёт, *какую* заявку менять. Поле причины отмены в образце экзамена заполняется при отмене; в модуле 6 мы покажем его только при выборе «Отменена», а сервер будет проверять, что при отмене причина указана.

**Таблица на телефоне.** Шесть столбцов на 390px не поместятся. Два приёма: (1) обертка `.table-wrap { overflow-x: auto; }` — таблица прокручивается внутри себя; (2) на телефоне показывать строку как карточку, а подпись столбца брать из `data-label`:

```css
.admin-table { width: 100%; border-collapse: collapse; }
.admin-table th,
.admin-table td { padding: var(--space-1); text-align: left; border-bottom: 1px solid var(--color-border); }

/* Телефон: строки превращаются в карточки */
@media (max-width: 767px) {
  .admin-table thead { position: absolute; width: 1px; height: 1px; overflow: hidden; clip-path: inset(50%); }
  .admin-table tr {
    display: block;
    margin-bottom: var(--space-2);
    background: var(--color-surface);
    border-radius: var(--radius);
    box-shadow: var(--shadow);
  }
  .admin-table td {
    display: grid;
    grid-template-columns: 90px 1fr;
    gap: var(--space-1);
  }
  .admin-table td::before {
    content: attr(data-label);   /* подпись из атрибута */
    font-weight: 600;
    color: var(--color-muted);
  }
}
```

Здесь мы сознательно отступили от mobile-first: таблица — исключение, ей естественнее быть таблицей «по умолчанию». Заголовок `thead` мы прячем визуально, но оставляем для экранного диктора — поэтому не `display: none`.

**Фильтр по статусу.** Над таблицей полезно поставить фильтр — это форма с `method="get"`, ведь фильтр не изменяет данные, и ссылку на отфильтрованный список можно сохранить. Саму фильтрацию сделаем в модуле 5 (ЛР30).

**Порядок заявок и даты.** Пользователь ожидает увидеть сверху самые свежие или ближайшие заявки — договоритесь об этом сейчас и отразите в тестовых данных, тогда в модуле 4 вы напишете `ORDER BY` под уже готовую вёрстку. Даты в карточке пишите так, как привыкли люди в России: `12.11.2026, 10:00`, а не `2026-11-12 10:00:00`, как они хранятся в базе. Если хотите, чтобы дата была понятна и машине, используйте тег `<time datetime="2026-11-12T10:00">12.11.2026, 10:00</time>`.

**Типичные ошибки:**

1. Каждая карточка свёрстана по-своему — PHP-цикл потом не получится.
2. Статус только цветом, без текста; белый текст на жёлтом.
3. Таблица из `div` или без `thead`/`th`.
4. Нет `name` у `select` статуса или нет скрытого `id` заявки.
5. Таблица рвёт мобильную страницу — нет `.table-wrap` или карточного режима.
6. Нет пустого состояния.

## Если не успел / для сильных

**Минимум:** `requests.html` с тремя карточками и бейджами и `admin.html` с таблицей в обёртке `.table-wrap` и select статуса.
**Усложнение:** выделите строку отменённой заявки в таблице без отдельного класса — через `tr:has(.badge--cancel)`.

:::quiz
? Почему все карточки заявок должны иметь одинаковую разметку?
- [ ] Иначе браузер не покажет больше трёх карточек
- [x] В модуле 5 одну карточку повторит PHP-цикл для всех заявок
- [ ] Одинаковая разметка нужна для печати страницы
- [ ] Так требуют правила тега `<article>`
> Позже вы оставите одну карточку-шаблон, а PHP выведет её в цикле для каждой заявки из базы. Карточки «каждая по-своему» так не превратить.

? Зачем в форме смены статуса скрытое поле `<input type="hidden" name="id">`?
- [ ] Чтобы спрятать номер заявки от администратора
- [ ] Чтобы форма отправлялась без нажатия кнопки
- [ ] Чтобы защитить заявку от изменения другими
- [x] Чтобы сервер узнал, у какой заявки менять статус
> Поле не видно на странице, но его значение уходит вместе с формой, и PHP понимает, какую именно заявку обновить.

? Почему фильтр по статусу отправляют методом `get`, а смену статуса — `post`?
- [x] Фильтр только показывает данные, а смена статуса их меняет
- [ ] `get` работает быстрее, а `post` надёжнее шифрует данные
- [ ] `get` нужен для `select`, а `post` — для кнопок
- [ ] Разницы нет, методы выбраны случайно
> GET кладёт параметры в адрес: фильтр можно сохранить ссылкой. Действия, которые меняют данные, отправляют через POST.

? Как в лекции превращают строку таблицы в карточку на телефоне?
- [ ] Заменяют `<table>` на `<div>` в медиазапросе
- [ ] Скрывают таблицу и показывают картинку с ней
- [x] Ячейки ставят столбиком, а подпись берут из `data-label` через `::before`
- [ ] Уменьшают шрифт таблицы, чтобы все столбцы влезли
> Каждой ячейке дают `data-label="Статус"`, а `td::before { content: attr(data-label); }` выводит эту подпись перед значением, когда заголовок таблицы скрыт.
:::
