## Элементы интерфейса

Откройте приложение банка, магазина и электронного дневника. Они разные, но собраны из одинаковых деталей: кнопка, поле ввода, галочка, карточка, значок колокольчика с красной цифрой. Такие детали называют **элементами интерфейса** (UI-элементами, от User Interface — интерфейс пользователя) или **компонентами**.

Пользователь уже знает, как ведут себя эти элементы: кнопку нажимают, в поле печатают, галочку ставят. Поэтому главное правило: **элемент должен выглядеть так, как он работает**. Кнопка похожа на кнопку, ссылка — на ссылку, поле — на поле. Если сделать кнопку, похожую на обычный текст, на неё никто не нажмёт.

## Кнопки

**Кнопка** запускает действие: отправить форму, добавить в корзину, открыть меню. Ссылка (`a`) **ведёт** на другую страницу, кнопка (`button`) **делает** что-то здесь. Частая ошибка — делать кнопку из `div`: такой «кнопке» нельзя перейти клавишей Tab, и программа экранного доступа не узнает, что это кнопка.

На одном экране действия неравны: одно главное, остальные — второстепенные. Поэтому у кнопок есть **иерархия** (вспомните прошлое занятие про иерархию):

| Вид | Как выглядит | Для чего | Пример |
|---|---|---|---|
| Первичная (primary) | Залита фирменным цветом, белый текст | Главное действие экрана, одно | «Записаться», «Оформить заказ» |
| Вторичная (secondary) | Прозрачная, с рамкой | Запасное действие | «Подробнее», «Отмена» |
| Текстовая (text, ghost) | Только текст, без рамки и фона | Мелкие действия | «Пропустить», «Сбросить фильтры» |

```html
<style>
  body { font-family: Arial, sans-serif; }
  .btn { min-height: 44px; padding: 0 20px; border: 2px solid transparent; border-radius: 8px; font-size: 16px; cursor: pointer; }
  .btn-primary { background: #1f5fa8; color: #ffffff; }
  .btn-secondary { border-color: #1f5fa8; background: transparent; color: #1f5fa8; }
  .btn-text { background: transparent; color: #1f5fa8; text-decoration: underline; }
</style>
<button class="btn btn-primary" type="button">Оформить заказ</button>
<button class="btn btn-secondary" type="button">Вернуться в корзину</button>
<button class="btn btn-text" type="button">Сбросить</button>
```

Что увидите: три кнопки одной высоты. Синяя залитая сразу притягивает взгляд, кнопка с рамкой — спокойнее, текстовая почти не спорит за внимание. У всех трёх `border: 2px solid transparent`: прозрачная рамка нужна, чтобы кнопки были одной высоты, даже если у одной рамка видна, а у другой нет.

Правила для кнопок:

- **Первичная кнопка на экране одна.** Две синие кнопки рядом — и человек не знает, какую нажать.
- **Текст — глагол.** «Сохранить», «Купить билет», а не «ОК» или «Да».
- **Все состояния:** обычное, наведение, фокус, нажатие, недоступна, загрузка. Вы разбирали их на занятии 43 — в UI-kit их рисуют для каждого вида кнопки.
- **Классы складываются:** общий `.btn` задаёт размер и скругление, а `.btn-primary` и `.btn-secondary` — только цвета. Так кнопки остаются одинаковыми по форме.

## Поля ввода

**Поле** (`input`, `textarea`, `select`) — место, куда пользователь что-то вводит или выбирает. Как сделать поле узнаваемым:

- у поля есть **рамка или фон**, отличающиеся от страницы. Поле без рамки на белом фоне невидимо;
- рамка достаточно контрастная: для элементов интерфейса WCAG требует контраст **3:1** с фоном. Бледно-серая рамка `#e5e5e5` на белом этого не проходит;
- высота поля — не меньше 44px, шрифт — не меньше 16px (иначе на iPhone страница сама увеличивается при вводе);
- над полем подпись `label` (прошлое занятие), под полем — место для подсказки или ошибки.

```html
<style>
  body { font-family: Arial, sans-serif; }
  label { display: block; margin-bottom: 4px; font-weight: bold; }
  input { box-sizing: border-box; width: 100%; max-width: 320px; min-height: 44px; padding: 0 12px; border: 1px solid #5a6475; border-radius: 6px; font-size: 16px; }
  input:focus-visible { outline: 3px solid #1f5fa8; outline-offset: 1px; }
</style>
<label for="city">Город</label>
<input id="city" name="city" type="text">
```

Что увидите: поле с тёмно-серой рамкой. Щёлкните в него — появится синяя обводка фокуса: пользователь видит, куда сейчас печатает.

## Чекбоксы, радиокнопки и переключатели

Три элемента для выбора выглядят похоже, но значат разное:

| Элемент | HTML | Когда использовать |
|---|---|---|
| **Чекбокс** (флажок) | `<input type="checkbox">` | Можно выбрать несколько вариантов или ни одного: «Сахар», «Молоко», «Сироп» |
| **Радиокнопка** | `<input type="radio">` с одинаковым `name` | Ровно один вариант из нескольких: размер S / M / L |
| **Переключатель** (switch, тумблер) | чекбокс с `role="switch"` | Включить/выключить настройку, которая срабатывает **сразу**: «Тёмная тема», «Уведомления» |

Главное отличие переключателя от чекбокса: переключатель работает мгновенно, как выключатель света. Чекбокс в форме ничего не делает, пока не нажата кнопка «Сохранить». Поэтому в анкете «Согласен с правилами» — чекбокс, а в настройках приложения «Получать уведомления» — переключатель.

```html
<style>
  body { font-family: Arial, sans-serif; }
  .choice { display: flex; align-items: center; gap: 8px; min-height: 44px; }
  .choice input { width: 20px; height: 20px; }
</style>
<fieldset>
  <legend>Добавки к кофе</legend>
  <label class="choice"><input type="checkbox" name="extra" value="milk"> Молоко</label>
  <label class="choice"><input type="checkbox" name="extra" value="syrup"> Сироп</label>
</fieldset>
<fieldset>
  <legend>Размер</legend>
  <label class="choice"><input type="radio" name="size" value="s"> Маленький</label>
  <label class="choice"><input type="radio" name="size" value="m" checked> Средний</label>
</fieldset>
<label class="choice"><input type="checkbox" role="switch" name="notify"> Присылать уведомления</label>
```

Что увидите: в первой группе можно отметить оба квадратика, во второй — только один кружок. Обратите внимание: `label` оборачивает и поле, и текст. Поэтому нажимать можно на слово «Молоко», а не целиться в маленький квадратик — область нажатия становится больше.

Частая ошибка: использовать чекбоксы там, где выбрать можно только один вариант. Человек отметит два размера сразу, и непонятно, что ему продавать.

## Карточки

**Карточка** — блок, который собирает всё об одном объекте: картинку, название, пару деталей и действие. Карточки товаров, новостей, курсов, книг. Карточка работает по принципу общей области из гештальта: всё внутри рамки — про один предмет.

Типичный порядок в карточке — как в иерархии: картинка → название (самое крупное) → детали (мельче, приглушённым цветом) → действие (кнопка или ссылка). Все карточки в ряду одинаковые по строению — принцип сходства.

```html
<style>
  body { font-family: Arial, sans-serif; }
  .card { max-width: 260px; padding: 16px; border: 1px solid #d0d7e2; border-radius: 12px; }
  .card img { display: block; width: 100%; height: auto; border-radius: 8px; }
  .card h3 { margin: 12px 0 4px; font-size: 20px; }
  .card p { margin: 0 0 12px; color: #5a6475; }
  .card a { color: #1f5fa8; font-weight: bold; }
</style>
<article class="card">
  <img src="img/art.svg" alt="Горы на закате">
  <h3>Фотокружок</h3>
  <p>По средам, 16:00, кабинет 305</p>
  <a href="#">Записаться в кружок</a>
</article>
```

Что увидите: аккуратную карточку со скруглёнными углами: картинка, крупное название, серые детали и ссылка-действие внизу.

## Иконки

**Иконка** — маленькая картинка-символ: лупа (поиск), корзина, колокольчик (уведомления), шестерёнка (настройки). Иконки экономят место и быстро узнаются, но только если значок **общепринятый**. Лупу понимают все. А что значит звёздочка: «избранное», «оценить» или «новое»?

Правила:

- **Иконка + подпись** — самый понятный вариант. Подпись снимает сомнения, а иконка помогает быстрее найти пункт глазами. В нижнем меню мобильных приложений почти всегда есть подписи.
- **Иконка без подписи** допустима только для самых известных значков (лупа, крестик «закрыть», корзина) — и тогда у кнопки обязательно `aria-label` с текстом, иначе программа экранного доступа прочитает просто «кнопка».
- Если рядом с иконкой есть текст, иконка — украшение, у неё `alt=""` (пустой), чтобы название не читалось дважды.
- Все иконки в интерфейсе — **из одного набора**: одна толщина линий, один стиль (контурные или залитые).

```html
<style>
  body { font-family: Arial, sans-serif; }
  .tool { display: inline-flex; align-items: center; gap: 8px; min-height: 44px; padding: 0 16px; border: 1px solid #5a6475; border-radius: 8px; background: #ffffff; font-size: 16px; }
  .tool img { width: 20px; height: 20px; }
</style>
<button class="tool" type="button"><img src="img/icon.svg" alt=""> Настройки</button>
<button class="tool" type="button" aria-label="Настройки"><img src="img/icon.svg" alt=""></button>
```

Что увидите: две кнопки с одинаковым значком. Первую понятно сразу, про вторую приходится гадать. Технически обе доступны, но первая удобнее для всех.

> **Попробуйте сами.** Уберите у второй кнопки `aria-label`. Внешне ничего не изменится, но для незрячего пользователя кнопка станет безымянной. Именно это проверяет общий пункт «у ссылок и кнопок есть понятное имя» в заданиях курса.

## Бейджи

**Бейдж** (значок, badge) — маленькая метка: число непрочитанных сообщений на колокольчике, «Новинка» на товаре, «В наличии» на книге. Бейдж должен быть заметным, но маленьким: мелкий шрифт (12–14px), яркий фон, скругление. Если это число, его форма — «таблетка» (`border-radius` больше половины высоты).

```html
<style>
  body { font-family: Arial, sans-serif; }
  .badge { display: inline-block; min-width: 20px; padding: 2px 8px; border-radius: 999px; background: #c62828; color: #ffffff; font-size: 13px; font-weight: bold; text-align: center; }
  .badge-new { background: #e8a33d; color: #1d2433; }
</style>
<p>Сообщения <span class="badge">3</span></p>
<p>Учебник по веб-дизайну <span class="badge badge-new">Новинка</span></p>
```

Что увидите: красную «таблетку» с цифрой 3 и оранжевую метку «Новинка». Обратите внимание на цвета: на оранжевом фоне текст тёмный, потому что белый на светлом оранжевом не проходит по контрасту.

## Модальные окна

**Модальное окно** — окно поверх страницы, которое блокирует всё остальное, пока его не закроют. Страница позади затемняется. Используйте модальные окна редко, только когда без ответа пользователя дальше нельзя: «Удалить файл безвозвратно?», вход в аккаунт, важное предупреждение.

Чего ждут от модального окна:

- понятный заголовок, что это за окно;
- кнопка закрытия (крестик) с `aria-label="Закрыть"`, закрытие по клавише Esc и по клику на затемнение;
- фокус переходит внутрь окна, а после закрытия возвращается туда, где был;
- не открывается само по себе через пять секунд после захода на сайт — это раздражает сильнее всего.

В HTML для этого есть готовый элемент `dialog`. Атрибут `open` показывает его сразу — так удобно посмотреть оформление (открывать его по кнопке умеет JavaScript, но это уже не тема сегодняшнего занятия):

```html
<style>
  body { font-family: Arial, sans-serif; }
  dialog { max-width: 320px; padding: 24px; border: 0; border-radius: 12px; box-shadow: 0 8px 32px rgba(0, 0, 0, 0.3); }
  dialog h2 { margin: 0 0 8px; font-size: 20px; }
  .actions { display: flex; gap: 8px; margin-top: 16px; }
</style>
<dialog open>
  <h2>Удалить черновик?</h2>
  <p>Черновик курсовой будет удалён без возможности восстановления.</p>
  <div class="actions">
    <button type="button">Удалить</button>
    <button type="button">Отмена</button>
  </div>
</dialog>
```

Что увидите: белое окошко с тенью поверх страницы, заголовок-вопрос и две кнопки. Заметьте: кнопка говорит «Удалить», а не «Да» — так ошибиться невозможно.

## Уведомления

**Уведомление** сообщает о результате действия или о событии. Бывают:

| Вид | Как выглядит | Пример |
|---|---|---|
| **Тост** (toast, «всплывашка») | Маленькая плашка в углу, исчезает сама или по крестику | «Товар добавлен в корзину» |
| **Баннер** | Полоса вверху страницы, висит, пока проблему не решат | «Нет подключения к интернету» |
| **Встроенное** (inline) | Текст прямо у места события | Ошибка под полем формы |

Чтобы о появившемся уведомлении узнали и незрячие пользователи, контейнеру дают `role="status"` (для спокойных сообщений) или `role="alert"` (для срочных ошибок). Программа экранного доступа сама прочитает текст, когда он появится.

Цвета уведомлений общепринятые: зелёный — успех, красный — ошибка, жёлтый — предупреждение, синий — информация. Но **не только цвет**: добавьте слово или иконку, ведь часть людей не различает красный и зелёный.

## Область нажатия 44×44

Палец — не курсор мыши. Подушечка пальца касается экрана пятном примерно в 1 см. Если кнопка меньше, человек промахивается и нажимает соседнюю.

- Apple рекомендует область нажатия не меньше **44×44** точки, Google — **48×48**.
- WCAG 2.2 требует минимум 24×24 пикселя, но это нижняя граница, а не цель.
- На этом курсе и на экзамене ориентируемся на **44×44 пикселя**.

Важно: область нажатия — это не размер иконки. Иконка может быть 20×20, но кнопка вокруг неё — 44×44 за счёт `padding` или `min-width` и `min-height`.

```css
.icon-btn {
  min-width: 44px;
  min-height: 44px;
  display: inline-flex;
  justify-content: center;
  align-items: center;
}
```

Частая ошибка: крестик «закрыть» 12×12 пикселей в углу уведомления. Попасть в него с телефона можно только с третьего раза.

> **Попробуйте сами.** Вернитесь к примеру с иконками и поставьте кнопкам `min-height: 24px`. Откройте пример на телефоне или сузьте окно и попробуйте попасть по кнопке пальцем (или представьте это). Верните 44px.

## Элементы как одна семья

Каждый элемент по отдельности можно нарисовать хорошо, а вместе они всё равно будут выглядеть чужими друг другу. Чтобы интерфейс воспринимался цельным, у всех элементов должны быть общие «гены»:

| Что общее | Пример договорённости |
|---|---|
| Высота управляющих элементов | Кнопки и поля — 44px, маленькие кнопки — не меньше 36px с увеличенной областью нажатия |
| Скругление | Кнопки, поля, карточки — 8px; бейджи-«таблетки» — полностью круглые |
| Толщина рамок | Поля и вторичные кнопки — одна и та же: 1px или 2px |
| Цвет фокуса | Одна обводка `outline` для всех элементов: пользователь клавиатуры всегда видит её одинаково |
| Отступы внутри | По горизонтали 16–24px у всех кнопок и полей |
| Набор состояний | У каждого интерактивного элемента — обычное, наведение, фокус, нажатие, недоступно |

Посмотрите на поле ввода и кнопку рядом: если поле 40px, а кнопка 48px, разница сразу бросается в глаза, особенно когда они стоят в одной строке, как в форме поиска. Частая ошибка новичков — подобрать каждому элементу «красивые» размеры отдельно и получить пять разных скруглений на одном экране.

Именно эти общие правила на следующем занятии мы запишем в **стайлгайд**, а сами элементы со всеми состояниями соберём в **UI-kit**. Тогда при вёрстке не придётся каждый раз придумывать, какого размера кнопка: ответ уже записан.

## Главное за занятие

- Элемент выглядит так, как работает: кнопка похожа на кнопку, поле — на поле.
- Кнопки бывают первичные, вторичные и текстовые; первичная на экране одна.
- Чекбокс — несколько вариантов, радиокнопка — один из нескольких, переключатель — настройка, которая срабатывает сразу.
- Иконка лучше всего работает с подписью; иконка без подписи — только общепринятая и с `aria-label`.
- Бейджи маленькие и яркие, модальные окна — редко и по делу, уведомления — с `role="status"` и не только цветом.
- Область нажатия не меньше 44×44 пикселя.

## Словарик

- **UI-элемент (компонент)** — типовая деталь интерфейса: кнопка, поле, карточка.
- **Первичная кнопка** — кнопка главного действия, залитая фирменным цветом.
- **Переключатель (switch)** — элемент «включено/выключено», который срабатывает сразу.
- **Бейдж** — маленькая метка с числом или словом.
- **Модальное окно** — окно поверх страницы, которое блокирует её до закрытия.
- **Тост** — небольшое всплывающее уведомление о результате действия.
- **Область нажатия** — зона, касание которой срабатывает как нажатие на элемент.

## Проверь себя

1. Чем первичная кнопка отличается от вторичной и текстовой? Сколько первичных кнопок должно быть на экране?
2. Когда нужен чекбокс, когда радиокнопки, а когда переключатель?
3. В каком случае иконке не нужна подпись и что тогда обязательно добавить в код?
4. Почему крестик «закрыть» размером 12×12 — плохая идея? Как увеличить область нажатия, не увеличивая иконку?
5. Когда модальное окно оправдано, а когда раздражает?
6. Почему уведомление об ошибке нельзя показывать только красным цветом?

## Если осталось время

Откройте на телефоне любое приложение, которым пользуетесь каждый день. Найдите в нём по одному примеру: первичной и вторичной кнопки, переключателя, бейджа, тоста. Нарисуйте их от руки или в Figma и подпишите, по каким признакам вы их узнали. Это заготовка для вашего будущего UI-kit.

:::quiz
? Чем кнопка `button` отличается по смыслу от ссылки `a`?
- [ ] Ничем, это одно и то же
- [x] Ссылка ведёт на другую страницу, кнопка выполняет действие
- [ ] Кнопка всегда синяя, ссылка всегда подчёркнута
> Для перехода — ссылка, для действия на месте (отправить, открыть, добавить) — кнопка.

? Сколько первичных (залитых фирменным цветом) кнопок должно быть на одном экране?
- [x] Одна — для главного действия
- [ ] Чем больше, тем заметнее
- [ ] Ни одной, лучше все кнопки с рамкой
> Первичная кнопка показывает главное действие. Если таких две, человек не знает, какую нажать.

? Пользователь выбирает размер футболки: S, M или L. Какой элемент нужен?
- [ ] Чекбоксы
- [ ] Переключатель
- [x] Радиокнопки с одинаковым `name`
> Вариант ровно один из нескольких — это радиокнопки.

? В настройках приложения пункт «Тёмная тема», который включается сразу. Какой элемент подходит лучше?
- [ ] Чекбокс и кнопка «Сохранить»
- [x] Переключатель
- [ ] Радиокнопка
> Переключатель срабатывает мгновенно, как выключатель света.

? Когда иконка допустима без видимой подписи?
- [ ] Всегда, иконки понятны всем
- [x] Только для общепринятых значков, и у кнопки есть `aria-label`
- [ ] Никогда
> Лупу или крестик узнают все. Но имя для программы экранного доступа всё равно нужно.

? Какой минимальный размер области нажатия мы используем на курсе и экзамене?
- [ ] 16×16 пикселей
- [ ] 24×24 пикселя
- [x] 44×44 пикселя
> 24×24 — нижняя граница WCAG, а удобная цель — 44×44 (так советует Apple).

? Зачем контейнеру уведомления атрибут `role="status"`?
- [ ] Чтобы уведомление стало зелёным
- [ ] Чтобы оно исчезало само
- [x] Чтобы программа экранного доступа прочитала его, когда оно появится
> `role="status"` сообщает вспомогательным программам, что здесь появляются сообщения.

? Когда модальное окно оправдано?
- [x] Когда без ответа пользователя дальше нельзя: например, подтверждение удаления
- [ ] Через 5 секунд после входа на сайт, чтобы предложить подписку
- [ ] Для показа каждой новости
> Модальное окно блокирует страницу, поэтому его используют редко и только по делу.
