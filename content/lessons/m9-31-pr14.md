## Лекция

**SELECT — это вопрос к базе.** Каждый раз, когда вы открываете ленту заказов в приложении доставки, сервер задаёт базе вопрос: «дай мне заказы этого пользователя, новые сверху». На SQL такой вопрос звучит через `SELECT`. На экзамене все страницы с данными — «Мои заявки», админ-панель, выпадающий список услуг — это `SELECT`. Сегодня работаем на учебной базе `portal_training` (импортируйте её, если ещё нет).

**Общий вид запроса.** Части пишутся строго в таком порядке:

```sql
SELECT   столбцы
FROM     таблица
JOIN     другая таблица ON условие связи
WHERE    условие отбора строк
GROUP BY по чему группировать
HAVING   условие отбора групп
ORDER BY по чему сортировать
LIMIT    сколько строк;
```

Запомнить порядок помогает фраза «**С**ам **Ф**едя **Д**жем **В**арит, **Г**ости **Х**валят, **О**ценки **Л**учшие» (Select, From, Join, Where, Group, Having, Order, Limit).

**Выбор столбцов.**

```sql
SELECT * FROM services;                 -- все столбцы
SELECT name, price FROM services;       -- только нужные
SELECT name AS service, price * 0.9 AS sale_price FROM services; -- псевдоним и вычисление
```

`*` удобна для проверки, но в коде страниц пишите конкретные столбцы: никто не хочет случайно отдать на страницу хеш пароля из `users`.

**WHERE — фильтр строк.**

```sql
SELECT name, price FROM services
WHERE price < 4000
ORDER BY price DESC;
```

Результат: «Химчистка ковров и мебели» 3500.00, «Общий клининг» 2500.00, «Мойка окон» 1800.00.

Операторы в `WHERE`:

| Оператор | Пример | Смысл |
|---|---|---|
| `=`, `<>`, `<`, `>`, `<=`, `>=` | `status_id = 1` | сравнение |
| `AND`, `OR`, `NOT` | `price > 2000 AND price < 5000` | комбинация условий |
| `IN (...)` | `status_id IN (1, 2)` | одно из списка |
| `BETWEEN a AND b` | `service_date BETWEEN '2026-10-01' AND '2026-10-31'` | диапазон, границы включены |
| `LIKE` | `full_name LIKE 'С%'` | по шаблону: `%` — любые символы, `_` — ровно один |
| `IS NULL` / `IS NOT NULL` | `cancel_reason IS NULL` | значение отсутствует |

Строки и даты — в одинарных кавычках: `'Новая'`, `'2026-10-25'`. Числа — без кавычек. Проверка на пустоту — только `IS NULL`: запись `cancel_reason = NULL` никогда не вернёт ни одной строки, потому что `NULL` ни с чем не равен, даже сам с собой.

Пример: пользователи, чьи фамилии начинаются на «С»:

```sql
SELECT login, full_name FROM users WHERE full_name LIKE 'С%';
-- sidorov_k  | Сидоров Кирилл Андреевич
-- smirnov_d  | Смирнов Дмитрий Олегович
```

Осторожно с `AND` и `OR` вместе: `AND` выполняется раньше. Запрос `WHERE status_id = 1 OR status_id = 2 AND user_id = 3` означает «все новые заявки всех пользователей плюс заявки в работе пользователя 3». Хотели другое — ставьте скобки: `WHERE (status_id = 1 OR status_id = 2) AND user_id = 3`.

**ORDER BY и LIMIT.** `ORDER BY поле` сортирует по возрастанию (`ASC`, можно не писать), `DESC` — по убыванию. Можно несколько полей: `ORDER BY service_date, service_time`. `LIMIT 3` — первые три строки, `LIMIT 10 OFFSET 20` — строки с 21-й по 30-ю (это основа пагинации в ЛР30).

```sql
-- три ближайшие активные заявки
SELECT id, service_date FROM requests
WHERE status_id IN (1, 2)
ORDER BY service_date
LIMIT 3;
-- 11 | 2026-10-21
--  5 | 2026-10-22
--  3 | 2026-10-25
```

**JOIN — собрать данные из нескольких таблиц.** В `requests` лежат только номера: `user_id = 2`, `status_id = 3`. Человеку нужно видеть «Иванов Алексей Петрович — Выполнено». Для этого таблицы соединяют по ключам:

```sql
SELECT r.id, u.full_name, st.name AS status
FROM requests r
JOIN users    u  ON u.id  = r.user_id
JOIN statuses st ON st.id = r.status_id
WHERE r.id <= 3;
-- 1 | Иванов Алексей Петрович | Выполнено
-- 2 | Иванов Алексей Петрович | Выполнено
-- 3 | Иванов Алексей Петрович | Новая
```

`r`, `u`, `st` — псевдонимы таблиц, чтобы не писать длинные имена. Условие `ON` почти всегда одно и то же: «первичный ключ родителя = внешний ключ ребёнка». Если в двух таблицах есть столбец с одинаковым именем (`name` есть и в `services`, и в `statuses`), обязательно указывайте таблицу: `s.name`, `st.name` — иначе ошибка `#1052 Column 'name' in field list is ambiguous`.

`JOIN` (он же `INNER JOIN`) оставляет только строки, у которых нашлась пара. **`LEFT JOIN`** оставляет все строки левой таблицы, даже если пары нет, — недостающие поля будут `NULL`. Так находят «пользователей без заявок» и «услуги, которые никто не заказывал».

**Агрегатные функции** считают итог по многим строкам:

```sql
SELECT COUNT(*), MIN(price), MAX(price), AVG(price), SUM(price) FROM services;
-- 5 | 1800.00 | 9000.00 | 4560.000000 | 22800.00
```

`COUNT(*)` считает строки, `COUNT(поле)` — только строки, где поле не `NULL`, `COUNT(DISTINCT user_id)` — сколько разных пользователей.

**GROUP BY** считает итог отдельно для каждой группы:

```sql
SELECT u.full_name, COUNT(r.id) AS cnt
FROM users u
LEFT JOIN requests r ON r.user_id = u.id
GROUP BY u.id, u.full_name
ORDER BY cnt DESC, u.full_name;
```

Результат: Смирнов 4, Иванов 3, Петрова 3, Сидоров 3, Кузнецова 2, Администратор 0, Орлова 0. Обратите внимание на `COUNT(r.id)`, а не `COUNT(*)`: при `LEFT JOIN` у Орловой есть одна строка с `NULL` вместо заявки, и `COUNT(*)` насчитал бы ей 1.

Правило `GROUP BY`: в `SELECT` можно писать только поля из `GROUP BY` и агрегатные функции. MySQL 8 по умолчанию (режим `ONLY_FULL_GROUP_BY`) выдаст ошибку `#1055`, если нарушить.

**HAVING** — это `WHERE` для групп. `WHERE` фильтрует строки до группировки, `HAVING` — готовые группы после:

```sql
SELECT st.name, COUNT(*) AS total
FROM requests r JOIN statuses st ON st.id = r.status_id
GROUP BY st.id, st.name
HAVING COUNT(*) > 3;
-- Новая     | 4
-- Выполнено | 6
```

**Типичные ошибки:**

1. Нарушен порядок частей: `WHERE` после `ORDER BY` — ошибка `#1064`.
2. `= NULL` вместо `IS NULL`.
3. Забыли условие `ON` — получается «каждый с каждым» (15 заявок × 7 пользователей = 105 строк).
4. `COUNT(*)` вместе с `LEFT JOIN` — нули превращаются в единицы.
5. Условие на агрегат в `WHERE` (`WHERE COUNT(*) > 3`) — ошибка, нужно `HAVING`.
6. Двойные кавычки и «ёлочки» из Word вместо прямых одинарных `'...'`.

**Связь с экзаменом.** Страница «Мои заявки» — это `SELECT … JOIN … WHERE user_id = … ORDER BY …`. Админ-панель — то же самое без фильтра по пользователю, но с ФИО. Выпадающий список услуг на форме — `SELECT id, name FROM services ORDER BY name`. Проверка логина при регистрации — `SELECT id FROM users WHERE login = …`. Если вы уверенно пишете эти четыре запроса, PHP в модуле 5 сведётся к тому, чтобы вставить их в код.

:::quiz
? Запрос `SELECT ... WHERE cancel_reason = NULL` не вернул ни одной строки. Как исправить?
- [ ] Написать `cancel_reason = 'NULL'` в кавычках
- [ ] Написать `cancel_reason == NULL`
- [x] Написать `cancel_reason IS NULL`
- [ ] Написать `cancel_reason = 0`
> `NULL` ни с чем не равен, даже сам с собой, поэтому для проверки на пустоту есть только `IS NULL`.

? Нужно вывести статусы, у которых больше 3 заявок. Куда поставить условие `COUNT(*) > 3`?
- [x] В `HAVING` после `GROUP BY`
- [ ] В `WHERE` перед `GROUP BY`
- [ ] В `ORDER BY` в конце запроса
- [ ] В условие `ON` у `JOIN`
> `WHERE` фильтрует строки до группировки, а условие на результат подсчёта проверяется уже по готовым группам в `HAVING`.

? Нужно найти пользователей, у которых нет ни одной заявки. Какое соединение нужно?
- [ ] `JOIN`, потому что он берёт все строки обеих таблиц
- [ ] Никакое, хватит `WHERE` по таблице `users`
- [ ] `JOIN` без условия `ON`
- [x] `LEFT JOIN`, потому что он оставляет пользователей без пары
> Обычный `JOIN` отбрасывает строки без пары, а `LEFT JOIN` оставляет всех пользователей, подставляя `NULL` вместо заявок.

? Что случится, если написать `WHERE` после `ORDER BY`?
- [ ] Сначала отсортирует, потом отфильтрует — всё сработает
- [x] Будет синтаксическая ошибка `#1064`
- [ ] MySQL просто проигнорирует `WHERE`
- [ ] Запрос вернёт пустой результат
> Части `SELECT` пишутся в строгом порядке: SELECT, FROM, JOIN, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT.
