## Три вопроса навигации

Представьте, что вы впервые пришли в большой торговый центр. Чтобы не потеряться, вам нужно понять три вещи: **где я сейчас**, **куда я могу пойти** и **как вернуться обратно**. В торговом центре на эти вопросы отвечают схемы на стенах, указатели и надписи над входами в магазины.

На сайте то же самое. **Навигация** — это все элементы, которые помогают пользователю перемещаться: меню, ссылки, кнопки «Назад», номера страниц. Хорошая навигация незаметна: человек просто находит нужное. Плохую замечают сразу — по фразе «а где тут…?».

| Вопрос пользователя | Что на него отвечает |
|---|---|
| Где я? | Заголовок страницы `h1`, выделенный пункт меню, хлебные крошки |
| Куда можно пойти? | Главное меню, ссылки в тексте, карточки разделов |
| Как вернуться? | Логотип-ссылка на главную, хлебные крошки, кнопка «Назад» |

## Виды навигации

### Меню в шапке

**Главное меню** — список основных разделов в верхней части сайта. Вы верстали его на занятиях 14 и 16: это `nav` со списком ссылок.

Правила хорошего меню:

- **5–7 пунктов.** Больше человек не охватит одним взглядом. Если разделов 15, их группируют.
- **Понятные слова.** «Расписание», «Контакты», а не «Сервисы» или «Решения». Пользователь не должен гадать, что за словом.
- **Текущий пункт выделен.** Человек видит, в каком он разделе. В HTML текущую ссылку помечают атрибутом `aria-current="page"` — тогда о ней узнают и программы экранного доступа для незрячих.
- **Одинаково на всех страницах.** Меню не прыгает и не меняет порядок пунктов.

```html
<style>
  body { font-family: Arial, sans-serif; }
  .menu { display: flex; gap: 8px; margin: 0; padding: 0; list-style: none; }
  .menu a { display: block; padding: 10px 14px; border-radius: 8px; color: #1f5fa8; text-decoration: none; }
  .menu a[aria-current="page"] { background: #1f5fa8; color: #ffffff; }
</style>
<nav aria-label="Главное меню">
  <ul class="menu">
    <li><a href="#">Главная</a></li>
    <li><a href="#" aria-current="page">Расписание</a></li>
    <li><a href="#">Библиотека</a></li>
    <li><a href="#">Контакты</a></li>
  </ul>
</nav>
```

Что увидите: горизонтальное меню, в котором пункт «Расписание» залит синим — это текущая страница. Обратите внимание на селектор `a[aria-current="page"]` из занятия про селекторы: стиль привязан не к лишнему классу, а к самому смысловому атрибуту.

### Бургер

**Бургер** — кнопка с тремя полосками (☰), за которой спрятано меню. Вы делали его на JavaScript на занятии 29. Бургер экономит место на телефоне, но у него есть цена: то, что спрятано, люди видят реже. Поэтому:

- на компьютере, где места хватает, меню лучше показать целиком;
- рядом с иконкой полезно написать слово «Меню» — так кнопку понимают все, даже те, кто не знает значка.

### Вкладки (табы)

**Вкладки** переключают содержимое внутри одной страницы: «Описание — Характеристики — Отзывы». Хороши, когда разделов 2–5 и пользователю нужен один из них за раз. Плохи, когда человеку надо сравнивать содержимое двух вкладок: придётся щёлкать туда-обратно. Текущая вкладка должна быть видна сразу.

### Хлебные крошки

**Хлебные крошки** (breadcrumbs) — строка с путём от главной до текущей страницы. Название — из сказки про Гензеля и Гретель, которые бросали крошки, чтобы найти дорогу домой.

`Главная / Каталог / Информатика`

Крошки отвечают сразу на два вопроса: «где я?» и «как вернуться?». Они нужны на сайтах с глубокой структурой: интернет-магазин, библиотека, сайт колледжа с разделами и подразделами. На одностраничном лендинге они не нужны.

Как их верстать:

- обёртка — `nav` с `aria-label="Хлебные крошки"`, чтобы отличать её от главного меню;
- внутри — **нумерованный** список `ol`: у пути есть порядок;
- все шаги, кроме последнего, — ссылки; последний — текущая страница, **не ссылка** (зачем ссылка на страницу, где ты уже находишься), с `aria-current="page"`;
- разделители `/` или `›` рисуют в CSS через `::before`, чтобы их не зачитывали как текст.

```html
<style>
  body { font-family: Arial, sans-serif; }
  .crumbs ol { display: flex; flex-wrap: wrap; margin: 0; padding: 0; list-style: none; }
  .crumbs li + li::before { content: "/"; margin: 0 8px; color: #5a6475; }
  .crumbs a { color: #1f5fa8; }
</style>
<nav class="crumbs" aria-label="Хлебные крошки">
  <ol>
    <li><a href="#">Главная</a></li>
    <li><a href="#">Каталог</a></li>
    <li aria-current="page">Информатика</li>
  </ol>
</nav>
<h1>Информатика</h1>
```

Что увидите: строку «Главная / Каталог / Информатика». Первые два слова — синие ссылки, последнее — обычный текст. Селектор `li + li::before` добавляет разделитель перед каждым пунктом, кроме первого: «пункт, перед которым стоит другой пункт».

### Пагинация

**Пагинация** — разбиение длинного списка на страницы с номерами: «‹ 1 2 3 … 10 ›». Её используют в каталогах, поиске, новостях. Альтернативы — кнопка «Показать ещё» (вы делали её на занятии 29) и бесконечная прокрутка.

| Способ | Хорош для | Минус |
|---|---|---|
| Пагинация | Каталог, поиск: можно вернуться на страницу 3 | Нужно много щёлкать |
| «Показать ещё» | Новости, ленты товаров | Трудно вернуться к месту |
| Бесконечная прокрутка | Соцсети, где просто листают | До подвала сайта не добраться никогда |

Правила пагинации:

- текущая страница выделена и помечена `aria-current="page"`;
- номера достаточно крупные для пальца: область нажатия не меньше **44×44 пикселя** (подробнее — на следующем занятии);
- есть «Назад» и «Вперёд»; на первой странице «Назад» недоступна, на последней — «Вперёд».

```html
<style>
  body { font-family: Arial, sans-serif; }
  .pages { display: flex; gap: 8px; margin: 0; padding: 0; list-style: none; }
  .pages a { display: flex; justify-content: center; align-items: center; min-width: 44px; min-height: 44px; border: 1px solid #1f5fa8; border-radius: 8px; color: #1f5fa8; text-decoration: none; }
  .pages a[aria-current="page"] { background: #1f5fa8; color: #ffffff; }
</style>
<nav aria-label="Страницы каталога">
  <ul class="pages">
    <li><a href="#" aria-current="page">1</a></li>
    <li><a href="#">2</a></li>
    <li><a href="#">3</a></li>
    <li><a href="#">Вперёд</a></li>
  </ul>
</nav>
```

Что увидите: ряд квадратных кнопок, первая залита синим. Свойства `min-width` и `min-height` гарантируют, что даже кнопка с одной цифрой «1» будет размером с подушечку пальца.

> **Попробуйте сами.** В примере с пагинацией перенесите `aria-current="page"` на ссылку «2». Выделение переедет само: стиль привязан к атрибуту.

### Подвал и навигация внутри страницы

Навигация есть не только наверху. **Подвал** сайта — второе меню: туда приходят те, кто долистал до конца и не нашёл нужного. В подвале обычно повторяют главные разделы, дают контакты, адрес, часы работы и ссылки на документы («Политика конфиденциальности», «Правила записи»). Пользователи привыкли искать телефон именно внизу страницы.

На длинной странице помогают ещё два приёма, знакомые вам по занятию 8:

- **оглавление из якорей** в начале страницы — список ссылок вида `href="#schedule"` на разделы ниже;
- **ссылка «Наверх»** в конце длинной страницы, особенно на телефоне, где прокрутка до шапки занимает несколько секунд.

### Как проверить навигацию

Простой тест, который можно провести на одногруппнике за пять минут. Откройте любую внутреннюю страницу своего макета и спросите:

1. На каком ты сайте и в каком разделе? (Ответ должен быть виден без прокрутки: логотип, выделенный пункт меню, `h1`.)
2. Как отсюда попасть на главную? (Логотип-ссылка или крошки.)
3. Как найти расписание (или другую важную страницу)? (Человек должен показать пальцем, а не искать.)

Если на любой вопрос человек думает дольше пары секунд, навигацию стоит переделать. Такой тест — уменьшенная версия юзабилити-тестирования, которое мы подробно разберём на занятии 52.

## Правило трёх кликов — миф

Вы наверняка услышите: «любая страница сайта должна открываться не больше чем за три клика». Звучит логично, но исследования его не подтверждают. Юзабилити-специалисты (например, Джошуа Портер в 2003 году) проверяли: люди не бросают поиск после третьего клика, и успешность не падает на четвёртом.

Пользователя раздражают не клики, а **сомнения**. Если на каждом шаге ясно, куда нажать дальше, человек спокойно сделает пять кликов. Если на первом же шаге приходится гадать между «Услугами» и «Решениями», он уйдёт и после одного.

Поэтому вместо «три клика» запомните правило **понятного следующего шага**:

- каждая ссылка честно говорит, что за ней («Расписание занятий», а не «Подробнее»);
- пользователь всегда видит, где он (выделенный пункт, крошки, `h1`);
- путь к главному действию короткий, но не за счёт того, что всё свалено на главную.

Частая ошибка: ради «трёх кликов» запихнуть в меню 20 пунктов. Найти нужный в такой стене труднее, чем сделать лишний клик.

## Удобные формы

Форма — место, где сайт что-то просит у человека: имя, телефон, пароль. Каждое лишнее поле и каждая непонятная ошибка — это люди, которые не дошли до конца. Вы уже умеете делать форму в HTML (занятие 10), оформлять её (занятие 11) и проверять на JavaScript (занятие 30). Теперь разберём, как сделать её **удобной**.

### Подпись — над полем

Самый быстро читаемый вариант — подпись **над** полем. Глаз движется по одной вертикали: подпись, поле, подпись, поле. Подписи слева от полей заставляют взгляд прыгать зигзагом, а на телефоне им просто не хватает места.

```css
.field label { display: block; margin-bottom: 4px; }
.field input { display: block; width: 100%; }
```

Частая ошибка: подпись **внутри поля** через `placeholder` вместо `label`. Как только человек начал печатать, подсказка исчезает, и уже не вспомнить, что это было за поле — телефон или почта. Плюс `placeholder` обычно бледный и плохо читается. Подсказку-пример можно оставить в `placeholder`, но подпись — всегда в `label`.

### Одна колонка

Поля идут друг под другом, в одну колонку. Две колонки сбивают порядок: непонятно, заполнять сначала строку или столбец. Исключение — короткие поля, которые по смыслу одно целое: «Дата рождения: день / месяц / год» или «Город, индекс».

### Только нужные поля

Каждое поле спрашивайте, только если без него нельзя. Для записи на пробную тренировку нужны имя и телефон. Отчество, адрес и дата рождения там лишние: с каждым дополнительным полем часть людей бросает заполнение.

### Правильная клавиатура на телефоне

На телефоне клавиатура подстраивается под **тип поля** `type`. Вы знаете эти типы с занятия 10, но теперь посмотрите на них глазами пользователя:

| Поле | `type` | Какая клавиатура откроется |
|---|---|---|
| Почта | `email` | С символом @ и точкой на виду |
| Телефон | `tel` | Цифровая, как у звонилки |
| Количество, возраст | `number` | С цифрами |
| Поиск | `search` | Кнопка «Найти» вместо Enter |
| Сайт | `url` | С «/» и «.ru» |

Если оставить телефону `type="text"`, человеку придётся переключать раскладку на цифры — мелочь, которая раздражает. Подробнее о вводе с телефона (атрибуты `inputmode` и `autocomplete`) поговорим на занятии 51.

### Подсказки и понятные ошибки

Если у поля есть формат, покажите **пример заранее**, а не после ошибки: «Например, +7 900 123-45-67». Подсказку связывают с полем атрибутом `aria-describedby`: в нём пишут `id` элемента с подсказкой. Тогда программа экранного доступа прочитает её вместе с подписью поля.

Сообщение об ошибке отвечает на два вопроса: **что случилось** и **как исправить** (вспомните занятие 43). «Ошибка!» — плохо. «Укажите почту в формате name@mail.ru» — хорошо. Ошибка стоит **рядом с полем**, а не одной строкой вверху формы.

```html
<style>
  body { font-family: Arial, sans-serif; }
  .field { max-width: 320px; margin-bottom: 16px; }
  .field label { display: block; margin-bottom: 4px; font-weight: bold; }
  .field input { box-sizing: border-box; width: 100%; padding: 10px; border: 1px solid #5a6475; border-radius: 6px; font-size: 16px; }
  .hint { margin: 4px 0 0; font-size: 14px; color: #5a6475; }
  .error { margin: 4px 0 0; font-size: 14px; color: #c62828; }
  .field input[aria-invalid="true"] { border-color: #c62828; }
</style>
<form>
  <div class="field">
    <label for="phone">Телефон</label>
    <input id="phone" name="phone" type="tel" aria-describedby="phone-hint">
    <p id="phone-hint" class="hint">Например, +7 900 123-45-67</p>
  </div>
  <div class="field">
    <label for="email">Почта</label>
    <input id="email" name="email" type="email" value="ivan.mail.ru" aria-invalid="true" aria-describedby="email-error">
    <p id="email-error" class="error">Укажите почту в формате name@mail.ru</p>
  </div>
  <button type="submit">Записаться на тренировку</button>
</form>
```

Что увидите: подписи над полями, под телефоном серый пример, под почтой красный текст ошибки, рамка поля тоже красная. Атрибут `aria-invalid="true"` говорит, что поле заполнено неверно (вы встречали его на занятии 30), а CSS красит рамку именно по нему.

### Кнопка отправки говорит, что будет

Текст на кнопке — это глагол и результат: «Записаться на тренировку», «Оформить заказ», «Найти книгу». Безликие «OK» и «Отправить» заставляют сомневаться: а что, собственно, произойдёт?

> **Попробуйте сами.** Откройте пример формы в песочнице и поменяйте у телефона `type="tel"` на `type="text"`. На компьютере разницы не видно. Если есть возможность, откройте любую форму с полем телефона на своём смартфоне и посмотрите, какая клавиатура появится.

### Чек-лист удобной формы

1. Каждое поле подписано `label`, подпись над полем.
2. Поля в одну колонку, только нужные.
3. Правильный `type` у почты, телефона, чисел.
4. Пример формата показан заранее и связан через `aria-describedby`.
5. Ошибка рядом с полем, объясняет, как исправить.
6. Кнопка говорит, что произойдёт.

На демоэкзамене форма есть почти всегда — и эксперты проверяют её именно по этим пунктам.

## Главное за занятие

- Навигация отвечает на вопросы «где я?», «куда идти?», «как вернуться?».
- Виды навигации: меню в шапке, бургер, вкладки, хлебные крошки, пагинация. Текущий пункт выделяют и помечают `aria-current="page"`.
- Хлебные крошки: `nav` + `ol`, последний шаг — не ссылка, разделители в CSS.
- «Правило трёх кликов» — миф. Важнее понятный следующий шаг.
- Удобная форма: подписи над полями, одна колонка, правильные `type`, подсказка заранее, понятная ошибка рядом с полем, честный текст кнопки.

## Словарик

- **Навигация** — элементы, которые помогают перемещаться по сайту.
- **Хлебные крошки** — строка пути от главной до текущей страницы.
- **Пагинация** — разбиение списка на пронумерованные страницы.
- **Вкладки (табы)** — переключатель содержимого внутри одной страницы.
- **`aria-current="page"`** — атрибут, который помечает текущую страницу или пункт.
- **`aria-describedby`** — атрибут, который связывает поле с подсказкой или ошибкой по `id`.

## Если осталось время

Найдите на сайте любого интернет-магазина хлебные крошки и пагинацию. Посмотрите их код (правая кнопка → «Просмотреть код»): есть ли `nav`, `ol`, `aria-current`? Затем откройте форму регистрации на любом сайте и пройдитесь по чек-листу удобной формы. Запишите, какие пункты нарушены.

:::quiz
? На какой вопрос пользователя отвечают хлебные крошки?
- [ ] «Сколько стоит товар?»
- [x] «Где я и как вернуться назад?»
- [ ] «Как связаться с поддержкой?»
> Крошки показывают путь от главной до текущей страницы, и по нему можно вернуться на любой уровень.

? Как правильно разметить последний пункт хлебных крошек?
- [ ] Ссылкой на текущую страницу
- [ ] Ссылкой на главную
- [x] Обычным текстом с `aria-current="page"`
> Ссылка на страницу, где ты уже находишься, бесполезна. А `aria-current` сообщает, что это текущее место.

? Почему «правило трёх кликов» считают мифом?
- [x] Людей раздражают не клики, а неуверенность, куда нажать дальше
- [ ] Потому что правильно — два клика
- [ ] Потому что клики больше никто не считает
> Исследования показали: при понятном пути люди спокойно делают и пять кликов.

? Где лучше разместить подпись поля формы?
- [ ] Только в `placeholder` внутри поля
- [x] Над полем, в элементе `label`
- [ ] Справа от поля
> Подпись над полем читается быстрее всего и не исчезает, когда человек печатает.

? Какой `type` дать полю телефона, чтобы на смартфоне открылась цифровая клавиатура?
- [ ] `text`
- [ ] `number`
- [x] `tel`
> `tel` открывает клавиатуру звонилки. `number` для телефона не подходит: он для чисел, которые считают.

? Какое сообщение об ошибке лучше?
- [ ] «Ошибка!»
- [ ] «Неверный ввод данных»
- [x] «Укажите почту в формате name@mail.ru»
> Хорошая ошибка говорит, что не так и как исправить.

? Зачем полю атрибут `aria-describedby="phone-hint"`?
- [x] Связать поле с подсказкой, у которой `id="phone-hint"`
- [ ] Сделать поле обязательным
- [ ] Показать подсказку внутри поля
> Программа экранного доступа прочитает подсказку вместе с подписью поля.

? Какой текст лучше для кнопки в форме записи в спортзал?
- [ ] OK
- [x] Записаться на тренировку
- [ ] Отправить данные
> Кнопка должна говорить, что произойдёт после нажатия.
:::
