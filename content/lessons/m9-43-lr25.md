## Лекция

Сегодня портал научится узнавать пользователей. После этой работы цепочка «зарегистрировался → вошёл → увидел своё меню → вышел» будет работать полностью.

**Алгоритм входа.** Запомните его как стихотворение — на экзамене он пишется по памяти:

1. Получить логин и пароль из POST.
2. Найти в базе пользователя **по логину** (подготовленным запросом).
3. Если пользователь найден **и** `password_verify(пароль, хеш_из_базы)` вернул `true` — вход успешен.
4. Сменить ID сессии: `session_regenerate_id(true)`.
5. Положить в `$_SESSION['user']` id, логин, ФИО и роль.
6. Редирект: администратора — в `admin.php`, пользователя — в `requests.php`.
7. Иначе — показать «Неверный логин или пароль» и оставить введённый логин в поле.

Частая ошибка новичков — искать пользователя запросом `WHERE login = ? AND password_hash = ?`. Это не сработает: хеш каждый раз разный (ЛР24). Ищем **только по логину**, пароль сверяем в PHP.

**Почему одно сообщение на оба случая.** Если писать «логин не найден» и «пароль неверный» по-разному, злоумышленник узнает, какие логины существуют, и будет подбирать пароль только к ним. Поэтому сообщение одно. По ТЗ экзамена при неверных данных пользователь должен увидеть понятное сообщение, а не пустую страницу и не ошибку PHP.

**Сообщение после регистрации.** В ЛР24 мы перенаправили нового пользователя на `login.php?registered=1`. Здесь проверим этот параметр и покажем зелёную плашку «Регистрация прошла успешно».

**Выход.** Выход — это не просто «удалить пользователя из сессии». Делаем три шага: очищаем массив `$_SESSION`, удаляем cookie сессии в браузере и уничтожаем саму сессию на сервере. После этого — редирект на вход.

**Полный файл `login.php`:**

```php
<?php
require_once __DIR__ . '/includes/auth.php';

if (current_user() !== null) {
    redirect('index.php');
}

$error = '';
$login = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $login    = post('login');
    $password = post('password');

    $stmt = $pdo->prepare('SELECT id, fio, login, password_hash, role FROM users WHERE login = ?');
    $stmt->execute([$login]);
    $found = $stmt->fetch();

    if ($found && password_verify($password, $found['password_hash'])) {
        session_regenerate_id(true);           // защита от фиксации сессии
        $_SESSION['user'] = [
            'id'    => (int)$found['id'],
            'login' => $found['login'],
            'fio'   => $found['fio'],
            'role'  => $found['role'],
        ];
        redirect($found['role'] === 'admin' ? 'admin.php' : 'requests.php');
    }

    $error = 'Неверный логин или пароль';
}

$title = 'Вход';
require __DIR__ . '/includes/header.php';
?>
<div class="row justify-content-center">
    <div class="col-md-6 col-lg-4">
        <h1 class="h3 mb-3">Вход</h1>

        <?php if (isset($_GET['registered'])): ?>
            <div class="alert alert-success">Регистрация прошла успешно. Войдите в систему.</div>
        <?php endif; ?>

        <?php if ($error !== ''): ?>
            <div class="alert alert-danger"><?= e($error) ?></div>
        <?php endif; ?>

        <form method="post" action="login.php">
            <div class="mb-3">
                <label class="form-label" for="login">Логин</label>
                <input class="form-control" id="login" name="login" value="<?= e($login) ?>" required autofocus>
            </div>
            <div class="mb-3">
                <label class="form-label" for="password">Пароль</label>
                <input class="form-control" id="password" name="password" type="password" required>
            </div>
            <button class="btn btn-primary w-100" type="submit">Войти</button>
        </form>
        <p class="mt-3 text-center">Нет аккаунта? <a href="register.php">Зарегистрироваться</a></p>
    </div>
</div>
<?php require __DIR__ . '/includes/footer.php'; ?>
```

Пароль мы читаем через `post()`, а значит, с `trim()`. Это сознательное решение: и при регистрации, и при входе пробелы по краям обрезаются одинаково, поэтому пароль всегда совпадёт. Главное — обрабатывать его одинаково в обоих файлах.

**Полный файл `logout.php`:**

```php
<?php
require_once __DIR__ . '/config.php';

$_SESSION = [];

if (ini_get('session.use_cookies')) {
    $p = session_get_cookie_params();
    setcookie(session_name(), '', time() - 3600, $p['path'], $p['domain'], $p['secure'], $p['httponly']);
}

session_destroy();
redirect('login.php');
```

`logout.php` подключает только `config.php`: база для выхода не нужна.

**Меню после входа.** Шапку из ЛР23 трогать не нужно: она уже читает `current_user()` и показывает разные пункты для гостя, пользователя и администратора. Как только в сессии появился `user`, меню изменится само. Это и есть польза от продуманного каркаса.

**Как отлаживать вход.** Если «правильный» пароль не подходит:

1. Посмотрите в phpMyAdmin, что в `password_hash` действительно хеш `$2y$...` длиной 60 символов.
2. Временно добавьте перед `if` строку `var_dump($found);` — нашёлся ли пользователь вообще? Если `false` — проблема в логине (пробел, регистр, не та база).
3. Если пользователь найден, проверьте `var_dump(password_verify($password, $found['password_hash']));`. Если `false` — пароль при регистрации хешировался иначе (например, без `trim`) или поле было коротким и хеш обрезался.
4. Не забудьте удалить `var_dump` после отладки.

**Что происходит «под капотом».** Откройте DevTools → Network, поставьте галочку Preserve log и войдите. Вы увидите два запроса:

1. `POST login.php` — ответ с кодом **302** и заголовком `Location: requests.php`. В заголовках ответа есть `Set-Cookie: PHPSESSID=...` — это новый ID сессии после `session_regenerate_id()`.
2. `GET requests.php` — браузер сам переходит по адресу из `Location` и отправляет cookie `PHPSESSID`. По ней PHP находит сессию, в которой лежит `user`, — и страница «знает», кто вы.

Если в первом запросе код 200, а не 302, значит, вход не удался и страница показала ошибку. Это самый быстрый способ понять, на каком шаге сломался вход.

**А «Запомнить меня»?** Наш вход живёт, пока жива сессия: обычно до закрытия браузера или около 24 минут бездействия (настройка `session.gc_maxlifetime`). Галочка «Запомнить меня» требует отдельного долгоживущего токена в базе — это уже за рамками экзамена, и делать её «на коленке», записав логин в cookie, нельзя: cookie подделывается (ПР18).

**Порядок кода на странице входа.** Обратите внимание: вся обработка POST стоит **до** подключения `header.php`. Иначе `redirect()` после успешного входа не сработает — заголовки уже будут отправлены вместе с HTML шапки.

**Типичные ошибки.**

- Редирект на `requests.php` есть, но в меню всё ещё «Вход» — сессия не стартовала (страница не подключила `auth.php`/`config.php`) или данные кладутся не в `$_SESSION['user']`.
- После выхода кнопка «Назад» в браузере показывает старую страницу — это кеш браузера; если обновить страницу, она должна перекинуть на вход (в ЛР26 добавим защиту).
- `password_verify()` всегда `false` — в базе пароль открытым текстом (пользователь создан вручную через phpMyAdmin). Такого пользователя нужно пересоздать через регистрацию.
- Ошибка «неверный логин или пароль» не показывается — вывод `$error` забыт в HTML.

**Безопасность.** Подготовленный запрос по логину, `password_verify`, `session_regenerate_id(true)` после входа, единое сообщение об ошибке, в сессии нет пароля, полный выход с удалением cookie. Все шесть пунктов — то, что эксперт ожидает увидеть в коде по критерию «безопасность ИС».

**Связь с экзаменом.** Экзаменатор проверяет: вход с неверными данными (должно быть сообщение), вход обычным пользователем (его меню и его заявки), выход, вход администратором `adminka`/`password` (ЛР26). Каждый сценарий — отдельные баллы.

## Задание

**Цель:** реализовать вход по логину и паролю с проверкой хеша, хранение пользователя в сессии и выход.

**Ход работы:**

1. Создайте `login.php` по образцу.
2. Замените заготовку `logout.php` на полную версию.
3. Временно сделайте в `requests.php` вывод приветствия: `Здравствуйте, <?= e(current_user()['fio'] ?? 'гость') ?>`.
4. Протестируйте и заполните таблицу «сценарий — ожидание — результат»:
   - вход с несуществующим логином;
   - вход с верным логином и неверным паролем;
   - вход с пустыми полями (уберите `required` в DevTools);
   - вход тестовым пользователем из ЛР24 — редирект на `requests.php`, приветствие, меню пользователя;
   - выход — меню гостя, `requests.php` после выхода не показывает ФИО;
   - регистрация нового пользователя — плашка «Регистрация прошла успешно» на странице входа.
5. В DevTools сравните значение `PHPSESSID` до и после входа — оно должно измениться.
6. Убедитесь, что после входа страница `login.php` и `register.php` перекидывают на главную.
7. Коммит «ЛР25: вход и выход».

**Что сдать:** `login.php`, `logout.php`, таблицу тестирования, скриншоты меню гостя и меню вошедшего пользователя.

## Критерии оценки

| Аспект | 2 балла | 1 балл | 0 баллов |
|---|---|---|---|
| Проверка пароля | Поиск по логину + `password_verify` | — | Сравнение паролей открытым текстом или по хешу в SQL |
| Сессия | `session_regenerate_id(true)`, в сессии id/login/fio/role, без пароля | Нет `session_regenerate_id` | Пользователь не сохраняется в сессии |
| Сообщение о неверных данных | Единое понятное сообщение, логин остаётся в поле | Сообщение есть, но поле очищается | Нет сообщения или ошибка PHP |
| Выход | Очистка сессии, удаление cookie, редирект | Выход работает частично | Выхода нет |
| Редирект по роли | Админ → `admin.php`, пользователь → `requests.php` | Все на одну страницу | Нет редиректа |
