## Что такое стандарт и зачем он нужен

Розетки в вашем доме подходят к любому зарядному устройству, купленному в России. Это потому, что есть стандарт: размер вилки, напряжение, расстояние между штырьками. Производители чайников и производители розеток договорились заранее.

В вебе то же самое. Сайты пишут миллионы людей, а браузеры делают несколько компаний. Чтобы ваш `<h1>` везде стал заголовком, а `color: red` везде покрасил текст в красный, нужны общие правила. **Веб-стандарт** — документ, который точно описывает, как должны работать HTML, CSS и другие технологии веба.

Когда-то стандартов не соблюдали. В начале 2000-х сайты делали «под Internet Explorer» или «под Netscape», и на главной висела надпись «Лучше смотреть в браузере X». Разработчикам приходилось писать две версии одной страницы. Сегодня браузеры следуют стандартам, и одна страница работает везде — если её автор тоже их соблюдает.

## Кто пишет стандарты

| Организация | Что делает |
|---|---|
| **W3C** (World Wide Web Consortium, Консорциум Всемирной паутины) | Основан в 1994 году создателем веба Тимом Бернерсом-Ли. Отвечает за CSS, стандарты доступности WCAG, формат SVG и многое другое. Сайт: w3.org |
| **WHATWG** (рабочая группа по технологиям веб-гипертекстовых приложений) | Объединение разработчиков браузеров: Apple, Google, Mozilla, Microsoft. Ведёт «живой стандарт» HTML (HTML Living Standard) и стандарт DOM. Сайт: whatwg.org |

Раньше HTML выходил версиями: HTML 4, XHTML, HTML5. Теперь у HTML нет номеров: WHATWG постоянно дополняет **живой стандарт** (Living Standard), и браузеры подхватывают новое по мере готовности. Слово «HTML5» осталось как название современного HTML — на следующем занятии мы разберём его теги.

**Спецификация** — сам текст стандарта. Например, спецификация говорит: «элемент `img` должен иметь атрибут `src`; атрибут `alt` описывает картинку для тех, кто её не видит». Спецификации написаны для разработчиков браузеров и очень подробные. Новичку удобнее справочник: **MDN Web Docs** (developer.mozilla.org) — там есть статьи на русском с примерами и таблицей поддержки браузерами.

## Валидация: проверка кода по стандарту

Браузер очень терпелив. Вы забыли закрыть тег, перепутали порядок, написали несуществующий атрибут — он всё равно что-нибудь покажет. Поэтому ошибки в HTML часто незаметны: «у меня же работает».

Проблема в том, что каждый браузер угадывает по-своему, и то, что работает у вас, может сломаться у другого. Ещё хуже — ошибку не заметит человек, но заметит экранный диктор или поисковик.

**Валидация** — автоматическая проверка кода по стандарту. Программа-**валидатор** читает ваш код и сообщает, где он нарушает правила.

- HTML: **validator.w3.org** — официальный валидатор W3C. Можно вставить ссылку на сайт, загрузить файл или вставить код (вкладка Validate by Direct Input).
- CSS: **jigsaw.w3.org/css-validator** — валидатор CSS.

Что находит валидатор:

```html
<p id="info">Консультации проходят <b>по понедельникам</p></b>
<p id="info">Кабинет 214</p>
<img src="img/icon.svg">
```

- `</p></b>` — теги закрыты в неправильном порядке.
- `id="info"` повторяется — а id должен быть уникальным.
- У `img` нет атрибута `alt`.

Исправленный вариант:

```html
<p id="info">Консультации проходят <strong>по понедельникам</strong></p>
<p id="room">Кабинет 214</p>
<img src="img/icon.svg" alt="Календарь консультаций" width="48" height="48">
```

Что увидите: внешне почти то же самое. Но теперь код одинаково поймут все браузеры, экранный диктор прочитает «Календарь консультаций», а валидатор скажет: «Document checking completed. No errors or warnings to show».

Сообщения валидатора бывают двух видов: **Error** (ошибка — нарушение стандарта, исправлять обязательно) и **Warning** (предупреждение — подозрительное место, стоит посмотреть). Совет: исправляйте ошибки сверху вниз. Одна незакрытая скобка может породить десять сообщений ниже — исправите первую, и остальные исчезнут.

На сайте курса работает **линтер** — упрощённый валидатор прямо в редакторе: он подсвечивает ошибки красным. Но перед сдачей проекта и на экзамене проверяйте страницы на validator.w3.org: чистая валидация — один из критериев оценки вёрстки.

### Устаревшие теги

Некоторые теги из старого HTML убрали из стандарта. Браузеры их ещё показывают, чтобы не сломались старые сайты, но валидатор считает их ошибкой.

| Устаревший тег | Что делал | Чем заменить |
|---|---|---|
| `<center>` | Выравнивал по центру | CSS `text-align: center` или `margin: 0 auto` |
| `<font color="…" size="…">` | Цвет и размер текста | CSS `color`, `font-size` |
| `<big>`, `<strike>`, `<tt>` | Крупный, зачёркнутый, моноширинный текст | CSS или теги `<s>`, `<code>` |
| `<frameset>`, `<frame>` | Деление окна на рамки | Обычные страницы, `iframe` |
| атрибуты `bgcolor`, `align`, `border` у таблиц | Оформление | CSS |

Общее правило стандартов: **HTML отвечает за смысл, CSS — за вид**. Всё, что про внешний вид, уходит в CSS.

> **Попробуйте сами.** Нажмите «Попробовать» под первым примером с ошибками. Посмотрите, как браузер «угадал» разметку: где кончается жирный текст? Потом вставьте этот код в валидатор validator.w3.org (Validate by Direct Input) и прочитайте сообщения.

## Кроссбраузерность и caniuse

**Кроссбраузерность** — свойство сайта одинаково правильно работать в разных браузерах: Chrome, Яндекс Браузере, Firefox, Safari, Edge — и на компьютере, и на телефоне.

Браузеры следуют стандартам, но внедряют новое в разное время. Например, свойство, которое появилось в CSS в прошлом году, в Chrome уже работает, а в Safari на старом iPhone — ещё нет.

Как узнать, можно ли пользоваться свойством? Сайт **caniuse.com** («можно ли использовать»). Вводите название — `gap`, `:focus-visible`, `dialog` — и видите таблицу браузеров:

- зелёная ячейка — поддерживается;
- жёлтая — поддерживается частично или с оговорками (читайте примечания);
- красная — не поддерживается.

Вверху страницы показан процент пользователей в мире, у которых свойство работает. Если там 95% и больше — смело используйте. Похожая таблица есть внизу каждой статьи на MDN.

Как проверять свою страницу:

1. Откройте её минимум в двух разных браузерах.
2. Проверьте телефонную ширину: в инструментах разработчика (F12) есть режим устройства — значок телефона.
3. Пройдите страницу клавишей Tab: всё ли доступно с клавиатуры.

## Прогрессивное улучшение

**Прогрессивное улучшение** (progressive enhancement) — подход, при котором сначала делают базовую версию, которая работает у всех, а потом добавляют улучшения для тех браузеров, которые их понимают.

Как торт: коржи (HTML) есть у всех, крем (CSS) — почти у всех, украшения (новые свойства и JavaScript) — у кого получится. Если украшения не удались, торт всё равно съедобен.

Примеры из жизни:

- Форма записи отправляется обычной кнопкой `submit`, даже если JavaScript не загрузился. JavaScript лишь добавляет красивую проверку полей.
- Картинка с `alt`: если она не загрузилась, человек прочитает описание.
- Шрифт со **стеком**: если фирменного шрифта нет, браузер возьмёт запасной.

Как это выглядит в CSS. Браузер **пропускает** свойства и значения, которых не понимает, и идёт дальше. Поэтому можно писать запасной вариант:

```css
/* Шрифтовой стек: если нет PT Sans, будет Arial, если нет и его — любой без засечек */
.title { font-family: "PT Sans", Arial, sans-serif; }

/* Переменная с запасным значением: если --brand не объявлена, возьмётся #1f4e79 */
.title { color: var(--brand, #1f4e79); }
```

У `var()` есть второй аргумент — **запасное значение**. Оно сработает, если переменная не объявлена: например, файл с переменными не загрузился.

```html
<style>
  .title { color: var(--brand, #1f4e79); font-family: "Шрифт, которого нет", Georgia, serif; }
</style>
<h1 class="title">Неделя открытых дверей</h1>
```

Что увидите: синий заголовок с засечками. Переменная `--brand` нигде не объявлена, шрифта с таким названием нет — сработали запасные варианты.

> **Попробуйте сами.** Уберите из примера `, #1f4e79` внутри `var()`. Заголовок станет чёрным: переменной нет, запаса нет — браузер взял цвет по наследству.

Противоположный подход — **изящная деградация** (graceful degradation): сначала делают «полную» версию для современных браузеров, а потом чинят, где сломалось. Прогрессивное улучшение надёжнее: базовая версия работает всегда.

## Доступность и WCAG

**Доступность** (accessibility, сокращённо a11y — между «a» и «y» 11 букв) — возможность пользоваться сайтом для всех людей, в том числе:

- незрячих и слабовидящих — они слушают сайт через **экранный диктор** (программу, которая читает страницу вслух) или увеличивают шрифт;
- людей с нарушением цветового зрения — около 8% мужчин плохо различают красный и зелёный;
- тех, кто не может пользоваться мышью и работает с клавиатуры;
- пожилых людей, людей с временной травмой руки, человека с телефоном на ярком солнце.

Требования к доступности собраны в стандарте **WCAG** (Web Content Accessibility Guidelines — руководство по доступности веб-контента) от W3C. У каждого требования есть уровень:

| Уровень | Что значит |
|---|---|
| **A** | Минимум. Без этого сайтом некоторые люди не смогут пользоваться совсем |
| **AA** | Нормальный уровень. Его требуют законы многих стран и сайты госорганов. Ориентируемся на него |
| **AAA** | Максимум. Для специальных сайтов, всегда выполнить его трудно |

Главные требования, которые проверяют и на сайте курса, и на экзамене:

1. **Альтернативный текст.** У каждой картинки есть `alt`. Значимая картинка — описание, декоративная — пустой `alt=""`.
2. **Контраст.** Обычный текст — не ниже **4,5:1** к фону, крупный (от 24px или от 19px жирным) — не ниже **3:1**.
3. **Клавиатура.** Всё, что можно нажать мышью, можно нажать и с клавиатуры: Tab переходит, Enter нажимает. Рамка фокуса видна.
4. **Подписи полей.** У каждого поля формы есть `label`. Подсказка `placeholder` подписью не считается: она исчезает, как только начинаешь печатать.
5. **Понятные ссылки.** Текст ссылки объясняет, куда она ведёт. «Нажмите здесь» и «подробнее» — плохо: экранный диктор умеет зачитывать список всех ссылок страницы, и человек услышит «здесь, здесь, подробнее».
6. **Язык страницы.** `<html lang="ru">`, а фразы на другом языке размечены: `<span lang="en">Learn by doing</span>`. Тогда диктор прочитает их с правильным произношением.
7. **Не только цвет.** Ошибку в форме показывают не одним красным цветом, но и текстом.

Частая ошибка — кнопка из `div`:

```html
<div class="button">Записаться</div>
```

Мышью на неё можно нажать (если добавить JavaScript), но клавишей Tab до неё не дойти, а экранный диктор не скажет, что это кнопка. Правильно — настоящая кнопка:

```html
<style>
  .button { padding: 10px 20px; border: 0; background-color: #1f4e79; color: #ffffff; font-size: 16px; cursor: pointer; }
  .button:focus-visible { outline: 3px solid #f2a541; }
</style>
<label for="name">Ваше имя</label>
<input id="name" type="text">
<button class="button" type="submit">Записаться</button>
```

Что увидите: подписанное поле и синюю кнопку. Щёлкните в предпросмотре и нажимайте Tab: фокус переходит с поля на кнопку, у кнопки видна жёлтая рамка.

## Почему стандарты важны на экзамене

На демонстрационном экзамене вёрстку оценивают по критериям. Многие из них — это и есть веб-стандарты:

- страница проходит валидацию без ошибок;
- нет устаревших тегов и атрибута `style` — оформление в CSS;
- семантическая разметка, заголовки по порядку;
- у картинок есть `alt`, у полей — подписи, контраст достаточный;
- страница одинаково работает в разных браузерах и на телефоне.

Каждое задание на сайте курса проверяет эти пункты автоматически — строки «Семантика», «Доступность», «Контраст», «Линтер» в чек-листе. Привычка писать чисто сэкономит вам баллы.

## Главное за занятие

- Веб-стандарты пишут W3C (CSS, WCAG) и WHATWG (живой стандарт HTML). Справочник для разработчика — MDN.
- Валидатор validator.w3.org проверяет HTML по стандарту. Ошибки исправляем сверху вниз.
- Устаревшие теги (`center`, `font`) заменяем CSS: HTML — смысл, CSS — вид.
- Поддержку свойств браузерами проверяют на caniuse.com.
- Прогрессивное улучшение: базовая версия работает у всех, улучшения — сверху. Запасные варианты: шрифтовой стек, `var(--x, запас)`.
- WCAG AA: `alt` у картинок, контраст 4,5:1, работа с клавиатуры, подписи полей, понятные ссылки, `lang`.

## Словарик

- **Веб-стандарт** — документ, который описывает, как должна работать веб-технология.
- **W3C** — Консорциум Всемирной паутины, разрабатывает стандарты веба.
- **WHATWG** — группа разработчиков браузеров, ведёт живой стандарт HTML.
- **Спецификация** — текст стандарта.
- **Валидация** — проверка кода на соответствие стандарту.
- **Кроссбраузерность** — одинаково правильная работа сайта в разных браузерах.
- **Прогрессивное улучшение** — сначала базовая версия для всех, потом улучшения.
- **Доступность (a11y)** — возможность пользоваться сайтом для всех людей.
- **WCAG** — стандарт доступности веб-контента, уровни A, AA, AAA.
- **Экранный диктор** — программа, которая читает страницу вслух.
