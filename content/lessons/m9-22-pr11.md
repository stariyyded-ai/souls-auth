## Лекция

**Портал заявок — это формы.** Регистрация — форма, вход — форма, новая заявка — форма, смена статуса в админке — тоже форма. Если посчитать, больше половины экзаменационного интерфейса состоит из полей и кнопок. Хорошая новость: HTML умеет очень многое сам — проверять обязательные поля, формат email, длину логина, показывать на телефоне нужную клавиатуру. Нужно только правильно написать атрибуты.

**Тег `<form>` и его атрибуты.** Форма — это контейнер, который собирает данные полей и отправляет их на сервер:

```html
<form action="register.php" method="post">
  ...
  <button type="submit">Зарегистрироваться</button>
</form>
```

- `action` — куда отправить данные (в модуле 5 это будет PHP-файл; пока можно оставить `#`);
- `method` — как отправить. `post` — для регистрации, входа, создания заявки (данные идут в теле запроса и не видны в адресной строке); `get` — для поиска и фильтров (параметры видны в адресе, страницу можно сохранить в закладки).

**`name` — самый важный атрибут, о котором забывают.** Сервер получает данные в виде пар «имя=значение». Поле без `name` просто не отправится, и в PHP в `$_POST` его не будет. Поэтому у каждого поля обязательно `name`, причём латиницей и без пробелов: `login`, `fio`, `phone`, `email`.

**`<label>` — подпись, которую можно нажать.** Подпись связывается с полем через `for` и `id`:

```html
<label for="login">Логин</label>
<input type="text" id="login" name="login">
```

Зачем это нужно: нажатие на подпись ставит курсор в поле (на телефоне попасть в крупную подпись проще, чем в узкое поле), а экранный диктор читает незрячему пользователю, что это за поле. `placeholder` подписью **не является**: он исчезает при вводе, и пользователь забывает, что вводил. Placeholder — это подсказка формата: `placeholder="+7(900)-123-45-67"`.

**Типы `<input>`.** Тип влияет и на проверку, и на клавиатуру телефона:

| Тип | Для чего | Что даёт на телефоне |
|---|---|---|
| `text` | логин, ФИО, адрес | обычная клавиатура |
| `password` | пароль | символы скрыты точками |
| `email` | почта | клавиатура с `@`, браузер проверяет формат |
| `tel` | телефон | цифровая клавиатура (формат не проверяет!) |
| `date`, `time` | дата и время заявки | системный календарь и часы |
| `datetime-local` | дата и время одним полем | календарь + время |
| `number` | количество комнат, гостей | цифровая клавиатура, стрелки |
| `checkbox` | «Согласен с правилами» | галочка |
| `radio` | один вариант из нескольких | кружок-переключатель |

**Правила проверки (встроенная валидация).** Браузер не даст отправить форму, пока поля не соответствуют атрибутам:

- `required` — поле обязательно;
- `minlength` / `maxlength` — минимальная и максимальная длина текста;
- `min` / `max` — границы для чисел и дат;
- `pattern` — регулярное выражение, которому должно соответствовать **всё** значение целиком.

Теперь посмотрим на требования к регистрации из образца экзамена: логин не короче 6 символов, ФИО кириллицей, телефон в формате +7(XXX)-XXX-XX-XX, email. Переведём их на язык HTML:

```html
<form action="#" method="post" class="form">
  <div class="field">
    <label for="login">Логин</label>
    <input type="text" id="login" name="login"
           required minlength="6" autocomplete="username">
  </div>

  <div class="field">
    <label for="password">Пароль</label>
    <input type="password" id="password" name="password"
           required minlength="6" autocomplete="new-password">
  </div>

  <div class="field">
    <label for="fio">ФИО</label>
    <input type="text" id="fio" name="fio" required
           pattern="[А-Яа-яЁё\s\-]+"
           title="Только русские буквы, пробелы и дефис"
           autocomplete="name">
  </div>

  <div class="field">
    <label for="phone">Телефон</label>
    <input type="tel" id="phone" name="phone" required
           pattern="\+7\(\d{3}\)-\d{3}-\d{2}-\d{2}"
           placeholder="+7(900)-123-45-67"
           autocomplete="tel">
  </div>

  <div class="field">
    <label for="email">Email</label>
    <input type="email" id="email" name="email" required autocomplete="email">
  </div>

  <button type="submit" class="btn btn--block">Зарегистрироваться</button>
</form>
```

Разберём `pattern` для телефона: `\+7` — символ «плюс» и семёрка (плюс экранируем обратным слешем, потому что в регулярках это спецсимвол), `\(` — открывающая скобка, `\d{3}` — ровно три цифры, `-` — дефис и так далее. Проверять начало и конец строки (`^` и `$`) в `pattern` не нужно — браузер сам требует совпадения всего значения. В ФИО-шаблоне `[А-Яа-яЁё\s\-]+` означает «одна или больше русских букв, пробелов или дефисов». Буква `Ё` стоит отдельно, потому что в таблице символов она не входит в диапазон `А-Я` — частая ошибка: «Артём» без `Ёё` не пройдёт. Дефис внутри квадратных скобок экранируем: современные браузеры разбирают `pattern` в строгом режиме и неэкранированный дефис могут посчитать ошибкой, после чего шаблон просто перестанет работать.

Атрибут `title` браузер показывает в подсказке ошибки — напишите там по-человечески, что не так.

**`select` — выпадающий список.** На экзамене в форме заявки есть выбор услуги из справочника:

```html
<div class="field">
  <label for="service">Вид услуги</label>
  <select id="service" name="service_id" required>
    <option value="">— Выберите услугу —</option>
    <option value="1">Общий клининг</option>
    <option value="2">Генеральная уборка</option>
    <option value="3">Послестроительная уборка</option>
    <option value="4">Химчистка ковров и мебели</option>
  </select>
</div>
```

Пустой первый `option` с `value=""` вместе с `required` заставляет пользователя сделать выбор осознанно. Атрибут `value` — то, что уйдёт на сервер (номер услуги из базы данных), а текст между тегами — то, что видит человек.

**`radio` — один вариант из нескольких.** Например, тип оплаты. Все переключатели одной группы имеют **одинаковый** `name` и разные `value`. Группу оборачивают в `<fieldset>` с подписью `<legend>`:

```html
<fieldset class="field">
  <legend>Тип оплаты</legend>
  <label><input type="radio" name="payment" value="cash" required> Наличными</label>
  <label><input type="radio" name="payment" value="card"> Банковской картой</label>
</fieldset>
```

Если `name` у кнопок разный, можно выбрать обе сразу — это уже не радио, а баг. `required` достаточно поставить на одну кнопку группы.

**`textarea` и `checkbox`.** Для длинного текста (например, «Иная услуга — опишите» или причина отмены в админке) используют `<textarea name="comment" rows="3"></textarea>`. Для согласия — `<label><input type="checkbox" name="agree" required> Согласен на обработку данных</label>`.

**Подсветка ошибок CSS-ом.** Браузер ставит полям псевдоклассы `:valid` и `:invalid`. Проблема `:invalid` в том, что пустое обязательное поле красное сразу при открытии страницы — выглядит как будто пользователь уже ошибся. Современный псевдокласс `:user-invalid` срабатывает только после того, как человек взаимодействовал с полем:

```css
input:user-invalid {
  border-color: var(--color-error);
}
input:focus-visible {
  outline: 3px solid var(--color-accent);
  outline-offset: 2px;
}
```

**Важное предупреждение.** HTML-проверку легко обойти: достаточно удалить атрибут в DevTools или отправить запрос без браузера. Поэтому на экзамене валидация делается и на клиенте (HTML + JS, модуль 6), и **обязательно** на сервере (PHP, модуль 5). HTML-атрибуты — это удобство для пользователя, а не защита.

**Типичные ошибки:**

1. Нет `name` — данные не доходят до сервера.
2. `label` без `for` или `for` не совпадает с `id`.
3. Placeholder вместо подписи.
4. `type="tel"` без `pattern` — и вы думаете, что телефон проверяется. Не проверяется.
5. Забыли `Ёё` в шаблоне ФИО.
6. Кнопка внутри формы без `type`: по умолчанию она `submit` и отправит форму, даже если вы хотели «Отмена». Для обычной кнопки пишите `type="button"`.
7. Радиокнопки с разными `name`.
