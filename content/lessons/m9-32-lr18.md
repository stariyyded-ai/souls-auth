## Лекция

**Пустая база — бесполезная база.** Представьте, что вы открыли маркетплейс, а там ни одного товара. Так же выглядит ваш портал без данных: страница «Мои заявки» пустая, админ-панель пустая, проверить, правильно ли работает фильтр по статусу, невозможно. Поэтому сразу после создания структуры базу наполняют **тестовыми данными**: справочниками (услуги, статусы, способы оплаты), администратором и десятком-двумя «живых» заявок. Сегодня учимся делать это тремя способами: командой `INSERT`, формой phpMyAdmin и импортом CSV-файла.

**INSERT — добавить строки.**

Одна строка:

```sql
INSERT INTO services (name, price) VALUES ('Общий клининг', 2500.00);
```

Несколько строк одним запросом (быстрее и короче):

```sql
INSERT INTO statuses (id, name) VALUES
(1, 'Новая'),
(2, 'В работе'),
(3, 'Выполнено'),
(4, 'Отменено');
```

Правила, которые важно запомнить:

1. **Всегда перечисляйте столбцы** в скобках после имени таблицы. Запрос `INSERT INTO services VALUES (...)` без списка столбцов сломается, как только в таблицу добавят новое поле.
2. **`id` с `AUTO_INCREMENT` можно не указывать** — СУБД выдаст следующий номер сама. А для справочников, наоборот, номера удобно задать явно: мы договорились, что статус «Новая» — это `1`, и на этом держится `DEFAULT 1` в `requests.status_id`.
3. **Поля с `DEFAULT` можно пропускать**: `created_at` заполнится текущим временем, `role` — значением `user`, `status_id` — единицей.
4. **Текст и даты — в одинарных кавычках**, формат даты строго `'ГГГГ-ММ-ДД'`, времени — `'ЧЧ:ММ:СС'`. Запись `'25.10.2026'` MySQL не поймёт: в строгом режиме будет ошибка, в нестрогом — дата `0000-00-00`.
5. **Апостроф внутри текста удваивается**: `'Кафе ''У Ашота'''`.
6. **Порядок вставки — как порядок создания**: сначала справочники и пользователи, потом заявки. Иначе внешние ключи не пустят (`#1452`).

Узнать номер только что добавленной строки:

```sql
INSERT INTO users (login, password, full_name, phone, email)
VALUES ('test_user', '$2y$10$EJkOXBoeT9jIG81Wrpo...ca3by5XwO08Zkln897D6tcsewNzxWye',
        'Тестов Тест Тестович', '+7(900)-123-45-67', 'test@mail.ru');
SELECT LAST_INSERT_ID();
```

В PHP это будет `$pdo->lastInsertId()` — понадобится, например, чтобы сразу после регистрации залогинить пользователя.

**Администратор `adminka`.** Пароль в базе хранится только в виде хеша. Хеш строки `password`, сделанный функцией PHP `password_hash()`, выглядит так (он же лежит в учебной базе):

```sql
INSERT INTO users (login, password, full_name, phone, email, role) VALUES
('adminka', '$2y$10$/N4KM4pMzylZ/MJilQ2z/ekN1nfR0dfiidq6o59aXNPa8FCgSQStm',
 'Администратор Портала', '+7(900)-000-00-00', 'admin@portal.local', 'admin');
```

Свой хеш можно получить одной строкой в консоли XAMPP (кнопка Shell): `php -r "echo password_hash('password', PASSWORD_DEFAULT);"`. Хеши каждый раз получаются разные — это нормально: внутри хеша зашита случайная «соль», а `password_verify()` всё равно их узнает. Не пытайтесь «исправить» хеш руками и не храните пароль открытым текстом: это прямая потеря баллов по аспекту «безопасность ИС».

**Вставка формой.** Таблица → вкладка «Вставить». Удобно для 1–2 строк, особенно когда нужно проверить, как ведут себя умолчания: оставьте поле `created_at` пустым и посмотрите, что подставится. Но для 20 заявок форма — это 20 минут кликов. Тут нужен CSV.

**CSV — таблица в текстовом файле.** CSV (Comma-Separated Values) — это обычный текст, где строка файла = строка таблицы, а значения разделены запятыми. Его умеют сохранять Excel, LibreOffice Calc и Google Таблицы, поэтому тестовые данные удобно готовить в таблице, а потом загружать в БД одним импортом.

```
id,login,password,full_name,phone,email,role
2,belova_t,$2y$10$...,Белова Татьяна Юрьевна,+7(912)-101-01-01,belova@mail.ru,user
```

Если значение само содержит запятую (адрес «ул. Мира, 1, кв. 10»), его берут в двойные кавычки: `"ул. Мира, 1, кв. 10"`.

**Импорт CSV в phpMyAdmin.** Откройте **таблицу** (не базу!) → «Импорт»:

1. «Обзор» → выберите файл. «Кодировка файла» — `utf-8`.
2. «Формат» — `CSV`.
3. «Столбцы разделены» — `,` (или `;`, если файл из русского Excel).
4. «Значения столбцов заключены в» — `"`.
5. Поставьте галочку **«Первая строка файла содержит имена столбцов таблицы»** — иначе строка заголовков попытается стать записью.
6. Если в файле не все столбцы таблицы — в поле «Имена столбцов» перечислите через запятую те, что есть в файле, в том же порядке: `user_id,service_id,status_id,...`.
7. «Вперёд». Сверху должно появиться «Импорт успешно завершён, выполнено N запросов».

Есть и SQL-способ — `LOAD DATA INFILE`, но в XAMPP ему часто мешают настройки безопасности, поэтому на занятиях и экзамене пользуемся импортом phpMyAdmin.

**Пустые значения в CSV.** Пустая ячейка в CSV при импорте превращается в пустую строку `''`, а не в `NULL`. Для `cancel_reason` это важно: в админке мы будем проверять «есть ли причина отмены» через `IS NULL`. Поэтому после импорта нормализуем данные:

```sql
UPDATE requests SET cancel_reason = NULL WHERE cancel_reason = '';
```

(Подробно про `UPDATE` — в ПР15; пока просто выполните эту строку.)

**utf8mb4 и «кракозябры».** Кириллица ломается в трёх местах, и симптомы разные:

| Симптом | Причина | Что делать |
|---|---|---|
| `????????` вместо ФИО | база/таблица в `latin1` | изменить сравнение на `utf8mb4_unicode_ci` в «Операциях» и залить данные заново |
| `Ð˜Ð²Ð°Ð½Ð¾Ð²` | файл в UTF-8 прочитан как другая кодировка | выбрать при импорте кодировку `utf-8` |
| `Èâàíîâ` или ошибка импорта | CSV сохранён Excel в Windows-1251 | пересохранить как «CSV UTF-8 (разделитель — запятая)» или в LibreOffice с кодировкой UTF-8 |

Если скрипт `.sql` выполняется в консоли MySQL, а не в phpMyAdmin, первой строкой пишите `SET NAMES utf8mb4;` — это сообщает серверу, в какой кодировке вы присылаете текст. В PHP то же самое делается параметром `charset=utf8mb4` в строке подключения PDO (модуль 5).

**Хорошие тестовые данные** — не «аааа», «тест», «123». Это данные, которые помогут найти ошибки:

- ФИО — настоящие кириллические, с буквой «ё» (Алёна, Ковалёв): проверим кодировку и будущую валидацию.
- Телефоны — строго в формате ТЗ `+7(XXX)-XXX-XX-XX`.
- Заявки — во всех статусах, у отменённых есть причина.
- Есть пользователь без заявок и услуга без заказов — пригодится для `LEFT JOIN`.
- Даты — и прошедшие, и будущие.

**Типичные ошибки:**

1. Импортировали CSV в базу, а не в таблицу, — phpMyAdmin создаёт новую таблицу `TABLE 6` с колонками `COL 1`, `COL 2`.
2. Забыли галочку про первую строку — ошибка «Incorrect integer value: 'id'».
3. Заявки импортируются раньше пользователей — `#1452`.
4. Разделитель `;` в файле, а в настройках `,` — всё оказывается в первом столбце.
5. Пароль в CSV открытым текстом `123456` — на странице входа `password_verify()` его не примет.
6. Повторный импорт того же файла с явными `id` — `#1062 Duplicate entry '2' for key 'PRIMARY'`. Сначала очистите таблицу или уберите `id` из файла.

**Связь с экзаменом.** На экзамене тестовые данные нужны, чтобы показать эксперту работающую систему: заявки в разных статусах, отменённую заявку с причиной, вход `adminka`. Готовые справочники по ТЗ (услуги варианта, статусы, способы оплаты) вставляются одним `INSERT`, и эта заготовка из ЛР18 у вас останется.
