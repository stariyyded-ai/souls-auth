## Лекция

**Зачем вообще JavaScript, если PHP уже всё проверяет?** Представь: пользователь заполнил регистрацию, нажал «Зарегистрироваться», страница перезагрузилась, и только тогда он узнал, что телефон введён не так. Половина полей ещё и стёрлась. Раздражает? Вот поэтому есть проверка в браузере: она срабатывает сразу, пока человек печатает. PHP-проверку при этом **не убираем никогда**: JS можно отключить в браузере или обойти, отправив запрос напрямую. Правило на всю жизнь: *JS — для удобства, PHP — для безопасности*.

**Где живёт JS.** Код пишем в отдельном файле и подключаем внизу страницы или с атрибутом `defer`:

```html
<!-- в <head> страницы register.php -->
<script src="js/register.js" defer></script>
```

`defer` значит «скачай сразу, а выполни, когда HTML уже разобран». Без него скрипт в `<head>` запустится раньше, чем появится форма, и `document.querySelector('form')` вернёт `null`. Это ошибка номер один у новичков: «Cannot read properties of null».

**DOM — дерево страницы.** Браузер превращает HTML в дерево объектов (Document Object Model). Каждый тег — это объект, у которого есть свойства (`value`, `textContent`, `classList`) и методы. Найти элемент можно так:

```js
const form = document.querySelector('#register-form');     // первый по CSS-селектору
const inputs = document.querySelectorAll('.form-control'); // все подходящие (NodeList)
const loginInput = document.getElementById('login');       // по id
```

Селекторы — те же, что в CSS: `#id`, `.class`, `input[name="phone"]`. Если `querySelector` ничего не нашёл, он вернёт `null`, а не ошибку, так что проверяй опечатки в id.

**Что можно сделать с элементом.**

```js
const loginInput = document.getElementById('login');
console.log(loginInput.value);          // что ввёл пользователь (всегда строка!)
loginInput.value = loginInput.value.trim(); // убрать пробелы по краям

const hint = document.getElementById('login-error');
hint.textContent = 'Логин слишком короткий'; // безопасно: текст, не HTML
loginInput.classList.add('is-invalid');      // повесить класс (Bootstrap подсветит красным)
loginInput.classList.remove('is-valid');
loginInput.classList.toggle('is-invalid', true); // добавить/убрать по условию
```

Почему `textContent`, а не `innerHTML`? `innerHTML` разбирает строку как HTML. Если туда попадёт то, что ввёл пользователь, можно получить XSS — ту самую уязвимость из ПР19, только на стороне браузера. Для текста всегда `textContent`.

**События.** Браузер постоянно сообщает о том, что происходит: нажали кнопку, ввели символ, ушли с поля, отправили форму. Подписаться на событие — `addEventListener`:

```js
loginInput.addEventListener('input', () => {
  console.log('Сейчас в поле:', loginInput.value);
});
```

Самые нужные для форм события:

| Событие | Когда срабатывает | Для чего |
|---|---|---|
| `input` | при каждом изменении значения | живая проверка, маска телефона |
| `blur` | поле потеряло фокус | проверка «когда закончил вводить» |
| `change` | значение изменилось и поле покинули (для select — сразу) | выпадающие списки, чекбоксы |
| `submit` | форму отправляют (кнопкой или Enter) | финальная проверка всей формы |
| `click` | клик | кнопки, открытие окон |

**Остановить отправку формы.** Если в форме ошибки, отправлять её на сервер незачем. Для этого у объекта события есть `preventDefault()`:

```js
const form = document.getElementById('register-form');

form.addEventListener('submit', (event) => {
  const login = form.login.value.trim(); // form.login — поле с name="login"
  if (login.length < 6) {
    event.preventDefault();               // форма НЕ уйдёт на сервер
    alert('Логин должен быть не короче 6 символов');
  }
});
```

Обрати внимание: `form.login` — удобный доступ к полю по атрибуту `name`. У тебя поля уже названы `fio`, `phone`, `email`, `login`, `password` — так и обращайся.

**Условия и логика.** Проверка — это просто `if`. Пригодятся операторы: `===` (строгое равенство, используем всегда вместо `==`), `!==`, `&&` (и), `||` (или), `!` (не).

```js
const password = form.password.value;
if (password === '') {
  showError('password', 'Введите пароль');
} else if (password.length < 6) {
  showError('password', 'Пароль не короче 6 символов');
} else {
  clearError('password');
}
```

**Функции, чтобы не копировать.** Показ и скрытие ошибки повторяется для каждого поля — вынесем в функции. Договоримся о разметке: под каждым полем есть `<div class="invalid-feedback" id="ИМЯ-error"></div>`.

```js
function showError(name, message) {
  const input = document.querySelector(`[name="${name}"]`);
  const box = document.getElementById(`${name}-error`);
  input.classList.add('is-invalid');
  input.setAttribute('aria-invalid', 'true');
  box.textContent = message;
}

function clearError(name) {
  const input = document.querySelector(`[name="${name}"]`);
  const box = document.getElementById(`${name}-error`);
  input.classList.remove('is-invalid');
  input.removeAttribute('aria-invalid');
  box.textContent = '';
}
```

Обратные кавычки `` ` `` — шаблонные строки: внутрь `${...}` можно подставить переменную. Это удобнее, чем склеивать плюсами.

**Полный рабочий пример.** Мини-форма: кнопка «Отправить» активна только когда оба поля заполнены.

```html
<form id="demo-form">
  <input name="login" placeholder="Логин">
  <input name="password" type="password" placeholder="Пароль">
  <button id="demo-btn" disabled>Войти</button>
  <p id="counter"></p>
</form>
<script>
  const demoForm = document.getElementById('demo-form');
  const btn = document.getElementById('demo-btn');
  const counter = document.getElementById('counter');

  demoForm.addEventListener('input', () => {   // событие «всплывает» от поля к форме
    const login = demoForm.login.value.trim();
    const pass = demoForm.password.value;
    btn.disabled = !(login !== '' && pass !== '');
    counter.textContent = `Символов в логине: ${login.length}`;
  });
</script>
```

Здесь использован приём **делегирования**: мы слушаем `input` не на каждом поле, а на всей форме. Событие от любого поля «всплывает» вверх до формы, и один обработчик ловит всё.

**Отладка.** Открой DevTools (F12) → вкладка Console. `console.log(переменная)` — твой лучший друг. Красная строка в консоли — ошибка, кликни по ссылке справа, и браузер покажет строку кода. Вкладка Elements показывает, повесился ли класс `is-invalid` на поле.

**Типичные ошибки.**
- Скрипт подключён без `defer` в `<head>` → элементы ещё не существуют, `null`.
- Опечатка в id: `getElementById('Login')` и `id="login"` — разные вещи, регистр важен.
- `value` — это всегда строка. `'5' + 1` даст `'51'`. Для чисел — `Number(value)`.
- `=` вместо `===` внутри `if`: `if (x = 5)` присваивает, а не сравнивает.
- Забыли `event.preventDefault()` → форма отправилась, хотя ошибки показались на долю секунды.
- `innerHTML` с данными пользователя → дыра XSS.

**Связь с экзаменом.** В задании 3 нужна валидация полей регистрации. Без умения найти поле, повесить обработчик и вывести текст ошибки рядом с полем регулярки из следующей работы просто некуда вставить. Эксперт смотрит не только «есть ли проверка», но и «понятно ли пользователю, что не так» — поэтому ошибка выводится под конкретным полем, а не одним `alert` на всю форму.

## Критерии оценки

| Аспект | 2 балла | 1 балл | 0 баллов |
|---|---|---|---|
| Поиск элементов и подключение скрипта | `defer`/низ страницы, нет ошибок в консоли | работает, но есть ошибки в консоли | скрипт не работает |
