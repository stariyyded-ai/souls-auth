## Лекция

Панель администратора — последняя обязательная часть задания 1 и место, где теряется больше всего баллов: админ не входит, статус не сохраняется, причина отмены не требуется. Сегодня делаем `admin.php` полностью.

**Что умеет админ (по образцу ТЗ):**

1. Видит **все** заявки всех пользователей с ФИО и контактами заказчика.
2. Меняет статус заявки.
3. При отмене **обязательно** указывает причину, и пользователь её видит (ЛР28).

**Запрос: заявки + пользователи + услуги.** Админу нужно знать, чья заявка, поэтому соединяем три таблицы:

```sql
SELECT r.*, u.fio, u.login, u.email, s.name AS service_name
FROM requests r
JOIN users u    ON u.id = r.user_id
JOIN services s ON s.id = r.service_id
ORDER BY r.created_at DESC
```

Здесь нет переменных — можно `query()`. В ЛР30 появятся фильтры, и запрос станет подготовленным.

**Смена статуса: форма в каждой строке.** Самый простой и надёжный для экзамена вариант — у каждой заявки своя маленькая POST-форма: скрытое поле `id`, выпадающий список статусов, поле «причина отмены» и кнопка «Сохранить». (В модуле 6, ЛР36, вы сделаете то же самое через модальное окно и `fetch`, но серверная логика останется этой.)

**Логика обработки:**

1. `check_csrf()` — смена статуса меняет данные, токен обязателен.
2. `id` приводим к целому `(int)`, статус проверяем по ключам `STATUSES`.
3. Если статус `cancelled` — причина обязательна (не пустая, до 255 символов). Если статус другой — причину записываем как `NULL`, чтобы у выполненной заявки не висела старая причина отмены.
4. `UPDATE ... WHERE id = ?` подготовленным запросом.
5. `rowCount()` подскажет, нашлась ли заявка. Внимание: MySQL считает только **изменённые** строки, поэтому если сохранить тот же статус, будет 0. Чтобы не путать, проверим существование заявки отдельным запросом.
6. Успех — редирект (PRG) с сообщением, ошибка — показываем страницу с текстом ошибки без редиректа.

**Полный файл `admin.php`:**

```php
<?php
require_once __DIR__ . '/includes/auth.php';
require_admin();

$error = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    check_csrf();

    $id     = (int)post('id');
    $status = post('status');
    $reason = post('cancel_reason');

    $stmt = $pdo->prepare('SELECT id FROM requests WHERE id = ?');
    $stmt->execute([$id]);

    if (!$stmt->fetch()) {
        $error = 'Заявка не найдена';
    } elseif (!array_key_exists($status, STATUSES)) {
        $error = 'Недопустимый статус';
    } elseif ($status === 'cancelled' && ($reason === '' || mb_strlen($reason) > 255)) {
        $error = "Заявка №$id: при отмене укажите причину (до 255 символов)";
    } else {
        $stmt = $pdo->prepare('UPDATE requests SET status = ?, cancel_reason = ? WHERE id = ?');
        $stmt->execute([$status, $status === 'cancelled' ? $reason : null, $id]);
        redirect('admin.php?updated=' . $id);
    }
}

$requests = $pdo->query(
    'SELECT r.*, u.fio, u.login, u.email, s.name AS service_name
     FROM requests r
     JOIN users u    ON u.id = r.user_id
     JOIN services s ON s.id = r.service_id
     ORDER BY r.created_at DESC'
)->fetchAll();

$title = 'Панель администратора';
require __DIR__ . '/includes/header.php';
?>
<h1 class="h3 mb-3">Панель администратора</h1>

<?php if (isset($_GET['updated'])): ?>
    <div class="alert alert-success">Статус заявки №<?= e((int)$_GET['updated']) ?> сохранён.</div>
<?php endif; ?>
<?php if ($error !== ''): ?>
    <div class="alert alert-danger"><?= e($error) ?></div>
<?php endif; ?>

<p class="text-muted">Всего заявок: <?= count($requests) ?></p>

<div class="table-responsive">
<table class="table table-bordered align-middle">
    <thead class="table-light">
        <tr>
            <th>№</th><th>Заказчик</th><th>Услуга</th><th>Дата и время</th>
            <th>Адрес</th><th>Оплата</th><th>Статус</th><th>Изменить</th>
        </tr>
    </thead>
    <tbody>
    <?php foreach ($requests as $r): ?>
        <tr>
            <td><?= e($r['id']) ?><br><span class="small text-muted"><?= e(format_dt($r['created_at'])) ?></span></td>
            <td>
                <?= e($r['fio']) ?><br>
                <span class="small"><?= e($r['phone']) ?><br><?= e($r['email']) ?></span>
            </td>
            <td><?= $r['custom_service'] !== null ? 'Иная: ' . e($r['custom_service']) : e($r['service_name']) ?></td>
            <td><?= e(format_dt($r['date_time'])) ?></td>
            <td><?= e($r['address']) ?></td>
            <td><?= e(PAYMENTS[$r['payment']] ?? $r['payment']) ?></td>
            <td>
                <?= status_badge($r['status']) ?>
                <?php if ($r['cancel_reason'] !== null): ?>
                    <div class="small text-danger mt-1"><?= e($r['cancel_reason']) ?></div>
                <?php endif; ?>
            </td>
            <td style="min-width: 220px">
                <form method="post" action="admin.php" class="d-grid gap-1">
                    <?= csrf_field() ?>
                    <input type="hidden" name="id" value="<?= e($r['id']) ?>">
                    <select name="status" class="form-select form-select-sm">
                        <?php foreach (STATUSES as $value => $label): ?>
                            <option value="<?= e($value) ?>" <?= $value === $r['status'] ? 'selected' : '' ?>>
                                <?= e($label) ?>
                            </option>
                        <?php endforeach; ?>
                    </select>
                    <input name="cancel_reason" class="form-control form-control-sm"
                           placeholder="Причина отмены" maxlength="255"
                           value="<?= e($r['cancel_reason'] ?? '') ?>">
                    <button class="btn btn-sm btn-primary" type="submit">Сохранить</button>
                </form>
            </td>
        </tr>
    <?php endforeach; ?>
    </tbody>
</table>
</div>
<?php require __DIR__ . '/includes/footer.php'; ?>
```

Разберём решения.

- `require_admin()` — первая строка после подключения. Без неё всё остальное не имеет смысла.
- `(int)post('id')` — любое «мусорное» значение станет числом (или 0), и запрос безопасен даже теоретически.
- Причина отмены проверяется **на сервере**. Подсказка в интерфейсе (поле рядом) — для удобства, но если админ выбрал «Отменена» и не написал причину, сервер вернёт ошибку.
- `table-responsive` — на телефоне таблица прокручивается по горизонтали, а не ломает страницу. Если в макете админки у вас карточки — используйте их, логика та же.
- В `redirect('admin.php?updated=' . $id)` `$id` — уже целое число, а при выводе ещё и `(int)` + `e()`: в адресной строке пользователь может написать что угодно.

**А если в ТЗ правила переходов статусов?** Иногда ТЗ говорит, например, «отменить можно только новую заявку» или «выполненную заявку менять нельзя». Тогда перед `UPDATE` добавьте проверку текущего статуса (достаньте его вместе с `id` в первом запросе). Внимательно читайте ТЗ своего варианта.

**Типичные ошибки.**

- Все формы меняют одну и ту же заявку — скрытое поле `id` вне `<form>` или с неправильным значением.
- Статус сохраняется, но причина нет — поле причины называется в HTML иначе, чем в `post('cancel_reason')`.
- Отмена без причины проходит — проверка только атрибутом `required` в HTML (его и так нельзя ставить: при других статусах причина не нужна).
- `Data truncated for column 'status'` — в `<option>` значения по-русски («Отменена»), а `ENUM` ждёт `cancelled`.
- После обновления страницы F5 спрашивает о повторной отправке — нет редиректа после `UPDATE`.

**Связь с экзаменом.** Эксперт входит как `adminka`/`password`, находит заявку, созданную им же от имени пользователя, меняет статус на «В работе», затем пытается отменить без причины, потом с причиной, и возвращается в аккаунт пользователя проверить, видны ли статус и причина. Весь этот сценарий должен проходить без единой ошибки PHP.

## Задание

**Цель:** создать панель администратора со списком всех заявок и сменой статуса с обязательной причиной отмены.

**Ход работы:**

1. Создайте `admin.php` по образцу (заготовка из ЛР26 заменяется полностью).
2. Войдите как `adminka`/`password`. Проверьте, что видны заявки всех пользователей с ФИО, телефоном и email.
3. Смените статус одной заявки на «В работе», другой — на «Выполнена». Проверьте сообщение и обновление бейджей.
4. Попробуйте отменить заявку без причины — должна появиться ошибка, статус не меняется. Отмените с причиной.
5. Войдите пользователем-владельцем отменённой заявки и проверьте в `requests.php` статус и причину.
6. Верните отменённую заявку в «В работе» — причина должна очиститься (`NULL` в базе).
7. Проверки безопасности: в DevTools поменяйте скрытый `id` на `99999` — «Заявка не найдена»; поменяйте значение `option` на `deleted` — «Недопустимый статус»; удалите поле `csrf` — ответ 400; обычным пользователем откройте `admin.php` — 403.
8. Проверьте страницу на ширине 390 px. Коммит «ЛР29: панель администратора».

**Что сдать:** `admin.php`, скриншоты: панель со всеми статусами, ошибка «укажите причину», карточка отменённой заявки у пользователя.

## Критерии оценки

| Аспект | 2 балла | 1 балл | 0 баллов |
|---|---|---|---|
| Список всех заявок | Все заявки с ФИО и контактами заказчика, услугой, датой, оплатой, статусом | Не хватает части данных | Видны не все заявки или страница с ошибкой |
| Смена статуса | Работает для любой заявки, PRG, сообщение об успехе | Работает без PRG/сообщения | Не работает |
| Причина отмены | Обязательна при отмене (проверка на сервере), очищается при другом статусе, видна пользователю | Обязательна только в HTML или не очищается | Нет |
| Безопасность | `require_admin()`, CSRF, проверка `id` и статуса, подготовленные запросы | Не хватает одной проверки | Админка открыта или SQL с переменными |

:::quiz
? Почему в панели администратора соединяют три таблицы?
- [ ] Без трёх таблиц `UPDATE` не выполнится
- [ ] Так заявки сами сортируются по дате
- [ ] Это нужно для пагинации по 10 штук
- [x] Нужны заявка, ФИО заказчика и название услуги
> `requests` даёт саму заявку, `users` — кто её подал и контакты, `services` — название услуги.

? Почему обязательность причины отмены проверяют на сервере, а не `required`?
- [ ] `required` не работает у текстовых полей
- [x] Причина нужна только при отмене, и HTML легко обойти
- [ ] Сервер проверяет быстрее, чем браузер
- [ ] `required` нельзя ставить внутри таблицы
> При других статусах причина не нужна, а `required` требовал бы её всегда; к тому же проверку в браузере легко отключить.

? Зачем при смене статуса на «Выполнена» писать `cancel_reason = NULL`?
- [x] Чтобы у заявки не осталась старая причина отмены
- [ ] Иначе MySQL не даст сохранить новый статус
- [ ] Чтобы заявка пропала из истории пользователя
- [ ] Так экономится место в таблице заявок
> Если заявку отменяли, а потом выполнили, пользователь не должен видеть устаревшую причину отмены.

? Почему `rowCount()` после `UPDATE` может вернуть 0 для существующей заявки?
- [ ] Заявка была удалена другим администратором
- [ ] `rowCount()` работает только после `SELECT`
- [x] Статус сохранили тот же, и строка не изменилась
- [ ] Не передан CSRF-токен в форме
> MySQL считает только реально изменённые строки, поэтому существование заявки проверяют отдельным запросом.
