## Лекция

Сегодня мы закладываем фундамент портала. Это самая «скучная» и одновременно самая важная работа: на экзамене каркас пишется за первые 10–15 минут, и если он сделан правильно, всё остальное просто «навешивается» сверху.

**Зачем делить проект на файлы.** Каждой странице портала нужно одно и то же: настройки, подключение к базе, сессия, шапка с меню, подвал. Если писать это в каждом файле, то при смене пароля к базе придётся править восемь мест — и в одном вы обязательно ошибётесь. Поэтому общее выносим в отдельные файлы и подключаем через `require_once`. Цепочка подключений у нас такая:

```text
страница (например, requests.php)
  └─ require_once includes/auth.php
        └─ require_once db.php
              └─ require_once config.php
  └─ require includes/header.php   (HTML-шапка)
  ... содержимое страницы ...
  └─ require includes/footer.php   (HTML-подвал)
```

Страница подключает только `auth.php` — и автоматически получает и настройки, и базу, и функции.

**config.php — настройки и общие функции.** Здесь хранятся параметры подключения к базе (в XAMPP по умолчанию пользователь `root` без пароля), включается показ ошибок и запускается сессия. Сессию стартуем один раз и в одном месте — так не будет ошибки «session already started».

Также здесь живут две функции, которые будут нужны везде:

- `e()` — экранирует текст перед выводом в HTML (превращает `<` в `&lt;` и т. д.). Это защита от XSS: если пользователь в поле «адрес» напишет `<script>`, браузер покажет это как текст, а не выполнит. Правило курса: **любые данные из базы или формы выводим только через `e()`**.
- `redirect()` — отправляет браузер на другую страницу и **обязательно** останавливает скрипт (`exit`). Без `exit` код после редиректа продолжит выполняться — это классическая дыра: «редирект на вход» есть, а секретная страница всё равно отработала.

**db.php — подключение через PDO.** PDO (PHP Data Objects) — встроенный в PHP способ работать с базами данных. Почему не старый `mysqli_query`? PDO удобно работает с подготовленными запросами (защита от SQL-инъекций, ПР19) и выбрасывает понятные исключения при ошибках. Разберём настройки:

- `charset=utf8mb4` в строке подключения — иначе вместо русских букв в базе окажутся «кракозябры» или вопросики;
- `ERRMODE_EXCEPTION` — при ошибке SQL PHP сразу скажет, что не так (а не промолчит);
- `FETCH_ASSOC` — строки из базы приходят ассоциативными массивами `['fio' => '...']`, как в ПР16;
- `EMULATE_PREPARES => false` — настоящие подготовленные запросы на стороне MySQL, числа приходят числами.

Подключение оборачиваем в `try/catch`: если MySQL не запущен, пользователь увидит понятное сообщение, а не простыню с паролем к базе.

**header.php и footer.php.** Шапка содержит `<!doctype>`, `<head>`, меню и открывающий `<main>`. Меню зависит от того, кто вошёл: гостю — «Вход» и «Регистрация», пользователю — «Мои заявки» и «Новая заявка», администратору — «Панель администратора». Пока входа нет, меню будет «гостевым», но код уже готов. Заголовок вкладки страница передаёт через переменную `$title`, которую задаёт **до** подключения шапки.

Bootstrap подключаем **локальной копией** (`css/bootstrap.min.css`): на экзамене интернета может не быть, а CDN-ссылка тогда даст страницу без стилей.

**index.php — развилка.** Главная страница ничего не показывает, а отправляет: гостя — на вход, администратора — в панель, пользователя — к его заявкам.

**База данных.** Базу вы создали в модуле 4. Для сверки — эталонный скрипт (выполните его во вкладке SQL phpMyAdmin, если вашей базы нет или она отличается):

```sql
CREATE DATABASE IF NOT EXISTS portal CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE portal;

CREATE TABLE users (
  id            INT AUTO_INCREMENT PRIMARY KEY,
  fio           VARCHAR(150) NOT NULL,
  phone         VARCHAR(20)  NOT NULL,
  email         VARCHAR(100) NOT NULL,
  login         VARCHAR(50)  NOT NULL UNIQUE,
  password_hash VARCHAR(255) NOT NULL,
  role          ENUM('user','admin') NOT NULL DEFAULT 'user'
) ENGINE=InnoDB;

CREATE TABLE services (
  id   INT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(100) NOT NULL
) ENGINE=InnoDB;

CREATE TABLE requests (
  id             INT AUTO_INCREMENT PRIMARY KEY,
  user_id        INT NOT NULL,
  address        VARCHAR(255) NOT NULL,
  phone          VARCHAR(20)  NOT NULL,
  date_time      DATETIME     NOT NULL,
  service_id     INT NOT NULL,
  custom_service VARCHAR(255) NULL,
  payment        ENUM('cash','card') NOT NULL,
  status         ENUM('new','in_work','done','cancelled') NOT NULL DEFAULT 'new',
  cancel_reason  VARCHAR(255) NULL,
  created_at     TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id)    REFERENCES users(id),
  FOREIGN KEY (service_id) REFERENCES services(id)
) ENGINE=InnoDB;

INSERT INTO services (name) VALUES
  ('Общий клининг'), ('Генеральная уборка'), ('Послестроительная уборка'),
  ('Химчистка ковров и мебели'), ('Иная услуга');
```

Обратите внимание: `password_hash VARCHAR(255)`, а не `VARCHAR(32)` — хеш длинный, и если поле короткое, он обрежется и вход перестанет работать. Услуга «Иная услуга» лежит в справочнике как обычная строка: если пользователь выберет её, он обязан описать услугу в поле `custom_service` (ЛР27).

**Файлы каркаса.**

`config.php`:

```php
<?php
// config.php — настройки проекта. Подключается раньше всех остальных файлов.

const DB_HOST  = 'localhost';
const DB_NAME  = 'portal';
const DB_USER  = 'root';
const DB_PASS  = '';            // в XAMPP по умолчанию пароля нет
const APP_NAME = 'Портал заявок';

// Пока разрабатываем — показываем все ошибки.
error_reporting(E_ALL);
ini_set('display_errors', '1');

// Сессия: запускаем один раз, cookie недоступна из JavaScript.
if (session_status() === PHP_SESSION_NONE) {
    session_set_cookie_params(['httponly' => true, 'samesite' => 'Lax']);
    session_start();
}

// Справочники для вывода по-русски
const STATUSES = [
    'new'       => 'Новая',
    'in_work'   => 'В работе',
    'done'      => 'Выполнена',
    'cancelled' => 'Отменена',
];
const PAYMENTS = [
    'cash' => 'Наличные',
    'card' => 'Банковская карта',
];

// Экранирование вывода (защита от XSS). Используем ВЕЗДЕ при выводе данных.
function e(mixed $value): string
{
    return htmlspecialchars((string)$value, ENT_QUOTES, 'UTF-8');
}

// Перенаправление на другую страницу. exit обязателен!
function redirect(string $url): never
{
    header('Location: ' . $url);
    exit;
}
```

`db.php`:

```php
<?php
// db.php — подключение к MySQL. После подключения файла доступна переменная $pdo.
require_once __DIR__ . '/config.php';

try {
    $pdo = new PDO(
        'mysql:host=' . DB_HOST . ';dbname=' . DB_NAME . ';charset=utf8mb4',
        DB_USER,
        DB_PASS,
        [
            PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
            PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
            PDO::ATTR_EMULATE_PREPARES   => false,
        ]
    );
} catch (PDOException $ex) {
    error_log('Ошибка подключения к БД: ' . $ex->getMessage());
    http_response_code(500);
    exit('Не удалось подключиться к базе данных. Проверьте, запущен ли MySQL в XAMPP и верны ли настройки в config.php.');
}
```

`includes/auth.php` (пока заготовка, наполним в ЛР25–26):

```php
<?php
// includes/auth.php — всё про пользователя: кто вошёл, какая роль.
require_once __DIR__ . '/../db.php';

// Возвращает массив с данными вошедшего пользователя или null.
function current_user(): ?array
{
    return $_SESSION['user'] ?? null;
}

function is_admin(): bool
{
    return (current_user()['role'] ?? '') === 'admin';
}
```

**Типичные ошибки.**

- `SQLSTATE[HY000] [1049] Unknown database 'portal'` — база называется иначе; исправьте `DB_NAME`.
- `SQLSTATE[HY000] [2002] Connection refused` — не запущен MySQL в XAMPP.
- `Failed opening required '.../includes/db.php'` — неверный путь. В `auth.php` путь к `db.php` идёт на уровень выше: `__DIR__ . '/../db.php'`.
- `Call to undefined function current_user()` — страница подключила `header.php`, но забыла подключить `auth.php`.
- Страница без стилей — нет файла `css/bootstrap.min.css` (скачайте с getbootstrap.com архив «Compiled CSS and JS» и положите файл в `css/`).
- Строка после `?>` в конце `config.php` (даже пустая) может дать `headers already sent` при редиректе. Поэтому в файлах, где только PHP, закрывающий `?>` **не пишем**.

**Безопасность.** Уже сейчас: ошибки подключения не показываем пользователю (в них может быть логин БД), cookie сессии с флагом `httponly`, вывод только через `e()`, после `redirect()` всегда `exit`.

**Связь с экзаменом.** Экзаменатор открывает ваш портал в браузере и ходит по страницам. Единая шапка с правильным меню для каждой роли и отсутствие ошибок PHP на любой странице — это первое впечатление и часть аспектов «интерфейс по ТЗ». Каркас из этой работы вы будете писать по памяти на ЛР32 и на экзамене.

## Критерии оценки

| Аспект | 2 балла | 1 балл | 0 баллов |
|---|---|---|---|
| Структура файлов | Все файлы и папки по схеме модуля | 1–2 файла отсутствуют или названы иначе | Структуры нет, всё в одном файле |
| Подключение к БД через PDO | utf8mb4, исключения, `try/catch` с понятным сообщением | Подключение есть, но без обработки ошибок | Нет подключения или используется устаревший `mysql_*` |
| Общие шапка и подвал | Подключены на всех страницах, `$title` работает | Подключены не везде | Шапка скопирована в каждый файл |
| Функции `e()` и `redirect()` | Есть, `redirect()` завершает скрипт | Есть, но без `exit` | Нет |
| Отсутствие ошибок | Ни на одной странице нет Warning/Fatal | Есть предупреждения | Есть страницы с фатальной ошибкой |

## Если не успел / для сильных

**Минимум для зачёта:** `config.php`, `db.php` с рабочим подключением и одна страница с шапкой и подвалом.
**Для сильных:** выделите активный пункт меню (класс `active`) — сравнивайте `basename($_SERVER['SCRIPT_NAME'])` с адресом ссылки.
