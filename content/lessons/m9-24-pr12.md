## Лекция

**Почему портал должен «тянуться».** Экзаменационный макет нарисован под 390×844 — это размер популярных iPhone. Но у вашего одногруппника Android шириной 360px, у преподавателя планшет 768px, а эксперт, скорее всего, сначала откроет сайт на обычном мониторе 1920px. Если страница свёрстана «гвоздями» под 390px, на компьютере она будет узкой полосой у левого края, а на 360px — с обрезанной кнопкой. Адаптивная вёрстка — это когда **одна и та же страница** удобно выглядит на любом экране.

**Mobile-first: сначала телефон.** Есть два подхода. *Desktop-first*: сверстать большой экран, а потом «ломать» его под маленький. *Mobile-first*: сверстать мобильную версию как основную, а для больших экранов **добавлять** правила. Для нас выбор очевиден — у нас мобильный макет, и мобильные стили пишутся первыми, без всяких условий. Второе преимущество: мобильная раскладка почти всегда проще (всё в одну колонку), а расширять простое легче, чем упрощать сложное.

**Media queries — условия для CSS.** Медиазапрос говорит браузеру: «применяй эти правила, только если выполнено условие». В mobile-first используют `min-width` — «от такой-то ширины и шире»:

```css
/* Базовые стили: телефон, одна колонка */
.requests {
  display: grid;
  grid-template-columns: 1fr;
  gap: var(--space-2);
}

/* От 768px (планшет): две колонки */
@media (min-width: 768px) {
  .requests {
    grid-template-columns: 1fr 1fr;
  }
}

/* От 1200px (компьютер): три колонки */
@media (min-width: 1200px) {
  .requests {
    grid-template-columns: repeat(3, 1fr);
  }
}
```

Правила внутри медиазапроса не заменяют базовые целиком — они **дописываются поверх**. Поэтому внутри `@media` пишите только то, что меняется. Порядок важен: запросы с `min-width` идут от меньшего к большему, иначе более поздний перебьёт нужный.

**Контрольные точки (breakpoints).** Ширины, на которых меняется раскладка, называются брейкпоинтами. Не нужно подбирать их под конкретные модели телефонов — ставьте их там, где **ваша вёрстка начинает выглядеть плохо**. Для ориентира можно взять брейкпоинты Bootstrap 5, с которым мы будем работать в ЛР14: 576, 768, 992, 1200 и 1400px. Для портала заявок обычно хватает двух: 768px и 1200px.

Современный CSS позволяет писать диапазоны короче: `@media (width >= 768px)` — то же самое, что `(min-width: 768px)`. Все актуальные браузеры это понимают, но классическая запись встречается в примерах чаще, поэтому знать нужно обе.

**Относительные единицы.** Пиксели — абсолютная единица: 16px всегда 16px. Адаптивная вёрстка держится на единицах, которые зависят от чего-то ещё:

| Единица | Относительно чего | Где применять |
|---|---|---|
| `%` | размер родителя | ширина блоков, картинок |
| `rem` | размер шрифта корня (`html`), обычно 16px | шрифты, отступы |
| `em` | размер шрифта самого элемента | padding кнопки, чтобы он рос вместе с текстом |
| `vw` / `vh` | 1% ширины / высоты окна | крупные заголовки, полноэкранные блоки |
| `dvh` | 1% *видимой* высоты экрана с учётом панелей браузера | страница входа на весь экран |
| `fr` | доля свободного места в Grid | колонки сетки |
| `ch` | ширина символа «0» | ограничение длины строки текста |

Почему шрифты лучше в `rem`: если человек со слабым зрением увеличил шрифт в настройках браузера, вёрстка на `rem` вырастет вместе с ним, а на `px` — нет. `1.25rem` = 20px при стандартных настройках.

**Функции `min()`, `max()`, `clamp()`.** Они позволяют обойтись вообще без медиазапросов для плавных изменений. Самая полезная — `clamp(минимум, желаемое, максимум)`:

```css
h1 {
  /* на телефоне ~28px, растёт с шириной экрана, но не больше 40px */
  font-size: clamp(1.75rem, 1.2rem + 2vw, 2.5rem);
}

.page {
  /* ширина = 100% минус поля, но не больше 1100px */
  width: min(100% - 32px, 1100px);
  margin-inline: auto;
}
```

**Картинки и таблицы.** Две вещи, которые чаще всего ломают мобильную вёрстку:

```css
img {
  max-width: 100%;   /* никогда не шире родителя */
  height: auto;      /* сохранить пропорции */
}

.table-wrap {
  overflow-x: auto;  /* широкая таблица прокручивается внутри своего блока, а не вся страница */
}
```

Таблица заявок в админке на 390px не поместится — шесть колонок по 100px уже 600px. Варианты: обернуть её в блок с прокруткой или на телефоне превращать строки в карточки (это сделаем в ЛР13).

**Не только ширина.** Медиазапросы умеют проверять и другие свойства устройства. Два самых полезных для портала:

```css
/* Эффект наведения только там, где есть мышь: на телефоне «залипающий» hover мешает */
@media (hover: hover) {
  .request-card:hover { box-shadow: 0 8px 20px rgb(15 23 42 / 0.12); }
}

/* Горизонтальный телефон: форма входа не помещается по высоте — убираем центрирование */
@media (orientation: landscape) and (max-height: 500px) {
  .page--auth { justify-content: flex-start; }
}
```

На телефоне нет курсора, и после касания карточка может «застрять» в состоянии `:hover`, пока пользователь не нажмёт куда-то ещё. Запрос `(hover: hover)` включает эффект только на устройствах с мышью или тачпадом. А про горизонтальную ориентацию часто забывают совсем: пользователь повернул телефон, высота стала 390px, и кнопка «Войти» оказалась за краем экрана.

**Зоны нажатия.** Адаптив — это не только раскладка, но и размеры под палец. Палец намного толще курсора мыши, поэтому кнопки, ссылки меню и переключатели на телефоне должны быть не меньше 44×44px, а между соседними ссылками — промежуток хотя бы 8px. Ссылка «Выход» размером 12px в углу шапки — гарантированный промах.

**Как проверять адаптив.** В DevTools в режиме устройства выберите Responsive и тяните край окна от 320px до 1920px. Смотрите на три вещи: нет ли горизонтальной прокрутки, не слиплись ли элементы, читается ли текст. Если что-то «вылезает», найдите виновника: в консоли DevTools можно временно добавить всем элементам рамку `* { outline: 1px solid red; }` и увидеть, кто шире экрана.

**Типичные ошибки:**

1. Медиазапросы с `max-width` и `min-width` вперемешку — правила перебивают друг друга непредсказуемо.
2. Внутри `@media` скопированы *все* свойства блока, а не только изменённые.
3. Фиксированные `width: 390px` или `height: 844px` — макет подменяют реальностью.
4. `100vh` на телефоне — нижняя кнопка уходит под панель браузера.
5. Нет `max-width: 100%` у картинок — логотип рвёт шапку.
6. Не проверили 320–360px: в макете 390, а у реальных людей бывает уже.

**Связь с экзаменом.** Задание требует мобильный дизайн 390×844, но «разработка веб-приложения по ТЗ» оценивается в работающем браузере. Mobile-first даёт двойную выгоду: мобильная версия точно совпадёт с макетом, а на компьютере эксперта страница не развалится.

## Задание

**Цель:** понять принцип mobile-first и научиться писать медиазапросы и относительные размеры.

**Исходные данные:** файл `pr12.html` (выдаётся преподавателем), в нём шапка с меню из трёх ссылок, заголовок «Мои заявки» и шесть карточек заявок. Стили написаны desktop-first на пикселях:

```css
.page { width: 1100px; margin: 0 auto; }
h1 { font-size: 40px; }
.requests { display: grid; grid-template-columns: repeat(3, 1fr); gap: 24px; }
.nav a { margin-left: 32px; font-size: 18px; }
@media (max-width: 768px) {
  .page { width: 100%; }
  .requests { grid-template-columns: 1fr; }
  h1 { font-size: 28px; }
}
```

**Ход работы:**

1. Откройте `pr12.html` в DevTools на 390, 360 и 768px. Запишите, что ломается на каждой ширине.
2. Перепишите стили в порядке mobile-first: базовые правила — для телефона (одна колонка, `h1` 1.75rem), затем `@media (min-width: 768px)` — две колонки, `@media (min-width: 1200px)` — три.
3. Замените все `px` в шрифтах на `rem`, а ширину `.page` — на `min(100% - 32px, 1100px)`.
4. Задайте `h1` размер через `clamp()` и проверьте, как он меняется при растягивании окна.
5. Сделайте так, чтобы на телефоне меню из трёх ссылок переносилось (`flex-wrap: wrap`) и не вызывало прокрутки.
6. Добавьте в одну карточку изображение 800×600 и убедитесь, что оно не выходит за пределы карточки.
7. В настройках браузера увеличьте размер шрифта до «Очень крупный». Сравните: что выросло, а что нет? Почему?
8. Проверьте страницу на ширинах 320, 390, 768, 1024, 1440px, сделайте 3 скриншота.

**Что сдать:** исправленный `pr12.html`, записи из пп. 1 и 7, три скриншота.

## Критерии оценки

| Аспект | 2 балла | 1 балл | 0 баллов |
|---|---|---|---|
| Mobile-first | базовые стили для телефона, медиазапросы только `min-width` по возрастанию | подход смешанный | остался desktop-first |
| Медиазапросы | 1/2/3 колонки на нужных ширинах, внутри `@media` только изменения | раскладка меняется, но с дублированием | раскладка не меняется |
| Относительные единицы | шрифты в rem, ширина через min()/%, заголовок через clamp() | частично | только px |
| Отсутствие переполнения | нет горизонтальной прокрутки от 320 до 1440px | прокрутка на одной ширине | прокрутка на телефоне |
| Анализ | объяснено поведение при увеличении шрифта | объяснение неполное | ответа нет |

## Если не успел / для сильных

**Минимум:** переписать раскладку карточек в mobile-first с двумя медиазапросами и убрать горизонтальную прокрутку на 390px.
**Усложнение:** сделайте карточку, которая меняет раскладку в зависимости от ширины своего контейнера, а не экрана, — через container queries (`container-type: inline-size` и `@container (min-width: 400px)`).
