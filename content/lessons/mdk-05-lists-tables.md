## Маркированный список: `ul`

На занятии 3 мы уже сделали меню из списка. Теперь разберёмся подробно.

**Маркированный список** — список, где порядок пунктов не важен: что взять в поход, состав блюда, пункты меню. Он делается тегом `<ul>` (unordered list — «неупорядоченный список»). Каждый пункт — тег `<li>` (list item — «элемент списка»):

```html
<p>Что взять на практику:</p>
<ul>
  <li>ноутбук с зарядкой</li>
  <li>флешку</li>
  <li>тетрадь для конспекта</li>
</ul>
```

Что увидите: три строки с чёрными точками-**маркерами** слева и отступом.

Правила:

- внутри `ul` могут быть **только** `li`. Текст или абзац прямо в `ul` — ошибка;
- а вот внутри `li` можно что угодно: текст, ссылку, картинку, абзац, другой список.

Частая ошибка: делать список из абзацев с чёрточками («- ноутбук», «- флешка»). Выглядит похоже, но диктор не скажет «список, три пункта», а в CSS такой «список» не оформить одним правилом.

## Нумерованный список: `ol`

Когда порядок **важен** — шаги инструкции, рейтинг, план занятия, — нужен **нумерованный список** `<ol>` (ordered list):

```html
<p>Как записаться в библиотеку:</p>
<ol>
  <li>Возьмите студенческий билет.</li>
  <li>Подойдите в кабинет 204.</li>
  <li>Заполните анкету читателя.</li>
  <li>Получите читательский билет.</li>
</ol>
```

Что увидите: пункты с номерами 1, 2, 3, 4. Цифры браузер ставит сам. Если вставить новый шаг в середину, номера пересчитаются автоматически — руками ничего править не надо.

Частая ошибка: писать номера в тексте, `<li>1. Возьмите билет</li>`. Получится «1. 1. Возьмите билет».

### Атрибуты `ol`: `start`, `reversed`, `type`

| Атрибут | Что делает | Пример |
|---|---|---|
| `start="5"` | начать нумерацию с 5 | продолжение списка после картинки |
| `reversed` | считать в обратном порядке | топ-3: 3, 2, 1 |
| `type="A"` | буквы A, B, C | варианты ответа в тесте |
| `type="i"` | римские цифры i, ii, iii | разделы документа |

```html
<p>Топ-3 блюд недели в столовой:</p>
<ol reversed>
  <li>Котлета с пюре</li>
  <li>Борщ</li>
  <li>Сырники</li>
</ol>
```

Что увидите: пункты пронумерованы 3, 2, 1. Атрибут `reversed` — **логический**: у него нет значения, само его присутствие включает настройку.

## Вложенные списки

Пункт списка может содержать свой список. Так делают многоуровневые меню, оглавления, план с подпунктами:

```html
<ul>
  <li>Первый курс
    <ul>
      <li>Основы HTML</li>
      <li>Основы CSS</li>
    </ul>
  </li>
  <li>Второй курс</li>
</ul>
```

Что увидите: у «Первого курса» под ним сдвинутый вправо список из двух пунктов с маркерами-кружками.

Главное правило: вложенный список стоит **внутри** `li`, до его закрывающего тега `</li>`. Не между двумя `li`.

Частая ошибка:

```html
<ul>
  <li>Первый курс</li>
  <ul>
    <li>Основы HTML</li>
  </ul>
</ul>
```

Браузер покажет почти то же самое, но это неверная разметка: `ul` не может лежать прямо в `ul`. Валидатор выдаст ошибку. Помогают отступы: вложенный список сдвинут вправо внутри своего `li`, и ошибку видно сразу.

> **Попробуйте сами.** Нажмите «Попробовать» под примером вложенного списка. Добавьте во «Второй курс» вложенный список из двух предметов. Потом замените внешний `ul` на `ol` и посмотрите, что изменится.

## Список определений: `dl`, `dt`, `dd`

Третий вид списка — **список определений** (description list). Он для пар «термин — пояснение»: словарик, вопрос-ответ, характеристики товара.

- `<dl>` — обёртка списка;
- `<dt>` — термин (description term);
- `<dd>` — его описание (description details).

```html
<dl>
  <dt>Тег</dt>
  <dd>Команда разметки в угловых скобках.</dd>
  <dt>Атрибут</dt>
  <dd>Настройка тега: имя и значение.</dd>
</dl>
```

Что увидите: термины слева, а их описания — ниже, с отступом. Внизу этого урока, в разделе «Словарик», мы как раз пользуемся этой идеей.

Пары `dt`–`dd` идут по очереди. У одного термина может быть несколько описаний (несколько `dd` подряд). В карточке товара так удобно описать характеристики: «Вес — 250 г», «Калорийность — 320 ккал».

## Где прячутся списки на настоящих сайтах

Откройте любой интернет-магазин и посмотрите внимательно. Списков там гораздо больше, чем кажется:

- **меню в шапке** — `ul` со ссылками, просто CSS выстроил пункты в ряд и убрал точки;
- **карточки товаров** в каталоге — часто тоже `ul`: каждая карточка — пункт `li`;
- **«хлебные крошки»** (Главная → Каталог → Чайники) — нумерованный список `ol`, ведь порядок важен;
- **характеристики товара** (Мощность — 2000 Вт, Объём — 1,7 л) — список определений `dl`;
- **ссылки в подвале** сайта — несколько `ul`, по одному на колонку.

Маркеры и отступы, которые мы видим в песочнице, — только оформление по умолчанию. В CSS их можно убрать, выстроить пункты в строку или в сетку. Поэтому выбирайте список по смыслу, а не по виду: «это перечень однотипных вещей?» — значит, список.

## Таблицы: когда они нужны

**Таблица** нужна, когда у данных есть строки и столбцы и каждое значение имеет смысл на пересечении: расписание (день × пара), прайс-лист (услуга × цена), результаты соревнований. Если вы можете представить эти данные в Excel — это таблица.

Таблица строится из тегов:

| Тег | Что это |
|---|---|
| `<table>` | вся таблица |
| `<tr>` | table row — строка |
| `<th>` | table header — ячейка-заголовок (жирная, по центру) |
| `<td>` | table data — обычная ячейка |
| `<caption>` | название таблицы, первым внутри `table` |

```html
<table>
  <caption>Цены в буфете</caption>
  <tr>
    <th>Блюдо</th>
    <th>Цена</th>
  </tr>
  <tr>
    <td>Пирожок с картошкой</td>
    <td>45&nbsp;₽</td>
  </tr>
  <tr>
    <td>Чай</td>
    <td>25&nbsp;₽</td>
  </tr>
</table>
```

Что увидите: подпись «Цены в буфете», под ней три строки по две ячейки. Первая строка жирная. Рамок не будет: по умолчанию у таблицы их нет, рамки рисуют в CSS (в заданиях этого урока они уже есть во вкладке `style.css`).

Таблица собирается **по строкам**: сначала `tr`, внутри — ячейки слева направо. Во всех строках должно получиться одинаковое число ячеек, иначе столбцы «поедут».

`caption` — название таблицы. Диктор прочитает его первым, и человек сразу поймёт, о чём таблица. На экзамене таблица без подписи — недочёт.

## Части таблицы: `thead`, `tbody`, `tfoot`

Большую таблицу делят на три части, как документ на шапку, текст и подвал:

- `<thead>` — строка (или строки) заголовков столбцов;
- `<tbody>` — основные данные;
- `<tfoot>` — итоги: «Всего», «Итого».

```html
<table>
  <caption>Заказ группы ИСП-11 в столовой</caption>
  <thead>
    <tr>
      <th scope="col">Блюдо</th>
      <th scope="col">Порций</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Суп</th>
      <td>18</td>
    </tr>
    <tr>
      <th scope="row">Котлета</th>
      <td>20</td>
    </tr>
  </tbody>
  <tfoot>
    <tr>
      <th scope="row">Всего</th>
      <td>38</td>
    </tr>
  </tfoot>
</table>
```

Что увидите: обычную таблицу из четырёх строк. Части не меняют вид, но дают смысл: браузер при печати длинной таблицы повторит `thead` на каждом листе, а в CSS можно оформить шапку и итоги отдельно.

### Атрибут `scope`

Заголовки бывают у столбцов и у строк. Атрибут `scope` у `th` говорит, к чему заголовок относится:

- `scope="col"` — заголовок **столбца** (обычно в `thead`);
- `scope="row"` — заголовок **строки** (первая ячейка строки).

Зачем? Незрячий человек слушает таблицу по ячейкам. Когда он дойдёт до числа «20», диктор благодаря `scope` скажет: «Котлета, Порций, 20». Без `scope` он услышит просто «20» и запутается.

## Объединение ячеек: `colspan` и `rowspan`

Иногда ячейка должна занять место нескольких. Например, в расписании обед тянется на всю ширину, а одна пара длится два часа подряд.

- `colspan="2"` — ячейка растягивается на **2 столбца** вправо;
- `rowspan="2"` — ячейка растягивается на **2 строки** вниз.

```html
<table>
  <caption>Вторник</caption>
  <tr>
    <th scope="col">Время</th>
    <th scope="col">Предмет</th>
    <th scope="col">Кабинет</th>
  </tr>
  <tr>
    <th scope="row">8:30</th>
    <td>Математика</td>
    <td rowspan="2">305</td>
  </tr>
  <tr>
    <th scope="row">10:10</th>
    <td>Физика</td>
  </tr>
  <tr>
    <th scope="row">11:40</th>
    <td colspan="2">Обед</td>
  </tr>
</table>
```

Что увидите: кабинет 305 записан один раз, но занимает две строки (математика и физика в одном кабинете). «Обед» растянут на два столбца.

Главное правило: если ячейка растянута, **соседние ячейки надо удалить**. В строке с обедом всего две ячейки (`th` и `td colspan="2"`) — вместе они дают три столбца. В строке с физикой тоже две: третью место занял `rowspan` сверху.

Частая ошибка: поставить `colspan="2"` и оставить все ячейки. Строка станет длиннее остальных, и таблица «вылезет» вправо.

> **Попробуйте сами.** В примере со вторником уберите `rowspan="2"` и посмотрите, что сломалось. Как починить? Добавьте в строку физики третью ячейку `<td>305</td>`.

## Как собрать таблицу по шагам

Таблицы пугают новичков количеством тегов. Если идти по порядку, всё просто. Допустим, администратор спортзала прислал данные:

```
Занятие      | Дни          | Время
Йога         | Пн, Ср       | 18:00
Бокс         | Вт, Чт       | 19:00
Бассейн      | каждый день  | 7:00–22:00
```

1. **Посчитайте столбцы.** Здесь их три. Это число нужно держать в голове до конца.
2. **Напишите каркас**: `table`, внутри `caption` с названием, `thead` и `tbody`.
3. **Шапка**: одна строка `tr` в `thead`, в ней три `th scope="col"`.
4. **Данные**: по строке `tr` на каждое занятие. Первая ячейка — название занятия, это заголовок строки: `th scope="row"`. Остальные — `td`.
5. **Проверьте счёт**: в каждой строке три ячейки (или меньше, если есть `colspan`).

```html
<table>
  <caption>Расписание спортзала</caption>
  <thead>
    <tr>
      <th scope="col">Занятие</th>
      <th scope="col">Дни</th>
      <th scope="col">Время</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Йога</th>
      <td>Пн, Ср</td>
      <td>18:00</td>
    </tr>
    <tr>
      <th scope="row">Бокс</th>
      <td>Вт, Чт</td>
      <td>19:00</td>
    </tr>
    <tr>
      <th scope="row">Бассейн</th>
      <td>каждый день</td>
      <td>7:00–22:00</td>
    </tr>
  </tbody>
</table>
```

Что увидите: название таблицы и четыре строки по три ячейки; названия занятий и шапка — жирные.

Совет: пишите отступы так, чтобы каждая ячейка была на своей строке. Тогда пропущенную ячейку видно сразу — столбик кода становится короче. А если таблица большая, сначала напишите одну строку данных, проверьте её в браузере и только потом копируйте для остальных.

## Таблица — только для данных

Двадцать лет назад сайты верстали таблицами: шапку клали в одну ячейку, меню — в другую, текст — в третью. Сегодня так делать **нельзя**:

- диктор объявит «таблица, 3 столбца, 5 строк» там, где никакой таблицы нет, и человек запутается;
- такая страница не перестраивается под телефон;
- код становится огромным и запутанным.

Для раскладки страницы по колонкам есть CSS (Flexbox и Grid — темы занятий 21–22). Правило для экзамена: **таблица — только для табличных данных**. Расписание, цены, сравнение тарифов — да. Шапка сайта, карточки товаров, фото рядом с текстом — нет.

| Задача | Чем размечать |
|---|---|
| Состав салата | `ul` |
| Шаги записи к врачу | `ol` |
| Словарь терминов, вопрос-ответ | `dl` |
| Расписание пар на неделю | `table` |
| Меню сайта | `ul` со ссылками |
| Фото слева, текст справа | не таблица, а CSS |

## Главное за занятие

- `ul` — порядок не важен, `ol` — важен. Пункты — только `li`, номера браузер ставит сам.
- У `ol` есть `start`, `reversed`, `type`. Вложенный список кладут внутрь `li`.
- `dl` — пары «термин `dt` — описание `dd`».
- Таблица: `table` → `tr` → `th`/`td`, название — `caption`, части — `thead`, `tbody`, `tfoot`.
- `scope="col"` и `scope="row"` объясняют диктору, к чему относится заголовок.
- `colspan` и `rowspan` объединяют ячейки; лишние ячейки при этом удаляют.
- Таблица — только для данных, не для раскладки страницы.

## Словарик

- **Маркированный список (ul)** — список, где порядок не важен.
- **Нумерованный список (ol)** — список, где важен порядок.
- **li** — пункт списка.
- **Список определений (dl)** — пары «термин — описание».
- **Таблица (table)** — данные в строках и столбцах.
- **Ячейка** — `td` с данными или `th` с заголовком.
- **caption** — название таблицы.
- **colspan / rowspan** — растянуть ячейку на несколько столбцов или строк.
- **Логический атрибут** — атрибут без значения, работает самим присутствием: `reversed`.

## Проверь себя

1. Какой список подойдёт для шагов «Как оплатить обучение» и почему?
2. Где ошибка: `<ul><li>Чай</li><p>Кофе</p></ul>`?
3. Куда правильно поставить вложенный список: внутрь `li` или между двумя `li`?
4. Зачем таблице `caption` и `scope`, если всё и так видно?
5. В таблице три столбца. В строке есть ячейка с `colspan="3"`. Сколько ещё ячеек должно быть в этой строке?
6. Почему нельзя раскладывать шапку сайта и меню по ячейкам таблицы?
