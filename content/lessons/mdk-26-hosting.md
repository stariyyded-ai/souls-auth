## Сайт у вас и сайт в интернете

Пока вы открываете `index.html` двойным щелчком, адрес в браузере выглядит так:

```
file:///C:/Users/Anna/Desktop/cafe/index.html
```

Слово `file:` значит: браузер взял файл **с вашего диска**. Ваш друг по этому адресу ничего не увидит: у него нет вашего диска. Чтобы сайт открывался у всех, файлы нужно положить на компьютер, который:

- всегда включён и подключён к интернету;
- умеет отвечать на запросы браузеров;
- имеет понятный адрес.

Такой компьютер мы уже знаем по первому занятию: это **сервер**. Вспомните цепочку: браузер отправляет запрос, сервер присылает файлы, браузер рисует страницу. Сегодня мы разберём, как ваши файлы оказываются на сервере и как люди находят его по имени.

## Домен и DNS

У каждого компьютера в интернете есть номер — **IP-адрес**, например `185.12.34.56`. Запомнить такие цифры трудно, поэтому придумали **домены** — имена вроде `college-cafe.ru`.

Домен читается справа налево, от общего к частному:

| Часть | Пример | Что значит |
|---|---|---|
| Домен первого уровня | `.ru` | Зона: страна или тип (`.ru`, `.рф`, `.com`, `.org`) |
| Домен второго уровня | `college-cafe` | Имя, которое вы покупаете |
| Поддомен | `menu.college-cafe.ru` | Отдельный раздел, его создаёте вы сами |

Домен **арендуют** у компании-**регистратора** обычно на год, потом продлевают. Частая ошибка начинающих: забыть продлить домен. Через месяц после окончания срока имя может купить кто-то другой.

Как браузер узнаёт IP-адрес по имени? Для этого есть **DNS** (Domain Name System, система доменных имён). Это «телефонная книга» интернета:

1. Вы вводите `college-cafe.ru`.
2. Браузер спрашивает у DNS-сервера: «Какой IP у этого имени?»
3. DNS отвечает: `185.12.34.56`.
4. Браузер идёт по этому адресу к серверу и просит файлы.

После покупки домена его нужно «привязать» к серверу: в настройках домена указать адрес хостинга. Изменения DNS расходятся по интернету не мгновенно, иногда до суток. Если сайт «не открывается» сразу после настройки — скорее всего, просто нужно подождать.

## Хостинг

**Хостинг** — услуга, когда компания даёт вам место на своём сервере и следит, чтобы он работал круглые сутки. Сервер стоит в **дата-центре** — здании с охраной, охлаждением и запасным питанием.

Хостинг бывает разный:

| Вид | Для чего | Пример задачи |
|---|---|---|
| **Статический хостинг** | Только файлы HTML, CSS, JS, картинки | Визитка, лендинг, портфолио, сайт из этого курса |
| **Виртуальный хостинг** | Сайты с программами на сервере и базами данных | Сайт на WordPress, интернет-магазин |
| **VPS / выделенный сервер** | Свой сервер целиком, всё настраиваете сами | Большие проекты, свои сервисы |

Всё, что мы делаем в этом курсе (HTML, CSS, немного JavaScript), — **статический сайт**: сервер ничего не вычисляет, а просто отдаёт файлы как есть. Для него подходит статический хостинг, часто бесплатный:

- **GitHub Pages** — бесплатно публикует сайт из репозитория на GitHub, адрес вида `имя.github.io`.
- **Netlify**, **Vercel**, **Cloudflare Pages** — перетащили папку в окно браузера, и сайт опубликован.
- Российские хостинги тоже дают тарифы для простых сайтов и бесплатный HTTPS.

Для портфолио к демоэкзамену бесплатного статического хостинга более чем достаточно.

## Как загрузить файлы на сервер

Способов несколько, все они делают одно и то же: копируют вашу папку проекта на сервер.

### Панель хостинга

У каждого хостинга есть **панель управления** — сайт, где вы настраиваете свой аккаунт. В ней обычно есть **файловый менеджер**: он похож на «Проводник». Открываете нужную папку, нажимаете «Загрузить» и выбираете файлы. Так проще всего залить маленький сайт.

### FTP и SFTP

**FTP** (File Transfer Protocol) — протокол для передачи файлов. Программа-клиент, например **FileZilla**, показывает два окна: слева ваш компьютер, справа сервер. Файлы перетаскиваются мышкой.

Для подключения хостинг выдаёт четыре вещи:

| Что | Пример |
|---|---|
| Сервер (хост) | `ftp.college-cafe.ru` |
| Логин | `cafe_admin` |
| Пароль | выдаётся в панели |
| Порт | `21` для FTP, `22` для SFTP |

Обычный FTP передаёт пароль **открытым текстом**: его может подсмотреть кто угодно в той же Wi-Fi-сети, например в кафе или колледже. Поэтому выбирайте **SFTP** — тот же обмен файлами, но зашифрованный. В FileZilla для этого в поле «Хост» пишут `sftp://` перед адресом.

### Через Git (для GitHub Pages)

На GitHub Pages файлы попадают через **репозиторий** — папку проекта, которая хранит историю изменений. Вы загружаете файлы в репозиторий (даже прямо в браузере кнопкой «Add file → Upload files»), включаете Pages в настройках, и через минуту сайт доступен.

> **Попробуйте сами.** Откройте папку любого вашего проекта и посмотрите, как называются файлы. Есть ли там пробелы, русские буквы или заглавные буквы? Запишите, что придётся переименовать перед публикацией — дальше станет понятно, почему.

## Папки на сервере

На сервере у сайта есть **корневая папка** (корень сайта). У разных хостингов она называется по-разному: `public_html`, `www`, `htdocs`. Всё, что лежит в ней, доступно из интернета.

```
public_html/
├── index.html      ← главная страница
├── 404.html        ← страница «не найдено»
├── robots.txt      ← правила для поисковых роботов
├── css/
│   └── style.css
├── js/
│   └── script.js
└── img/
    ├── logo.svg
    └── hall.jpg
```

Правила, которые нужно знать:

- Когда человек открывает `https://college-cafe.ru/`, сервер ищет в корне файл **`index.html`** и отдаёт его. Если файла нет, человек увидит ошибку или список файлов. Поэтому главная страница всегда называется `index.html`, маленькими буквами.
- То же работает для папок: адрес `https://college-cafe.ru/menu/` откроет файл `menu/index.html`.
- Если страницы нет, сервер отвечает кодом **404** («не найдено»). Многие хостинги показывают в этом случае ваш файл **`404.html`**. Так человек увидит не скучную ошибку, а страницу в стиле сайта со ссылкой на главную.

### Регистр букв и пробелы

Ваш компьютер на Windows не различает `Logo.svg` и `logo.svg`. А серверы почти всегда работают на **Linux**, и для них это **два разных файла**. Частая ошибка: на компьютере картинка видна, а после загрузки на хостинг — нет. Причина — в коде написано `img/Logo.svg`, а файл называется `logo.svg`.

Поэтому имена файлов и папок пишем так:

- латиницей, **маленькими буквами**: `contacts.html`, а не `Контакты.html` или `Contacts.html`;
- без пробелов, слова соединяем дефисом: `hall-photo.jpg`, а не `hall photo.jpg`;
- путь пишем через прямую косую `/`: `img/logo.svg`, а не `img\logo.svg`.

### Только относительные пути

На занятии про ссылки мы разбирали абсолютные и относительные пути. Перед публикацией проверьте, что в коде **нет путей к вашему диску**:

```html
<!-- Так работает только на вашем компьютере -->
<img src="C:\Users\Anna\Desktop\cafe\img\logo.svg" alt="Кафе «Зерно»">
<a href="file:///C:/Users/Anna/Desktop/cafe/menu.html">Меню</a>

<!-- Так работает везде -->
<img src="img/logo.svg" alt="Кафе «Зерно»">
<a href="menu.html">Меню</a>
```

Что увидите: в первом варианте на сервере вместо логотипа будет значок «битой» картинки, а ссылка «Меню» никуда не приведёт. Во втором всё откроется и на компьютере, и на хостинге.

## HTTPS и сертификат

Буква **s** в `https` значит, что данные между браузером и сервером шифруются. Для этого серверу нужен **SSL-сертификат** (сейчас правильнее говорить TLS, но слово SSL прижилось). Сертификат — это электронный «паспорт» сайта: он подтверждает, что `college-cafe.ru` — именно этот сервер, а не подделка.

Почему HTTPS нужен даже простой визитке:

- браузеры помечают сайты без HTTPS как **«Не защищено»** — это отпугивает посетителей;
- поисковики показывают такие сайты ниже;
- без шифрования данные формы (имя, телефон) может перехватить кто-то в той же сети.

Хорошая новость: сертификат **Let's Encrypt** бесплатный, и почти все хостинги выпускают его одной кнопкой в панели. GitHub Pages и Netlify включают HTTPS сами.

Частая ошибка после перехода на HTTPS — **смешанное содержимое**: страница открыта по `https://`, а картинка или скрипт подключены по `http://`. Браузер такие файлы блокирует или снова пишет «Не защищено». Решение: везде писать `https://` или относительные пути.

## Поддержка сайта

Опубликовать сайт — половина дела. Сайт нужно **поддерживать**, как машину: иначе через полгода он устареет или сломается.

| Что делать | Зачем | Как часто |
|---|---|---|
| Обновлять содержимое | Цены, расписание, контакты должны быть актуальными | По мере изменений |
| Делать резервные копии | Если что-то сломается или удалится, можно вернуть | Перед каждым изменением и по расписанию |
| Проверять ссылки | Чужие сайты переезжают, ваши страницы переименовываются | Раз в месяц |
| Следить за скоростью | Тяжёлые картинки замедляют сайт на телефоне | После добавления контента |
| Продлевать домен и хостинг | Иначе сайт пропадёт | Раз в год, лучше с автопродлением |
| Обновлять CMS и плагины | Старые версии взламывают | Сразу после выхода обновлений |

**Резервная копия** (бэкап) — копия всех файлов сайта, сохранённая отдельно: на вашем компьютере или в облаке. Простое правило: перед любой правкой на сервере скачайте текущую версию. Ошиблись — загрузили копию обратно.

**«Битые» ссылки** — ссылки на страницы, которых больше нет. Человек нажимает и попадает на ошибку 404. Найти их помогают онлайн-сервисы проверки ссылок и инструменты для вебмастеров у поисковиков.

**Скорость.** Самая частая причина медленного сайта — огромные фотографии. Снимок с телефона весит 3–5 МБ, а для сайта хватит 100–200 КБ. Как правильно сжимать и подбирать картинки, мы подробно разберём на практической работе №7. Проверить скорость можно сервисом **PageSpeed Insights**: он покажет оценку и подскажет, что исправить.

## Как поисковики находят сайт

Поисковые системы (Яндекс, Google) постоянно обходят интернет **роботами**: программами, которые открывают страницы и запоминают их содержимое. Помочь роботам можно двумя файлами в корне сайта.

**robots.txt** — правила для роботов: что можно читать, а что нет.

```
User-agent: *
Disallow: /drafts/
Sitemap: https://college-cafe.ru/sitemap.xml
```

Здесь написано: «всем роботам (`*`) не заходить в папку `drafts`, а список страниц лежит по такому адресу».

**sitemap.xml** — карта сайта для роботов: список всех страниц. Для маленького сайта её можно не делать, для большого — обязательно. Многие CMS создают её сами.

### Мета-теги title и description

Главное, что видит человек в результатах поиска, берётся из `head` страницы. На втором занятии мы писали `title`, теперь добавим **описание**:

```html
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Кофейня «Зерно» у колледжа — меню и цены</title>
  <meta name="description" content="Кофе, выпечка и обеды для студентов в двух минутах от колледжа. Скидка 10% по студенческому, открыты с 8:00.">
</head>
```

Что увидите в поиске: синей ссылкой — текст из `title`, под ним серым — текст из `description`.

Правила хорошего заголовка и описания:

- `title` — **до 60–70 знаков**, уникальный для каждой страницы. Сначала главное: «Меню — кофейня „Зерно“», а не «Главная | Сайт | Кофейня».
- `description` — **50–160 знаков**, живое описание страницы. Длиннее поисковик обрежет многоточием.
- В описании скажите, **чем страница полезна**: что тут есть, для кого, чем вы отличаетесь.
- Частая ошибка: одинаковый `title` «Главная» на всех страницах. В истории браузера и во вкладках их не отличить.

> **Попробуйте сами.** Найдите в поиске любое кафе вашего города. Сравните заголовок и описание в результатах поиска с тем, что написано в коде страницы (Ctrl+U, ищите `<title>` и `description`).

## Страница 404

Хорошая страница 404 не ругает человека, а помогает ему:

```html
<main class="not-found">
  <p class="code">404</p>
  <h1>Страница не найдена</h1>
  <p>Возможно, её переименовали или в адресе опечатка.</p>
  <p><a href="index.html">Перейти на главную</a></p>
</main>
```

Что увидите: крупное число 404, понятный заголовок, объяснение и ссылку на главную. Хорошо добавить ещё список популярных разделов: «Меню», «Контакты», «Акции». И не забудьте стиль: страница 404 должна выглядеть как часть вашего сайта, с той же шапкой и цветами.

## Чек-лист перед публикацией

Перед тем как загружать сайт, пройдите по списку. На демоэкзамене тоже стоит проверить эти пункты перед сдачей:

1. Главная страница называется `index.html`.
2. Имена файлов — латиница, маленькие буквы, без пробелов.
3. Все пути относительные, без `C:\` и `file://`.
4. Все картинки открываются, у каждой есть `alt`.
5. У каждой страницы свой `title` и `description`.
6. Есть `meta viewport`: без него сайт на телефоне будет мелким.
7. Внешние ссылки и подключения — через `https://`.
8. Есть страница `404.html` со ссылкой на главную.
9. Код проходит валидатор W3C без ошибок.

## Главное за занятие

- Домен — имя сайта, DNS превращает его в IP-адрес сервера.
- Хостинг — место на сервере; для HTML/CSS/JS хватит статического хостинга (GitHub Pages и аналоги).
- Файлы загружают через панель хостинга, SFTP или Git; обычный FTP передаёт пароль открыто.
- В корне сайта — `index.html` и `404.html`; имена файлов латиницей, маленькими буквами, без пробелов.
- HTTPS обязателен, бесплатный сертификат даёт Let's Encrypt.
- Поддержка: обновления, резервные копии, проверка ссылок, скорость.
- Для поиска: свой `title` и `description` у каждой страницы, `robots.txt` и `sitemap.xml`.

## Словарик

- **IP-адрес** — числовой адрес компьютера в сети.
- **Домен** — имя сайта: `college-cafe.ru`.
- **DNS** — система, которая по имени домена находит IP-адрес.
- **Хостинг** — аренда места на сервере, который работает круглые сутки.
- **Корень сайта** — папка на сервере, содержимое которой видно из интернета.
- **FTP / SFTP** — протоколы передачи файлов; SFTP — зашифрованный.
- **SSL-сертификат** — «паспорт» сайта для работы по HTTPS.
- **Резервная копия (бэкап)** — сохранённая копия файлов сайта.
- **robots.txt, sitemap.xml** — файлы-подсказки для поисковых роботов.
- **Мета-описание (description)** — краткое описание страницы для результатов поиска.

> DNS — «телефонная книга»: имя → IP-адрес. Шифрует HTTPS, хранит файлы хостинг.

? Какой хостинг подойдёт для сайта-визитки на HTML, CSS и JavaScript?
- [x] Статический, например GitHub Pages
- [ ] Только выделенный сервер
- [ ] Никакой, такой сайт работает без сервера
> Статическому сайту сервер нужен только чтобы отдавать файлы — с этим справится бесплатный статический хостинг.

? Почему вместо FTP лучше выбрать SFTP?
- [ ] SFTP загружает файлы быстрее в 10 раз
- [ ] Через FTP нельзя загрузить картинки
- [x] SFTP шифрует передачу, а FTP отправляет пароль открытым текстом
> Обычный FTP можно «подслушать» в общей Wi-Fi-сети.

? Человек открыл `https://college-cafe.ru/`. Какой файл сервер ищет в корне сайта?
- [ ] `main.html`
- [ ] `home.html`
- [x] `index.html`
> По умолчанию для адреса папки сервер отдаёт `index.html`.

? На компьютере логотип виден, на хостинге — нет. В коде `img/Logo.svg`, файл называется `logo.svg`. В чём дело?
- [ ] Хостинг не поддерживает SVG
- [x] Сервер различает заглавные и маленькие буквы в именах файлов
- [ ] Нужно купить сертификат
> Windows не различает регистр, а сервер на Linux различает: `Logo.svg` и `logo.svg` — разные файлы.

? Какой путь к картинке правильный для публикации?
- [ ] `C:\site\img\hall.jpg`
- [ ] `file:///C:/site/img/hall.jpg`
- [x] `img/hall.jpg`
> Относительный путь работает и на компьютере, и на сервере.

? Что такое «смешанное содержимое»?
- [x] Страница открыта по HTTPS, а картинка или скрипт подключены по HTTP

- [ ] Сайт на двух языках

? Где поисковик берёт серый текст под ссылкой в результатах поиска?
