## Лекция

Портал работает — а значит, самое время научиться быстро чинить его, когда он ломается, и навести порядок в коде. На экзамене 30 минут, потраченные на поиск одной опечатки, — это потерянный модуль. Цель сегодня: **любую ошибку находить за 2–3 минуты**.

## Часть 1. Читаем сообщения об ошибках

Сообщение PHP всегда отвечает на три вопроса: **что** случилось, **в каком файле**, **в какой строке**.

```text
Warning: Undefined array key "service" in C:\xampp\htdocs\portal\requests.php on line 41
   ↑ уровень        ↑ что случилось                    ↑ файл                       ↑ строка
```

Уровни ошибок:

| Уровень | Что значит | Скрипт |
|---|---|---|
| `Parse error` | Синтаксис: пропущены `;`, скобка, кавычка | Не запускается вообще |
| `Fatal error` / `Uncaught ...Error` | Вызвана несуществующая функция, неверный тип, не найден файл в `require` | Останавливается |
| `Uncaught PDOException: SQLSTATE[...]` | Ошибка в SQL или в данных | Останавливается |
| `Warning` | Нет ключа массива, нет переменной, не найден файл в `include` | Работает дальше, но результат неверный |
| `Deprecated` | Устаревшая конструкция | Работает, но стоит исправить |

**Правило поиска.** Для `Parse error` смотрите строку из сообщения **и строку выше**: точку с запятой забыли там, а PHP заметил это только на следующей. Для `Uncaught` — читайте до конца, внизу есть стек вызовов (`#0 ... #1 ...`): какая ваша строка вызвала ошибку.

**Шпаргалка по самым частым ошибкам портала.**

| Сообщение | Причина | Лечение |
|---|---|---|
| `syntax error, unexpected token "}"` | Лишняя/недостающая скобка, `;` | Проверить строку выше, парность скобок (VS Code подсвечивает) |
| `Undefined variable $user` | Опечатка или переменная не создана в этой области (внутри функции не видно внешних переменных) | Проверить имя; передать в функцию параметром |
| `Undefined array key "fio"` | Нет ключа: опечатка, поле формы без `name`, столбец не выбран в `SELECT` | `var_dump()` массива, сверить имена |
| `Call to undefined function e()` | Не подключён `config.php`/`auth.php` | Первая строка страницы — `require_once ... auth.php` |
| `Cannot modify header information - headers already sent by (output started at ...:1)` | Вывод до `header()`/`redirect()`/`session_start()` | Убрать пробел/BOM перед `<?php`, перенести обработку формы выше HTML |
| `SQLSTATE[42S22]: Column not found: 1054 Unknown column` | Опечатка в имени столбца | Сверить со структурой таблицы |
| `SQLSTATE[42S02]: Base table or view not found` | Нет таблицы или опечатка в имени | Проверить базу в `DB_NAME` |
| `SQLSTATE[HY093]: Invalid parameter number` | Число `?` не равно числу значений | Пересчитать |
| `SQLSTATE[23000]: ... Duplicate entry` | Нарушен `UNIQUE` | Проверка перед вставкой |
| `SQLSTATE[23000]: ... foreign key constraint fails` | Ссылка на несуществующую строку | Проверить `user_id`/`service_id` |
| `PDOStatement::execute(): Argument #1 must be of type ?array, int given` | `execute($id)` вместо `execute([$id])` | Квадратные скобки |
| Белый экран | Выключен вывод ошибок | `display_errors = 1` в `config.php` |

## Часть 2. Инструменты отладки

**`var_dump()` и `print_r()`** — «рентген» переменной. Показывают, что реально лежит внутри, вместе с типом:

```php
<?php
$row = ['id' => 5, 'status' => 'new', 'cancel_reason' => null];
echo '<pre>';
var_dump($row);      // типы и длины: int(5), string(3) "new", NULL
print_r($_POST);     // компактнее, без типов
echo '</pre>';
exit;                // остановиться здесь и посмотреть
```

Где ставить: в начале обработки формы — `var_dump($_POST)` (дошли ли поля?), после запроса — `var_dump($stmt->fetchAll())` (что вернула база?). Тег `<pre>` сохраняет переносы — читать легче.

Удобный помощник в `config.php` (только для разработки):

```php
<?php
// dd = dump and die: показать и остановиться
function dd(mixed ...$vars): never
{
    echo '<pre style="background:#222;color:#0f0;padding:10px">';
    foreach ($vars as $v) {
        var_dump($v);
    }
    echo '</pre>';
    exit;
}
```

**Отладка SQL.** Если запрос ведёт себя странно — скопируйте его во вкладку SQL phpMyAdmin, подставьте значения руками и выполните. Если там работает, а в PHP нет — проблема в передаваемых значениях (`var_dump` массива для `execute`).

**DevTools → Network.** Покажет, какой запрос ушёл (метод, поля формы во вкладке Payload), какой ответ пришёл (код 200/302/400/403/500) и куда был редирект.

**Логи.** На рабочем сервере ошибки **нельзя** показывать пользователю (в них пути и имена таблиц — подсказка взломщику), но их надо где-то видеть. Для этого — журнал. Обновим начало `config.php`:

```php
<?php
const DEBUG = true;   // при публикации (модуль 7) поставить false

error_reporting(E_ALL);
ini_set('display_errors', DEBUG ? '1' : '0');
ini_set('log_errors', '1');
ini_set('error_log', __DIR__ . '/logs/php-errors.log');
```

Создайте папку `logs/` (она уже в `.gitignore`). Теперь все ошибки дублируются в файл, а свои сообщения можно писать так: `error_log('Смена статуса заявки ' . $id);`. В XAMPP общий журнал Apache — `C:\xampp\apache\logs\error.log`.

## Часть 3. Рефакторинг и DRY

**Рефакторинг** — улучшение кода без изменения поведения. **DRY** («не повторяйся») — одна и та же логика должна жить в одном месте. Посмотрим на наш портал: регулярка телефона написана в `register.php` и `request_new.php`; сообщения об успехе передаются через `?created=1`, `?registered=1`, `?updated=5` — для каждого свой `if` на странице.

**Шаг 1. Общие проверки — в функции** (`config.php`):

```php
<?php
function valid_phone(string $phone): bool
{
    return (bool)preg_match('/^\+7\(\d{3}\)-\d{3}-\d{2}-\d{2}$/', $phone);
}

function valid_fio(string $fio): bool
{
    return (bool)preg_match('/^[А-ЯЁа-яё\s-]+$/u', $fio);
}
```

Теперь, если ТЗ поменяет формат телефона, правим одну строку.

**Шаг 2. Флеш-сообщения.** «Флеш» — сообщение, которое кладут в сессию перед редиректом и показывают **один раз** на следующей странице. Добавляем в `config.php`:

```php
<?php
function set_flash(string $type, string $text): void
{
    $_SESSION['flash'] = ['type' => $type, 'text' => $text];
}

function get_flash(): ?array
{
    $flash = $_SESSION['flash'] ?? null;
    unset($_SESSION['flash']);          // показали — и забыли
    return $flash;
}
```

В `includes/header.php` сразу после `<main class="container pb-5">`:

```php
<?php if ($flash = get_flash()): ?>
    <div class="alert alert-<?= e($flash['type']) ?>"><?= e($flash['text']) ?></div>
<?php endif; ?>
```

И заменяем по всему проекту:

```php
<?php
// было: redirect('requests.php?created=1');
set_flash('success', 'Заявка создана и отправлена администратору.');
redirect('requests.php');

// было: redirect('login.php?registered=1');
set_flash('success', 'Регистрация прошла успешно. Войдите в систему.');
redirect('login.php');

// было: redirect('admin.php?updated=' . $id);
set_flash('success', "Статус заявки №$id сохранён.");
redirect('admin.php');
```

Блоки `if (isset($_GET['created']))` и подобные со страниц удаляем — их работу делает шапка. Адреса стали чище, а F5 больше не показывает сообщение повторно.

**Шаг 3. Проверка после рефакторинга.** Рефакторинг без проверки — это просто «поломка». После каждого шага пройдите основной сценарий: регистрация → вход → заявка → админ меняет статус → пользователь видит статус. Коммит после каждого удачного шага — если что-то сломается, `git diff` покажет, что именно вы поменяли.

**Связь с экзаменом.** На экзамене ошибки будут у всех; выигрывает тот, кто их быстро читает. Включённые ошибки во время разработки, `var_dump` в нужном месте и проверка запроса в phpMyAdmin экономят десятки минут. Чистый код без копипасты упрощает и проверку экспертом.

## Если не успел / для сильных

**Минимум для зачёта:** найдены 5 ошибок в `broken.php` и включено логирование.
**Для сильных:** вынесите вывод поля формы с ошибкой (`field()` из ЛР24 и `invalid()/error_text()` из ЛР27) в один общий файл `includes/form.php` и используйте его на всех формах.

> **Для преподавателя — ошибки в `broken.php`:** 1) нет `;` после `current_user()` (Parse error); 2) столбец `r.created` вместо `r.created_at` (SQLSTATE 42S22); 3) `execute($user['id'])` без массива (TypeError); 4) `fetch()` вместо `fetchAll()` — перебирается одна строка по полям; 5) `count($request)` — опечатка в имени переменной; 6) `$r['service']` вместо `$r['service_name']`; 7) адрес выводится без `e()` (XSS); 8) `=` вместо `===` в условии — все заявки показываются отменёнными.
