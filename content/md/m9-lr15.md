## Лекция

**Анимация — это не украшение, а подсказка.** В образце экзамена анимация прямо входит в задание модуля «Проектирование, разработка и оптимизация». Но эксперт ждёт не салюта на весь экран, а уместного движения, которое помогает пользователю: кнопка откликнулась на нажатие, новая заявка плавно появилась в списке, поле с ошибкой «качнулось», сообщение об успехе мягко выехало сверху. Вспомните любимые приложения — доставку еды, банк: там почти всё движется, но вы этого не замечаете, потому что движения короткие и понятные. К этому и стремимся.

В CSS два инструмента: **transition** — плавный переход между двумя состояниями (было → стало), и **animation с @keyframes** — сценарий из нескольких кадров, который может запуститься сам.

**Transition: плавная смена состояния.** Без transition кнопка при наведении меняет цвет мгновенно, «щёлкает». С ним — плавно:

```css
.btn {
  background: var(--color-primary);
  transition: background-color 0.2s ease, transform 0.15s ease;
}

.btn:hover {
  background: var(--color-primary-dark);
}

.btn:active {
  transform: scale(0.97);     /* кнопка «вжимается» при нажатии */
}
```

Запись `transition: свойство длительность функция задержка`. Через запятую можно перечислить несколько свойств. Важно: transition пишется у **исходного** состояния (`.btn`), а не у `:hover` — тогда анимация работает в обе стороны, и при наведении, и при уходе мыши.

Функция плавности (timing function) задаёт характер движения:

- `ease` — по умолчанию, мягкий старт и финиш;
- `ease-out` — быстро начинается, плавно тормозит; лучший выбор для появления элементов;
- `ease-in` — медленно начинается; подходит для исчезновения;
- `linear` — равномерно; для вращения спиннера;
- `cubic-bezier(...)` — своя кривая.

**Какие свойства анимировать.** Браузер рисует страницу в несколько этапов: расчёт раскладки (layout), отрисовка (paint), склейка слоёв (composite). Если анимировать `width`, `height`, `top`, `margin`, браузер на каждом кадре пересчитывает раскладку всей страницы — на слабом телефоне анимация дёргается. А `transform` (сдвиг, масштаб, поворот) и `opacity` (прозрачность) обрабатываются на этапе склейки и обычно идут плавно. Правило: **двигаем через `transform`, проявляем через `opacity`**.

```css
/* Плохо: двигаем через top */
.card:hover { top: -4px; }

/* Хорошо: двигаем через transform */
.request-card {
  transition: transform 0.2s ease-out, box-shadow 0.2s ease-out;
}
.request-card:hover {
  transform: translateY(-4px);
  box-shadow: 0 8px 20px rgb(15 23 42 / 0.12);
}
```

`box-shadow` анимировать дороже, но на нескольких карточках это допустимо.

**Длительность.** Для интерфейса ориентируйтесь на 150–300 мс: наведение и нажатие — 100–200 мс, появление блока — 200–400 мс. Анимация дольше полсекунды на каждой кнопке раздражает: пользователь ждёт, пока интерфейс «додвигается».

**@keyframes: анимация по сценарию.** Ключевые кадры описывают, как элемент выглядит в разные моменты. Пример — плавное появление карточек при загрузке страницы:

```css
@keyframes fade-up {
  from {
    opacity: 0;
    transform: translateY(16px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

.request-card {
  animation: fade-up 0.4s ease-out both;
}
```

Запись `animation: имя длительность функция заполнение`. Значение `both` (свойство `animation-fill-mode`) означает: до старта элемент уже выглядит как первый кадр (невидим), а после окончания остаётся в последнем кадре. Без него карточка мелькнёт на долю секунды до начала анимации.

**Лесенка (stagger).** Если все карточки появляются одновременно, это выглядит как один большой блок. Красивее, когда они выезжают по очереди с небольшой задержкой. Задержку можно задать через `nth-child` или через CSS-переменную прямо в разметке:

```html
<article class="request-card" style="--i: 0">...</article>
<article class="request-card" style="--i: 1">...</article>
<article class="request-card" style="--i: 2">...</article>
```

```css
.request-card {
  animation: fade-up 0.4s ease-out both;
  animation-delay: calc(var(--i, 0) * 80ms);
}
```

Это исключение из правила «не писать style в HTML»: тут в атрибуте не оформление, а номер элемента, и в модуле 5 PHP подставит его в цикле.

**Анимация ошибки — «встряхивание».** Когда форма не прошла проверку, поле с ошибкой можно слегка качнуть — это привлекает взгляд к проблеме:

```css
@keyframes shake {
  0%, 100% { transform: translateX(0); }
  20%, 60% { transform: translateX(-6px); }
  40%, 80% { transform: translateX(6px); }
}

.field--error .field__input {
  animation: shake 0.35s ease-in-out;
}
```

Анимация проиграется один раз — когда элемент получил класс `field--error` (например, после ответа сервера). Чтобы повторить её без перезагрузки, нужен JS — это тема ЛР35.

**Появление сообщения:**

```css
@keyframes slide-down {
  from { opacity: 0; transform: translateY(-12px); }
  to   { opacity: 1; transform: translateY(0); }
}
.alert { animation: slide-down 0.3s ease-out both; }
```

**Спиннер загрузки** (пригодится, когда в модуле 6 форма будет отправляться через fetch):

```css
@keyframes spin { to { transform: rotate(360deg); } }

.spinner {
  width: 20px;
  height: 20px;
  border: 3px solid rgb(255 255 255 / 0.4);
  border-top-color: #fff;
  border-radius: 50%;
  animation: spin 0.8s linear infinite;
}
```

**prefers-reduced-motion: уважаем тех, кому движение мешает.** У некоторых людей (например, с вестибулярными нарушениями) анимация вызывает головокружение и тошноту. В настройках телефона и компьютера есть опция «Уменьшить движение», и браузер сообщает о ней сайту. Наша задача — в этом режиме убрать движение или сделать его минимальным:

```css
@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
    scroll-behavior: auto !important;
  }
}
```

Мы ставим почти нулевую длительность, а не `animation: none`, чтобы элементы всё равно оказались в конечном состоянии (видимыми) — иначе карточка с `opacity: 0` в первом кадре могла бы остаться невидимой. Спиннер в этом режиме можно заменить статичным текстом «Загрузка…». Проверить режим можно без смены настроек ОС: DevTools → три точки → More tools → Rendering → «Emulate CSS media feature prefers-reduced-motion».

Обычно анимации выносят в отдельный файл `css/animations.css` и подключают последним — так их легко найти, показать эксперту и при необходимости отключить.

**Типичные ошибки:**

1. Анимируют `width`, `top`, `margin` — дёрганье на телефоне.
2. `transition` написан внутри `:hover` — обратный переход мгновенный.
3. Длительности по 1–2 секунды, всё «плывёт».
4. Бесконечные мигания и пульсации без смысла — отвлекают от формы.
5. `transition: all` — анимируется всё подряд, в том числе то, что не должно.
6. Нет `prefers-reduced-motion`.
7. Карточки с `opacity: 0` без `both` — мелькают до начала анимации.

**Связь с экзаменом.** Анимация оценивается как часть интерфейса и «дизайна с учётом трендов». Две-три уместные анимации (отклик кнопки, появление карточек, встряхивание ошибки, всплывающее сообщение), сделанные аккуратно и с `prefers-reduced-motion`, — это то, что эксперт сможет увидеть и засчитать. Кроме того, в ЛР35 и ЛР36 вы будете запускать эти же `@keyframes` из JavaScript.
