## Коротко о теории

**Интерактивный прототип** — это макет, по которому можно «походить»: нажать кнопку и попасть на следующий экран, навести на карточку и увидеть подсветку. Программирования в нём нет, но для человека он выглядит почти как готовое приложение. Прототип нужен, чтобы **проверить сценарий до вёрстки**: заказчик и тестировщики видят, понятен ли путь, а исправить стрелку в Figma в сто раз дешевле, чем переписать код.

Вспомним, из чего состоит интерактивность:

| Понятие | Что это | Пример |
|---|---|---|
| **Экран** (фрейм) | Одно состояние приложения целиком | «Каталог», «Карточка книги» |
| **Переход** | Связь: с какого элемента на какой экран | «Подробнее» → «Карточка книги» |
| **Триггер** | Что делает пользователь | нажатие, наведение, ввод |
| **Действие** | Что происходит в ответ | открыть экран, показать окно, вернуться назад |
| **Состояние элемента** | Как выглядит элемент сейчас | обычная, наведение, нажата, фокус, выключена |

Состояния кнопки, которые должны быть в любом прототипе и на экзамене:

- **Default** (обычное) — как кнопка выглядит, пока её не трогают.
- **Hover** (наведение) — курсор над кнопкой: фон чуть темнее. Подсказывает «на меня можно нажать».
- **Active / Pressed** (нажатие) — момент нажатия: ещё темнее или кнопка «вдавливается».
- **Focus** (фокус) — кнопку выбрали клавишей Tab: вокруг заметная рамка. Без неё человек с клавиатурой не знает, где он.
- **Disabled** (выключена) — нажать нельзя: серый цвет, курсор «запрещено».

У поля ввода свои состояния: обычное, фокус (рамка), заполнено, ошибка (красная рамка и текст под полем), выключено.

> Частая ошибка: рисовать только «красивое» обычное состояние. Тогда на вёрстке программист сам придумает наведение и фокус — и стиль сайта развалится. На демоэкзамене состояния кнопок и полей — отдельный пункт критериев стайлгайда.

## Ход работы

### Шаг 1. Варианты кнопки в Figma

1. Откройте компонент кнопки из стайлгайда. Выделите его и на правой панели нажмите **Add variant** (значок «+» в рамке компонента). Появится набор вариантов — **Component set**, обведённый фиолетовым пунктиром.
2. Создайте пять вариантов. В свойстве варианта (по умолчанию `Property 1`) переименуйте его в `State` и задайте значения: `Default`, `Hover`, `Pressed`, `Focus`, `Disabled`.
3. Оформите каждый:
   - Hover — фон на 10–15% темнее основного;
   - Pressed — ещё темнее;
   - Focus — обводка 3px контрастного цвета (Stroke, Outside) с отступом;
   - Disabled — серый фон `#C9C9C9`, тёмно-серый текст `#4A4A4A`.
4. Так же сделайте варианты поля ввода: `Default`, `Focus`, `Filled`, `Error`, `Disabled`. В варианте Error добавьте под полем красный текст ошибки.

### Шаг 2. Интерактивный компонент

1. Перейдите на вкладку **Prototype** (справа вверху, рядом с Design).
2. Выделите вариант `Default`, потяните за синий кружок справа и бросьте стрелку на вариант `Hover`.
3. В появившемся окне выберите триггер **While hovering** (пока курсор над элементом), действие **Change to** (сменить вариант) → `Hover`, анимацию **Instant** или **Dissolve** 150 мс.
4. От `Hover` протяните стрелку к `Pressed` с триггером **While pressing**.

Теперь любая копия кнопки на ваших экранах сама реагирует на наведение и нажатие — рисовать это на каждом экране не нужно.

### Шаг 3. Переходы между экранами

1. Расставьте на холсте экраны сценария: «Главная» → «Каталог» → «Карточка книги» → «Книга забронирована».
2. На вкладке Prototype выделите кнопку «Каталог» на главной и протяните стрелку на фрейм «Каталог». Настройки: **On click** → **Navigate to** → «Каталог», анимация **Smart animate** или **Move in** 300 мс.
3. Повторите для всех кнопок сценария. Для «Назад» используйте действие **Back** — оно вернёт на предыдущий экран, откуда бы человек ни пришёл.
4. Для окна подтверждения используйте **Open overlay**: экран не сменится, а поверх появится окно.
5. Выделите первый фрейм и на правой панели в разделе **Flow starting point** нажмите «+». Назовите поток, например «Бронь книги».

> Частая ошибка: тупиковые экраны. Проверьте, что с каждого экрана можно уйти — хотя бы кнопкой «Назад» или «На главную».

### Шаг 4. Просмотр и ссылка

1. Нажмите треугольник **Present** (Play) справа вверху. Откроется прототип в отдельной вкладке.
2. Пройдите весь сценарий, как будто вы читатель библиотеки. Записывайте всё, что мешает: «не понял, куда нажать», «нет пути назад».
3. Кнопка **Share prototype** даёт ссылку. Сохраните её — её вы показываете преподавателю в конце занятия.

### Шаг 5. Состояния в CSS — задание 1 на сайте

Всё, что вы нарисовали в вариантах, в CSS описывается **псевдоклассами**:

```css
.btn { background-color: #1f5f8b; color: #ffffff; cursor: pointer; }
.btn:hover { background-color: #174a6c; }          /* Hover */
.btn:active { background-color: #10354e; }         /* Pressed */
.btn:focus-visible { outline: 3px solid #f2a900; } /* Focus */
.btn:disabled { background-color: #c9c9c9; color: #4a4a4a; cursor: not-allowed; }
```

Порядок важен: `:disabled` пишите **после** `:hover`. У них одинаковая специфичность, побеждает последнее правило, и тогда выключенная кнопка не будет темнеть при наведении. Выключают кнопку атрибутом `disabled` в HTML:

```html
<style>
  .btn { padding: 10px 18px; font-size: 16px; border: none; border-radius: 8px; background-color: #1f5f8b; color: #ffffff; cursor: pointer; }
  .btn:hover { background-color: #174a6c; }
  .btn:focus-visible { outline: 3px solid #f2a900; outline-offset: 2px; }
  .btn:disabled { background-color: #c9c9c9; color: #4a4a4a; cursor: not-allowed; }
</style>
<button class="btn" type="button">Забронировать</button>
<button class="btn" type="button" disabled>Нет в наличии</button>
```

Наведите курсор на обе кнопки и нажмите Tab: первая темнеет и получает жёлтую рамку, вторая не реагирует.

> **Попробуйте сами.** В примере выше поменяйте местами правила `.btn:hover` и `.btn:disabled`. Наведите курсор на выключенную кнопку: она стала синей, хотя нажать её нельзя. Верните порядок.

Частая ошибка: `outline: none` «чтобы убрать некрасивую рамку». Так фокус пропадает совсем, и с клавиатуры сайтом пользоваться невозможно. Рамку не убирают, а **оформляют** через `:focus-visible` — она появляется при работе с клавиатуры и не мешает при нажатии мышью.

### Шаг 6. Переходы на JavaScript — задание 2 на сайте

В браузере стрелок Figma нет. Переход между экранами в одностраничном прототипе — это «спрятать все экраны, показать нужный». Экраны — разделы `section` с id, кнопки хранят, куда вести, в **data-атрибуте** `data-go` (data-атрибуты были на занятии 18):

```html
<style>
  .screen { padding: 16px; border: 1px solid #d0d7de; border-radius: 12px; }
</style>
<section class="screen" id="screen-a">
  <h2>Экран А</h2>
  <button type="button" data-go="screen-b">Дальше</button>
</section>
<section class="screen" id="screen-b" hidden>
  <h2>Экран Б</h2>
  <button type="button" data-go="screen-a">Назад</button>
</section>
<script>
  const screens = document.querySelectorAll('.screen');
  function showScreen(id) {
    for (const screen of screens) {
      screen.hidden = screen.id !== id;
    }
  }
  for (const button of document.querySelectorAll('[data-go]')) {
    button.addEventListener('click', () => showScreen(button.dataset.go));
  }
</script>
```

Разберём:

- `showScreen(id)` проходит по всем экранам. Выражение `screen.id !== id` даёт `true` для «чужого» экрана (его прячем) и `false` для нужного (его показываем).
- `button.dataset.go` — значение атрибута `data-go`. Так JavaScript читает любые data-атрибуты: `data-go` → `dataset.go`. То же самое делает `button.getAttribute('data-go')`.
- Атрибут `hidden` прячет элемент — но только пока CSS не задал ему свой `display`.

> **Попробуйте сами.** Добавьте в `<style>` примера строку `.screen { display: flex; flex-direction: column; }` и нажмите «Дальше». Оба экрана видны одновременно! `display: flex` перебил `hidden`. Добавьте правило `.screen[hidden] { display: none; }` — всё снова работает.

Это ловушка из задания 2: в его CSS у экранов `display: flex`, поэтому правило `.screen[hidden] { display: none; }` обязательно.

### Шаг 7. Состояния, которые меняет JavaScript — задание 3 на сайте

Некоторые состояния зависят от действий человека: кнопка «Подтвердить» выключена, пока не стоит галочка согласия. Это делает одна строка:

```js
agree.addEventListener('change', () => {
  send.disabled = !agree.checked;
});
```

`agree.checked` — стоит ли галочка (`true` или `false`). Знак `!` переворачивает: галочка стоит → `disabled = false` → кнопка включена. После отправки показываем результат: меняем текст кнопки, выключаем её, пишем сообщение в элемент с `role="status"` — экранный диктор прочитает его вслух.
