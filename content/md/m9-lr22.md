## Лекция

**Это не экзамен, а примерка.** Контрольная проверяет одно: можете ли вы без подсказок перевести вопрос с человеческого языка на SQL. На демоэкзамене никто не скажет «напиши `JOIN`» — там будет «администратор видит все заявки с ФИО клиента». Поэтому сегодня вопросы сформулированы так, как их сформулировал бы заказчик. Перед контрольной — 20 минут повторения: шпаргалка по всему модулю, способ решать любой запрос по шагам и список ловушек.

**Шпаргалка модуля в одном экране.**

```sql
-- Выборка
SELECT столбцы FROM таблица
[JOIN другая ON другая.id = таблица.другая_id]
[WHERE условие]
[GROUP BY поля] [HAVING условие_на_группу]
[ORDER BY поле [DESC]] [LIMIT n [OFFSET m]];

-- Изменение данных
INSERT INTO таблица (поле1, поле2) VALUES (значение1, значение2);
UPDATE таблица SET поле = значение WHERE условие;
DELETE FROM таблица WHERE условие;

-- Структура
CREATE TABLE ... ; ALTER TABLE ... ; CREATE INDEX ... ;
```

| Хочу… | Пишу… |
|---|---|
| только часть строк | `WHERE` |
| по шаблону текста | `LIKE '%…%'` |
| диапазон дат или чисел | `BETWEEN … AND …` |
| отсутствует значение | `IS NULL` |
| текст вместо номера (ФИО, статус) | `JOIN` справочника |
| «у кого нет…», «ни разу не…» | `LEFT JOIN … WHERE правая.id IS NULL` |
| «сколько», «сумма», «среднее» | `COUNT`, `SUM`, `AVG` |
| «для каждого…» | `GROUP BY` |
| «у которых больше N» | `HAVING` |
| «самый», «топ-3» | `ORDER BY … DESC LIMIT …` |

**Как решать любой запрос: 5 вопросов к себе.**

1. **Что вывести?** Выпишите столбцы, которые хочет видеть заказчик. Это будет `SELECT`.
2. **Из каких таблиц эти столбцы?** ФИО — `users`, услуга — `services`, статус — `statuses`. Все таблицы, кроме главной, — это `JOIN`. Главная почти всегда та, где «много» строк, — `requests`.
3. **Какие строки нужны?** Условия → `WHERE`. Если условие по названию («статус Новая», «логин ivanov_a»), а не по номеру — фильтруем по полю справочника: `st.name = 'Новая'`.
4. **Нужен ли итог?** Слова «сколько», «сумма», «для каждого» → агрегат и `GROUP BY`. Условие на результат подсчёта → `HAVING`.
5. **В каком порядке и сколько?** `ORDER BY`, `LIMIT`.

Пример рассуждения. Вопрос: «Покажите для каждого клиента, сколько у него отменённых заявок, только тех, у кого они есть».
1) Вывести: ФИО и число. 2) ФИО — `users`, заявки — `requests`, «отменённые» — `statuses`. 3) Строки: только статус «Отменено». 4) «Для каждого клиента» — `GROUP BY` клиента, «сколько» — `COUNT`. 5) Порядок не задан — отсортируем по ФИО для читаемости.

```sql
SELECT u.full_name, COUNT(*) AS cancelled
FROM requests r
JOIN users u     ON u.id = r.user_id
JOIN statuses st ON st.id = r.status_id
WHERE st.name = 'Отменено'
GROUP BY u.id, u.full_name
ORDER BY u.full_name;
```

Результат на учебной базе: Петрова 1, Сидоров 1, Смирнов 1.

Второй пример — с «отрицанием». Вопрос: «Какие способы оплаты ни разу не выбирали?» 1) Вывести: название способа. 2) Способы — `payment_types`, выборы — `requests`. 3) Нужны способы, для которых **нет** заявок, — это сигнал для `LEFT JOIN` и проверки `IS NULL` на правой таблице. 4) Итог не нужен. 5) Порядок — по названию.

```sql
SELECT p.name
FROM payment_types p
LEFT JOIN requests r ON r.payment_type_id = p.id
WHERE r.id IS NULL
ORDER BY p.name;
```

На учебной базе результат пустой — оба способа оплаты используются. Пустой результат — тоже ответ, если запрос верен; в комментарии так и пишите: «0 строк».

**Читаем ошибки, а не пугаемся.** Сообщение MySQL почти всегда говорит, где искать:

| Ошибка | Что значит | Что проверить |
|---|---|---|
| `#1064 You have an error in your SQL syntax … near '…'` | синтаксис | текст после `near` — ошибка прямо перед ним: запятая, кавычка, порядок частей |
| `#1054 Unknown column '…'` | нет такого столбца | опечатка, псевдоним не той таблицы, кавычки вокруг строки забыли |
| `#1052 Column '…' is ambiguous` | столбец есть в двух таблицах | допишите псевдоним: `s.name` |
| `#1055 … not in GROUP BY` | в `SELECT` поле без агрегата и без `GROUP BY` | добавьте поле в `GROUP BY` |
| `#1452`, `#1451` | нарушение внешнего ключа | существует ли родитель / есть ли дети |
| `#1062 Duplicate entry` | нарушение `UNIQUE`/`PRIMARY KEY` | такое значение уже есть |

**Как проверить себя без преподавателя.**

- **Сверка с «ручным» подсчётом.** Откройте таблицу на вкладке «Обзор» и посчитайте глазами хотя бы для одной строки результата. Если запрос говорит, что у Смирнова 4 заявки, — найдите их.
- **Сумма частей равна целому.** Сумма заявок по всем статусам должна равняться `SELECT COUNT(*) FROM requests` (15). Не равна — где-то потерялись строки (чаще всего из-за `JOIN` вместо `LEFT JOIN`).
- **Подозрительно много строк** — забыли условие `ON`. Подозрительно мало — лишнее условие в `WHERE` или `JOIN` отсёк строки без пары.
- **Перед `UPDATE`/`DELETE` — `SELECT` с тем же `WHERE`.** На контрольной это проверяется отдельно.

**Ловушки, которые встретятся.**

1. `= NULL` вместо `IS NULL`.
2. `COUNT(*)` вместе с `LEFT JOIN` вместо `COUNT(поле_правой_таблицы)`.
3. Неоднозначный столбец: `name` есть в трёх справочниках, `id` — во всех таблицах. Пишите `s.name`, `r.id`.
4. `BETWEEN` для дат включает обе границы — это как раз то, что обычно нужно.
5. Строки и даты в одинарных кавычках, числа — без.
6. Порядок операций в изменениях данных: в `INSERT` не забудьте, что `status_id` и `created_at` заполнятся сами.
