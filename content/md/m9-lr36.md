## Лекция

**Задача.** В ЛР29 ты сделал админ-панель: администратор выбирает статус заявки, нажимает «Сохранить», страница перезагружается. Если выбрана отмена — нужно указать причину (`cancel_reason`). Сейчас сделаем это как в современных системах: администратор выбирает статус в выпадающем списке — и он сразу сохраняется без перезагрузки; если выбрано «Отменена», открывается модальное окно с полем причины. Здесь сходится всё, что было в модуле: DOM и события (ПР21), валидация (ЛР33), fetch и JSON (ПР22), бейджи (ЛР34), `<dialog>` и уведомления (ЛР35).

**Схема обмена.**

```
admin.php (браузер)                         update_status.php (сервер)
  select change ──► статус "cancelled"? ──да──► модалка ──► причина
        │                                                     │
        └──────── fetch POST {id, status, reason} ◄───────────┘
                                │
                                ▼
            проверка сессии и роли → проверка CSRF → проверка данных
                     → UPDATE ... (prepared) → JSON {ok, status}
                                │
  ◄──────────── ответ ──────────┘
  ok: обновить бейдж, toast «Статус изменён»
  ошибка: вернуть старое значение select, toast с ошибкой
```

**Безопасность — главное в этой работе.** Эндпоинт `update_status.php` — это «дверь» в базу данных. Отправить на него запрос может кто угодно: через DevTools, через Postman, через `curl`. То, что кнопка видна только админу, ничего не защищает. Поэтому сервер обязан сам проверить:

1. **Кто стучится** — пользователь вошёл и его роль `admin`. Иначе ответ 403.
2. **Запрос с нашего сайта** — CSRF-токен (ПР19) совпадает с токеном в сессии. Иначе злоумышленник может подсунуть админу страницу, которая отправит запрос от его имени.
3. **Данные корректны** — `id` целое число, статус из белого списка (`new`, `in_work`, `done`, `cancelled`), при отмене причина не пустая.
4. **SQL безопасен** — только prepared statement.

**HTTP-коды ответов.** Хороший API говорит не только текстом, но и кодом: 200 — всё хорошо, 400 — неверные данные, 403 — нет прав, 404 — заявка не найдена, 405 — не тот метод, 500 — ошибка сервера. В PHP: `http_response_code(403);`. В JS — `response.ok` и `response.status`.

**Серверная часть.** Предполагаем, что после входа (ЛР25–26) в сессии лежат `$_SESSION['user_id']` и `$_SESSION['role']`, а CSRF-токен создаётся один раз: `$_SESSION['csrf'] ??= bin2hex(random_bytes(32));`. Подставь свои имена ключей и таблицы.

```php
<?php
// update_status.php — смена статуса заявки (только для администратора), принимает JSON
session_start();
require_once 'db.php';                                   // $pdo из ЛР23
header('Content-Type: application/json; charset=utf-8');

function reply(int $code, array $data): never {
    http_response_code($code);
    echo json_encode($data, JSON_UNESCAPED_UNICODE);
    exit;
}

// 1. Только POST
if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    reply(405, ['ok' => false, 'error' => 'Метод не разрешён']);
}

// 2. Только администратор
if (($_SESSION['role'] ?? '') !== 'admin') {
    reply(403, ['ok' => false, 'error' => 'Недостаточно прав']);
}

// 3. CSRF-токен из заголовка
$token = $_SERVER['HTTP_X_CSRF_TOKEN'] ?? '';
if (!isset($_SESSION['csrf']) || !hash_equals($_SESSION['csrf'], $token)) {
    reply(403, ['ok' => false, 'error' => 'Неверный токен, обновите страницу']);
}

// 4. Читаем JSON-тело (в $_POST его НЕТ)
$data = json_decode(file_get_contents('php://input'), true);
if (!is_array($data)) {
    reply(400, ['ok' => false, 'error' => 'Некорректный JSON']);
}

$id     = filter_var($data['id'] ?? null, FILTER_VALIDATE_INT, ['options' => ['min_range' => 1]]);
$status = $data['status'] ?? '';
$reason = trim((string)($data['reason'] ?? ''));

$allowed = ['new', 'in_work', 'done', 'cancelled'];
if ($id === false || !in_array($status, $allowed, true)) {
    reply(400, ['ok' => false, 'error' => 'Неверная заявка или статус']);
}
if ($status === 'cancelled' && $reason === '') {
    reply(400, ['ok' => false, 'error' => 'Укажите причину отмены']);
}
if (mb_strlen($reason) > 255) {
    reply(400, ['ok' => false, 'error' => 'Причина слишком длинная (до 255 символов)']);
}

// 5. Обновляем — только prepared statement
$stmt = $pdo->prepare('UPDATE requests SET status = ?, cancel_reason = ? WHERE id = ?');
$stmt->execute([$status, $status === 'cancelled' ? $reason : null, $id]);

if ($stmt->rowCount() === 0) {
    // 0 строк: либо заявки нет, либо статус и причина не изменились
    $check = $pdo->prepare('SELECT COUNT(*) FROM requests WHERE id = ?');
    $check->execute([$id]);
    if ((int)$check->fetchColumn() === 0) {
        reply(404, ['ok' => false, 'error' => 'Заявка не найдена']);
    }
}

reply(200, ['ok' => true, 'id' => $id, 'status' => $status]);
```

Разбор неочевидного:
- `never` — тип возврата PHP 8.1+: функция никогда не возвращается (заканчивается `exit`). В XAMPP с PHP 8.2 работает; на старом PHP напиши `: void`.
- `hash_equals` сравнивает строки за одинаковое время — так токен нельзя подобрать по времени ответа.
- Заголовок `X-CSRF-Token` в PHP превращается в `$_SERVER['HTTP_X_CSRF_TOKEN']` (верхний регистр, дефисы → подчёркивания, приставка `HTTP_`).
- `in_array(..., true)` — строгое сравнение, чтобы `0` или `true` не «совпали» со строкой.
- При смене на любой статус, кроме отмены, причина очищается (`null`). Если у тебя поле `cancel_reason` объявлено `NOT NULL`, пиши пустую строку `''`.
- `rowCount()` в MySQL возвращает число *изменённых* строк: если админ выбрал тот же статус, будет 0, поэтому дополнительно проверяем, существует ли заявка.

**Клиентская часть.** Используем `closeModal` (ЛР35), `renderBadge` (ЛР34), `showToast` (ЛР35) — подключи их файлы раньше этого.

```js
// js/admin-status.js
const csrf = document.querySelector('meta[name="csrf-token"]').content;
const dialog = document.getElementById('cancel-dialog');
const cancelForm = document.getElementById('cancel-form');
const reasonInput = document.getElementById('cancel-reason');
const reasonError = document.getElementById('reason-error');
let pendingSelect = null;                       // какой select ждёт причину

async function saveStatus(select, status, reason = '') {
  const row = select.closest('tr');
  select.disabled = true;                       // защита от двойного клика
  try {
    const response = await fetch('update_status.php', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json', 'X-CSRF-Token': csrf },
      body: JSON.stringify({ id: Number(row.dataset.id), status, reason }),
    });
    const data = await response.json().catch(() => ({}));
    if (!response.ok || !data.ok) throw new Error(data.error || `Ошибка ${response.status}`);

    select.dataset.current = status;            // запоминаем новое значение
    renderBadge(row.querySelector('[data-badge]'), status);
    showToast('Статус изменён');
  } catch (err) {
    select.value = select.dataset.current;      // откат к старому значению
    showToast(err.message, 'error');
  } finally {
    select.disabled = false;
  }
}

document.querySelector('table')?.addEventListener('change', (e) => {
  const select = e.target.closest('.status-select');
  if (!select) return;
  if (select.value === 'cancelled') {
    pendingSelect = select;
    reasonInput.value = '';
    reasonError.textContent = '';
    reasonInput.classList.remove('is-invalid');
    dialog.showModal();
    reasonInput.focus();
  } else {
    saveStatus(select, select.value);
  }
});

cancelForm.addEventListener('submit', async (e) => {
  e.preventDefault();
  const reason = reasonInput.value.trim();
  if (reason === '') {
    reasonInput.classList.add('is-invalid');
    reasonError.textContent = 'Укажите причину отмены';
    reasonInput.focus();
    return;
  }
  const select = pendingSelect;
  pendingSelect = null;
  closeModal(dialog, 'ok');
  await saveStatus(select, 'cancelled', reason);
});

// закрыли окно без подтверждения (кнопка, Esc, фон) — вернуть select назад
dialog.addEventListener('close', () => {
  if (pendingSelect) {
    pendingSelect.value = pendingSelect.dataset.current;
    pendingSelect = null;
  }
});
document.querySelector('[data-cancel-close]').addEventListener('click', () => closeModal(dialog, 'cancel'));

// при загрузке превратить коды статусов в русские бейджи
document.querySelectorAll('[data-badge]').forEach((b) => renderBadge(b, b.textContent.trim()));
```

Ключевые идеи:
- **Один обработчик на таблицу** (делегирование, ПР21) — работает для любого числа строк.
- **`data-current`** хранит последнее *сохранённое* значение. Если сервер отказал или админ закрыл окно — откатываем select. Без этого интерфейс показывал бы статус, которого нет в базе, — худшая ошибка: пользователь видит одно, а в БД другое.
- **`disabled` на время запроса** — нельзя отправить два запроса подряд.
- `response.json().catch(() => ({}))` — если сервер вернул не JSON (PHP-ошибка), не падаем, а показываем код ответа.
- `finally` выполняется и при успехе, и при ошибке — разблокируем select в любом случае.

**Проверяем безопасность руками.** Это обязательная часть работы. Выйди из аккаунта админа, войди обычным пользователем, открой консоль и выполни:

```js
fetch('update_status.php', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ id: 1, status: 'done' }),
}).then((r) => r.json()).then(console.log);
// ожидаем: {ok: false, error: "Недостаточно прав"} и статус 403
```

**Типичные ошибки.**
- Проверка роли только в `admin.php`, а `update_status.php` открыт всем.
- Читают `$_POST['status']` — там пусто, потому что пришёл JSON.
- Статус вставляется в SQL без белого списка — можно записать любую строку.
- После ошибки select показывает новый статус, а в базе старый.
- `cancel_reason` не очищается при возврате заявки в работу.
- Причина выводится в таблицу без `htmlspecialchars` — XSS в админке.

**Связь с экзаменом.** Отмена заявки с обязательной причиной — часть функциональности портала по образцу 2025 года (задание 1), а удобная модалка, анимация и валидация — это интерфейс и анимация из задания 3. Проверки роли, CSRF и prepared statement закрывают критерий «безопасность ИС».
