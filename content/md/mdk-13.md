## Каскад: когда правила спорят

На прошлом занятии каждое правило выбирало свои элементы. Но на настоящем сайте сотни правил, и часто несколько из них задают **одно и то же свойство одному и тому же элементу**. Например:

```html
<style>
  p { color: #1f4e79; }
  p { color: #8e1f14; }
</style>
<p>Какого я цвета?</p>
```

Что вы увидите: абзац тёмно-красный. Оба правила говорят про цвет абзацев, и победило **последнее**.

Способ, которым браузер решает такие споры, и называется **каскадом** — отсюда «каскадные» в названии CSS. Браузер по очереди задаёт три вопроса:

1. **Насколько точный селектор?** Более точный побеждает (это специфичность, о ней ниже).
2. **Если точность одинаковая — какое правило ниже?** Побеждает то, что написано позже.
3. **Задано ли свойство вообще?** Если ни одно правило его не задало, значение берётся по наследству от родителя или по умолчанию.

Важно: спорят **отдельные свойства**, а не правила целиком. Если одно правило задаёт абзацу цвет и размер, а другое — только цвет, то цвет возьмётся из победителя, а размер останется из первого правила.

```html
<style>
  p { color: #1f4e79; font-size: 20px; }
  p { color: #8e1f14; }
</style>
<p>Цвет из второго правила, размер — из первого.</p>
```

Что вы увидите: тёмно-красный крупный текст 20px.

Правило «последнее побеждает» работает и для файлов. Если подключить два файла стилей, правила из второго перебьют такие же правила из первого. Поэтому свой `style.css` всегда подключают **после** чужих (например, после стилей фреймворка).

## Специфичность: у кого селектор точнее

Теперь интереснее:

```html
<style>
  .warning { color: #8e1f14; }
  p { color: #1f4e79; }
</style>
<p class="warning">Пары сокращены до 60 минут.</p>
```

Что вы увидите: текст тёмно-красный, хотя правило для `p` стоит ниже. Почему? Потому что класс — **более точный** (специфичный) селектор, чем тег. «Все абзацы» — это много элементов, «элементы с классом warning» — меньше. Точный выигрывает до того, как браузер посмотрит на порядок.

**Специфичность** считают как три числа: (id, классы, теги). Сравнивают слева направо, как номера версий:

| Селектор | id | классы | теги | Итог |
|---|---|---|---|---|
| `p` | 0 | 0 | 1 | 0-0-1 |
| `ul li` | 0 | 0 | 2 | 0-0-2 |
| `.warning` | 0 | 1 | 0 | 0-1-0 |
| `p.warning` | 0 | 1 | 1 | 0-1-1 |
| `.menu .link` | 0 | 2 | 0 | 0-2-0 |
| `#news` | 1 | 0 | 0 | 1-0-0 |
| `#news p` | 1 | 0 | 1 | 1-0-1 |

Сравниваем: `#news p` (1-0-1) сильнее `.menu .link` (0-2-0), потому что в первом столбце 1 больше 0. Дальше даже смотреть не нужно. Один id перевешивает хоть десять классов.

А атрибут `style` сильнее любого селектора из файла. Это ещё одна причина его не использовать: потом его не перебить обычными правилами.

> **Попробуйте сами.** Нажмите «Попробовать» под примером с `.warning`. Поменяйте правило `p` на `p.warning` — какой цвет теперь? Почему? Посчитайте специфичность обоих селекторов.

### Частая ошибка: война специфичности

Новичок пишет `#news p { color: #555555; }`, а потом удивляется, что `.lead { color: #1d5c3a; }` для одного из абзацев не работает. Начинает добавлять: `#news .lead`, потом `#news p.lead`… Через месяц в стилях невозможно разобраться.

Самое плохое «лекарство» — `!important`. Если дописать его после значения (`color: red !important;`), объявление побеждает почти всё. Кажется удобным, но следующий `!important` придётся перебивать ещё одним, и стили превращаются в гонку вооружений. На курсе автопроверка считает `!important` ошибкой.

Правильный путь — **держать специфичность низкой и ровной**:

- стилизуйте через классы, а не через id;
- не вкладывайте селекторы глубоко: `.menu a` лучше, чем `body div.header ul li a`;
- если правило не применяется — сначала посчитайте специфичность, а потом уже правьте.

Посмотреть, какое правило победило, можно в браузере: правая кнопка мыши по элементу → «Просмотреть код» (Ctrl+Shift+I). Во вкладке «Стили» (Styles) проигравшие объявления **зачёркнуты**. Это главный инструмент верстальщика: учитесь пользоваться им с первого дня.

## Наследование

Некоторые свойства элемент получает **по наследству от родителя** — элемента, внутри которого он лежит.

```html
<style>
  .card { color: #1f4e79; font-family: Georgia, serif; border: 2px solid #1f4e79; }
</style>
<div class="card">
  <h2>Курс веб-дизайна</h2>
  <p>Занятия по вторникам и четвергам.</p>
</div>
```

Что вы увидите: заголовок и абзац тёмно-синие и со шрифтом Georgia, хотя для `h2` и `p` правил нет. А рамка — только одна, вокруг всего блока: у заголовка и абзаца своих рамок нет.

Почему так? Цвет и шрифт **наследуются**, а рамка — **нет**. Разработчики CSS решили по здравому смыслу: если вы сделали блок синим, вы хотите, чтобы весь текст в нём был синим. А рамку у каждого абзаца вы точно не имели в виду.

| Наследуются (в основном про текст) | Не наследуются (про коробку) |
|---|---|
| `color` | `border` |
| `font-family`, `font-size`, `font-weight` | `padding`, `margin` |
| `line-height` | `width`, `height` |
| `text-align` | `background-color` |

Подсказка для запоминания: **наследуется то, что касается текста; не наследуется то, что касается коробки**.

Вы уже пользовались наследованием, сами того не зная: в заданиях курса правило `body { font-family: Arial, sans-serif; color: #222222; }` задаёт шрифт и цвет всей странице. Поэтому шрифт пишут один раз — у `body` или у общего блока, а не у каждого `p`, `li` и `h2`.

Наследование — самый слабый источник значения. Любое правило, которое прямо выбрало элемент, даже самое простое `p { … }`, сильнее наследства от родителя, каким бы точным ни был селектор родителя.

```html
<style>
  #news { color: #1f4e79; }
  p { color: #222222; }
</style>
<div id="news">
  <h2>Новости</h2>
  <p>Этот абзац тёмно-серый: правило p сильнее наследства от #news.</p>
</div>
```

Что вы увидите: заголовок синий (унаследовал от `#news`), абзац тёмно-серый.

Если нужно, чтобы свойство всё-таки взялось у родителя, есть значение `inherit`: `a { color: inherit; }` — ссылки того же цвета, что и окружающий текст.

## Блочные и строчные элементы

Все элементы страницы — прямоугольные **коробки**. Но ведут себя коробки по-разному. Это поведение задаёт свойство `display`.

**Блочные** элементы (`display: block`) — `h1`–`h6`, `p`, `ul`, `li`, `div`, `form`, `table`:

- начинаются с новой строки;
- занимают **всю доступную ширину**, даже если текста мало;
- слушаются `width`, `height`, `margin` и `padding` со всех сторон.

**Строчные** элементы (`display: inline`) — `a`, `strong`, `em`, `span`, `label`:

- стоят в строке текста, как слова;
- ширина — по содержимому;
- **не слушаются** `width` и `height`, а вертикальные `margin` у них не отодвигают соседей.

```html
<style>
  p, span { background-color: #fff3c4; }
</style>
<p>Абзац — блочный, фон на всю ширину.</p>
<p>Внутри абзаца <span>строчный span</span> — фон только под словами.</p>
```

Что вы увидите: жёлтые полосы на всю ширину под абзацами и короткий жёлтый кусочек под словами «строчный span».

Тег `div` — универсальный блочный контейнер без смысла, «просто коробка», чтобы сгруппировать элементы для оформления. `span` — то же самое, но строчный. Когда они уместны, а когда нужен смысловой тег, подробно обсудим на занятии 18.

Поведение можно поменять. Самые нужные значения `display`:

| Значение | Как ведёт себя | Типичный пример |
|---|---|---|
| `block` | С новой строки, на всю ширину | Подписи формы на отдельных строках (как на практике 3) |
| `inline` | В строке, размеры не слушает | Обычное поведение ссылки |
| `inline-block` | В строке, но слушает `width`, `height`, `margin`, `padding` | Ссылка-кнопка, метки-теги |
| `none` | Элемент полностью убран со страницы | Скрытое меню на телефоне |

Частая ошибка: сделать из ссылки кнопку, дать ей `padding` и `margin-top`, и удивляться, что отступ сверху не работает, а фон кнопки залезает на строку выше. Ссылка строчная. Дайте ей `display: inline-block` — и она поведёт себя как настоящая кнопка.

## Блочная модель: из чего состоит коробка

Каждая коробка состоит из четырёх слоёв, от центра наружу:

1. **content** — содержимое: текст, картинка. Его размер задают `width` и `height`.
2. **padding** — внутренний отступ: от содержимого до рамки. Фон коробки закрашивает и его.
3. **border** — рамка.
4. **margin** — внешний отступ: от рамки до соседей. Он всегда прозрачный.

![Схема блочной модели: содержимое в центре, вокруг padding, рамка border и внешний отступ margin](img/course/k13-box.svg)

Представьте картину в раме на стене. Картина — content. Белое паспарту вокруг неё — padding. Деревянная рама — border. Расстояние до соседней картины — margin.

```html
<style>
  .box {
    width: 200px;
    padding: 20px;
    border: 4px solid #1f4e79;
    margin: 30px;
    background-color: #e3edf7;
  }
</style>
<div class="box">Коробка с отступами и рамкой</div>
<div class="box">Вторая коробка</div>
```

Что вы увидите: две голубые коробки с синей рамкой. Голубой фон занимает и текст, и поля вокруг него (padding), а между коробками — пустое место (margin).

> **Попробуйте сами.** Откройте пример, нажмите правой кнопкой по коробке → «Просмотреть код». Внизу вкладки «Стили» (Styles) нарисована схема блочной модели с цифрами каждого слоя. Поменяйте `padding` на `5px`, а потом `margin` на `0`, и следите, что меняется.

### Как писать padding и margin

Отступы задают со всех четырёх сторон. Можно по одной:

```css
.box {
  padding-top: 10px;
  padding-right: 20px;
  padding-bottom: 10px;
  padding-left: 20px;
}
```

А можно короче — одним свойством. Порядок — **по часовой стрелке, начиная сверху**: верх, право, низ, лево.

| Запись | Что значит |
|---|---|
| `padding: 16px;` | Со всех сторон 16px |
| `padding: 10px 20px;` | Сверху и снизу 10px, справа и слева 20px |
| `padding: 10px 20px 30px;` | Сверху 10, по бокам 20, снизу 30 |
| `padding: 10px 20px 30px 40px;` | Верх, право, низ, лево |

Для `margin` всё точно так же. А `border` пишут тремя частями: толщина, стиль линии (`solid` — сплошная, `dashed` — штрихи, `dotted` — точки) и цвет: `border: 2px solid #1f4e79;`. Скругляют углы свойством `border-radius: 8px;`.

### Сколько места занимает коробка

Вопрос на засыпку: какой ширины коробка из примера выше? `width: 200px`, но на экране она шире! Считаем по умолчанию:

200 (content) + 20 + 20 (padding) + 4 + 4 (border) = **248 пикселей**.

По умолчанию `width` задаёт ширину только содержимого, а padding и border **прибавляются сверху**. Это неудобно: дизайнер в Figma говорит «карточка шириной 300», вы пишете `width: 300px`, добавляете отступы — и карточка уже 340, вёрстка разъехалась.

Это поведение меняет свойство **`box-sizing`**:

- `content-box` (по умолчанию) — `width` = только содержимое;
- `border-box` — `width` = содержимое + padding + border. Отступы «съедают» место изнутри, а внешний размер остаётся ровно таким, как вы написали.

```html
<style>
  .a, .b { width: 200px; padding: 20px; border: 4px solid #1f4e79; margin-bottom: 12px; }
  .b { box-sizing: border-box; }
</style>
<div class="a">content-box: 248px</div>
<div class="b">border-box: ровно 200px</div>
```

Что вы увидите: нижняя коробка заметно уже верхней, хотя `width` одинаковый.

С `border-box` считать намного проще, поэтому почти все верстальщики включают его для всех элементов сразу. Как это делают одним правилом на весь сайт, покажем на следующем занятии про общие стили.

### Схлопывание margin

Ещё одна неожиданность. Два абзаца, у каждого `margin: 20px`. Сколько между ними?

```html
<style>
  p { margin: 20px 0; background-color: #e3edf7; }
</style>
<p>Первый абзац, отступ снизу 20px.</p>
<p>Второй абзац, отступ сверху 20px.</p>
```

Что вы увидите: между голубыми полосами 20 пикселей, а не 40.

Это **схлопывание** (collapse) вертикальных отступов: когда нижний margin одного блока встречается с верхним margin следующего, они не складываются, а берётся **больший** из двух. 20 и 20 дают 20, 30 и 10 дают 30. По горизонтали схлопывания нет.

Отсюда частые вопросы новичков: «я задал `margin-top: 10px`, а ничего не изменилось» — потому что у соседа сверху уже был `margin-bottom: 20px`, и он больше. Совет: задавайте вертикальные отступы с **одной** стороны, например только снизу (`margin: 0 0 16px;`). Тогда схлопываться нечему и всё предсказуемо.

Кстати, у многих элементов есть margin **по умолчанию**: у `p` — сверху и снизу по размеру шрифта (16px), у `h1` — ещё больше, у `body` — 8px со всех сторон. Поэтому в заданиях курса в базовых стилях стоит `body { margin: 0; … }`.

## Ширина: width и max-width

`width` задаёт ширину жёстко. У блока с `width: 800px` на телефоне шириной 360 пикселей появится горизонтальная прокрутка — это серьёзная ошибка, на демоэкзамене за неё снимают баллы.

`max-width` задаёт **наибольшую** ширину: «не шире 800, а если экран уже — сжимайся». Это основа адаптивной вёрстки:

```html
<style>
  .page {
    max-width: 480px;
    margin: 0 auto;
    padding: 16px;
    background-color: #f4f1ea;
  }
</style>
<div class="page">
  <h1>Статья</h1>
  <p>На широком экране этот блок не шире 480 пикселей и стоит по центру. На узком — занимает всю ширину без прокрутки.</p>
</div>
```

Что вы увидите: бежевый блок по центру страницы. Если сузить окно, он сожмётся, но не вылезет за края.

Обратите внимание на `margin: 0 auto`: сверху и снизу 0, а слева и справа `auto` — браузер сам делит свободное место поровну. Так блок встаёт **по центру**. Это работает только у блочного элемента с заданной шириной (`width` или `max-width`). Частая ошибка — пытаться центрировать блок через `text-align: center`: так выравнивается текст внутри, а не сам блок.

Ещё пара полезных свойств: `min-width` (не уже чем) и `height`. Высоту новички задают слишком часто. Не делайте так: если текста станет больше, он вылезет за коробку. Пусть высоту определяет содержимое.

## Главное за занятие

- Каскад решает споры правил: сначала по специфичности, при равенстве — по порядку (последнее побеждает).
- Специфичность — (id, классы, теги). Один id сильнее любого числа классов. Держите её низкой: классы, без `!important`.
- Наследуется то, что про текст (`color`, `font-*`, `line-height`), не наследуется то, что про коробку (`border`, `padding`, `margin`, фон).
- `display`: `block` — на всю ширину, `inline` — в строке, `inline-block` — в строке, но с размерами, `none` — скрыт.
- Коробка = content + padding + border + margin. С `box-sizing: border-box` `width` — это внешняя ширина.
- Вертикальные margin соседей схлопываются: берётся больший.
- `max-width` + `margin: 0 auto` — блок по центру, который сжимается на телефоне.

## Словарик

- **Каскад** — правила, по которым браузер выбирает значение, когда несколько правил спорят.
- **Специфичность** — «точность» селектора: сколько в нём id, классов и тегов.
- **Наследование** — передача значения свойства от родителя к вложенным элементам.
- **Блочный элемент** — коробка с новой строки на всю ширину.
- **Строчный элемент** — коробка внутри строки текста по размеру содержимого.
- **padding** — внутренний отступ, **margin** — внешний отступ, **border** — рамка.
- **Схлопывание margin** — вертикальные отступы соседей не складываются, берётся больший.
