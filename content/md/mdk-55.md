## Коротко о теории

**Демонстрационный экзамен** проверяет не знания, а умение сделать работу: вы получаете задание, ограниченное время и рабочее место, а эксперты оценивают результат по заранее известным критериям. Для веб-разработки задание обычно состоит из нескольких **модулей**, каждый со своим временем:

1. **Проектирование и дизайн** — по ТЗ сделать в Figma стайлгайд и макеты страниц (компьютер и телефон).
2. **Вёрстка** — по своему макету сверстать страницы на HTML и CSS, адаптивно.
3. **Интерактивность** — добавить JavaScript: проверку формы, меню, переключатели.

Что важно знать заранее:

- **Критерии объективные.** Эксперт не ставит баллы за «красиво». Он проверяет конкретные пункты: «есть meta viewport», «на 360px нет горизонтальной прокрутки», «кнопка имеет состояние hover», «ошибка формы выводится рядом с полем». Каждый пункт — либо выполнен, либо нет.
- **Время жёсткое.** Не успели — не засчитано. Поэтому сначала делают всё по минимуму и только потом украшают.
- **Порядок важен.** Работающая простая страница лучше красивой половины страницы.
- **Файлы и папки по правилам** (занятие 35): `index.html`, `css/style.css`, `js/script.js`, `img/`; имена латиницей, без пробелов.

> Частая ошибка на экзамене: час рисовать идеальную шапку, а на форму не хватить времени. Сначала каркас всей страницы, потом детали.

## Техническое задание

**Заказчик:** ветеринарная клиника «Хвост и лапы».

**Цель сайта:** чтобы владельцы животных узнали об услугах и записались на приём без звонка.

**Целевая аудитория:** жители района 20–60 лет, владельцы кошек и собак. Заходят в основном с телефона, часто вечером, когда питомец заболел и хозяин волнуется.

**Страница:** одна, главная. Разделы:

1. Шапка: логотип-название «Хвост и лапы», меню из трёх ссылок (Услуги, Запись, Контакты).
2. Первый экран: заголовок «Ветклиника рядом с домом», короткий текст о режиме работы, кнопка «Записаться на приём».
3. Услуги: три карточки — Осмотр терапевта, Прививки, Груминг. В карточке картинка, название, описание с ценой.
4. Запись на приём: форма — имя, телефон, почта, согласие на обработку данных, кнопка «Записаться».
5. Подвал: адрес и телефон (по телефону можно позвонить одним касанием).

**Требования к дизайну:** спокойный, доверительный. Основной цвет — зелёный `#2d6a4f`, тёмный — `#1b4332`, фон блоков — `#f1f7f4`, акцент для фокуса — `#f4a261`, текст — `#1f2933`, ошибки — `#b3261e`. Шрифт без засечек (Arial). Скругление 8px, отступы кратны 8px.

**Адаптивность:** телефон 360px и компьютер от 768px. Мобильная версия — основная.

**Функции:** проверка формы на JavaScript. Ошибки показываются рядом с полем и объясняют, как исправить. При успешной отправке — сообщение «Спасибо, <имя>! Мы перезвоним в течение часа.»

**Доступность:** WCAG AA — контраст 4,5:1, все поля подписаны, видимый фокус, кнопки от 44px.

### Шаг 2. Стайлгайд в Figma (10 мин)

1. Создайте фрейм 1440 в ширину, назовите «Стайлгайд».
2. **Палитра:** пять квадратов с цветами из ТЗ, под каждым — название и HEX. Сохраните цвета как стили (Color styles) или переменные (Variables).
3. **Текст:** H1 32px жирный, H2 24px жирный, основной текст 16px, подпись 14px. Сохраните как Text styles.

### Шаг 3. Стайлгайд в коде — задание 1 на сайте (25 мин)

Стайлгайд из Figma переходит в код как **CSS-переменные** и **классы компонентов**. Переменные объявляют в `:root` — это корневой элемент страницы, переменные из него видны везде:

```html
<style>
  :root {
    --color-primary: #2d6a4f;
    --color-primary-dark: #1b4332;
    --color-accent: #f4a261;
    --radius: 8px;
  }
  .btn { min-height: 44px; padding: 10px 20px; font-size: 16px; border-radius: var(--radius); cursor: pointer; }
  .btn-primary { border: 2px solid var(--color-primary); background-color: var(--color-primary); color: #ffffff; }
  .btn-primary:hover { background-color: var(--color-primary-dark); }
  .btn:focus-visible { outline: 3px solid var(--color-accent); outline-offset: 2px; }
</style>
<button class="btn btn-primary" type="button">Записаться</button>
```

Зелёная кнопка со скруглением 8px; при наведении темнеет, при фокусе с клавиатуры — оранжевая рамка.

> **Попробуйте сами.** Поменяйте в `:root` значение `--color-primary` на `#1f5f8b`. Кнопка стала синей: одна строка поменяла цвет во всех местах, где стоит `var(--color-primary)`. Ради этого переменные и нужны.

У кнопки два класса: `btn` — общее для всех кнопок (размер, скругление), `btn-primary` — внешний вид основной. Вторичной кнопке достаточно `btn btn-secondary`.

### Шаг 4. Адаптивная страница — задание 2 на сайте (35 мин)

Порядок работы, который экономит время:

1. **Семантика.** Замените `div` на `header`, `nav`, `main`, `footer`. Классы оставьте — CSS привязан к ним.
2. **Телефон по умолчанию.** Всё в одну колонку, картинки резиновые, текст 16px. Проверьте на 360px: нет горизонтальной прокрутки.
3. **Компьютер в медиазапросе.** `@media (min-width: 768px)`: шапка в ряд, три карточки в ряд.
4. **Мелочи из ТЗ.** Телефон в подвале — ссылка `tel:`, кнопка от 44px, контраст.

```css
.card img { display: block; max-width: 100%; height: auto; }
.cards { display: grid; grid-template-columns: 1fr; gap: var(--space); }

@media (min-width: 768px) {
  .header { display: flex; justify-content: space-between; align-items: center; }
  .cards { grid-template-columns: repeat(3, 1fr); }
}
```

Частая ошибка: фиксированная ширина `width: 600px` у карточки. На телефоне карточка вылезет за экран и появится горизонтальная прокрутка — один из первых пунктов, которые проверяет эксперт. Ширину задаёт сетка, а не карточка.

### Шаг 5. Форма с проверкой — задание 3 на сайте (30 мин)

У формы атрибут `novalidate`: браузерные всплывающие подсказки выключены, проверку делает ваш скрипт. План обработчика:

```js
form.addEventListener('submit', (event) => {
  event.preventDefault();          // 1. страница не перезагружается
  let ok = true;                   // 2. пока считаем, что ошибок нет
  // 3. проверяем каждое поле: ошибка — текст в .error, aria-invalid="true", ok = false
  // 4. верное поле — очищаем ошибку, aria-invalid="false"
  if (ok) {
    // 5. сообщение об успехе
  }
});
```

Чтобы не повторять три строки для каждого поля, вынесите их в функцию — как в эталонных проектах на экзамене:

```js
function setError(input, message) {
  const errorEl = document.querySelector('#' + input.id + '-error');
  errorEl.textContent = message;
  input.setAttribute('aria-invalid', message ? 'true' : 'false');
  return message === '';
}
```

Функция пишет сообщение под поле (ищет элемент с id `имя-поля-error`), ставит `aria-invalid` и возвращает `true`, если ошибки нет. Пустая строка `''` — это «ошибки нет».

Проверка телефона: сначала оставляем только цифры, потом считаем их:

```js
const digits = phone.value.replace(/\D/g, '');
```

`replace(/\D/g, '')` заменяет каждый символ, который **не** цифра (`\D`), на пустоту. Из `+7 (900) 123-45-67` получится `79001234567` — 11 цифр.

> **Попробуйте сами.** В песочнице задания 3 введите в консоли браузера (F12 → Console) `'+7 (900) 123-45-67'.replace(/\D/g, '')` и нажмите Enter. Посмотрите, что останется.
