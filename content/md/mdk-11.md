## Коротко о теории

Форма — тег `form` с атрибутами `action` (куда отправить) и `method` (как: `post` для личных данных). Внутри — поля, у каждого:

- **тип** по смыслу данных: `text`, `email`, `tel`, `password`, `number`, `date`, `checkbox`, `radio`; для длинного текста — `textarea`, для выбора из многих — `select`;
- **подпись** `label`, связанная через `for` и `id` (или поле внутри `label`);
- **имя** `name` — под ним значение уйдёт на сервер.

Переключатели одной группы — с одинаковым `name` и разными `value`. Смысловые группы полей — `fieldset` с `legend`. Обязательные поля — `required` для браузера и звёздочка в подписи для человека. Кнопка — `button type="submit"` с текстом, который говорит, что произойдёт.

```html
<form action="/send" method="post">
  <fieldset>
    <legend>Контакты</legend>
    <label for="mail">Почта *</label>
    <input type="email" id="mail" name="email" required>
  </fieldset>
  <button type="submit">Отправить</button>
</form>
```

Что вы увидите: рамку с названием «Контакты», в ней подпись и поле почты, ниже кнопку. Попробуйте отправить пустую форму — браузер попросит заполнить поле.

## Ход работы

### Шаг 1. Продумываем поля на бумаге

Хорошая форма начинается не с кода, а с вопроса: **какие данные действительно нужны?** Каждое лишнее поле — повод закрыть страницу. Представьте, что колледж открывает вечерние курсы для всех желающих: «Компьютерная грамотность», «Основы веб-дизайна», «Фотография на телефон». Администратору, чтобы записать человека, нужно:

| Данные | Зачем | Обязательно? | Поле |
|---|---|---|---|
| Имя | Обращаться к человеку | Да | `input type="text"` |
| Почта | Прислать подтверждение | Да | `input type="email"` |
| Телефон | Позвонить, если курс перенесут | Нет | `input type="tel"` |
| Курс | Понять, куда записать | Да | `select` |
| Формат | Очно или онлайн | Да | два `radio` |
| Дата начала | Подобрать группу | Нет | `input type="date"` |
| Комментарий | Пожелания | Нет | `textarea` |
| Согласие на обработку данных | Так требует закон | Да | `checkbox` |

Нарисуйте такую таблицу у себя. Вычеркните то, что администратору не нужно: дату рождения, адрес, пол, «откуда вы о нас узнали». Обведите поля, которые встанут в одну группу: «Контактные данные» и «Курс».

### Шаг 2. Каркас формы — задание 1 на сайте

Откройте **задание 1**. Начните с каркаса и не пишите поля, пока он не готов:

```html
<form action="/enroll" method="post">
  <fieldset>
    <legend>Контактные данные</legend>
    <!-- имя, почта, телефон -->
  </fieldset>
  <fieldset>

</form>
```

Каркас сразу показывает структуру: две группы, под ними согласие и кнопка.

### Шаг 3. Поля по одному

Заполняйте группы сверху вниз. Каждое поле — одна и та же последовательность действий:

1. Подпись `label` с `for`.
2. Поле с таким же `id`, нужным `type` и `name`.
3. Если поле обязательное — `required` у поля и звёздочка `*` в подписи.
4. Щелчок по подписи в предпросмотре: курсор прыгнул в поле? Значит, связь есть.

```html
<label for="name">Имя *</label>
<input type="text" id="name" name="name" required>
```

Для **формата занятий** сделайте группу внутри группы: вложенный `fieldset` с `legend` «Формат занятий». Так программа экранного чтения объявит вопрос, к которому относятся «Очно» и «Онлайн».

```html
<fieldset>
  <legend>Формат занятий *</legend>
  <input type="radio" id="offline" name="format" value="offline" required>
  <label for="offline">Очно</label>
  <input type="radio" id="online" name="format" value="online">
  <label for="online">Онлайн</label>
</fieldset>
```

`required` достаточно поставить одному переключателю группы: браузер не отправит форму, пока не выбран хотя бы один вариант с этим `name`.

**Телефон** проверьте шаблоном: `pattern="\+7[0-9]{10}"` и пример в `placeholder="+79001234567"`. **Дате** поставьте `min` — первый день набора, например `min="2026-09-01"`: записаться в прошлое нельзя.

Последним идёт согласие и кнопка: «Записаться на курс». Частая ошибка — поставить кнопку внутрь последнего `fieldset`. Кнопка относится ко всей форме, а не к группе «Курс».

### Шаг 4. Чужая форма — задание 2 на сайте

В **задании 2** форма регистрации на олимпиаду выглядит нормально, но пользоваться ей тяжело, а с программой экранного чтения — невозможно. Пройдитесь по чек-листу:

1. У каждого поля есть `label`? Подсказка `placeholder` подписью не считается.
2. Переключатели собраны в `fieldset` с `legend`?
3. Пароль скрыт (`type="password"`) и не короче 8 символов (`minlength="8"`)?
4. Обязательные поля отмечены `required` и звёздочкой?
5. Текст кнопки говорит, что будет: не «ОК», а «Зарегистрироваться»?

Чинить чужое полезно: на экзамене вы будете смотреть на свою форму так же придирчиво.

### Шаг 5. Оформляем форму по образцу — задание 3 на сайте

Голая форма выглядит как в 1995 году: поля впритык к подписям, всё серое и мелкое. Внешний вид задаёт **CSS**. Подробно его начнём изучать на следующем занятии, а сегодня поработаем по образцу. CSS-**правило** выглядит так:

```css
label {
  display: block;
  margin-bottom: 4px;
}
```

- `label` — **селектор**: к каким элементам применить. Здесь — ко всем подписям.
- В фигурных скобках — **свойства** и их **значения** через двоеточие, в конце каждой строки точка с запятой.
- `display: block` ставит подпись на отдельную строку, `margin-bottom: 4px` — отступ 4 пикселя снизу.

Несколько селекторов через запятую получают одни и те же свойства: `input, select, textarea { … }`.

В **задании 3** правило для `label` уже написано — это образец. Ниже в шаблоне комментариями описано, какие правила дописать и с какими значениями. Пишите по одному правилу и сразу смотрите в предпросмотр: что изменилось? Вот что означают свойства, которые встретятся:

| Свойство | Что делает | Пример |
|---|---|---|
| `padding` | Внутренний отступ: от рамки до текста | `padding: 8px;` |
| `margin-bottom` | Внешний отступ снизу | `margin-bottom: 20px;` |
| `border` | Рамка: толщина, вид, цвет | `border: 1px solid #767676;` |
| `border-radius` | Скругление углов | `border-radius: 4px;` |
| `font-size` | Размер шрифта | `font-size: 16px;` |
| `font-weight` | Жирность | `font-weight: bold;` |
| `color` | Цвет текста | `color: #ffffff;` |
| `background-color` | Цвет фона | `background-color: #1f4e79;` |

Почему рамка у полей `#767676`, а не светло-серая? Граница поля должна быть заметна: по правилам доступности её контраст с фоном — не меньше 3:1. Светло-серую рамку на белом слабовидящий человек не увидит и не поймёт, куда писать. А почему шрифт в полях 16px? На iPhone при шрифте меньше 16px страница сама увеличивается, когда вы касаетесь поля, и это раздражает.

Частые ошибки в CSS: забытая точка с запятой, двоеточие вместо точки с запятой, пробел между числом и `px` (`16 px` — ошибка). Линтер в редакторе подчеркнёт такие места красным.
