## Лекция

**Что такое UI-кит.** UI-кит (библиотека компонентов) — это «конструктор Лего» вашего интерфейса: набор готовых кнопок, полей, карточек, бейджей во всех состояниях. Экраны потом собираются из этих деталей как из кубиков. В реальных компаниях это называется дизайн-системой. Для портала заявок кит небольшой, 6–8 компонентов, но он закрывает 90% всех экранов. На экзамене UI-кит — ваш главный ускоритель: сделали его один раз, и экраны собираются за минуты.

**Минимальный кит портала заявок:**

| Компонент | Варианты / состояния |
|---|---|
| Button | Type: Primary, Secondary, Text; State: Default, Hover, Pressed, Disabled |
| Input | State: Default, Focus, Filled, Error, Disabled |
| Select (выпадающий список) | Closed, Open |
| Radio / Checkbox | Off, On |
| Badge (статус) | New, InWork, Done, Cancelled |
| Card (карточка заявки) | User, Admin |
| Alert (сообщение) | Success, Error, Info |
| Header / Nav | Guest, User, Admin |

**Почему состояния так важны.** Интерфейс — это не картинка, а живая вещь, которая реагирует на действия. Пользователь должен всегда понимать: куда я нажал, что сейчас активно, где ошибка, что недоступно. Если в макете нарисованы только «спокойные» кнопки и поля, разработчик (то есть вы же в модуле 3) не знает, как показать ошибку. А на экзамене нужно показывать сообщения об ошибках на страницах регистрации и входа.

**Состояния кнопки:**

- **Default** — обычное: заливка Primary, белый текст.
- **Hover** — наведение мышью (на телефоне нет, но для веба рисуют): цвет на 8–10% темнее.
- **Pressed / Active** — нажатие: ещё темнее или лёгкое уменьшение.
- **Focus** — фокус с клавиатуры: заметное кольцо (outline) 2 px вокруг кнопки с отступом 2 px. Без него пользователь клавиатуры «теряется».
- **Disabled** — недоступна: серый фон `#E5E7EB` и серый текст `#9CA3AF`. Контраст тут может быть ниже 4.5:1, WCAG это допускает для неактивных элементов, но кнопка всё равно должна читаться.
- **Loading** (по желанию) — спиннер вместо текста после нажатия «Отправить».

**Иерархия кнопок.** Primary — заливка, одна на экран (главное действие). Secondary — контур или светлая заливка (`Primary/Light`) для второстепенного («Отмена»). Text — просто текст акцентного цвета («Забыли пароль?»). Опасное действие («Отменить заявку») часто делают в красном, но тоже Secondary или Text, чтобы не нажали случайно.

**Состояния поля ввода:**

- **Default:** рамка серая (не светлее 3:1 к фону), подпись над полем, плейсхолдер серым.
- **Focus:** рамка цветом Primary толщиной 2 px, иногда мягкое кольцо-тень.
- **Filled:** введён текст тёмным цветом.
- **Error:** рамка красная `#DC2626`, под полем текст ошибки 14 px тем же красным и, желательно, иконка. Текст ошибки конкретный: не «Ошибка», а «Логин должен быть не короче 6 символов».
- **Disabled:** фон серый, текст серый, курсор not-allowed.

Пример текстов ошибок для портала по правилам задания:

```
Логин:    «Минимум 6 символов: латинские буквы и цифры»
ФИО:      «Только кириллица, пробелы и дефис»
Телефон:  «Формат: +7(XXX)-XXX-XX-XX»
Email:    «Проверьте адрес: например, ivan@mail.ru»
Логин занят: «Этот логин уже занят, попробуйте другой»
Вход:     «Неверный логин или пароль»
```

Эти же состояния потом станут CSS:

```css
.input { border: 1px solid #6B7280; border-radius: 8px; height: 48px; padding: 0 16px; }
.input:focus { outline: none; border: 2px solid var(--primary); }
.input.is-error { border-color: #DC2626; }
.input:disabled { background: #F3F4F6; color: #9CA3AF; }
.btn:focus-visible { outline: 2px solid var(--primary); outline-offset: 2px; }
```

**Бейджи статусов.** Статус — самая важная информация для пользователя портала. Бейдж — маленькая плашка: высота 24, padding 4/8 (или 2/8), скругление 12 (таблетка) или 6, текст 12–14 px Medium. Лучший приём — **светлый фон + тёмный текст того же тона**: читается отлично и не «кричит».

| Статус | Фон | Текст |
|---|---|---|
| Новая | `#DBEAFE` | `#1D4ED8` |
| В работе | `#FEF3C7` | `#B45309` |
| Выполнена | `#DCFCE7` | `#15803D` |
| Отменена | `#FEE2E2` | `#B91C1C` |

Помните про «не только цвет»: в бейдже всегда есть слово, а при желании — иконка (часы, галочка, крестик).

**Как это собрать в Figma через варианты.**

1. Сделайте кнопку на auto layout (ЛР5), примените стили (ЛР6), превратите в компонент.
2. В правой панели нажмите **Add variant** (плюсик в разделе компонента). Появится component set с двумя вариантами.
3. В панели свойств переименуйте свойство `Property 1` в `State`, значения — `Default`, `Disabled`. Добавьте ещё свойство `Type` со значениями `Primary`, `Secondary`, `Text`.
4. Для каждого варианта поменяйте оформление. Имена вариантов в слоях выглядят так: `Type=Primary, State=Disabled`.
5. Добавьте **component properties**: Text-свойство `Label` (менять надпись с панели экземпляра), Boolean `Icon` (показать/скрыть иконку).
6. Расположите варианты аккуратной таблицей: строки — Type, столбцы — State. Для этого включите auto layout у самого component set (Wrap) или разложите вручную с одинаковыми отступами.

На экране вы вставляете экземпляр кнопки и в правой панели выбираете из выпадающих списков: Type Secondary, State Disabled. Никакого перерисовывания.

**Интерактивные компоненты (по желанию).** Во вкладке Prototype можно связать варианты: `While hovering → Change to State=Hover`. Тогда в режиме презентации кнопка реагирует на мышь. На экзамене сдаются PNG, поэтому это бонус для показа, а не обязательная часть.

**Карточка заявки.** Это составной компонент: внутри экземпляры Badge и Button. Структура: номер и дата (Caption, серый) — услуга (H3) — адрес и время (Body) — бейдж статуса справа сверху. Для администратора — дополнительно ФИО и телефон клиента, выпадающий список статуса и поле «Причина отмены».

**Типичные ошибки:**

- Состояния нарисованы отдельными несвязанными компонентами: `Button`, `Button 2`, `Button grey`.
- Ошибка поля показана только красной рамкой, без текста.
- Focus не отличается от Default.
- Бейджи насыщенного цвета с белым текстом мелкого размера — плохой контраст.
- Кит лежит вперемешку с экранами на одной странице.

**Связь с экзаменом.** Единый кит = единая дизайн-концепция на всех страницах. Сообщения об ошибках на регистрации и входе, статусы заявок и причина отмены в админке — функциональные части задания, и все они опираются на компоненты, которые мы делаем сегодня.

## Задание

**Цель:** собрать UI-кит портала с вариантами и состояниями.

**Исходные данные:** стайл-гайд из ЛР6, шкала и отступы из ПР7. Статусы заявки по ТЗ вашего варианта (для образца: «Новая», «В работе», «Выполнена», «Отменена»).

**Ход работы:**
1. На странице `UI-kit` создайте фреймы-разделы: Buttons, Inputs, Badges, Cards, Alerts.
2. Button: component set с Type (Primary/Secondary/Text) × State (Default/Hover/Pressed/Disabled) = 12 вариантов; добавьте свойство Label.
3. Input: подпись + поле + текст ошибки/подсказки; варианты State = Default, Focus, Filled, Error, Disabled. Текст подсказки — Boolean-свойство (показать/скрыть).
4. Select (Closed/Open) и Radio (Off/On) для типа оплаты.
5. Badge: свойство Status с 4 значениями; проверьте контраст текста на фоне (≥4.5:1).
6. Alert: Success и Error (иконка + текст), например «Заявка отправлена» и «Неверный логин или пароль».
7. Card: карточка заявки пользователя из экземпляров Badge; вариант Admin с ФИО, телефоном, Select статуса и полем «Причина отмены».
8. Проверка: вставьте на чистый фрейм 390×844 по экземпляру каждого компонента и переключите все состояния через панель свойств.
9. Сделайте скриншот/экспорт страницы UI-kit.

**Что сдать:** PNG страницы UI-kit (все разделы) и ссылку на файл Figma.
