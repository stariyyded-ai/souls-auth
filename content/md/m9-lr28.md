## Лекция

Пользователь создал заявку — теперь он хочет видеть, что с ней происходит: принята ли, в работе, выполнена или отменена (и почему). Это страница `requests.php`.

**Главное правило: только свои заявки.** Запрос обязательно содержит `WHERE r.user_id = ?`, а значение берётся **из сессии**. Никаких `requests.php?user_id=5` — иначе любой, поменяв число в адресе, прочитает чужие адреса и телефоны. Такая уязвимость называется IDOR (небезопасная прямая ссылка на объект), и эксперт её легко найдёт, просто поменяв цифру в адресной строке.

**Запрос с JOIN.** В таблице `requests` хранится только `service_id`, а пользователю нужно название услуги. Соединяем таблицы, как в ЛР19:

```sql
SELECT r.id, r.address, r.phone, r.date_time, r.payment, r.status,
       r.cancel_reason, r.custom_service, r.created_at, s.name AS service_name
FROM requests r
JOIN services s ON s.id = r.service_id
WHERE r.user_id = ?
ORDER BY r.created_at DESC
```

`AS service_name` даёт столбцу понятное имя в массиве PHP. Сортировка «новые сверху» — привычна пользователю.

**Перевод значений для людей.** В базе статус хранится как `in_work`, а показать нужно «В работе». Для этого у нас в `config.php` есть константы `STATUSES` и `PAYMENTS`: `STATUSES[$r['status']]`. Цвет бейджа тоже зависит от статуса — сделаем маленькую функцию, чтобы не писать четыре `if` в шаблоне. Добавим её в `config.php`, она пригодится и в админ-панели:

```php
<?php
// Бейдж статуса в стиле Bootstrap
function status_badge(string $status): string
{
    $colors = [
        'new'       => 'primary',
        'in_work'   => 'warning',
        'done'      => 'success',
        'cancelled' => 'danger',
    ];
    $color = $colors[$status] ?? 'secondary';
    $text  = STATUSES[$status] ?? $status;
    return '<span class="badge text-bg-' . $color . '">' . e($text) . '</span>';
}
```

**Даты по-русски.** Из базы приходит `2027-05-20 14:30:00`. Пользователю приятнее `20.05.2027 14:30`. Делаем так: `date('d.m.Y H:i', strtotime($r['date_time']))`. Тоже вынесем в функцию `format_dt()`.

**Услуга с учётом «иной».** Если `custom_service` не пустой — показываем «Иная услуга: <описание>», иначе название из справочника.

**Пустое состояние.** Если заявок ещё нет, страница не должна быть просто пустой. Покажите текст «У вас пока нет заявок» и кнопку «Создать заявку». Это мелочь, но она есть в критериях интерфейса.

**Карточки или таблица?** На телефоне (а дизайн у нас мобильный 390×844, модуль 2) таблица из 7 колонок не помещается. Поэтому выводим **карточки** — вы верстали их в ЛР13.

И функция для дат в `config.php`:

```php
<?php
// Дата из MySQL ('2027-05-20 14:30:00') в вид '20.05.2027 14:30'
function format_dt(?string $value): string
{
    return $value ? date('d.m.Y H:i', strtotime($value)) : '';
}
```

Обратите внимание: `status_badge()` уже возвращает безопасный HTML (текст внутри экранирован), поэтому её результат выводим без `e()`. А вот всё «сырое» из базы — адрес, телефон, описание услуги, причина отмены — через `e()`.

**Как проверить изоляцию данных.** Войдите пользователем А, запомните номера его заявок. Войдите пользователем Б — заявок А не видно. Это и есть главная проверка страницы.

**Что означает каждый статус для пользователя.** Полезно договориться о смысле статусов заранее — тогда и тексты, и цвета будут последовательными на всех страницах:

| Статус в БД | Подпись | Цвет | Что видит и может пользователь |
|---|---|---|---|
| `new` | Новая | синий | Заявка принята, ждёт администратора |
| `in_work` | В работе | жёлтый | Исполнитель назначен, работа идёт |
| `done` | Выполнена | зелёный | Работа завершена (в ЛР31 — можно оставить отзыв) |
| `cancelled` | Отменена | красный | Видна причина отмены от администратора |

Цвет не должен быть единственным носителем смысла (ПР6, доступность): рядом всегда есть текст статуса — так его поймёт и человек с нарушением цветового зрения, и экранный диктор.

**Связь с админ-панелью.** Эта страница и `admin.php` (ЛР29) — две стороны одних данных: админ меняет `status` и `cancel_reason`, пользователь их читает. Поэтому общие вещи — `STATUSES`, `status_badge()`, `format_dt()` — живут в `config.php`, а не копируются в оба файла. Поменяли цвет «В работе» — он поменялся везде.

**Типичные ошибки.**

- Видны заявки всех пользователей — забыт `WHERE r.user_id = ?`.
- Заявка с несуществующей услугой не видна — при `JOIN` строка без пары пропадает. У нас `service_id` обязательный с внешним ключом, так что этого не случится; но если в вашем варианте услуга может быть `NULL`, используйте `LEFT JOIN`.
- `Undefined array key "name"` — в `SELECT` переименовали столбец через `AS service_name`, а в шаблоне обращаетесь к `$r['name']`.
- Статус выводится как `in_work` — забыли перевести через `STATUSES`.
- `Warning: Undefined array key "in_work"` — в константе `STATUSES` опечатка в ключе.

**Связь с экзаменом.** По ТЗ пользователь видит историю своих заявок с их статусами, а при отмене — причину. Эксперт сменит статус в админке и проверит, что пользователь это увидел.
