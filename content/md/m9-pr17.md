## Лекция

Портал заявок — это по сути набор форм: регистрация, вход, новая заявка, смена статуса. Сегодня разбираемся, как данные из формы попадают в PHP, как их проверить и как красиво показать ошибки.

**Путь данных из формы.** У тега `<form>` есть два важных атрибута:

- `action` — куда отправить (адрес PHP-файла). Если пусто или не указано — на ту же страницу. Мы почти всегда отправляем форму «самой себе»: один файл и показывает форму, и обрабатывает её.
- `method` — как отправить: `get` или `post`.

Каждое поле должно иметь атрибут **`name`** — именно он становится ключом в PHP. Поле без `name` на сервер не уходит вообще (очень частая ошибка: «форма отправляется, а данных нет»).

**GET и POST.**

| | GET | POST |
|---|---|---|
| Где данные | В адресной строке: `?status=new&page=2` | В теле запроса, в адресе не видно |
| Массив в PHP | `$_GET` | `$_POST` |
| Для чего | Поиск, фильтры, сортировка, номер страницы — то, чем можно поделиться ссылкой | Всё, что **меняет данные**: регистрация, вход, создание заявки, смена статуса |
| Пароли | Никогда | Да |

Правило простое: **читаем — GET, изменяем — POST.**

**Как понять, что форма отправлена.** Страница открывается дважды: сначала просто (пустая форма), потом после нажатия кнопки. Различаем по методу запроса:

```php
<?php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // форму отправили — обрабатываем
}
// дальше — показ формы
```

**Читаем поля безопасно.** Если поля нет, обращение `$_POST['fio']` даст предупреждение. Кроме того, хитрый пользователь может отправить вместо строки массив (`fio[]=1`), и функции вроде `trim()` упадут. Поэтому добавляем в `config.php` портала (и используем в упражнениях) маленькую функцию:

```php
<?php
// Возвращает значение поля формы как строку без пробелов по краям.
function post(string $key): string
{
    $value = $_POST[$key] ?? '';
    return is_string($value) ? trim($value) : '';
}
```

`trim()` убирает случайные пробелы в начале и конце — пользователь скопировал логин с пробелом, а потом не может войти.

**Валидация на сервере — обязательно.** В модуле 3 вы ставили `required` и `pattern` в HTML, а в модуле 6 будет проверка на JavaScript. Но и то, и другое — работает в браузере пользователя и **отключается за 5 секунд** через DevTools. Настоящая проверка — только на сервере. Клиентская — для удобства, серверная — для надёжности.

Схема проверки: заводим пустой массив ошибок `$errors`, проверяем каждое поле, при проблеме кладём сообщение **с ключом поля**. Если после всех проверок массив пуст — данные хорошие.

```php
<?php
$errors = [];
$fio   = post('fio');
$email = post('email');

if ($fio === '') {
    $errors['fio'] = 'Укажите ФИО';
} elseif (!preg_match('/^[А-ЯЁа-яё\s-]+$/u', $fio)) {
    $errors['fio'] = 'ФИО — только кириллица, пробелы и дефис';
}

if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
    $errors['email'] = 'Некорректный email';
}

if (!$errors) {
    // всё хорошо: сохраняем
}
```

`preg_match()` проверяет строку регулярным выражением. Модификатор `/u` **обязателен** для русских букв — без него кириллица проверяется побайтно, и проверка ломается. Для длины строки с кириллицей используйте `mb_strlen()`, а не `strlen()`: `strlen('Иван')` вернёт 8 (байт), `mb_strlen('Иван')` — 4 (символа).

**Вывод ошибок и «старые значения».** Пользователь ненавидит, когда после ошибки форма очищается и всё надо вводить заново. Поэтому:

1. Рядом с полем выводим текст его ошибки.
2. В `value` поля подставляем то, что пользователь ввёл (кроме пароля!).
3. И то, и другое — через `e()`, ведь это пользовательские данные.

```php
<input type="text" name="fio" value="<?= e($fio) ?>"
       class="form-control <?= isset($errors['fio']) ? 'is-invalid' : '' ?>">
<?php if (isset($errors['fio'])): ?>
    <div class="invalid-feedback"><?= e($errors['fio']) ?></div>
<?php endif; ?>
```

Классы `is-invalid` и `invalid-feedback` из Bootstrap сами покрасят поле в красный и покажут текст.

**PRG: Post/Redirect/Get.** Представьте: пользователь создал заявку и нажал F5. Браузер спросит «Отправить данные повторно?», человек нажмёт «Да» — и в базе две одинаковые заявки. Лечится паттерном **PRG**:

1. **P**ost — форма отправлена методом POST, данные сохранены.
2. **R**edirect — сразу после успешного сохранения делаем `redirect()`.
3. **G**et — браузер открывает новую страницу обычным GET-запросом. F5 теперь просто обновит страницу.

Важно: редирект делаем **только при успехе**. При ошибках мы показываем ту же форму с сообщениями, без редиректа — иначе потеряются и ошибки, и введённые данные.

Как сказать пользователю «Готово!» после редиректа? Пока — простым GET-параметром: `redirect('feedback.php?sent=1')`, а на странице `if (isset($_GET['sent']))`. В ПР20 заменим это на «флеш-сообщения» в сессии.

**Полный пример: форма обратной связи** (`practice/feedback.php`):

```php
<?php
function e(mixed $v): string { return htmlspecialchars((string)$v, ENT_QUOTES, 'UTF-8'); }
function post(string $key): string
{
    $value = $_POST[$key] ?? '';
    return is_string($value) ? trim($value) : '';
}

$errors = [];
$name = $email = $message = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $name    = post('name');
    $email   = post('email');
    $message = post('message');

    if (mb_strlen($name) < 2) {
        $errors['name'] = 'Имя — не короче 2 символов';
    }
    if (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
        $errors['email'] = 'Укажите корректный email';
    }
    if ($message === '' || mb_strlen($message) > 500) {
        $errors['message'] = 'Сообщение от 1 до 500 символов';
    }

    if (!$errors) {
        // здесь могла бы быть запись в базу
        header('Location: feedback.php?sent=1');   // PRG
        exit;
    }
}
?>
<!doctype html>
<html lang="ru">
<head><meta charset="utf-8"><title>Обратная связь</title>
<style>.error{color:#c00;font-size:14px}</style></head>
<body>
<h1>Обратная связь</h1>
<?php if (isset($_GET['sent'])): ?>
    <p style="color:green">Спасибо! Сообщение отправлено.</p>
<?php endif; ?>

<form method="post" novalidate>
    <p>Имя<br><input name="name" value="<?= e($name) ?>">
        <span class="error"><?= e($errors['name'] ?? '') ?></span></p>
    <p>Email<br><input name="email" type="email" value="<?= e($email) ?>">
        <span class="error"><?= e($errors['email'] ?? '') ?></span></p>
    <p>Сообщение<br><textarea name="message"><?= e($message) ?></textarea>
        <span class="error"><?= e($errors['message'] ?? '') ?></span></p>
    <button>Отправить</button>
</form>
</body>
</html>
```

Атрибут `novalidate` у формы выключает браузерную проверку — так удобно тестировать серверную. На реальных страницах его не ставят.

**Пример GET-формы: фильтр.**

```php
<?php
$services = ['Общий клининг', 'Генеральная уборка', 'Мойка окон', 'Химчистка'];
$q = $_GET['q'] ?? '';
$q = is_string($q) ? trim($q) : '';
$found = $q === ''
    ? $services
    : array_filter($services, fn($s) => mb_stripos($s, $q) !== false);
?>
<form method="get">
    <input name="q" value="<?= htmlspecialchars($q, ENT_QUOTES, 'UTF-8') ?>" placeholder="Поиск услуги">
    <button>Найти</button>
</form>
<ul>
<?php foreach ($found as $s): ?>
    <li><?= htmlspecialchars($s, ENT_QUOTES, 'UTF-8') ?></li>
<?php endforeach; ?>
</ul>
```

Наберите «уборка» — адрес станет `...?q=уборка`, и этой ссылкой можно поделиться. Именно так в ЛР30 будет работать фильтр по статусам.

**Типичные ошибки.**

- У поля нет `name` → в `$_POST` его нет.
- `method="post"` забыли → форма ушла GET-ом, пароль виден в адресной строке.
- Проверили `if ($_POST)` вместо проверки метода — работает, но хуже читается; используйте `REQUEST_METHOD`.
- Редирект после ошибки валидации → ошибки не видны.
- `Cannot modify header information - headers already sent` → перед `header()` уже был вывод (HTML, `echo`, пробел перед `<?php`). Вся обработка формы должна быть **в начале файла, до любого HTML**.

**Связь с экзаменом.** Регистрация с проверками полей (логин ≥ 6 символов, ФИО кириллицей, телефон в формате +7(XXX)-XXX-XX-XX, email), форма заявки, смена статуса — всё это формы. Аспекты «разработка модулей ИС по ТЗ» и «безопасность» проверяют, что данные действительно проверяются на сервере, а ошибки понятны пользователю.

| Аспект | 2 балла | 1 балл | 0 баллов |

| Приём данных | POST и GET используются по назначению, поля читаются через `post()` | Метод выбран неверно в одной форме | Данные не принимаются |
