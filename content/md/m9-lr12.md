## Лекция

**Три формы — половина экзамена.** На ПР11 вы научились *правильно* писать поля. Сегодня задача другая: сделать так, чтобы формы выглядели **как в вашем макете** и были удобны на телефоне. Браузерные поля по умолчанию — мелкие, серые, у каждого браузера свои. Эксперт, открыв такую страницу, сразу видит «студенческую» вёрстку. Поэтому стили полей — это отдельный компонент нашего `style.css`, такой же, как кнопка.

**Компонент «поле».** Каждое поле в макете обычно состоит из трёх частей: подпись, само поле и строка для ошибки или подсказки. Оборачиваем их в общий блок:

```html
<div class="field">
  <label class="field__label" for="login">Логин</label>
  <input class="field__input" type="text" id="login" name="login"
         required minlength="6" aria-describedby="login-hint">
  <p class="field__hint" id="login-hint">Не менее 6 символов</p>
</div>
```

```css
.form {
  display: flex;
  flex-direction: column;
  gap: var(--space-2);           /* 16px между полями */
}

.field {
  display: flex;
  flex-direction: column;
  gap: 4px;
}

.field__label {
  font-weight: 600;
  font-size: var(--fs-small);
}

.field__input {
  width: 100%;
  min-height: 48px;              /* удобно попасть пальцем */
  padding: 0 var(--space-2);
  border: 1px solid var(--color-border);
  border-radius: var(--radius);
  background: var(--color-surface);
  font: inherit;                 /* иначе у полей «свой» шрифт браузера */
  font-size: 16px;               /* меньше 16px — iPhone приближает страницу при фокусе */
  color: var(--color-text);
}

.field__input:focus-visible {
  outline: 3px solid var(--color-accent);
  outline-offset: 1px;
  border-color: var(--color-primary);
}

.field__hint {
  margin: 0;
  font-size: var(--fs-small);
  color: var(--color-muted);
}
```

Две строки заслуживают особого внимания. `font: inherit` — поля и кнопки *не наследуют* шрифт страницы по умолчанию, поэтому без этой строки ваш красивый Inter в полях превращается в системный шрифт. `font-size: 16px` — если шрифт поля меньше 16px, Safari на iPhone при нажатии на поле приближает всю страницу, и пользователю приходится отдалять её пальцами.

**Состояние ошибки.** В ЛР8 вы рисовали экран регистрации с сообщениями об ошибках. В коде это отдельный класс-модификатор. Сейчас мы верстаем его «статически» (вручную добавляем класс, чтобы показать, как это выглядит), а в модуле 5 PHP будет добавлять его сам, если логин уже занят или телефон в неверном формате:

```html
<div class="field field--error">
  <label class="field__label" for="phone">Телефон</label>
  <input class="field__input" type="tel" id="phone" name="phone"
         value="8900123" aria-invalid="true" aria-describedby="phone-error">
  <p class="field__error" id="phone-error">Введите телефон в формате +7(XXX)-XXX-XX-XX</p>
</div>
```

```css
.field--error .field__input { border-color: var(--color-error); }
.field__error {
  margin: 0;
  font-size: var(--fs-small);
  color: var(--color-error);
}
.field__input:user-invalid { border-color: var(--color-error); }
```

`aria-invalid="true"` и `aria-describedby` нужны экранному диктору: он прочитает не просто «Телефон, поле ввода», а «Телефон, недопустимое значение, введите телефон в формате...». Цвет ошибки — не единственный признак: текст сообщения обязателен, потому что не все различают красный (вы проходили это на ПР6 и ПР9).

**Общий блок-сообщение.** На странице входа ошибка относится не к одному полю, а ко всей форме: «Неверный логин или пароль». Не нужно подсказывать, что именно неверно — это помогает злоумышленнику подбирать логины. Для таких сообщений сделаем компонент `.alert`:

```html
<div class="alert alert--error" role="alert">Неверный логин или пароль</div>
```

```css
.alert {
  padding: 12px var(--space-2);
  border-radius: var(--radius);
  font-size: var(--fs-small);
}
.alert--error   { background: #fef2f2; color: #991b1b; border: 1px solid #fecaca; }
.alert--success { background: #f0fdf4; color: #166534; border: 1px solid #bbf7d0; }
```

`alert--success` пригодится после успешной регистрации («Аккаунт создан, войдите») и создания заявки.

**Select, radio и checkbox в фирменном стиле.** Выпадающий список стилизуем так же, как поле, — классом `.field__input` (он подходит и для `select`, и для `textarea`). Для `textarea` добавьте `min-height: 96px; padding: 12px 16px; resize: vertical;`. Для радиокнопок и чекбоксов есть простой современный способ покрасить их в фирменный цвет — свойство `accent-color`:

```css
input[type="radio"],
input[type="checkbox"] {
  accent-color: var(--color-primary);
  width: 20px;
  height: 20px;
}

.choice {
  display: flex;
  align-items: center;
  gap: var(--space-1);
  min-height: 44px;        /* вся строка — зона нажатия */
}
```

```html
<fieldset class="field">
  <legend class="field__label">Тип оплаты</legend>
  <label class="choice"><input type="radio" name="payment" value="cash" required> Наличными</label>
  <label class="choice"><input type="radio" name="payment" value="card"> Банковской картой</label>
</fieldset>
```

У `fieldset` браузер рисует рамку и отступы — уберите их: `fieldset { border: 0; padding: 0; margin: 0; min-width: 0; }`.

**Раскладка страниц входа и регистрации.** На этих страницах обычно нет навигации — пользователь ещё не вошёл. Типичная мобильная композиция: логотип сверху, заголовок, форма, кнопка на всю ширину, под ней ссылка на соседнюю страницу.

```html
<main class="page page--auth">
  <img class="auth__logo" src="img/logo.svg" alt="ЧистоДом" width="160" height="40">
  <h1>Вход</h1>
  <form class="form" action="#" method="post">
    <!-- поля логина и пароля -->
    <button class="btn btn--block" type="submit">Войти</button>
  </form>
  <p class="auth__link">Ещё нет аккаунта? <a href="register.html">Зарегистрироваться</a></p>
</main>
```

```css
.page--auth {
  min-height: 100dvh;           /* на всю высоту экрана телефона */
  display: flex;
  flex-direction: column;
  justify-content: center;
}
```

Единица `dvh` (dynamic viewport height) учитывает, что адресная строка мобильного браузера то появляется, то прячется. Обычный `100vh` на телефоне бывает чуть выше видимой области — и кнопка «Войти» уезжает под край.

**Форма новой заявки.** По образцу экзамена в заявке есть адрес, контактный телефон, дата и время, вид услуги из списка (с возможностью указать иную услугу), тип оплаты. Дату и время можно сделать двумя полями рядом — это хорошее место для Grid:

```html
<div class="form__row">
  <div class="field">
    <label class="field__label" for="date">Дата</label>
    <input class="field__input" type="date" id="date" name="date" required>
  </div>
  <div class="field">
    <label class="field__label" for="time">Время</label>
    <input class="field__input" type="time" id="time" name="time" required>
  </div>
</div>
```

```css
.form__row {
  display: grid;
  grid-template-columns: 1fr 1fr;
  gap: var(--space-2);
}
```

**Подсказки браузеру.** Атрибут `autocomplete` (`username`, `current-password`, `new-password`, `name`, `tel`, `email`, `street-address`) позволяет телефону подставить сохранённые данные одним касанием — пользователь не набирает ФИО на маленькой клавиатуре. А `inputmode="numeric"` показывает цифровую клавиатуру там, где тип поля текстовый. Мелочь, но именно из таких мелочей складывается впечатление «удобного» интерфейса, которое эксперт оценивает в аспекте требований целевой аудитории.

**Типичные ошибки:**

1. Нет `font: inherit` — шрифт полей отличается от макета.
2. Поля высотой 30px — на телефоне в них сложно попасть. Ориентир — не меньше 44–48px.
3. Ошибка показана только красной рамкой без текста.
4. На странице входа выводят «Такого логина нет» — лишняя подсказка взломщику.
5. Страница входа «прилипла» к верху, а в макете форма по центру — расхождение с дизайном.
6. Состояния ошибок нарисованы в макете, но не сверстаны — потом при подключении PHP их придётся придумывать заново.

**Связь с экзаменом.** Аспекты «интерфейс по ТЗ» и «интеграция дизайна» оценивают, насколько страницы совпадают с макетом и удобны. Формы, где сразу заложены классы `field--error` и `alert`, в модуле 5 оживают почти без правки вёрстки: PHP просто подставит нужный класс и текст.

## Критерии оценки

| Аспект | 2 балла | 1 балл | 0 баллов |
|---|---|---|---|
| Соответствие макету | три страницы узнаваемо совпадают с макетом: цвета, шрифт, отступы, порядок полей | есть заметные расхождения на одной странице | вёрстка не похожа на макет |
| Состав полей по ТЗ | все поля регистрации и заявки на месте с верными типами и атрибутами | не хватает 1–2 полей или проверок | форм меньше трёх |
| Состояния ошибок | ошибки у полей и общий alert свёрстаны, текст + цвет, aria-атрибуты | ошибки только цветом или только на одной странице | состояний нет |
| Мобильное удобство | поля и кнопки ≥ 44px, шрифт полей 16px, нет прокрутки вбок на 390px | одно нарушение | несколько нарушений |
| Клавиатура и доступность | label у всех полей, видимый фокус, логичный порядок Tab | фокус виден не везде | фокус не виден, подписи не связаны |
