## Лекция

**Регулярное выражение** — это шаблон, с которым сравнивают строку. Вместо десятка `if` («первый символ плюс? второй семёрка? потом скобка?») пишем одну строку-шаблон. В JS регулярка записывается между слешами: `/шаблон/флаги`. Главный метод — `test()`: возвращает `true` или `false`.

```js
/^\d{3}$/.test('123');   // true — ровно три цифры
/^\d{3}$/.test('12a');   // false
```

**Азбука регулярок (минимум для экзамена).**

| Запись | Значит |
|---|---|
| `^` и `$` | начало и конец строки. Без них шаблон ищет совпадение *где-то внутри* |
| `\d` | любая цифра 0–9 |
| `\s` | пробельный символ |
| `[абв]` | один символ из перечисленных; `[А-Я]` — диапазон |
| `[^@]` | любой символ, *кроме* перечисленных |
| `+` | один или больше раз |
| `*` | ноль или больше раз |
| `{3}`, `{6,}`, `{2,4}` | ровно 3; 6 и больше; от 2 до 4 |
| `(?: ... )` | группа (без запоминания) — чтобы повторить кусок целиком |
| `\(` `\)` `\+` `\.` | экранирование: скобка, плюс и точка — служебные, чтобы искать их буквально, ставим `\` |

Самая частая ошибка — забыть `^` и `$`. Шаблон `/\d{3}/` вернёт `true` для `'abc123xyz'`, потому что три цифры внутри есть. Для проверки поля *целиком* якоря обязательны.

**Четыре проверки задания 3.** Разберём каждую — их ты будешь писать на экзамене по памяти.

*1. Логин — не менее 6 символов.* Здесь регулярка даже не нужна:

```js
const isLoginOk = (v) => v.trim().length >= 6;
```

Если в твоём варианте ТЗ дополнительно сказано «латиница и цифры», используй шаблон `/^[A-Za-z0-9_]{6,}$/`. Читай ТЗ внимательно и не добавляй ограничений, которых там нет: эксперт проверяет соответствие ТЗ, а не твою фантазию.

*2. ФИО — только кириллица (и пробелы между словами).*

```js
const fioRe = /^[А-ЯЁа-яё]+(?:[ -][А-ЯЁа-яё]+)*$/;
fioRe.test('Иванов Иван Иванович');  // true
fioRe.test('Петрова-Водкина Анна');  // true — двойная фамилия через дефис
fioRe.test('Ёлкин Пётр');            // true
fioRe.test('Ivanov Ivan');           // false — латиница
fioRe.test('Иванов1');               // false — цифра
fioRe.test('Иванов  Иван');          // false — два пробела подряд
```

Читаем: «одно или больше кириллических букв, потом ноль или больше раз: пробел-или-дефис и снова буквы». Буква **Ё** не входит в диапазон `А-Я` (она стоит в таблице Unicode отдельно), поэтому её добавляем явно: `[А-ЯЁа-яё]`. Забыть Ё — классическая потеря: Пётр Алёшин не сможет зарегистрироваться.

*3. Телефон в формате +7(XXX)-XXX-XX-XX.*

```js
const phoneRe = /^\+7\(\d{3}\)-\d{3}-\d{2}-\d{2}$/;
phoneRe.test('+7(912)-345-67-89');  // true
phoneRe.test('+7(912)345-67-89');   // false — нет дефиса после скобки
phoneRe.test('8(912)-345-67-89');   // false — начинается с 8
phoneRe.test('+7(912)-345-67-8');   // false — не хватает цифры
```

Обрати внимание на формат из ТЗ: после закрывающей скобки стоит **дефис**. Сравни посимвольно: `+7(912)-345-67-89`. Плюс и скобки экранированы обратным слешем.

*4. Email.* Идеальной регулярки для email не существует (стандарт очень сложный), но для учебного и экзаменационного уровня достаточно: «что-то без пробелов и @, затем @, затем домен, точка и зона минимум из двух символов».

```js
const emailRe = /^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/;
emailRe.test('user@mail.ru');   // true
emailRe.test('user@mail');      // false — нет зоны
emailRe.test('user mail@x.ru'); // false — пробел
```

Можно ещё поставить у поля `type="email"` — браузер тоже проверит, но его сообщения выглядят по-разному в разных браузерах. Мы хотим свои аккуратные сообщения, поэтому у формы ставим `novalidate`, а проверяем сами.

**Сборка в одну систему.** Хороший приём — описать правила объектом: поле → функция проверки → текст ошибки. Тогда добавить новое поле — это одна строка.

```js
// js/validation.js
const rules = {
  fio:      { test: (v) => /^[А-ЯЁа-яё]+(?:[ -][А-ЯЁа-яё]+)*$/.test(v), msg: 'ФИО — только кириллица и пробелы' },
  phone:    { test: (v) => /^\+7\(\d{3}\)-\d{3}-\d{2}-\d{2}$/.test(v),   msg: 'Телефон в формате +7(XXX)-XXX-XX-XX' },
  email:    { test: (v) => /^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/.test(v),      msg: 'Введите корректный email' },
  login:    { test: (v) => v.length >= 6,                                msg: 'Логин — не менее 6 символов' },
  password: { test: (v) => v.length >= 6,                                msg: 'Пароль — не менее 6 символов' },
};

function validateField(input) {
  const rule = rules[input.name];
  if (!rule) return true;                 // для поля нет правила — пропускаем
  const value = input.value.trim();
  const box = document.getElementById(`${input.name}-error`);
  let message = '';
  if (value === '') message = 'Поле обязательно';
  else if (!rule.test(value)) message = rule.msg;

  input.classList.toggle('is-invalid', message !== '');
  input.classList.toggle('is-valid', message === '');
  if (box) box.textContent = message;
  return message === '';
}

const form = document.getElementById('register-form');
if (form) {
  // проверяем поле, когда пользователь его покинул
  form.addEventListener('focusout', (e) => {
    if (e.target.name) validateField(e.target);
  });
  // финальная проверка перед отправкой
  form.addEventListener('submit', (e) => {
    const fields = [...form.querySelectorAll('input[name]')];
    const results = fields.map(validateField);   // map — чтобы проверились ВСЕ, а не до первой ошибки
    if (results.includes(false)) {
      e.preventDefault();
      form.querySelector('.is-invalid')?.focus(); // курсор в первое поле с ошибкой
    }
  });
}
```

Почему `focusout`, а не `blur`? `blur` не всплывает, а `focusout` всплывает — его можно ловить на всей форме. Почему `map`, а не `every`? `every` останавливается на первой ошибке, и пользователь увидит только одну подсветку. Оператор `?.` (опциональная цепочка) не даст упасть, если элемента нет.

**Маска телефона.** Требовать от человека руками набрать `+7(912)-345-67-89` с правильными скобками и дефисами жестоко. Маска делает это за него: человек вводит только цифры, а скобки и дефисы появляются сами. Идея простая: на каждый `input` выкидываем из значения всё, кроме цифр, и собираем строку заново.

```js
// js/phone-mask.js
function formatPhone(value) {
  let digits = value.replace(/\D/g, '');          // \D — всё, что НЕ цифра; g — заменить везде
  if (digits.startsWith('7') || digits.startsWith('8')) digits = digits.slice(1); // убираем код страны
  digits = digits.slice(0, 10);                   // в номере 10 цифр после +7
  if (digits.length === 0) return '';
  let result = '+7(' + digits.slice(0, 3);
  if (digits.length > 3) result += ')-' + digits.slice(3, 6);
  if (digits.length > 6) result += '-' + digits.slice(6, 8);
  if (digits.length > 8) result += '-' + digits.slice(8, 10);
  return result;
}

document.querySelectorAll('input[name="phone"]').forEach((input) => {
  input.addEventListener('input', () => {
    input.value = formatPhone(input.value);
  });
});
```

Проверено: `'9123456789'`, `'89123456789'`, `'+7 912 345 67 89'` превращаются в `+7(912)-345-67-89`, а повторный прогон готового номера ничего не меняет. Закрывающая скобка добавляется только с четвёртой цифрой — иначе Backspace «застревал» бы на ней: стёр скобку, а маска вернула её обратно. Это частая ловушка самодельных масок.

Полезно добавить полю `inputmode="tel"` (на телефоне откроется цифровая клавиатура), `maxlength="17"` (длина `+7(XXX)-XXX-XX-XX`) и `placeholder="+7(XXX)-XXX-XX-XX"`.

**Сервер всё равно проверяет.** В `register.php` (ЛР24) должны стоять те же шаблоны через `preg_match`. В PHP для кириллицы обязателен флаг `u`: `preg_match('/^[А-ЯЁа-яё]+(?:[ -][А-ЯЁа-яё]+)*$/u', $fio)`. Без `u` PHP считает байты, а не буквы, и проверка ФИО ломается.

**Типичные ошибки.**
- Нет `^` и `$` — проходит мусор вокруг правильного значения.
- Неэкранированные `+`, `(`, `)`, `.` в шаблоне телефона.
- Забыта буква Ё.
- Проверка только при `submit` — пользователь узнаёт об ошибках поздно. И наоборот, только `input` — раздражает красным с первой буквы. Лучший вариант: при уходе с поля и при отправке.
- Сообщение «Ошибка!» без объяснения. Пиши, *как* правильно: «Телефон в формате +7(XXX)-XXX-XX-XX».

**Связь с экзаменом.** Это прямой кусок задания 3: валидация логина, ФИО, телефона и email. Эксперт будет вводить неправильные данные и смотреть, что ответит форма. Понятное сообщение под полем + маска = максимальный балл за этот аспект.
