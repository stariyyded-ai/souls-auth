## Зачем нужны формы

**Форма** — часть страницы, куда человек вводит данные, чтобы отправить их сайту. Вы пользуетесь формами каждый день:

- строка поиска — форма из одного поля;
- вход в электронный дневник — форма из двух полей (логин и пароль);
- запись к врачу на Госуслугах — большая форма из нескольких шагов;
- «Оставьте отзыв» на сайте кафе — форма с текстом и оценкой.

Формы — самая важная часть интерфейса для бизнеса: через них приходят заказы, заявки и деньги. Неудобная форма — потерянные клиенты. На демоэкзамене форма есть почти в каждом задании: обратная связь, запись, регистрация. Её проверяют строго: подписи, типы полей, обязательные поля.

## Тег form и как форма отправляется

Все поля формы живут внутри тега `<form>`:

```html
<form action="https://yandex.ru/search/" method="get">
  <label for="q">Что ищем</label>
  <input type="text" id="q" name="text">
  <button type="submit">Найти</button>
</form>
```

Что вы увидите: подпись «Что ищем», поле ввода и кнопку «Найти». Если ввести «котики» и нажать кнопку, откроется поиск Яндекса по слову «котики» (в песочнице сайта курса переход может быть запрещён — попробуйте этот код в отдельном файле).

Как это работает:

1. Человек заполняет поля и нажимает кнопку отправки.
2. Браузер собирает пары **имя = значение**. Имя берётся из атрибута `name` поля, значение — то, что ввёл человек. Здесь получится `text=котики`.
3. Браузер отправляет эти пары по адресу из атрибута `action` («действие») — туда, где сервер ждёт данные.
4. Сервер обрабатывает их (ищет, сохраняет заявку, отправляет письмо) и присылает в ответ новую страницу.

Атрибут `method` («способ») говорит, **как** отправить данные:

| Метод | Как отправляет | Когда использовать |
|---|---|---|
| `get` | Дописывает данные в адрес: `…/search/?text=котики` | Поиск, фильтры каталога: такой адрес можно сохранить и отправить другу |
| `post` | Отправляет данные отдельно, в адресе их не видно | Регистрация, пароли, заявки, личные данные |

Частая ошибка — отправить форму входа методом `get`. Тогда пароль окажется прямо в адресной строке, в истории браузера и в журналах сервера.

На нашем курсе нет своего сервера, поэтому в `action` мы пишем адрес-заготовку, например `/send`. Программист потом поставит туда настоящий. Ваша задача как верстальщика — правильно собрать форму.

## Поле ввода input и подпись label

Главный элемент формы — `<input>` («ввод»). Это одиночный тег, как `img` и `br`: у него нет закрывающей пары. Какое поле получится, решает атрибут `type`.

Каждое поле обязательно **подписывают** тегом `<label>` («ярлык»). Подпись связывают с полем: атрибут `for` у подписи равен `id` у поля.

```html
<label for="user-name">Имя</label>
<input type="text" id="user-name" name="name">
```

Что вы увидите: слово «Имя» и пустое поле рядом. Щёлкните по слову «Имя» — курсор сам прыгнет в поле.

Зачем связывать подпись и поле:

- **Программа экранного чтения** скажет «Имя, поле ввода». Без связи незрячий человек услышит просто «поле ввода» и будет гадать, что туда писать.
- **Щелчок по подписи** ставит курсор в поле. Для маленьких флажков и переключателей это спасение: в подпись попасть пальцем легче, чем в квадратик 13 на 13 пикселей.

Можно и по-другому — обернуть поле в `label`. Тогда `for` и `id` не нужны:

```html
<label>Имя <input type="text" name="name"></label>
```

Частая ошибка: вместо подписи — только подсказка внутри поля (`placeholder`, о нём ниже). Она исчезает, как только человек начал печатать, и он забывает, что это было за поле. Автопроверка на сайте курса считает такое поле неподписанным.

Ещё частая ошибка: `for` и `id` не совпадают из-за опечатки (`for="phone"`, а `id="tel"`). Тогда связи нет, хотя на вид всё в порядке. Проверка простая: щёлкните по подписи — курсор должен оказаться в поле.

### name и id — в чём разница

Новички путают эти атрибуты, потому что часто они одинаковые. Но работают они на разных людей:

- `id` — для **страницы**: связывает подпись с полем (и работает как якорь, вы знаете это с занятия 3). Должен быть уникальным на странице.
- `name` — для **сервера**: под этим именем значение уйдёт при отправке. Поле без `name` не отправится вообще.

> **Попробуйте сами.** Нажмите «Попробовать» под примером с поиском Яндекса. Удалите у поля атрибут `name` — что теперь окажется в адресе после отправки? Верните `name`, но поменяйте `for` у подписи на `qq` — работает ли щелчок по подписи?

## Типы полей input

Атрибут `type` меняет поведение поля. На телефоне это особенно заметно: для каждого типа появляется своя клавиатура.

| `type` | Что это | Что делает браузер |
|---|---|---|
| `text` | Обычный текст: имя, город | Обычная клавиатура |
| `email` | Электронная почта | Клавиатура с `@`, проверяет, что есть `@` и точка |
| `tel` | Телефон | Цифровая клавиатура на телефоне |
| `password` | Пароль | Прячет символы за точками |
| `number` | Число: возраст, количество | Стрелочки «больше-меньше», цифровая клавиатура |
| `date` | Дата | Календарик для выбора |
| `checkbox` | Флажок «да / нет» | Квадратик с галочкой |
| `radio` | Переключатель: один из нескольких | Кружок с точкой |
| `search` | Поиск | Крестик для очистки поля |

```html
<form action="/register" method="post">
  <p><label for="email">Почта</label> <input type="email" id="email" name="email"></p>
  <p><label for="tel">Телефон</label> <input type="tel" id="tel" name="phone"></p>
  <p><label for="pass">Пароль</label> <input type="password" id="pass" name="password"></p>
  <p><label for="age">Возраст</label> <input type="number" id="age" name="age"></p>
  <p><label for="birth">Дата рождения</label> <input type="date" id="birth" name="birth"></p>
</form>
```

Что вы увидите: пять подписанных полей друг под другом. В поле пароля вместо букв — точки, у поля возраста — стрелочки, у даты — значок календаря.

Правильный тип — это забота о человеке: ему не придётся переключать клавиатуру на телефоне, чтобы найти `@`. На демоэкзамене тип поля проверяют обязательно: почта в `type="text"` — ошибка.

## Флажки и переключатели

**Флажок** (`checkbox`) отвечает на вопрос «да или нет»: подписаться на новости, согласиться с правилами. Флажков в группе можно отметить сколько угодно.

**Переключатель** (`radio`, как кнопки старого радиоприёмника) — выбор **одного** варианта из нескольких: очно или заочно, утро или вечер.

```html
<form action="/order" method="post">
  <p>Размер пиццы:</p>
  <p>
    <input type="radio" id="s25" name="size" value="25">
    <label for="s25">25 см</label>
    <input type="radio" id="s30" name="size" value="30" checked>
    <label for="s30">30 см</label>
    <input type="radio" id="s35" name="size" value="35">
    <label for="s35">35 см</label>
  </p>
  <p>
    <input type="checkbox" id="cheese" name="extra" value="cheese">
    <label for="cheese">Двойной сыр</label>
  </p>
</form>
```

Что вы увидите: три кружка с размерами, отмечен «30 см», и квадратик «Двойной сыр». Выберите 35 — отметка с 30 исчезнет сама.

Три правила переключателей:

1. **У всех переключателей группы одинаковый `name`.** Именно так браузер понимает, что они — одна группа и отметить можно только один. Частая ошибка: разные `name` — и человек может отметить все три размера сразу.
2. **У каждого свой `value`** — что уйдёт на сервер. Подпись «25 см» видит человек, `value="25"` получает сервер.
3. **`checked`** отмечает вариант заранее. Это атрибут без значения — достаточно его написать.

## Многострочный текст: textarea

Для длинного текста (отзыв, комментарий, вопрос) поле `input` маловато. Есть `<textarea>` — парный тег, текст по умолчанию пишется между тегами:

```html
<label for="review">Ваш отзыв</label>
<textarea id="review" name="review" rows="4" cols="40"></textarea>
```

Что вы увидите: большое поле на 4 строки. Человек может растянуть его за уголок.

`rows` — сколько строк видно, `cols` — примерная ширина в символах. Частая ошибка: написать `<textarea></textarea>` на разных строках с отступом. Пробелы между тегами окажутся внутри поля, и курсор встанет не в начало.

## Выпадающий список: select и option

Когда вариантов много (группа, город, врач), переключатели займут пол-экрана. Тогда выручает выпадающий список `<select>` с пунктами `<option>`:

```html
<label for="doctor">Врач</label>
<select id="doctor" name="doctor">
  <option value="">Выберите врача</option>
  <option value="therapist">Терапевт</option>
  <option value="dentist">Стоматолог</option>
  <option value="oculist">Офтальмолог</option>
</select>
```

Что вы увидите: поле со стрелкой и текстом «Выберите врача». Щёлкнете — откроется список.

Как и у переключателей, человек видит текст пункта, а сервер получает `value`. Первый пункт с пустым `value` — подсказка: если человек ничего не выбрал, придёт пустое значение, и это легко проверить. Атрибут `selected` у `option` выбирает пункт заранее.

Когда что выбирать: до 4–5 вариантов — переключатели (все варианты видны сразу), больше — выпадающий список.

## Кнопки

Кнопку делают тегом `<button>`. Её тип задаёт атрибут `type`:

| `type` | Что делает |
|---|---|
| `submit` | Отправляет форму. Его ставят по умолчанию |
| `reset` | Очищает все поля формы |
| `button` | Ничего сам не делает. Нужен для JavaScript (занятие 28) |

```html
<form action="/send" method="post">
  <label for="mail">Почта для рассылки</label>
  <input type="email" id="mail" name="email">
  <button type="submit">Подписаться</button>
</form>
```

Пишите `type` всегда, даже для `submit`: так код понятнее, и кнопка «Показать пароль» внутри формы случайно не отправит её.

Текст кнопки говорит, **что случится**: «Записаться», «Отправить заявку», «Найти». Не «ОК» и не «Далее», если можно сказать точнее. А кнопку `reset` лучше не ставить совсем: случайное нажатие стирает всё, что человек вводил десять минут.

Частая ошибка: сделать кнопку из `div` или `p` с текстом «Отправить». Она не нажимается с клавиатуры, программа экранного чтения не знает, что это кнопка, и форма не отправится.

## Подсказки и проверка ввода

Браузер умеет сам проверять поля до отправки. Для этого есть атрибуты:

| Атрибут | Что значит | Пример |
|---|---|---|
| `required` | Обязательное поле | `<input type="text" required>` |
| `placeholder` | Пример внутри пустого поля | `placeholder="+79001234567"` |
| `min`, `max` | Наименьшее и наибольшее число или дата | `min="1" max="10"` |
| `minlength`, `maxlength` | Длина текста | `minlength="8"` для пароля |
| `pattern` | Шаблон, которому должен соответствовать текст | `pattern="[0-9]{6}"` — шесть цифр |

```html
<form action="/signup" method="post">
  <p><label for="nick">Имя (обязательно)</label> <input type="text" id="nick" name="name" required></p>
  <p><label for="index">Почтовый индекс</label> <input type="text" id="index" name="index" pattern="[0-9]{6}" placeholder="420111"></p>
  <p><label for="guests">Сколько гостей</label> <input type="number" id="guests" name="guests" min="1" max="10"></p>
  <p><button type="submit">Отправить</button></p>
</form>
```

Что вы увидите: три поля и кнопку. Нажмите «Отправить» с пустым именем — браузер покажет подсказку «Заполните это поле» и форму не отправит. Введите в индекс буквы или в гостей число 20 — тоже не отправит.

Как читать `pattern`. Квадратные скобки — «один символ из этих»: `[0-9]` — любая цифра. Фигурные — «сколько раз»: `{6}` — ровно шесть. Значит, `[0-9]{6}` — шесть цифр. Шаблон `\+7[0-9]{10}` — плюс, семёрка и десять цифр (обратная косая черта перед плюсом значит «просто символ +»). Сложные шаблоны на курсе не понадобятся.

Про `placeholder` важно помнить: это **пример**, а не подпись. Светло-серый текст плохо читается, а при вводе исчезает. Подпись — всегда `label`.

Обязательные поля принято отмечать и для человека — звёздочкой или словом «обязательно» в подписи. Браузер узнает об этом из `required`, а человек — из подписи.

Проверка браузера — только первая линия защиты, для удобства человека. Злоумышленник легко её обойдёт, поэтому сервер всё равно проверяет данные сам. Свои сообщения об ошибках на JavaScript мы научимся делать на занятии 30.

> **Попробуйте сами.** В примере выше поменяйте у поля гостей `max="10"` на `max="4"` и попробуйте отправить 5. Потом допишите `required` полю индекса и отправьте форму с пустым индексом.

## Группы полей: fieldset и legend

Длинную форму делят на смысловые группы: «Контактные данные», «Доставка», «Оплата». Группу оборачивают в `<fieldset>` («набор полей»), а её название пишут в `<legend>` («легенда», подпись группы) — первым элементом внутри.

```html
<form action="/booking" method="post">
  <fieldset>
    <legend>Контактные данные</legend>
    <p><label for="fio">Имя</label> <input type="text" id="fio" name="name" required></p>
    <p><label for="ph">Телефон</label> <input type="tel" id="ph" name="phone" required></p>
  </fieldset>
  <fieldset>
    <legend>Время визита</legend>
    <p>
      <input type="radio" id="morning" name="time" value="morning">
      <label for="morning">Утро</label>
      <input type="radio" id="evening" name="time" value="evening">
      <label for="evening">Вечер</label>
    </p>
  </fieldset>
  <p><button type="submit">Записаться</button></p>
</form>
```

Что вы увидите: две рамки, на верхнем крае каждой — название группы. В первой — имя и телефон, во второй — выбор времени.

`fieldset` особенно нужен **переключателям**. Подписи «Утро» и «Вечер» без группы непонятны: утро — чего? Программа экранного чтения, зайдя в группу, скажет «Время визита, группа» — и всё встанет на места.

## Как собрать хорошую форму: чек-лист

На экзамене и в жизни проверяйте форму по списку:

1. Все поля внутри `form`, у формы есть `action` и `method`.
2. У каждого поля есть подпись `label`, связанная через `for` и `id`.
3. У каждого поля есть `name`, у переключателей группы он одинаковый.
4. Тип поля подходит к данным: почта — `email`, телефон — `tel`.
5. Обязательные поля отмечены `required` и видно для человека.
6. Связанные поля собраны в `fieldset` с `legend`.
7. Кнопка — `button type="submit"` с понятным текстом.
8. Полей ровно столько, сколько нужно. Каждое лишнее поле — минус несколько процентов заявок.

## Главное за занятие

- Форма `form` отправляет пары `name=значение` по адресу `action` способом `method`: `get` — в адресе, `post` — скрыто.
- Поле `input` меняет поведение по `type`: `text`, `email`, `tel`, `password`, `number`, `date`, `checkbox`, `radio`.
- Каждому полю — подпись `label for` = `id`. `placeholder` — пример, а не подпись.
- У переключателей одной группы одинаковый `name` и разные `value`.
- `textarea` — для длинного текста, `select` с `option` — для выбора из многих вариантов.
- `required`, `min`, `max`, `pattern` — проверка браузером до отправки.
- Группы полей — `fieldset` с `legend`; кнопка — `button type="submit"`.

## Словарик

- **Форма** — часть страницы для ввода и отправки данных.
- **Поле** — элемент, куда человек вводит или выбирает значение.
- **Подпись** (`label`) — текст, связанный с полем.
- **Флажок** (`checkbox`) — выбор «да / нет».
- **Переключатель** (`radio`) — выбор одного варианта из группы.
- **Выпадающий список** (`select`) — выбор из списка, который раскрывается по щелчку.
- **Валидация** — проверка введённых данных.
