## Коротко о теории

**Зачем проверять на JavaScript.** Браузер умеет проверять поля сам (`required`, `type="email"`, `minlength`), но его сообщения выглядят по-разному в разных браузерах, их нельзя оформить, и они исчезают через пару секунд. Поэтому на сайтах (и на экзамене) пишут свою проверку: сообщение стоит прямо под полем и не пропадает, пока ошибку не исправят.

Чтобы браузер не мешал своей проверкой, у формы ставят атрибут `novalidate`. Атрибуты `required` и типы полей при этом оставляем: они подсказывают клавиатуру на телефоне и помогают программам экранного доступа.

> Проверка в браузере — для удобства человека. Злоумышленник может её обойти, поэтому настоящий сайт **ещё раз** проверяет данные на сервере. Это делают программисты сервера, но знать об этом нужно.

**Хорошее сообщение об ошибке** говорит, *что не так и как исправить*: «Пароль — не меньше 8 символов», а не «Ошибка ввода» и не «Неверное значение».

**Разметка поля с местом для ошибки:**

```html
<form novalidate>
  <label for="email">Почта</label>
  <input id="email" type="email" aria-describedby="email-error">
  <p class="error" id="email-error"></p>
</form>
```

- `p.error` пустой, пока ошибки нет. JavaScript пишет в него текст.
- `aria-describedby="email-error"` связывает поле с сообщением: программа экранного доступа, попав в поле, прочитает и подпись, и текст ошибки.
- Когда поле с ошибкой, ставим ему `aria-invalid="true"`, когда исправлено — `"false"`. Так незрячий человек узнает, какое поле неверное.

**Новое из JavaScript на сегодня:**

```js
'anna@mail.ru'.includes('@');   // true — есть ли в строке такой кусок
'anna'.includes('@');           // false
'секрет12'.length;              // 8 — длина строки
```

**Итоговое сообщение** выводим в элемент с `role="status"`: программа экранного доступа сама зачитает новый текст, даже если человек в этот момент в другом месте страницы.

**Общий план любой проверки:**

```js
form.addEventListener('submit', function (event) {
  event.preventDefault();      // 1. не отправлять и не перезагружать
  let valid = true;            // 2. пока считаем, что всё хорошо

  if (/* поле неверное */) {   // 3. проверяем каждое поле
    // показать ошибку
    valid = false;
  } else {
    // убрать ошибку
  }

  if (valid) {                 // 4. итог
    // «Заявка отправлена»
  }
});
```

Частая ошибка — забыть ветку `else`. Человек исправил поле, а красное сообщение так и висит.

## Ход работы

### Шаг 1. Разметка формы (задание 1)

Откройте задание «Имя и почта». Форма уже свёрстана: у каждого поля есть `label`, `aria-describedby` и пустой абзац `.error` под ним. У формы стоит `novalidate`. Найдите в HTML все три связи «поле → сообщение» по `id`.

### Шаг 2. Найти элементы и поймать отправку (задание 1)

```js
const form = document.querySelector('#signup');
const nameInput = document.querySelector('#name');
const nameError = document.querySelector('#name-error');
// так же — поле почты и его сообщение

form.addEventListener('submit', function (event) {
  event.preventDefault();
  // проверки — в следующих шагах
});
```

### Шаг 3. Проверить имя (задание 1)

Имя неверное, если после `trim()` осталась пустая строка:

```js
if (nameInput.value.trim() === '') {
  nameError.textContent = 'Введите имя';
  nameInput.setAttribute('aria-invalid', 'true');
} else {
  nameError.textContent = '';
  nameInput.setAttribute('aria-invalid', 'false');
}
```

### Шаг 4. Проверить почту (задание 1)

У почты две разные ошибки, поэтому три ветки:

1. Пусто — «Введите почту».
2. Нет `@` **или** нет точки — «Почта должна быть в формате name@mail.ru». «Или» в JavaScript — `||`, «нет» — `!`: `!email.includes('@') || !email.includes('.')`.
3. Иначе — ошибки нет.

Проверьте: пустая форма должна показать **обе** ошибки сразу, а не по одной.

### Шаг 5. Регистрация: три поля (задание 2)

Во втором задании к имени и почте добавляется пароль: не меньше 8 символов. Пароль **не обрезаем** `trim()`: пробел в пароле — тоже символ.

### Шаг 6. Функция setError (задание 2)

Код «показать ошибку / убрать ошибку» повторяется для каждого поля. Вынесите его в функцию:

```js
function setError(input, errorEl, message) {
  errorEl.textContent = message;
  if (message === '') {
    input.setAttribute('aria-invalid', 'false');
  } else {
    input.setAttribute('aria-invalid', 'true');
  }
}
```

Теперь проверка поля — одна строка в каждой ветке: `setError(nameInput, nameError, 'Введите имя');` или `setError(nameInput, nameError, '');`.

### Шаг 7. Итоговое сообщение (задание 2)

Заведите `let valid = true;` в начале обработчика, в каждой ветке с ошибкой ставьте `valid = false;`. В конце: если `valid` — в `#result` пишем «Заявка отправлена», иначе очищаем `#result`. Иначе получится странно: человек отправил форму, потом стёр почту, нажал ещё раз — а «Заявка отправлена» всё висит.

### Шаг 8. Почините чужую проверку (задание 3)

В третьем задании скрипт уже написан, но с пятью ошибками: форма перезагружает страницу, ошибки не исчезают, пароль из 6 символов проходит, почта ругается на правильный адрес, а «Заявка отправлена» пишется всегда. Консоль молчит — ошибки логические. Читайте код построчно и сравнивайте с планом проверки из теории.

### Шаг 9. Проверка руками

Проверьте каждое задание сами, прежде чем нажимать «Проверить»:

| Что ввести | Что должно случиться |
