## Лекция

**Зачем анимация, если и так работает.** Анимация в интерфейсе — не украшение, а подсказка. Окно плавно выезжает — пользователь понимает, *откуда* оно появилось. Уведомление «Заявка создана» мягко всплывает и исчезает — человек замечает его, но оно не мешает. Карточки заявок проявляются по очереди — глазу проще пробежать список. В задании 3 анимация — отдельное требование, и проверяют её «вживую»: эксперт кликает и смотрит.

**Разделение труда: CSS рисует, JS командует.** В ЛР15 ты уже делал `transition` и `@keyframes`. Правило этого модуля: *как* двигается — описываем в CSS, *когда* — решает JS, добавляя и убирая классы. Так анимации легко менять, а JS остаётся коротким.

**Что анимировать, чтобы не тормозило.** Браузер быстро анимирует только `transform` (сдвиг, масштаб, поворот) и `opacity` (прозрачность). Анимация `width`, `height`, `top`, `margin` заставляет пересчитывать раскладку всей страницы на каждом кадре — на слабом телефоне будет дёргаться. Хорошие длительности для интерфейса: 150–300 мс. Больше 500 мс — уже раздражает.

**Уважение к пользователю: `prefers-reduced-motion`.** У некоторых людей движение на экране вызывает головокружение, и они включают в системе «уменьшить движение». Сайт обязан это учитывать:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

Ставим почти ноль, а не `none`, чтобы события `transitionend`/`animationend`, на которые опирается наш JS, всё равно сработали. В JS эту настройку можно узнать так: `matchMedia('(prefers-reduced-motion: reduce)').matches`.

**1. Карточки заявок: появление по очереди.** На `requests.php` у каждой карточки класс `.request-card`. Сначала прячем, потом JS по очереди «включает».

```css
.request-card {
  opacity: 0;
  transform: translateY(16px);
  transition: opacity .3s ease-out, transform .3s ease-out;
}
.request-card.is-visible { opacity: 1; transform: none; }
.request-card:hover { transform: translateY(-2px); box-shadow: 0 6px 16px rgb(0 0 0 / .08); }
```

```js
// js/cards.js
const cards = document.querySelectorAll('.request-card');

const observer = new IntersectionObserver((entries) => {
  entries.forEach((entry) => {
    if (!entry.isIntersecting) return;
    entry.target.classList.add('is-visible');
    observer.unobserve(entry.target);         // анимируем один раз
  });
}, { threshold: 0.1 });

cards.forEach((card, i) => {
  card.style.transitionDelay = `${Math.min(i, 5) * 60}ms`; // «лесенка», но не дольше 300 мс
  observer.observe(card);
});
```

`IntersectionObserver` сообщает, когда элемент попал в видимую область экрана. Карточки внизу длинного списка проявятся, когда до них долистают. `Math.min(i, 5)` ограничивает задержку: 40-я карточка не должна ждать 2,4 секунды.

Важный момент про надёжность: если JS не загрузился, карточки останутся с `opacity: 0` — невидимыми! Защита: прячем только когда JS точно работает. Добавь в начало `cards.js` строку `document.documentElement.classList.add('js');` и пиши селектор `.js .request-card { opacity: 0; ... }`.

**2. Модальное окно на `<dialog>`.** Раньше модалки собирали из `div` и кучи кода. Сейчас в HTML есть элемент `<dialog>`: метод `showModal()` сам затемняет фон, не даёт кликать по странице, закрывается по Esc и держит фокус внутри окна. Это одновременно меньше кода и выше доступность.

```html
<button type="button" data-open="confirm-dialog">Удалить черновик</button>

<dialog id="confirm-dialog" class="modal-anim" aria-labelledby="confirm-title">
  <h2 id="confirm-title">Точно удалить?</h2>
  <p>Действие нельзя отменить.</p>
  <form method="dialog">
    <button value="cancel">Нет</button>
    <button value="ok">Да, удалить</button>
  </form>
</dialog>
```

`<form method="dialog">` — особая форма: нажатие кнопки внутри неё закрывает окно и записывает `value` кнопки в `dialog.returnValue`. Никакого JS для закрытия!

Анимация открытия и закрытия:

```css
.modal-anim { border: none; border-radius: var(--radius, 12px); padding: 24px; max-width: min(90vw, 360px); }
.modal-anim[open] { animation: modal-in .25s ease-out; }
.modal-anim[open]::backdrop { background: rgb(0 0 0 / .45); animation: fade-in .25s ease-out; }
.modal-anim.is-closing { animation: modal-out .2s ease-in forwards; }
.modal-anim.is-closing::backdrop { animation: fade-in .2s ease-in reverse forwards; }

@keyframes modal-in  { from { opacity: 0; transform: translateY(24px) scale(.97); } }
@keyframes modal-out { to   { opacity: 0; transform: translateY(24px) scale(.97); } }
@keyframes fade-in   { from { opacity: 0; } }
```

Открытие анимируется само (срабатывает при появлении атрибута `open`). Закрытие хитрее: `dialog.close()` прячет окно мгновенно, анимация не успевает. Поэтому сначала вешаем класс `is-closing`, ждём окончания анимации и только потом закрываем:

```js
// js/modal.js
function openModal(dialog) {
  dialog.showModal();
}

function closeModal(dialog, value = '') {
  dialog.classList.add('is-closing');
  dialog.addEventListener('animationend', () => {
    dialog.classList.remove('is-closing');
    dialog.close(value);
  }, { once: true });                      // обработчик сам удалится после срабатывания
}

// кнопки с data-open="id" открывают свои окна
document.addEventListener('click', (e) => {
  const opener = e.target.closest('[data-open]');
  if (opener) openModal(document.getElementById(opener.dataset.open));
});

document.querySelectorAll('dialog.modal-anim').forEach((dialog) => {
  // Esc: отменяем мгновенное закрытие и закрываем с анимацией
  dialog.addEventListener('cancel', (e) => { e.preventDefault(); closeModal(dialog, 'cancel'); });
  // клик по затемнённому фону (сам dialog, а не его содержимое) закрывает окно
  dialog.addEventListener('click', (e) => { if (e.target === dialog) closeModal(dialog, 'cancel'); });
  // кнопки формы method="dialog": тоже закрываем с анимацией
  dialog.querySelector('form[method="dialog"]')?.addEventListener('submit', (e) => {
    e.preventDefault();
    closeModal(dialog, e.submitter?.value ?? '');
  });
});
```

`data-open="confirm-dialog"` в HTML превращается в `opener.dataset.open` в JS — так хранят настройки прямо в разметке. `closest()` ищет ближайшего предка (или сам элемент) по селектору — нужно, если внутри кнопки есть иконка и клик пришёлся по ней.

Клик по фону: у `<dialog>` фон (`::backdrop`) — часть самого элемента, поэтому клик мимо содержимого приходит с `e.target === dialog`. Чтобы это работало, отступы задаём `padding` у dialog, а содержимое не должно занимать весь его размер. Если внутри у тебя обёртка на весь диалог — проверяй координаты клика.

**3. Уведомления (toast).** Маленькое сообщение в углу экрана: «Заявка отправлена», «Статус изменён». Само появляется, само исчезает.

```html
<div id="toasts" class="toasts" aria-live="polite"></div>
```

```css
.toasts { position: fixed; left: 16px; right: 16px; bottom: 16px; display: grid; gap: 8px; z-index: 1000; }
.toast {
  padding: 12px 16px; border-radius: 10px; color: #fff; background: var(--color-text, #222);
  opacity: 0; transform: translateY(12px); transition: opacity .25s, transform .25s;
}
.toast.is-shown { opacity: 1; transform: none; }
.toast--success { background: var(--color-success, #1f9d55); }
.toast--error   { background: var(--color-danger, #d33a3a); }
```

```js
// js/toast.js
function showToast(text, type = 'success', ms = 3000) {
  const box = document.getElementById('toasts');
  const toast = document.createElement('div');
  toast.className = `toast toast--${type}`;
  toast.textContent = text;
  box.append(toast);

  requestAnimationFrame(() => toast.classList.add('is-shown')); // дать браузеру нарисовать начальное состояние

  setTimeout(() => {
    toast.classList.remove('is-shown');
    toast.addEventListener('transitionend', () => toast.remove(), { once: true });
  }, ms);
}
```

Зачем `requestAnimationFrame`? Если добавить элемент и сразу повесить класс, браузер «склеит» оба шага, и перехода не будет — элемент просто появится. Мы просим: «сначала нарисуй, на следующем кадре добавь класс». `aria-live="polite"` заставляет программу экранного чтения произнести уведомление вслух.

Как показать toast после PHP-редиректа? После создания заявки `request_new.php` делает редирект (PRG из ПР17). Передай флаг: `header('Location: requests.php?created=1')`, а в JS:

```js
const params = new URLSearchParams(location.search);
if (params.get('created') === '1') {
  showToast('Заявка успешно создана');
  history.replaceState(null, '', location.pathname);  // убрать ?created=1, чтобы F5 не повторял
}
```

**Типичные ошибки.**
- Анимируют `height`/`top` вместо `transform` — дёргается.
- Анимации по 1–2 секунды — пользователь ждёт интерфейс.
- Нет `prefers-reduced-motion`.
- `dialog.close()` сразу — анимация закрытия не видна.
- Карточки спрятаны в CSS навсегда: JS упал — список пустой.
- В toast вставляют текст через `innerHTML`.

**Связь с экзаменом.** Требование задания 3 — анимация. Эксперту надо *увидеть* её быстро: открытие модалки, появление уведомления, наведение на карточку. Три осмысленные анимации, привязанные к действиям пользователя, убедительнее одной вращающейся картинки на главной.
