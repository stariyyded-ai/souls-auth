## Коротко о теории

**Все три элемента устроены одинаково:** есть кнопка, и она управляет каким-то блоком — показывает, прячет или переключает. Значит, в коде всегда одни и те же шаги: найти кнопку и блок, подписаться на `click`, поменять `hidden`, класс и подсказку для экранного доступа.

**Кнопка — это `<button type="button">`.** Не `div` и не ссылка. Кнопка сама получает фокус клавишей Tab и нажимается клавишами Enter и Пробел. `div` с обработчиком щелчка с клавиатуры не нажмётся — частая ошибка на экзамене.

**Атрибуты из JavaScript.** Прочитать атрибут — `getAttribute('имя')`, записать — `setAttribute('имя', 'значение')`:

```js
const button = document.querySelector('#burger');
console.log(button.getAttribute('aria-expanded'));   // 'false' — строка!
button.setAttribute('aria-expanded', 'true');
```

Значение атрибута — всегда строка: `'true'`, а не `true`.

**Подсказки для экранного доступа (ARIA).** Незрячий человек не видит, что меню открылось. Ему об этом скажет программа экранного доступа, если на кнопке есть атрибуты:

| Атрибут | Что сообщает | Пример |
|---|---|---|
| `aria-expanded` | Раскрыт ли блок, которым управляет кнопка | `"false"` — закрыт, `"true"` — открыт |
| `aria-controls` | id блока, которым управляет кнопка | `aria-controls="menu"` |
| `aria-selected` | Выбрана ли вкладка | `"true"` у текущей вкладки |

Атрибут `aria-controls` полезен и нам: по нему JavaScript находит нужный блок.

```js
const id = button.getAttribute('aria-controls');     // 'answer-1'
const block = document.querySelector('#' + id);      // элемент с id="answer-1"
```

**Атрибут `hidden` и CSS.** Если в CSS у элемента задан `display: flex`, он перебивает `hidden`. Это можно использовать специально: на телефоне меню спрятано атрибутом `hidden`, а на компьютере медиазапрос показывает его всегда:

```css
@media (min-width: 768px) {
  .menu, .menu[hidden] { display: flex; }
}
```

Селектор `.menu[hidden]` значит «элемент с классом `menu`, у которого есть атрибут `hidden`».

**Один обработчик на много кнопок.** Если кнопок несколько, находим все через `querySelectorAll` и вешаем обработчик в цикле `for…of`:

```js
for (const question of document.querySelectorAll('.faq-question')) {
  question.addEventListener('click', function () {
    // question — та кнопка, по которой щёлкнули
  });
}
```

## Ход работы

### Шаг 1. Разметка меню-«бургера» (задание 1)

Откройте задание «Меню-бургер». Разметка уже готова, разберите её:

```html
<button class="burger" id="burger" type="button" aria-expanded="false" aria-controls="menu">Меню</button>
<nav aria-label="Главное меню">
  <ul class="menu" id="menu" hidden>
    <li><a href="#coffee">Кофе</a></li>
    <li><a href="#food">Выпечка</a></li>
    <li><a href="#contacts">Контакты</a></li>
  </ul>
</nav>
```

- Кнопка подписана словом «Меню» — так её поймут все. Три полоски-иконку можно добавить потом, но текст оставьте.
- `aria-expanded="false"` — меню закрыто.
- У списка `hidden`: на телефоне меню при загрузке спрятано.

### Шаг 2. Медиазапрос для компьютера (задание 1)

На ширине от 768px кнопка не нужна, а меню должно стоять в строку. Допишите в CSS в конец:

```css
@media (min-width: 768px) {
  .burger { display: none; }
  nav { flex-basis: auto; }
  .menu, .menu[hidden] { display: flex; gap: 24px; }
}
```

Проверьте предпросмотр в режимах «компьютер» и «телефон»: на компьютере меню в строку и без кнопки, на телефоне видна только кнопка.

### Шаг 3. Скрипт меню (задание 1)

Во вкладке script.js:

```js
const burger = document.querySelector('#burger');
const menu = document.querySelector('#menu');

burger.addEventListener('click', function () {
  menu.hidden = !menu.hidden;
  // дальше: aria-expanded и текст кнопки
});
```

Допишите: если меню теперь открыто, `aria-expanded` становится `'true'`, а надпись — «Закрыть»; если закрыто — `'false'` и «Меню». Нажмите «Проверить».

### Шаг 4. Разметка вкладок (задание 2)

Вкладки показывают расписание секций по дням. Каждая вкладка — кнопка с `aria-controls`, каждая панель — `div` с тем же `id`. Видна только одна панель, остальные с `hidden`. У текущей вкладки класс `active` (закрашена) и `aria-selected="true"`.

### Шаг 5. Скрипт вкладок (задание 2)

План обработчика щелчка по вкладке:

1. У **всех** вкладок убрать класс `active` и поставить `aria-selected="false"`.
2. **Все** панели спрятать (`hidden = true`).
3. Нажатой вкладке добавить `active` и `aria-selected="true"`.
4. Найти её панель по `aria-controls` и показать (`hidden = false`).

Шаги 1–2 — два цикла `for…of` по вкладкам и панелям. Сначала «всё выключить», потом «включить одно» — самый надёжный способ, так не останется двух активных вкладок.

### Шаг 6. Аккордеон «вопрос-ответ» (задание 3)

**Аккордеон** — список вопросов, где ответ раскрывается по щелчку на вопрос. Вопрос — кнопка внутри заголовка `h2`, чтобы по нему можно было переходить и с клавиатуры, и по заголовкам:

```html
<div class="faq-item">
  <h2><button class="faq-question" type="button" aria-expanded="false" aria-controls="a1">Какие документы нужны?</button></h2>
  <p class="faq-answer" id="a1" hidden>Паспорт, аттестат, фото 3×4 и медицинская справка.</p>
</div>
```

В скрипте — цикл по всем `.faq-question`. В обработчике найдите ответ по `aria-controls`, переключите `hidden` и обновите `aria-expanded`. Каждый вопрос открывается независимо: открытие одного не закрывает другие.

### Шаг 7. Кнопка «Показать ещё» (задание 3)

Последние два вопроса спрятаны: у их блоков `.faq-item` стоит класс `extra` и атрибут `hidden`. Кнопка `#more` «Показать ещё» должна показать все блоки `.extra`, а потом спрятать саму себя: больше показывать нечего.

Важно: вешайте обработчики на вопросы **все сразу** при загрузке, в том числе на спрятанные. Тогда после «Показать ещё» новые вопросы тоже будут раскрываться.

### Шаг 8. Проверка с клавиатуры

Откройте любую из страниц у себя в браузере (или повторите в VS Code). Уберите мышь. Нажимайте Tab: фокус должен переходить по кнопкам и ссылкам, а Enter и Пробел — открывать меню, вкладки, ответы. Если что-то не нажимается с клавиатуры — скорее всего, вместо `button` использован другой тег.
