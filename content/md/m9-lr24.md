## Лекция

Регистрация — первая «настоящая» страница портала: она принимает данные, проверяет их, обращается к базе и сохраняет нового пользователя. Здесь сходятся всё, что мы прошли: формы, валидация, PDO.

**Что требует ТЗ.** По образцу экзамена у пользователя есть ФИО, телефон, email, логин и пароль. Правила проверки (модуль 3 КИМ): логин — не короче 6 символов, ФИО — кириллицей, телефон — в формате `+7(XXX)-XXX-XX-XX`, email — корректный адрес. Плюс логин должен быть **уникальным**: двух `ivanov` в системе быть не может. Для пароля в нашем проекте берём минимум 6 символов (точное правило всегда смотрите в ТЗ своего варианта).

**Пароли никогда не храним открытым текстом.** Если база «утечёт» (а базы утекают постоянно), злоумышленник получит пароли, которые люди используют и в почте, и в банке. Поэтому храним **хеш** — результат необратимого преобразования. В PHP для этого есть готовая пара функций:

```php
<?php
$hash = password_hash('secret123', PASSWORD_DEFAULT);
echo $hash;   // $2y$10$Qe8... (60 символов, каждый раз разный!)

var_dump(password_verify('secret123', $hash));  // bool(true)
var_dump(password_verify('secret124', $hash));  // bool(false)
```

Почему хеш каждый раз разный? `password_hash` сам добавляет случайную «соль» и записывает её внутрь хеша. Поэтому:

- **нельзя** проверять пароль так: `WHERE password_hash = '" . password_hash($pass) . "'` — хеши не совпадут никогда;
- **правильно**: достать хеш по логину и сравнить через `password_verify()` (ЛР25).

И забудьте про `md5()` и `sha1()` для паролей — они быстрые, а значит, перебираются за минуты. На экзамене хранение пароля открытым текстом или в `md5` — прямая потеря баллов по безопасности.

**Подготовленные запросы.** Данные пользователя **никогда** не вклеиваем в текст SQL. Вместо значений ставим знаки `?`, а значения передаём отдельно в `execute()`:

```php
<?php
// ПЛОХО — SQL-инъекция (подробно в ПР19):
// $pdo->query("SELECT id FROM users WHERE login = '$login'");

// ХОРОШО:
$stmt = $pdo->prepare('SELECT id FROM users WHERE login = ?');
$stmt->execute([$login]);
$exists = $stmt->fetch();   // массив или false
```

**Проверка уникальности: два уровня.** Первый уровень — запрос «есть ли такой логин» перед вставкой, чтобы показать понятную ошибку. Второй — индекс `UNIQUE` на столбце `login` в базе. Он страхует от ситуации, когда два человека одновременно регистрируют один логин: проверку прошли оба, но вставит MySQL только одного, а второму выдаст ошибку с кодом 1062 (Duplicate entry). Её мы ловим и превращаем в обычное сообщение.

**Порядок работы страницы:**

1. Если пользователь уже вошёл — регистрация ему не нужна, отправляем на главную.
2. Если пришёл POST — читаем поля, проверяем, при отсутствии ошибок проверяем логин в базе, хешируем пароль, вставляем строку, делаем редирект на вход.
3. Показываем форму (с ошибками и старыми значениями, если они есть).

**Полный файл `register.php`:**

```php
<?php
require_once __DIR__ . '/includes/auth.php';

if (current_user() !== null) {
    redirect('index.php');
}

$errors = [];
$old = ['fio' => '', 'phone' => '', 'email' => '', 'login' => ''];

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    foreach (array_keys($old) as $field) {
        $old[$field] = post($field);
    }
    $password = post('password');

    // 1. Проверка полей
    if (!preg_match('/^[А-ЯЁа-яё\s-]+$/u', $old['fio'])) {
        $errors['fio'] = 'ФИО: только кириллица, пробелы и дефис';
    }
    if (!preg_match('/^\+7\(\d{3}\)-\d{3}-\d{2}-\d{2}$/', $old['phone'])) {
        $errors['phone'] = 'Телефон в формате +7(XXX)-XXX-XX-XX';
    }
    if (!filter_var($old['email'], FILTER_VALIDATE_EMAIL)) {
        $errors['email'] = 'Укажите корректный email';
    }
    if (mb_strlen($old['login']) < 6 || preg_match('/\s/u', $old['login'])) {
        $errors['login'] = 'Логин — не короче 6 символов, без пробелов';
    }
    if (mb_strlen($password) < 6) {
        $errors['password'] = 'Пароль — не короче 6 символов';
    }

    // 2. Уникальность логина
    if (!isset($errors['login'])) {
        $stmt = $pdo->prepare('SELECT id FROM users WHERE login = ?');
        $stmt->execute([$old['login']]);
        if ($stmt->fetch()) {
            $errors['login'] = 'Такой логин уже занят';
        }
    }

    // 3. Сохранение
    if (!$errors) {
        try {
            $stmt = $pdo->prepare(
                'INSERT INTO users (fio, phone, email, login, password_hash, role)
                 VALUES (?, ?, ?, ?, ?, ?)'
            );
            $stmt->execute([
                $old['fio'],
                $old['phone'],
                $old['email'],
                $old['login'],
                password_hash($password, PASSWORD_DEFAULT),
                'user',
            ]);
            redirect('login.php?registered=1');   // PRG
        } catch (PDOException $ex) {
            if (($ex->errorInfo[1] ?? 0) === 1062) {   // нарушен UNIQUE
                $errors['login'] = 'Такой логин уже занят';
            } else {
                throw $ex;
            }
        }
    }
}

$title = 'Регистрация';
require __DIR__ . '/includes/header.php';

// Небольшой помощник, чтобы не повторять один и тот же код для 5 полей
function field(string $name, string $label, string $type, array $old, array $errors, string $hint = ''): void
{
    $invalid = isset($errors[$name]) ? ' is-invalid' : '';
    $value = $type === 'password' ? '' : ($old[$name] ?? '');
    echo '<div class="mb-3">';
    echo '<label class="form-label" for="' . e($name) . '">' . e($label) . '</label>';
    echo '<input class="form-control' . $invalid . '" type="' . e($type) . '" id="' . e($name)
        . '" name="' . e($name) . '" value="' . e($value) . '" placeholder="' . e($hint) . '" required>';
    if ($invalid) {
        echo '<div class="invalid-feedback">' . e($errors[$name]) . '</div>';
    }
    echo '</div>';
}
?>
<div class="row justify-content-center">
    <div class="col-md-6 col-lg-5">
        <h1 class="h3 mb-3">Регистрация</h1>
        <form method="post" action="register.php">
            <?php
            field('fio', 'ФИО', 'text', $old, $errors, 'Иванов Иван Иванович');
            field('phone', 'Телефон', 'tel', $old, $errors, '+7(900)-123-45-67');
            field('email', 'Email', 'email', $old, $errors, 'name@mail.ru');
            field('login', 'Логин', 'text', $old, $errors, 'не короче 6 символов');
            field('password', 'Пароль', 'password', $old, $errors, 'не короче 6 символов');
            ?>
            <button class="btn btn-primary w-100" type="submit">Зарегистрироваться</button>
        </form>
        <p class="mt-3 text-center">Уже есть аккаунт? <a href="login.php">Войти</a></p>
    </div>
</div>
<?php require __DIR__ . '/includes/footer.php'; ?>
```

Разберём неочевидные места.

- `foreach (array_keys($old) ...)` — читаем четыре поля одним циклом, а не четырьмя одинаковыми строками.
- Роль `'user'` задаём **на сервере**. Никогда не берите роль из формы: иначе любой допишет в DevTools `<input name="role" value="admin">`.
- Функция `field()` выводит поле с подписью, ошибкой и старым значением. Пароль обратно в форму не подставляется.
- `throw $ex` — если ошибка не про дубликат логина, мы её не «глотаем», а пропускаем дальше: так в режиме разработки вы её увидите.
- Редирект ведёт на `login.php?registered=1`. В ЛР25 страница входа покажет по этому параметру «Регистрация прошла успешно, войдите».

**Как проверить, что всё сохранилось.** Откройте таблицу `users` в phpMyAdmin. В столбце `password_hash` должна быть строка вида `$2y$10$...` длиной 60 символов. Если там ваш пароль открытым текстом — вы забыли `password_hash()`. Если хеш обрезан — поле короче 255 символов.

**Типичные ошибки.**

- `SQLSTATE[HY093]: Invalid parameter number` — количество `?` не совпадает с количеством значений в `execute()`.
- `SQLSTATE[42S22]: Column not found: Unknown column 'pasword_hash'` — опечатка в имени столбца; сверяйтесь со структурой таблицы.
- `SQLSTATE[23000]: Integrity constraint violation: 1062 Duplicate entry` — сработал `UNIQUE`; значит, не сработала проверка перед вставкой.
- ФИО «Иванов Иван» не проходит проверку — забыт `/u` или файл сохранён не в UTF-8.
- Телефон не проходит — в шаблоне не экранированы `+`, `(`, `)`: в регулярках это спецсимволы, нужно `\+7\(`.

**Безопасность.** Пароль — только `password_hash`. Все запросы — подготовленные. Роль — с сервера. Все значения в форме — через `e()`. Проверки — на сервере, даже если в HTML есть `required`.

**Связь с экзаменом.** Регистрация — первая функция, которую проверяет экзаменатор: он попробует зарегистрироваться с ошибками (короткий логин, латинское ФИО, телефон без скобок), потом с занятым логином, потом правильно. Каждая проверка, которая «пропускает» плохие данные, — потерянные баллы.
