## Лекция

**phpMyAdmin — это «проводник» для базы данных.** Писать всё руками в консоли можно, но на экзамене у вас 210 минут на всё, и удобнее пользоваться тем, что уже стоит в XAMPP. phpMyAdmin — веб-интерфейс к MySQL: открывается по адресу `http://localhost/phpmyadmin`, показывает базы слева, а справа — вкладки для работы с выбранной базой или таблицей. Любое действие мышкой phpMyAdmin превращает в SQL-запрос и показывает его вам сверху зелёным блоком. Это лучший учебник: создали таблицу формой — посмотрели, какой `CREATE TABLE` получился.

**Главные вкладки, которые понадобятся:**

| Вкладка | Где | Зачем |
|---|---|---|
| Базы данных | главная страница | создать базу |
| Структура | база или таблица | список таблиц / столбцов, кнопки «Изменить», «Удалить», «Индекс» |
| SQL | база или таблица | выполнить любой запрос |
| Обзор | таблица | посмотреть строки |
| Вставить | таблица | добавить строку формой |
| Импорт / Экспорт | база | загрузить / выгрузить `.sql` или `.csv` |
| Связи (Relation view) | таблица → Структура | настроить внешние ключи |
| Дизайнер | база → Ещё | схема базы в виде диаграммы |

**От ER-диаграммы к таблицам.** В ЛР3 вы нарисовали ER-диаграмму своего портала в draw.io. Теперь переводим её «один в один» по правилам:

1. **Каждая сущность → таблица.** Название — латиницей, во множественном числе, маленькими буквами: `users`, `services`, `requests`. Никаких пробелов, русских букв и слов вроде `order` (это зарезервированное слово SQL — придётся всё время брать его в обратные кавычки).
2. **Каждый атрибут → столбец** с типом из ПР13.
3. **У каждой таблицы — `id`**: `INT UNSIGNED`, первичный ключ, `AUTO_INCREMENT` (в phpMyAdmin галочка **A_I**).
4. **Связь 1:N → внешний ключ на стороне N.** Пользователь 1 — заявки N, значит в `requests` появляется `user_id`. Имя по шаблону `<таблица_в_ед_числе>_id`.
5. **Связь M:N → отдельная таблица-связка.** Если в одной заявке может быть несколько услуг (бывает в вариантах «курсы», «ремонт»), делаем `request_services (request_id, service_id)`.
6. **Справочник — всё, что выбирают из списка**: услуги, статусы, способы оплаты, типы техники, залы. Это отдельные таблицы, а в заявке — только их `id`.

**Создание базы мышкой.** Главная → «Базы данных» → имя `portal` (или как велит ТЗ варианта) → в выпадающем списке сравнения выбрать `utf8mb4_unicode_ci` → «Создать». Проверка: база → «Операции» → внизу «Сравнение» должно быть `utf8mb4_unicode_ci`. Если ошиблись — там же можно изменить, поставив галочку «Изменить сравнение всех таблиц».

**Создание таблицы формой.** В базе: «Создать таблицу» → имя → число столбцов → «Вперёд». Откроется форма, где одна строка — один столбец. Поля формы:

- **Имя** — `login`;
- **Тип** — `VARCHAR`;
- **Длина/Значения** — `50`. Для `ENUM` тут пишут список: `'user','admin'`;
- **По умолчанию** — «Как определено:» и значение (`user`), либо `CURRENT_TIMESTAMP` для даты создания;
- **Атрибуты** — `UNSIGNED` для всех `id` и `..._id`;
- **Null** — галочку ставим только там, где значение может отсутствовать (причина отмены);
- **Индекс** — `PRIMARY` для `id`, `UNIQUE` для логина;
- **A_I** — автоинкремент, только у `id`.

Внизу формы: «Подсистема хранения» = `InnoDB`, «Сравнение» = `utf8mb4_unicode_ci`. Нажимаете «Сохранить» — и сверху видите получившийся `CREATE TABLE`. Скопируйте его себе в файл: на экзамене готовые скрипты экономят время.

**Внешние ключи в phpMyAdmin.** Связи настраиваются у дочерней таблицы: `requests` → «Структура» → ссылка **«Связи»** (Relation view; в старых версиях — «Просмотр связей»). Для каждого внешнего ключа:

1. «Имя ограничения» — `fk_requests_user`;
2. «Столбец» — `user_id`;
3. «Ссылка на» — база `portal`, таблица `users`, столбец `id`;
4. `ON DELETE` — `CASCADE`, `ON UPDATE` — `CASCADE`;
5. «Сохранить».

Если phpMyAdmin выдал ошибку `#1005 … errno: 150` или в списке «Ссылка на» нет нужного столбца, проверьте по чек-листу: обе таблицы InnoDB; типы одинаковые, включая `UNSIGNED`; в дочерней таблице нет «висячих» значений (например, `user_id = 99`, а пользователя 99 нет); родительский столбец — первичный ключ.

Тот же результат одной командой на вкладке SQL:

```sql
ALTER TABLE requests
    ADD CONSTRAINT fk_requests_user FOREIGN KEY (user_id)
    REFERENCES users (id) ON DELETE CASCADE ON UPDATE CASCADE;
```

**Как проверить, что связи работают.** Проще всего — попробовать их сломать:

```sql
-- должна быть ошибка #1452: пользователя 999 не существует
INSERT INTO requests (user_id, service_id, payment_type_id, address, contact_phone, service_date, service_time)
VALUES (999, 1, 1, 'ул. Тестовая, 1', '+7(900)-000-00-01', '2026-11-01', '10:00:00');
```

Если вставка прошла без ошибки — внешнего ключа нет, и эксперт это увидит.

Вторая проверка — «Дизайнер»: база → «Ещё» → «Дизайнер». Таблицы, соединённые линиями, — связи есть. Таблица «висит» отдельно — связь забыли.

**Администратор.** По ТЗ экзамена в системе должен быть администратор с логином `adminka` и паролем `password`. Роль храним в `users.role` (`ENUM('user','admin')`). Саму запись администратора с хешем пароля добавим в ЛР18 — в БД пароль никогда не хранится открытым текстом.

**Типичные ошибки в ЛР:**

1. База создана со сравнением `latin1_swedish_ci` (по умолчанию в некоторых сборках XAMPP) — в ЛР18 русские ФИО превратятся в `????`.
2. Таблица создана как MyISAM — вкладка «Связи» не даёт добавить внешний ключ.
3. Забыли галочку `A_I` у `id` — при вставке ошибка «Field 'id' doesn't have a default value».
4. `user_id` создан как `INT`, а `users.id` — как `INT UNSIGNED`.
5. Названия столбцов вперемешку: `UserID`, `user_id`, `idUser`. Выберите стиль `snake_case` и держитесь его — в PHP потом писать именно эти имена.
6. Статусы заведены как `ENUM` в заявке, хотя админка должна их выбирать из списка и, возможно, пополнять. Для портала заявок справочная таблица надёжнее.

**Связь с экзаменом.** Создание БД — первое, что делается в задании 1, на это стоит закладывать не больше 20 минут. Аспекты «разработка модулей ИС по ТЗ» и «безопасность ИС» начинаются здесь: уникальный логин, связанные таблицы, отдельное поле для хеша пароля. А в задании 3 по этой базе строится диаграмма, так что чистая структура сразу превращается в чистую картинку.

**Цель:** создать в phpMyAdmin базу своего варианта портала по собственной ER-диаграмме из ЛР3, со всеми ключами и связями.

| Таблица | Обязательные поля |
|---|---|
| `users` | `id`, `login` (UNIQUE), `password` (255), `full_name`, `phone`, `email`, `role`, `created_at` |

| `requests` | `id`, `user_id`, `service_id`, `status_id` (DEFAULT 1), `payment_type_id`, поля вашего варианта (адрес, дата, время, кол-во гостей и т. п.), `cancel_reason` (NULL), `created_at` |

**Ход работы:**

1. Откройте ER-диаграмму из ЛР3. Подпишите на ней карандашом (или в комментарии draw.io) тип каждого атрибута. Если какая-то связь M:N — нарисуйте таблицу-связку.
2. Создайте базу `portal_<фамилия>` (латиницей) со сравнением `utf8mb4_unicode_ci`.
3. **Мышкой** через формы phpMyAdmin создайте справочники: `statuses`, `payment_types`, `services` (или аналог). После каждой таблицы скопируйте показанный SQL в файл `lr17.sql`.
4. Создайте мышкой `users`. Проверьте: `login` — `UNIQUE`, `role` — `ENUM('user','admin')` с умолчанием `user`, `created_at` — умолчание `CURRENT_TIMESTAMP`.
5. Создайте `requests` с полями своего варианта. Все `..._id` — `INT UNSIGNED NOT NULL`, у `status_id` умолчание `1`, `cancel_reason` — `TEXT` с галочкой `Null`.
6. Через «Структура» → «Связи» создайте внешние ключи `requests` → `users` (CASCADE), → `services`, → `statuses`, → `payment_types` (RESTRICT). Скопируйте SQL в `lr17.sql`.
7. Проверьте связи: выполните «ломающий» `INSERT` с `user_id = 999` из лекции. Скриншот ошибки `#1452` — в отчёт.
8. Откройте «Дизайнер», расставьте таблицы так, чтобы линии не пересекались, сделайте скриншот.
9. Финальная проверка: удалите базу (база → «Операции» → «Удалить базу данных»), создайте её заново пустой и выполните ваш `lr17.sql` целиком на вкладке SQL. Если всё создалось без ошибок — скрипт годится для экзамена-тренировки.
10. Закоммитьте `lr17.sql` в репозиторий проекта (папка `db/`).
