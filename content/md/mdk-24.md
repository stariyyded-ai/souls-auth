## Коротко о теории

- **Mobile first**: обычные правила CSS — для телефона. Широкие экраны **добавляются** в `@media (min-width: …)` в конце файла.
- Точки перелома курса: **360px** (телефон), **768px** (планшет), **1280px** (компьютер). Медиазапросы идут по возрастанию: сначала 768, потом 1280.
- Внутри медиазапроса пишем **только то, что меняется**. Цвета, шрифты, скругления уже есть в базовых правилах, повторять их не нужно.
- Главные причины горизонтальной прокрутки: фиксированная ширина (`width: 960px`), картинка шире экрана, колонки в пикселях, длинное слово без пробелов, ряд flex-элементов без переноса.
- Резиновая картинка: `max-width: 100%; height: auto;`. Контейнер: `max-width` вместо `width` и `margin: 0 auto`.
- Новое свойство на сегодня: `overflow-wrap: anywhere`. Оно разрешает браузеру перенести длинное «слово» без пробелов (адрес почты, ссылку) в любом месте, а не выталкивать его за край экрана.

### Шаг 1. Находим, что сломано

Откройте задание «Шапка и первый экран на телефоне». В нём верх страницы из прошлой работы, только меню стало длиннее — пять пунктов. Нажмите «Проверить»: проверки с пометкой «телефон 360px» покраснеют.

Найдите в CSS все причины поломки. Это хорошая привычка: сначала **прочитать** CSS и выписать, что не влезет в 360px, потом исправлять:

- `.container { width: 960px; }` — страница всегда шириной 960px, даже на телефоне;
- шапка в строку — пять пунктов меню и логотип не помещаются в 312px;
- `font-size: 48px` у заголовка — на телефоне по два слова в строке;
- `padding: 64px 48px` у первого экрана — на телефоне съедает треть ширины.

### Шаг 2. Шапка и первый экран (задание 1)

Перестраиваем CSS по принципу mobile first. Базовые правила превращаем в телефонные:

```css
.container {
  max-width: 1200px; /* не шире 1200px, но и не шире экрана */
  margin: 0 auto;
}
.header {
  display: flex;
  flex-direction: column;  /* логотип над меню */
  align-items: flex-start;
  gap: 12px;
}
.menu {
  display: flex;
  flex-wrap: wrap;         /* пункты переносятся */
  gap: 8px 16px;
}
.hero h1 { font-size: 30px; }
.btn {
  display: block;          /* во всю ширину */
  text-align: center;
}
```

А всё, что было «компьютерным», переносим в медиазапрос в самом конце CSS:

```css
@media (min-width: 768px) {
  .header {
    flex-direction: row;
    justify-content: space-between;
    align-items: center;
  }
  .hero h1 { font-size: 48px; }
  .btn { display: inline-block; }
}
```

Частая ошибка: написать медиазапрос **в начале** CSS. Тогда базовые правила ниже перекроют его, и на компьютере всё останется телефонным. Медиазапросы — всегда после обычных правил.

Нажмите «Проверить». Если не проходит «нет горизонтальной прокрутки», ищите, какой блок шире экрана: в предпросмотре сузьте окно и посмотрите, что вылезает справа.

### Шаг 3. Преимущества и меню (задание 2)

Откройте задание «Преимущества и меню на трёх экранах». Здесь три состояния, а не два, поэтому медиазапросов будет два:

```css
/* Телефон */
.features__list { flex-direction: column; }
.catalog__grid { grid-template-columns: 1fr; }

/* Планшет */
@media (min-width: 768px) {
  .features__list { flex-direction: row; }
  .catalog__grid { grid-template-columns: repeat(2, 1fr); }
}

/* Компьютер */
@media (min-width: 1280px) {
  .catalog__grid { grid-template-columns: repeat(3, 1fr); }
}
```

Обратите внимание: в медиазапросе на 1280px нет преимуществ. Они уже в ряд с 768px, и это правило продолжает работать на всех более широких экранах. Это и есть сила `min-width`: правила **накапливаются** снизу вверх.

Сайт курса проверяет страницу на 1024px — это между планшетом и компьютером, поэтому там должно быть две колонки меню. Три колонки сайт проверяет по тексту CSS.

Частая ошибка: поменять местами медиазапросы — сначала 1280, потом 768. На экране 1400px сработают оба, но нижний (768) перекроет верхний, и меню останется в две колонки.

### Шаг 4. Картинка, почта и подвал (задание 3)

Откройте задание «Картинка, длинная почта и подвал». Здесь три последние причины прокрутки:

1. Картинка шириной 600px. Удалите `width` и `height` из CSS, напишите `max-width: 100%; height: auto;`. Атрибуты `width` и `height` в HTML оставьте: по ним браузер заранее знает пропорции картинки и не «прыгает», пока она грузится.
2. Колонки `600px 1fr` у блока «О нас». В базовых стилях колонок нет (картинка над текстом), а `1fr 1fr` — в медиазапросе на 768px.
3. Адрес почты `zakazy.kofeyni.zerno.kolledzh@example.ru` — одно длинное слово. Его спасает `overflow-wrap: anywhere`.

Подвал на телефоне — flex-столбик (`flex-direction: column`), в медиазапросе — снова строка с `justify-content: space-between`.

### Шаг 5. Проверяем в браузере

1. Перенесите изменения из трёх заданий в `css/style.css` вашей папки `zerno`. Удобно сделать так: сначала все базовые правила, в самом конце — `@media (min-width: 768px)`, за ним — `@media (min-width: 1280px)`. Одинаковые медиазапросы из разных заданий объедините в один.
2. Откройте страницу через Live Server, нажмите F12, включите режим устройства (значок телефона с планшетом).
3. Проверьте ширины 360, 768 и 1280. На каждой: нет ли полосы прокрутки внизу, всё ли читается, не налезают ли блоки.
4. Протяните ширину плавно от 360 до 1400 — страница не должна «ломаться» и между точками перелома.
5. Покажите преподавателю страницу на трёх ширинах.
