## Лекция

**Проблема.** Пользователь придумал логин `ivanov`, заполнил ещё шесть полей, нажал «Зарегистрироваться» — и сервер ответил: «Логин занят». Обидно. А что если спросить сервер о логине прямо в момент, когда человек ушёл с поля, и не перезагружать страницу? Для этого в браузере есть функция `fetch`.

**Как это устроено.** Обычная форма: браузер отправляет запрос → сервер возвращает *целую новую страницу* → браузер её перерисовывает. С `fetch` иначе: JS сам отправляет маленький запрос → сервер возвращает *только данные* → JS сам решает, что поменять на странице. Страница остаётся на месте, введённое не стирается. Раньше этот подход называли AJAX, суть та же.

**JSON — язык, на котором говорят JS и PHP.** Данные удобно передавать в формате JSON (JavaScript Object Notation). Выглядит как объект JS, но это просто текст:

```json
{ "login": "ivanov", "free": false, "message": "Логин уже занят" }
```

Правила JSON строже, чем у объектов JS: ключи только в двойных кавычках, строки только в двойных кавычках, нет запятой после последнего элемента, нет комментариев.

Переводы туда-обратно:

```js
const obj = { login: 'ivanov', free: true };
const text = JSON.stringify(obj);   // объект → строка '{"login":"ivanov","free":true}'
const back = JSON.parse(text);      // строка → объект
console.log(back.free);             // true
```

В PHP то же самое: `json_encode($array)` превращает массив в JSON-строку, `json_decode($text, true)` — строку в ассоциативный массив (второй аргумент `true` важен, иначе получишь объект).

**Асинхронность: почему нельзя просто `const answer = fetch(...)`.** Запрос к серверу занимает время — от миллисекунд до секунд. JS не ждёт и не замораживает страницу: `fetch` сразу возвращает **Promise** («обещание», что ответ будет потом). Чтобы дождаться ответа, используем `async`/`await`:

```js
async function getHello() {
  const response = await fetch('hello.php');  // ждём ответ сервера
  const data = await response.json();         // ждём, пока тело разберётся из JSON
  console.log(data);
}
getHello();
```

`await` работает только внутри функции, помеченной `async`. Два `await` подряд — не опечатка: сначала приходят заголовки ответа, потом тело.

**Проверка статуса ответа.** `fetch` не считает ошибкой ответ 404 или 500 — он падает только если сети нет вообще. Поэтому проверяем `response.ok` (true для кодов 200–299):

```js
const response = await fetch('check_login.php?login=ivanov');
if (!response.ok) {
  throw new Error(`Сервер ответил ${response.status}`);
}
const data = await response.json();
```

А ошибки сети и `throw` ловим через `try/catch`:

```js
try {
  // ... fetch ...
} catch (err) {
  console.error(err);
  hint.textContent = 'Не удалось проверить логин, попробуйте позже';
}
```

**Серверная часть: `check_login.php`.** Маленький PHP-скрипт, который не рисует HTML, а отвечает JSON:

```php
<?php
// check_login.php — отвечает, свободен ли логин
require_once 'db.php';                       // $pdo из ЛР23
header('Content-Type: application/json; charset=utf-8');

$login = trim($_GET['login'] ?? '');

if (mb_strlen($login) < 6) {
    echo json_encode(['free' => false, 'message' => 'Логин — не менее 6 символов'], JSON_UNESCAPED_UNICODE);
    exit;
}

$stmt = $pdo->prepare('SELECT COUNT(*) FROM users WHERE login = ?');
$stmt->execute([$login]);
$taken = $stmt->fetchColumn() > 0;

echo json_encode([
    'free'    => !$taken,
    'message' => $taken ? 'Логин уже занят' : 'Логин свободен',
], JSON_UNESCAPED_UNICODE);
```

Разбор:
- `header('Content-Type: application/json')` — говорим браузеру, что это JSON, а не HTML.
- `prepare` + `execute([$login])` — prepared statement из ПР19. Логин приходит из адресной строки, его может прислать кто угодно; склеивать его с SQL нельзя.
- `JSON_UNESCAPED_UNICODE` — чтобы русский текст пришёл буквами, а не `Л...` (JS понял бы и так, но в DevTools читать удобнее).
- Никаких `echo` HTML и пробелов до `<?php`: любой лишний символ испортит JSON, и `response.json()` упадёт с ошибкой «Unexpected token».

Открой в браузере `http://localhost/портал/check_login.php?login=adminka` — увидишь сырой JSON. Так удобно отлаживать серверную часть отдельно от JS.

**Клиентская часть.**

```js
// js/check-login.js
const loginInput = document.querySelector('input[name="login"]');
const loginBox = document.getElementById('login-error');

async function checkLogin() {
  const login = loginInput.value.trim();
  if (login.length < 6) return;          // короткий — пусть ругается валидация из ЛР33

  try {
    const url = 'check_login.php?login=' + encodeURIComponent(login);
    const response = await fetch(url);
    if (!response.ok) throw new Error('HTTP ' + response.status);
    const data = await response.json();

    loginInput.classList.toggle('is-invalid', !data.free);
    loginInput.classList.toggle('is-valid', data.free);
    loginBox.textContent = data.free ? '' : data.message;
  } catch (err) {
    console.error(err);
    loginBox.textContent = 'Не удалось проверить логин';
  }
}

loginInput?.addEventListener('blur', checkLogin);
```

`encodeURIComponent` нужен, чтобы символы вроде `&`, `#`, пробела или кириллицы не сломали адрес. Без него логин `a&b=1` превратится в два параметра.

**Отправка JSON методом POST.** GET подходит для «спросить». Когда мы что-то меняем (а это будет в ЛР36), используют POST и передают тело:

```js
const response = await fetch('api.php', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ id: 15, status: 'done' }),
});
```

На стороне PHP JSON-тело читают не из `$_POST` (там будет пусто!), а так: `$data = json_decode(file_get_contents('php://input'), true);`. Об этом спотыкаются почти все — запомни.

**Где смотреть, что происходит.** DevTools → вкладка **Network** (Сеть). Каждый `fetch` виден строкой: адрес, статус, время. Клик по строке → вкладки *Headers* (что отправили), *Response* (что сервер ответил дословно). Если `response.json()` падает — смотри *Response*: там почти всегда PHP-предупреждение (`Warning: ...`) перед JSON.

**Не перестарайся.** Каждый `fetch` — это запрос к серверу и к базе. Если отправлять проверку на каждую нажатую клавишу, при наборе логина из 10 букв уйдёт 10 запросов, и ответы могут прийти в другом порядке, чем ушли: на экране окажется результат для старого значения. Поэтому в лекции проверка висит на `blur` — один запрос, когда человек закончил ввод. Вариант «проверять при вводе, но с паузой» — в задании для сильных.

**Типичные ошибки.**
- Забыли `await` → в `data` лежит Promise, а не объект; `data.free` — `undefined`.
- `await` вне `async`-функции → SyntaxError.
- PHP выводит предупреждение или пробел до JSON → «Unexpected token < in JSON».
- Читают `$_POST`, когда прислали JSON → пустой массив.
- Склеили логин с SQL-строкой → SQL-инъекция.
- Нет `try/catch` → при выключенном XAMPP страница молча ничего не делает.

**Связь с экзаменом.** Требование «уникальный логин» проверяется на сервере (задание 1), но в задании 3 оценивают удобство интерфейса и валидацию. Мгновенная подсказка «логин занят» — плюс к впечатлению эксперта, а сам приём `fetch` + JSON + prepared statement понадобится в ЛР36 для смены статуса заявки.
