## Коротко о теории

**Ссылка** — элемент `<a>`. Куда она ведёт, пишут в атрибуте `href`:

```html
<p><a href="about.html">Обо мне</a></p>
<p><a href="https://example.ru">Сайт колледжа</a></p>
```

Первая ссылка — **относительная**: браузер ищет файл `about.html` рядом с текущей страницей. Вторая — **абсолютная**: полный адрес с `https://`. Для своих страниц всегда пишем относительные пути: сайт тогда работает и на вашем компьютере, и на хостинге.

**Якорь** — ссылка на место внутри страницы. Нужны две части:

1. У цели есть атрибут `id` — уникальное имя: `<h2 id="contacts">Контакты</h2>`.
2. У ссылки в `href` стоит решётка и это имя: `<a href="#contacts">Контакты</a>`.

Нажали — браузер прокрутил страницу к заголовку. Решётка `#` пишется **только в ссылке**, в самом `id` её нет.

Правила для `id`, которые сберегут нервы:

- латинские буквы, цифры и дефис: `new-books`, `day-2`;
- без пробелов: `id="new books"` не сработает;
- регистр важен: `#Rules` и `rules` — разные имена;
- на странице `id` не повторяется.

**Меню** — это список ссылок. Пункты меню однотипны и идут по порядку, поэтому их размечают списком `ul`:

```html
<ul>
  <li><a href="index.html">Главная</a></li>
  <li><a href="skills.html">Навыки</a></li>
  <li><a href="contacts.html">Контакты</a></li>
</ul>
```

Пока меню выглядит как обычный список с точками. В горизонтальную полоску его превратит CSS на занятии 16. Сейчас важно другое: правильная разметка. Программа экранного чтения (её используют незрячие люди) объявит «список, три пункта», и человек сразу поймёт, сколько разделов на сайте.

Текст ссылки должен говорить, **куда** она ведёт. «Нажмите сюда» и «подробнее» — плохие ссылки: вырванные из текста, они ничего не значат.

## Ход работы

### Шаг 1. Папка сайта

Сайт из нескольких страниц — это папка с несколькими HTML-файлами. В VS Code откройте папку визитки (Файл → Открыть папку) и сделайте такую структуру:

```text
vizitka/
  index.html      ← главная: имя, фото, о себе
  skills.html     ← навыки
  schedule.html   ← расписание
  contacts.html   ← контакты
  404.html        ← страница «не найдено»
  img/
    photo.jpg
```

Новый файл создают кнопкой «New File» над списком файлов. Имена — латиницей, маленькими буквами, без пробелов. Почему так строго, разберём на занятии 35, а пока просто запомните: `Мои Навыки.html` — плохое имя, `skills.html` — хорошее.

Главная страница всегда называется `index.html`. Когда сайт выложат в интернет, сервер откроет её сам, если в адресе нет имени файла.

### Шаг 2. Каркас каждой страницы

Каждый HTML-файл — отдельная полноценная страница. Значит, в каждом нужен каркас из занятия 2: `<!DOCTYPE html>`, `html lang="ru"`, `head` с `meta charset` и `title`, `body`. Скопируйте каркас из `index.html` в остальные файлы и **поменяйте `title`**: «Навыки — Анна Смирнова», «Контакты — Анна Смирнова». Название вкладки браузера — первое, что видит человек с десятком открытых вкладок.

Перенесите содержимое визитки по страницам: список навыков — в `skills.html`, таблицу расписания — в `schedule.html`, контакты со ссылками `mailto:` и `tel:` — в `contacts.html`.

### Шаг 3. Одно меню на всех страницах

Вставьте меню сразу после `<body>` на **каждой** странице:

```html
<ul>
  <li><a href="index.html">Главная</a></li>
  <li><a href="skills.html">Навыки</a></li>
  <li><a href="schedule.html">Расписание</a></li>
  <li><a href="contacts.html">Контакты</a></li>
</ul>
<h1>Анна Смирнова</h1>
```

Пункты меню на всех страницах одинаковые и стоят в одном порядке. Если на одной странице «Контакты» вторые, а на другой — четвёртые, человек будет промахиваться.

Хороший приём: на текущей странице пункт меню помечают атрибутом `aria-current="page"` («это текущая страница»). Программа экранного чтения скажет «текущая страница», а позже через CSS мы выделим этот пункт цветом.

```html
<ul>
  <li><a href="index.html">Главная</a></li>
  <li><a href="skills.html" aria-current="page">Навыки</a></li>
  <li><a href="schedule.html">Расписание</a></li>
</ul>
```

### Шаг 4. Проверка переходов

Откройте `index.html` через Live Server (правая кнопка мыши → Open with Live Server). Пройдите по всем пунктам меню на всех страницах. Частые ошибки:

- **опечатка в имени файла**: `shedule.html` вместо `schedule.html` — браузер покажет «файл не найден»;
- **файл в другой папке**: если страница лежит в папке `pages/`, путь к ней — `pages/skills.html`, а обратно на главную — `../index.html`;
- **забыли сохранить файл** — Ctrl+S, белая точка на вкладке VS Code значит «не сохранено».

Ссылка может вести сразу на место на **другой** странице: имя файла плюс якорь.

```html
<p>Консультации — <a href="schedule.html#thursday">по четвергам</a>.</p>
```

Браузер откроет `schedule.html` и прокрутит её к элементу с `id="thursday"`.

### Шаг 5. Длинная страница с оглавлением — задание 1 на сайте

Бывает, что разделов мало и разносить их по файлам незачем. Тогда делают одну длинную страницу с оглавлением сверху. Каждому разделу — `id`, в оглавлении — ссылки на эти `id`.

В конце каждого раздела ставят ссылку «Наверх»: на телефоне длинную страницу листать вверх долго. Цель для неё — сам заголовок страницы:

```html
<h1 id="top">Анна Смирнова</h1>
<ul>
  <li><a href="#about">Обо мне</a></li>
  <li><a href="#contacts">Контакты</a></li>
</ul>
<h2 id="about">Обо мне</h2>
<p>Учусь на первом курсе. Люблю рисовать и разбираться, как всё устроено.</p>
<p><a href="#top">Наверх</a></p>
<h2 id="contacts">Контакты</h2>
<p><a href="mailto:anna@example.ru">anna@example.ru</a></p>
<p><a href="#top">Наверх</a></p>
```

Частая ошибка: `<a href="top">` без решётки. Браузер решит, что это файл `top` рядом со страницей, и покажет ошибку.

Сделайте **задание 1** на сайте: в нём уже есть длинная визитка, вам нужно добавить оглавление, `id` разделов и ссылки «Наверх».

### Шаг 6. Сломанная навигация — задание 2 на сайте

Чужие ошибки искать полезно: потом свои видны сразу. В **задании 2** — страница библиотеки колледжа, в которой ни одна ссылка меню не работает как надо. Проверяйте каждую пару «ссылка — `id`» по правилам из «Коротко о теории». Заодно вспомните занятие 3: ссылка с `target="_blank"` открывает новую вкладку и требует `rel="noopener"`.

### Шаг 7. Страница 404 — задание 3 на сайте

Если человек ошибся в адресе или ссылка устарела, сервер отвечает кодом **404** — «не найдено». Без своей страницы человек увидит серое «404 Not Found» и уйдёт. Хорошая страница 404:

- честно говорит, что страницы нет, без обвинений («Вы ввели неверный адрес!» — плохо);
- предлагает, куда пойти дальше: на главную и в основные разделы;
- даёт способ сообщить о сломанной ссылке, например почту;
- выглядит как часть сайта, а не как авария.

Когда сайт выложат на хостинг, файл `404.html` сервер будет показывать сам. Как это настраивается, разберём на занятии 26. Сделайте **задание 3** на сайте, а потом создайте такую же страницу `404.html` в папке визитки.
