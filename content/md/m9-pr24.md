## Лекция

**Что значит «опубликовать сайт».** Пока проект открывается по адресу `http://localhost/portal/`, его видите только вы: веб-сервер Apache и MySQL работают на вашем компьютере. Публикация (деплой) — это перенос трёх вещей на компьютер, который круглосуточно подключён к интернету:

1. **Файлы** проекта: `.php`, `.css`, `.js`, картинки, папка `uploads/`.
2. **База данных**: структура таблиц и данные (справочник услуг, учётка администратора).
3. **Настройки**: адрес БД, логин, пароль, режим вывода ошибок — на сервере они другие, чем в XAMPP.

Забыли любую из трёх частей — сайт не работает. Самая частая картина у новичков: файлы залили, а базу забыли, и на главной странице висит `SQLSTATE[HY000] [1049] Unknown database`.

**Где размещать.** Есть три типичных варианта:

- **Виртуальный хостинг** (Beget, Timeweb, Sprinthost, учебный сервер колледжа). Вам дают папку на общем сервере, панель управления, phpMyAdmin и FTP. Просто и дёшево (часто есть бесплатный тестовый период), но нет полного контроля: PHP-модули и версия выбираются в панели.
- **VPS** (виртуальный сервер). Вы получаете целую систему Linux с root-доступом по SSH и ставите Apache/Nginx, PHP и MySQL сами. Гибко, но требует навыков администрирования.
- **Учебный сервер колледжа** — обычно это Linux с Apache, где каждому студенту создан пользователь `st_ivanov` и база `st_ivanov_db`. На ЛР38 мы работаем именно так (или на бесплатном тарифе хостинга, если сервера нет).

Перед выбором проверьте главное: **PHP 8.x** (наш код использует 8.2), **MySQL/MariaDB**, расширение **pdo_mysql**, поддержка **utf8mb4**.

**Как передать файлы: FTP и SFTP.**

**FTP** (порт 21) — старый протокол передачи файлов. Логин и пароль идут по сети открытым текстом, поэтому в серьёзных проектах его заменяют. **SFTP** (порт 22) — передача файлов поверх SSH, всё зашифровано. Если хостинг предлагает оба — выбирайте SFTP. (Не путайте с FTPS — это FTP с TLS, тоже допустим.)

Клиент, которым пользуемся, — **FileZilla** (бесплатный, есть для Windows/Linux/macOS). Альтернативы: WinSCP (Windows), встроенное расширение VS Code «SFTP». Порядок работы в FileZilla:

1. *Файл → Менеджер сайтов → Новый сайт*.
2. Протокол: `SFTP – SSH File Transfer Protocol`; хост: `students.college.ru` (или выданный хостингом); порт `22`; тип входа «Нормальный»; пользователь и пароль из письма хостинга.
3. Подключиться. Слева — ваш компьютер, справа — сервер.
4. Справа откройте корневую папку сайта. У разных хостингов она называется по-разному: `public_html`, `www`, `htdocs`, `~/site.ru/public_html`. Если положить файлы на уровень выше — сайт покажет пустую страницу хостинга.
5. Слева выделите **содержимое** папки проекта (не саму папку, если хотите, чтобы сайт открывался по корню домена) и перетащите вправо.

Что **не** надо заливать: папку `.git`, файлы `.vscode`, дампы `*.sql` с паролями, `phpinfo.php` и тестовые скрипты. Если в проекте есть `.gitignore`, это хороший ориентир.

**SSH: работа с сервером из консоли.** SSH — защищённый удалённый терминал. В Windows 10/11 клиент уже встроен (PowerShell), также можно использовать PuTTY.

```bash
ssh st_ivanov@students.college.ru        # подключиться (спросит пароль)
pwd                                      # где я нахожусь
ls -la                                   # список файлов с правами
cd public_html                           # перейти в папку сайта
php -v                                   # какая версия PHP на сервере
mysql --version                          # есть ли клиент MySQL
exit                                     # выйти
```

Файлы можно передать и без FileZilla — командой `scp` (копирование через SSH) с вашего компьютера:

```bash
scp -r ./portal/* st_ivanov@students.college.ru:~/public_html/
scp portal_dump.sql st_ivanov@students.college.ru:~/
```

Вместо пароля удобнее SSH-ключ: `ssh-keygen -t ed25519` создаёт пару ключей, а `ssh-copy-id st_ivanov@students.college.ru` кладёт открытый ключ на сервер. После этого пароль больше не спрашивают.

Если проект лежит на GitHub, на сервере можно сделать `git clone https://github.com/ivanov/portal.git public_html` и потом обновлять одной командой `git pull`. Это самый аккуратный способ: на сервере ровно то, что в репозитории.

**Перенос базы данных.** Шаг 1 — сделать дамп на своём компьютере (вы это уже умеете с ЛР20). В phpMyAdmin XAMPP: выбрать базу → *Экспорт* → «Быстрый», формат SQL. Или из консоли XAMPP:

```bash
C:\xampp\mysql\bin\mysqldump -u root --default-character-set=utf8mb4 portal > portal_dump.sql
```

Перед экспортом проверьте две вещи. Первое: в дампе **не должно быть** строки `CREATE DATABASE portal` и `USE portal`, если на хостинге база называется иначе (`st_ivanov_db`) — иначе импорт упадёт с «Access denied». Второе: таблицы в `utf8mb4`, иначе кириллица превратится в «????».

Шаг 2 — создать базу на сервере. На хостинге это делается в панели («Базы данных MySQL → Создать»), там же задаются пользователь и пароль. На учебном сервере база обычно уже создана.

Шаг 3 — импортировать. Через **phpMyAdmin хостинга**: открыть базу → *Импорт* → выбрать файл → кодировка utf8 → *Вперёд*. Ограничение — размер файла (обычно 2–50 МБ), для учебного проекта этого хватает. Через **SSH**:

```bash
mysql -u st_ivanov -p st_ivanov_db < ~/portal_dump.sql
mysql -u st_ivanov -p st_ivanov_db -e "SHOW TABLES;"
```

Вторая команда сразу показывает, что таблицы на месте. Обязательно проверьте, что в таблице `users` есть администратор `adminka` с хешем пароля — без него админ-панель не открыть.

**Конфиг для сервера.** В ЛР23 вы вынесли настройки в `config.php`. Теперь это окупается: меняется только один файл.

```php
<?php
// config.php — версия для сервера
define('DB_HOST', 'localhost');      // на хостинге иногда другой, смотрите в панели
define('DB_NAME', 'st_ivanov_db');
define('DB_USER', 'st_ivanov');
define('DB_PASS', 'S3cr3t!pass');
define('BASE_URL', '/');             // было '/portal/' в XAMPP

ini_set('display_errors', '0');      // посетителям ошибки не показываем
ini_set('log_errors', '1');          // но пишем их в лог
error_reporting(E_ALL);
```

Хорошая практика — держать в Git файл `config.example.php` без паролей, а настоящий `config.php` добавить в `.gitignore`. Тогда пароль от боевой базы не окажется на GitHub. Проверьте также, нет ли в коде «зашитых» путей вида `http://localhost/portal/` — их нужно заменить на относительные или на `BASE_URL`.

**Права на файлы.** На Linux у каждого файла есть права для владельца, группы и остальных: чтение (r=4), запись (w=2), выполнение (x=1). Стандарт для сайта:

```bash
find ~/public_html -type d -exec chmod 755 {} \;   # папки: rwxr-xr-x
find ~/public_html -type f -exec chmod 644 {} \;   # файлы: rw-r--r--
chmod 600 ~/public_html/config.php                # конфиг читает только владелец (если сервер запускает PHP от вашего пользователя)
```

Папка `uploads/` (ЛР31) должна быть доступна веб-серверу на запись — обычно `755` хватает, если PHP работает от вашего пользователя; на некоторых серверах нужно `775`. **Никогда не ставьте 777** — так любой процесс на сервере может подменить ваши файлы. В FileZilla права меняются через ПКМ → «Права доступа к файлу».

Ещё одна ловушка Linux: **регистр имён файлов**. В Windows `Header.php` и `header.php` — один файл, на сервере — два разных. Если в коде `include 'Header.php'`, а файл называется `header.php`, локально всё работало, а на сервере — белый экран.

**Проверка после деплоя.** Деплой не закончен, пока вы не прошли сценарий руками. Мини-чек-лист:

1. Главная открывается по адресу без ошибок, стили и картинки подгрузились (DevTools → Network, нет красных 404).
2. Регистрация нового пользователя → запись появилась в БД.
3. Вход этим пользователем, создание заявки, заявка видна в истории.
4. Вход `adminka`/`password`, смена статуса, причина отмены.
5. Кириллица везде отображается нормально.
6. Попытка открыть `admin.php` без входа — редирект.
7. Мобильный вид в DevTools 390×844.

Если белый экран — смотрите лог ошибок: в панели хостинга раздел «Логи», на сервере `tail -n 30 ~/logs/error.log` (путь зависит от хостинга). Временно можно включить `display_errors = 1`, но не забудьте выключить. Типичные причины: неверные данные в `config.php`, не та версия PHP, регистр имён файлов, отсутствие таблиц.
