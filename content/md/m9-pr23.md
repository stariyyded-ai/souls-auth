## Лекция

**Почему «оптимизация» в названии экзаменационного модуля.** Задание 3 называется «Проектирование, разработка и *оптимизация*». Работающий сайт — это половина дела. Вторая половина — чтобы он быстро открывался на телефоне с плохим интернетом и им мог пользоваться любой человек, в том числе со слабым зрением или без мыши. Измерять это «на глаз» нельзя, нужен инструмент. Встроенный в Chrome инструмент называется **Lighthouse**.

**Lighthouse: как запустить.** DevTools (F12) → вкладка Lighthouse (если не видно — за значком `»`). Режим *Navigation*, устройство *Mobile*, категории: Performance, Accessibility, Best Practices, SEO. Нажми «Analyze page load». Через полминуты получишь четыре оценки от 0 до 100 и список проблем с объяснениями.

Советы, чтобы цифры были честными:
- запускай в окне инкогнито (Ctrl+Shift+N) — расширения браузера портят результат;
- запускай 2–3 раза, цифры немного «гуляют»;
- для страниц за логином (`requests.php`, `admin.php`) сначала войди в аккаунт в этом же окне.

**Главные метрики производительности (простыми словами).**

| Метрика | Что значит | Хорошо |
|---|---|---|
| LCP (Largest Contentful Paint) | когда показался самый большой элемент (картинка, заголовок) | до 2,5 с |
| CLS (Cumulative Layout Shift) | насколько «прыгает» страница при загрузке | до 0,1 |
| TBT (Total Blocking Time) | сколько времени JS «вешал» страницу | до 200 мс |

**Изображения — главный пожиратель скорости.** Типичная ситуация: студент вставляет фото услуги с телефона — 4000×3000 пикселей, 5 МБ, а показывает его в карточке шириной 350 px. Браузер качает 5 МБ ради картинки, которой хватило бы 40 КБ. Что делать:

1. **Уменьшить размер.** Картинка не должна быть шире, чем максимально показывается на экране × 2 (для чётких экранов). Для карточки 350 px — около 700 px.
2. **Современный формат.** WebP весит на 25–35% меньше JPEG при том же качестве. Сконвертировать можно в Squoosh (squoosh.app) или прямо из Figma.
3. **Указать размеры.** `width` и `height` у `<img>` позволяют браузеру заранее зарезервировать место — страница не прыгает (CLS).
4. **Ленивая загрузка.** `loading="lazy"` — картинка грузится, только когда до неё долистали. Для первой картинки на экране (логотип, баннер) lazy *не* ставим — она нужна сразу.

```html
<img src="img/cleaning.webp" alt="Уборка квартиры после ремонта"
     width="700" height="467" loading="lazy" decoding="async">
```

```css
img { max-width: 100%; height: auto; }  /* картинка не вылезет за экран и сохранит пропорции */
```

Если в ЛР31 пользователи загружают фото, на сервере можно уменьшать их через GD (`imagecreatefromjpeg`, `imagescale`, `imagewebp`), но это вариативная часть — минимум сделай для своих статичных картинок.

**JavaScript и CSS.** Скрипты без `defer` в `<head>` блокируют отрисовку: браузер ждёт, пока скачает и выполнит JS, а пользователь видит белый экран. Поэтому все наши скрипты — с `defer`. Ещё проверь:
- не подключены ли лишние библиотеки (jQuery «на всякий случай», полный Bootstrap JS, если ты используешь только сетку);
- нет ли ошибок в консоли — Lighthouse снижает Best Practices за каждую;
- `console.log` для отладки перед сдачей лучше убрать.

**Доступность (accessibility, a11y).** Сайтом должны пользоваться все. Lighthouse проверяет автоматически около 50 правил. Самые частые проблемы студенческих порталов:

1. **Поле без подписи.** Placeholder — не подпись: он исчезает при вводе, и программа чтения экрана может его не озвучить. У каждого поля должен быть `<label for="id">`.
   ```html
   <label for="phone">Телефон</label>
   <input id="phone" name="phone" type="tel" inputmode="tel" autocomplete="tel"
          aria-describedby="phone-error">
   <div id="phone-error" class="invalid-feedback"></div>
   ```
   `aria-describedby` связывает поле с текстом ошибки: незрячий пользователь услышит «Телефон, поле ввода, Телефон в формате +7(XXX)-XXX-XX-XX». Атрибут `autocomplete` позволяет браузеру подставить сохранённые данные — и это тоже критерий Lighthouse.
2. **Картинки без `alt`.** Содержательная картинка — описание в `alt`. Декоративная — пустой `alt=""`, чтобы её пропустили.
3. **Низкий контраст.** Светло-серый текст на белом — классика. Требование WCAG AA: 4,5:1 для обычного текста (ты разбирал это в ПР6). В DevTools: выдели элемент → в панели Styles кликни на квадратик цвета → там указан Contrast ratio с галочками.
4. **Кнопки-иконки без текста.** `<button>✕</button>` для программы чтения — «кнопка, знак умножения». Нужно `<button aria-label="Закрыть">✕</button>`.
5. **Нет `lang`.** `<html lang="ru">` — без него синтезатор речи читает русский текст английскими правилами.
6. **Клик по `div`.** Если повесил `click` на `<div>`, на него нельзя попасть клавишей Tab. Для действий — `<button>`, для переходов — `<a>`.
7. **Убран контур фокуса.** `outline: none` без замены — пользователь клавиатуры не видит, где он. Если не нравится стандартный — сделай свой: `:focus-visible { outline: 3px solid var(--color-primary); outline-offset: 2px; }`.

**Маленький JS-аудитор.** Lighthouse проверяет одну страницу. Быстро найти проблемы можно скриптом прямо в консоли:

```js
// вставь в консоль на любой странице портала
const report = [];
document.querySelectorAll('img:not([alt])').forEach((el) => report.push(['img без alt', el.src]));
document.querySelectorAll('img:not([width]), img:not([height])').forEach((el) => report.push(['img без размеров', el.src]));
document.querySelectorAll('input:not([type=hidden]), select, textarea').forEach((el) => {
  const hasLabel = (el.id && document.querySelector(`label[for="${el.id}"]`)) || el.closest('label') || el.getAttribute('aria-label');
  if (!hasLabel) report.push(['поле без label', el.name || el.outerHTML.slice(0, 60)]);
});
document.querySelectorAll('button').forEach((el) => {
  if (!el.textContent.trim() && !el.getAttribute('aria-label')) report.push(['кнопка без текста', el.outerHTML.slice(0, 60)]);
});
if (!document.documentElement.lang) report.push(['нет lang у <html>', '']);
console.table(report.length ? report : [['Проблем не найдено', '']]);
```

`console.table` выводит массив красивой таблицей. Скрипт ничего не меняет — только ищет.

**Проверка клавиатурой — 2 минуты, которые многое показывают.** Отложи мышь. Нажимай Tab по странице регистрации: видно ли, где фокус? Порядок логичный (сверху вниз)? Можно ли заполнить и отправить форму, открыть и закрыть модальное окно (Esc)? Если где-то застрял — это проблема доступности.

**Типичные ошибки.**
- «Оптимизировали» до 100 баллов, удалив половину контента. Цель — улучшить, не сломав.
- Lighthouse запущен в обычном окне с десятком расширений.
- `loading="lazy"` на логотипе в шапке — он загружается позже, LCP хуже.
- `alt="картинка"` или `alt="image1.jpg"` — формально есть, по смыслу нет.
- Убрали outline у всех элементов ради красоты.

**Связь с экзаменом.** Критерии КИМ включают «разработку веб-приложения по ТЗ» и «интерфейс по ТЗ», а модуль называется «… и оптимизация». Подписанные поля, читаемые ошибки, контраст, лёгкие картинки — это то, что отличает аккуратный интерфейс от «как-нибудь работает». Привычка запускать Lighthouse за 5 минут до сдачи ловит мелкие потери.
