# Как писать занятия курса МДК.08.01

Этот файл — правила для авторов уроков и заданий курса. План всех 55 занятий — в `content/mdk-08-01-plan.md`.
Образец, на который равняться: урок `content/lessons/mdk-01-web-html.md`, задания `content/tasks/k01.js`, решения `tools/solutions/k01.js`.

## Для кого пишем

Первый курс колледжа. Студенты **никогда не писали код**. Каждое новое слово объясняем при первом появлении. После курса — демонстрационный экзамен: дизайн в Figma (макет, стайлгайд) и вёрстка сайта (HTML, CSS, адаптив, немного JavaScript). Где тема пригодится на экзамене, говорим об этом одной фразой.

Стиль: на «вы», короткие предложения, живые примеры из жизни студента (колледж, библиотека, кафе, спортзал, запись к врачу, магазин). Без канцелярита и без «как известно». Термин — жирным при первом появлении. Английские названия тегов и свойств — в обратных кавычках: `margin`.

Обязательно: каждое правило с примером кода; после примера — что увидит студент. Типичные ошибки новичков называем прямо («частая ошибка: …»).

## Одно занятие = 2 часа

Студент должен быть занят все 120 минут: чтение и примеры, квиз, задания на сайте, итоги. Сумма в таблице «План занятия» = 120 минут, а время на задания в ней ≈ сумма поля `minutes` заданий.

- **Лекция:** теория 35–45 мин (текст 1800–3000 слов с примерами), квиз 8 вопросов (~10 мин), 2–3 задания на 45–60 мин, итоги 10 мин.
- **Практическая работа:** короткое напоминание теории, подробный ход работы по шагам, 2–3 задания на 70–90 мин (крупнее, чем в лекции), критерии оценки, контрольные вопросы, квиз 5 вопросов.

## Файл урока: `content/lessons/mdk-NN-slug.md`

```
---
id: mdk-07
module: mdk1
lesson: 7
session: 7
kind: practice
title: Практическая работа №2 (ч. 1). Страница-визитка на HTML
difficulty: Лёгкий
minutes: 120
tasks: [k0701, k0702, k0703]
---
```

- `id`, `module`, `lesson` (номер в теме), `session` (номер занятия 1–55), `title` — строго как в плане.
- `kind`: `lecture` или `practice`. `difficulty`: Лёгкий, Средний или Сложный. `minutes`: всегда 120.
- `tasks`: id заданий в порядке выполнения. Id задания: `k` + номер занятия из двух цифр + номер задания: `k0701`.

Текст урока — Markdown (GitHub-таблицы работают). Заголовок урока страница рисует сама, поэтому в тексте начинайте с `##`. Разделы лекции по порядку:

1. Вводная цитата: `> **Занятие N из 55 · лекция · 2 часа.** Что сегодня и зачем.`
2. `## План занятия` — таблица «Время | Что делаем».
3. Теория: несколько `##`-разделов с примерами. В 2–3 местах — блок `> **Попробуйте сами.** …` с маленьким действием в песочнице.
4. `## Главное за занятие` — 4–7 пунктов.
5. `## Словарик` — термины занятия.
6. `## Проверь себя` — 4–6 вопросов без ответов.
7. `## Если осталось время` — дополнительное задание для быстрых.
8. Квиз.

Разделы практической работы: вводная цитата (`· практическая работа №K ·`), `## Цель работы`, `## Что понадобится`, `## План занятия`, `## Коротко о теории`, `## Ход работы` (Шаг 1, Шаг 2… — подробно, что нажать и что написать; отметьте, какие шаги — задания на сайте), `## Задания на сайте` (список с пояснением порядка), `## Критерии оценки` (таблица «5 / 4 / 3»), `## Контрольные вопросы`, `## Если осталось время`, квиз.

Практики про Figma и проектирование: в «Ходе работы» описываем работу в Figma (фреймы, сетка, компоненты) — это студент делает и показывает преподавателю, а на сайте — задания, где то же самое делается в HTML/CSS и проверяется автоматически.

### Примеры кода

- ` ```html `, ` ```css `, ` ```js ` — с указанием языка.
- Под блоком ` ```html ` страница показывает кнопку «Попробовать»: код открывается в песочнице. Поэтому HTML-пример должен работать сам по себе. Если надо показать CSS или JS вживую, сделайте целый HTML-пример со `<style>` или `<script>` внутри.
- Отдельные ` ```css ` и ` ```js ` блоки — для чтения, без кнопки.
- Не используйте внешние картинки и шрифты по ссылкам. Картинки: `img/art.svg` (пейзаж 300×150), `img/icon.svg` (иконка). Можно добавить свою маленькую SVG в `img/course/` (до 5 КБ, без скриптов).

### Квиз

Блок в конце файла:

```
:::quiz
? Вопрос (можно `код`)
- [ ] неверный вариант
- [x] верный вариант
- [ ] неверный вариант
> Пояснение: почему так. Его увидят после ответа.
:::
```

Лекция — 8 вопросов, практика — 5. 3–4 варианта, один верный, верный стоит в разных позициях. Без «все варианты верны». Вопросы проверяют понимание, а не память на мелочи.

## Файл заданий: `content/tasks/kNN.js`

```js
/* Занятие 7. Страница-визитка на HTML */
(() => {
  const { BASE, IMG, ICON, rgb, near } = window.COURSE_KIT;
  window.COURSE_TASKS.push(
    {
      id: 'k0701', lesson: 'mdk-07', module: 'mdk1', mech: 'build',
      title: 'Шапка визитки', level: 'Лёгкое', minutes: 25, points: 120,
      story: 'Одно-два предложения: зачем это нужно, живая ситуация.',
      goal: 'Точное условие. Каждое требование из tests должно быть здесь названо.',
      hints: ['первая подсказка — направление', 'вторая — конкретнее', 'третья — почти ответ'],
      html: `шаблон HTML`,
      css: `${BASE}\nшаблон CSS`,
      tests: [
        { name: 'Требование как пункт чек-листа', check: h => условие || 'что не так, коротко' }
      ]
    }
  );
})();
```

- `mech`: `build` — сделай сам (основной), `fix` — почини, `optimize` — сократи код, `adaptive` — адаптив под 360px, `a11y` — доступность. 
- `level`: Лёгкое / Среднее / Сложное. `points`: 100 / 150 / 200 по сложности. `minutes`: честная норма для новичка.
- `hints`: 2–4 подсказки, от общей к конкретной. Студент открывает их по одной.
- `BASE` — светлая страница: `body { margin: 0; padding: 24px; font-family: Arial, sans-serif; color: #222222; background: #ffffff; }`.
- HTML студента вставляется внутрь `<body>`. Если задание про структуру документа (doctype, head, title), проверяйте сырой текст кода: `h.html` — строка с HTML студента.
- Задание с JavaScript: добавьте поле `js` (шаблон, можно `''`), тогда в редакторе появится вкладка script.js.

### Проверки

Обычная проверка `{ name, check: h => true | 'причина' }` получает помощника `h` для страницы 1024px (`at: 360` — для телефона 360px):

- `h.$(sel)`, `h.$$(sel)` (массив), `h.count(sel)`, `h.text(sel)` (текст без лишних пробелов)
- `h.cs(sel, 'color')` — вычисленный стиль строкой (цвет — `rgb(…)`, сравнивайте с `rgb('#hex')`), `h.px(sel, 'font-size')` — число
- `h.rect(sel)`, `h.sameRow([элементы])`, `h.before(a, b)`, `h.inside(a, b)`, `h.overflow()` — есть ли горизонтальная прокрутка
- `h.contrast(sel)` — контраст текста, `h.rules` — CSS-правила `{ selector, style, media }`, `h.has(/регэксп/)` — есть ли в CSS
- `h.html`, `h.css`, `h.js` — исходный код строкой; `h.doc`, `h.win` — документ и окно

Проверка JavaScript: `{ name, js: true, check: async h => … }`. Она выполняется **внутри** страницы студента, на свежезагруженной странице для каждой проверки. Функция передаётся как текст, поэтому **не может использовать ничего снаружи** (ни `rgb`, ни `near`, ни переменные файла) — только `h` и встроенное в браузер. Помощник:

- `h.$`, `h.$$`, `h.count`, `h.text`, `h.cs`, `h.px`, `h.visible(sel)`
- `h.click(sel)`, `h.type(sel, 'значение')` (шлёт input и change), `h.submit('form')` (событие submit; вернёт false, если обработчик вызвал preventDefault), `h.key(sel, 'Enter')`, `await h.wait(60)`
- `h.get('имя')` — переменная или функция студента; `h.alerts`, `h.logs`, `h.errors` — alert, console.log и ошибки выполнения.

Правила проверок:

- Шаблон **должен проваливать** хотя бы одну проверку, эталон — проходить все.
- Не привязывайтесь к точному тексту, который студент пишет сам (имя, описание): проверяйте наличие и структуру. Точный текст — только если он дан в шаблоне.
- Не проверяйте размеры, зависящие от шрифта. Цвета, отступы, `display`, количество элементов, порядок, ширина при 360px — можно.
- Сообщение-причина — коротко и по-русски: «нет alt у картинки», «сейчас 12px».

### Общие проверки качества (для всех заданий, эталон обязан их проходить)

Нет устаревших тегов (`font`, `center`…); заголовки без пропуска уровней; у каждой `img` есть `alt`; у ссылок и кнопок есть текст; каждое поле формы подписано (`label for`, обёртка `label` или `aria-label`); контраст текста по WCAG AA (4,5:1, крупный 3:1); нет атрибута `style`; нет `!important`; нет пустых и повторяющихся CSS-правил; **каждый CSS-селектор что-то находит на странице** (не оставляйте в шаблоне CSS для элементов, которых не будет); линтер HTML/CSS/JS без ошибок. В заданиях с полем `js` проверки «каждый селектор что-то находит» нет: качество смотрится до запуска скриптов, а стили для состояний, которые добавляет скрипт (`body.dark`, `[aria-invalid="true"]`), законны. Шаблон задания «почини скрипт» может содержать ошибку, которая падает при запуске: check-tasks её покажет, но провалом не посчитает. Отключить общую проверку можно полем `skipQuality: ['inline']` только когда задание именно про это (например, урок, где показываем атрибут style), с комментарием почему.

## Как проверить свою работу

```
python3 -m http.server 3801 &      # в корне проекта, свой порт
node tools/check-tasks.mjs http://localhost:3801/ --only k07,k08
node tools/build-content.mjs --check --only 07,08
```

`check-tasks` должен написать «Все N заданий в порядке», `build-content --check` — «Проверено». Запускайте только с `--check --only <ваши номера>`: полная сборка меняет общие файлы, а чужие занятия в это время могут быть недописаны.
