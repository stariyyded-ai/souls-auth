# Пепельный Пиксель — школа вёрстки в духе Souls

Учебная платформа по HTML и CSS в пиксельном стиле с элементами Souls: вход и регистрация, личный кабинет, уроки с квизами, 25 игровых заданий с автопроверкой, магазин, таблица лидеров и админ-панель. Сервер на Node.js (Express) и SQLite хранит аккаунты, прогресс, покупки и файлы лекций.

Макет в Figma: https://www.figma.com/design/moDxOqbZLMUTl4PL1uOSHc

## Страницы

| Файл | Что на странице |
| --- | --- |
| `index.html` | Вход. При успехе окно рассыпается на пиксельные кубики. Студент попадает в кабинет, администратор — в админку. Пароль короче 4 символов показывает «ВЫ ПОГИБЛИ». |
| `register.html` | Регистрация. Слизняк в кнопке уползает в дверь, затем открывается вход с подставленным именем. |
| `cabinet.html` | Личный кабинет: уровень (Новичок → Джун → Мидл → Сеньор), опыт до следующего, прогресс полосами HP/XP, души, достижения с редкостью и датами, история заданий, группа и курсы, надетые аватар, рамка и звание. |
| `lessons.html` | Уроки по модулям (текст, код, квиз, мини-задание) и лекции преподавателя в PDF и Word. |
| `tasks.html` | 25 заданий по HTML/CSS: редактор кода, линтер, предпросмотр, автотесты, подсчёт очков. |
| `shop.html` | Магазин: звания, аватары, рамки, бустеры, бонусы за души. |
| `leaderboard.html` | Таблица лидеров по опыту, фильтр «моя группа», можно скрыть себя. |
| `admin.html` | Админ-панель, видна только администратору. |
| `home.html` | Заглушка главной страницы. |

## Как запустить

Нужен Node.js 22.13 или новее (SQLite встроен в Node, компилировать ничего не надо):

```bash
npm install
npm start          # http://localhost:3000
```

При первом запуске сервер создаёт базу `data/ash.db` и кладёт в неё демо-данные. Как выложить сайт в интернет (Render, Railway или свой сервер) — в [DEPLOY.md](DEPLOY.md).

## Аккаунты

| Кто | Логин | Пароль |
| --- | --- | --- |
| Администратор | `123` | `123123123` |
| Демо-студент «Солер из Асторы» | `Солер из Асторы` или `soler24@ashen.pixel` | `astora123` |

Войти можно по имени персонажа или логину. Студент регистрируется сам по **коду группы**, который выдаёт преподаватель (коды видны в админке, раздел «Группы»). Персональных данных сайт не собирает: при регистрации нужны только игровое имя, код группы и пароль, без e-mail и настоящего имени. Без кода зарегистрироваться нельзя, а в заполненную группу (квота) — тоже. Перевести студента в другую группу можно в админке. Новичок начинает с нуля: прогресс кабинета считается по урокам из `content/lessons` (урок пройден, когда квиз решён без ошибок и мини-задание сдано), места модуля сверх опубликованных уроков показаны закрытыми.

## Сервер и безопасность

- Пароли хранятся только как хеш scrypt с солью.
- После входа браузер получает cookie `ash_sid` (HttpOnly, SameSite=Lax, Secure на HTTPS). Галочка «Запомнить у костра» продлевает вход на две недели, без неё вход живёт до закрытия браузера.
- Роль проверяет сервер. Без входа страницы кабинета, уроков, заданий, магазина и лидеров открывают страницу входа, а `admin.html` и все запросы `api/admin/*` пускают только администратора.
- Изменения принимаются только с заголовком `X-Ash`, поэтому чужой сайт не может отправить запрос от имени вошедшего.
- После 10 неудачных попыток входа за 10 минут с одного адреса сервер просит подождать.
- Студент получает только то, что ему положено: опубликованные лекции своей группы, других игроков без e-mail, скрывшихся из таблицы лидеров — без имени и опыта. Файл лекции сервер отдаёт, только если лекция открыта группе студента.
- **Защита от накрутки.** Правила экономики лежат в `js/student-logic.js` и работают и в браузере, и на сервере. Страница отправляет только действия («купить s12», «квиз: ответы 1, 0, 2», «отчёт проверки задания t05»), а сервер применяет их сам: цены и остатки берёт из базы, ответы квизов сверяет сам, время решения считает по своим часам, очки — по своей формуле. Итоговое состояние приходит с сервера и заменяет посчитанное страницей. Прислать себе опыт или души нельзя.
- Остаётся одно допущение: сам код задания проверяется в браузере (ему нужен настоящий движок вёрстки). Сервер проверяет, что отчёт совпадает с заданием, и ограничивает награду максимумом задания, а код решения сохраняет в базе. Полная проверка на сервере возможна через Playwright на своём VPS.
- E-mail не хранится. Если база создана старой версией, при запуске сервер сам удаляет e-mail у всех аккаунтов. Что хранит сайт, описано в `privacy.html`.
- Уроки группе выдаёт преподаватель в разделе «Уроки групп»: урок можно добавить группе (виден студентам) и разрешить его проходить (без разрешения он с замком, квиз и отметки сервер не засчитывает). Новая группа начинает без уроков. Группам, которые ещё не настраивали, открыты уроки по старому правилу из описания урока.
- Закрытый курс студент просит открыть кнопкой в кабинете. Заявка приходит в раздел «Заявки» админки: счётчик в меню, уведомление в открытой админке, кнопки «Открыть курс» и «Отклонить».

### API

| Запрос | Что делает |
| --- | --- |
| `GET api/boot.js` | данные для страницы: кто вошёл, его состояние, разделы (подключается в `<head>`) |
| `POST api/register`, `api/login`, `api/logout` | регистрация, вход, выход |
| `GET api/me` | кто вошёл и его состояние |
| `POST api/me/actions` | действия студента: покупка, надеть, квиз, отчёт задания, черновик; сервер применяет их сам и возвращает состояние |
| `POST api/me/password` | сменить свой пароль (нужен текущий) |
| `POST api/me/course-request` | попросить открыть курс (заявка приходит в раздел «Заявки» админки) |
| `GET api/admin/db` | все данные админки |
| `POST/PUT/DELETE api/admin/<раздел>[/<id>]` | группы, курсы, модули, задания, лекции, достижения, магазин |
| `POST api/admin/users/<id>/role`, `/group`, `/courses`, `/password`, `/reset`, `/achievements` | роль, группа, личный доступ к курсам, новый пароль, сброс прогресса, выдача достижений (`{ ids: [...] }`) |
| `POST api/admin/achievements/<id>/grant` | одно достижение сразу нескольким (`{ users: [...] }`) |
| `GET api/admin/requests`, `POST api/admin/requests/<id>/approve` или `/decline` | заявки студентов на курсы |
| `DELETE api/admin/users/<id>` | удалить пользователя |
| `POST api/admin/reset-demo` | вернуть демо-данные |
| `POST api/files`, `GET/DELETE api/files/<id>` | файлы лекций |

## Экономика и геймификация

- **Опыт (XP)** определяет уровень: Новичок с 0, Джун с 1000, Мидл с 3000, Сеньор с 6000.
- **Души** — валюта магазина.
- **Очки за задание** = базовый балл + бонус за чистоту кода + бонус за скорость (`js/economy.js`):
  - базовый балл — доля выполненных требований × баллы задания (100, 150 или 200);
  - чистота кода — до 40% баллов, по доле пройденных проверок качества;
  - скорость — до 30% баллов, если уложились в норму времени, дальше бонус тает до нуля к двойной норме;
  - бонусы начисляются, только когда выполнены все требования;
  - перерешивать можно сколько угодно, но награда даётся только за прирост к лучшему результату.
- **Бустеры** из магазина: «Эстус опыта» (опыт ×2 на 3 задания), «Кольцо жадности» (души ×1,5 на 3 задания), «Зелёный цветок» (полный бонус за скорость на 1 задание).
- **Квиз урока**: 20 XP и 20 душ за каждый новый верный ответ.
- **Достижения** с редкостью: обычные, редкие, эпические, легендарные. Часть выдаётся автоматически (первое задание, пять заданий, чистый код, скорость, квиз без ошибок, первая покупка), остальные — вручную в админке.
- **Таблица лидеров**: студент может скрыть себя переключателем, тогда другие его не видят, а он видит, на каком месте был бы.

Состояние студента хранится на сервере (`js/student-store.js` отправляет его через полсекунды после каждого изменения). Опыт, души, покупки и награды сразу видны в админке: в пользователях, дашборде и логах. Если администратор сбросил прогресс или выдал награду, открытая страница студента перечитает данные.

## Задания

25 заданий, пять механик по пять:

| Механика | Задания |
| --- | --- |
| Почини сайт | 01–05 |
| Собери макет (фрагменты кода, среди них ловушки) | 06–10 |
| Оптимизируй код | 11–15 |
| Адаптив за 5 минут | 16–20 |
| Доступность и семантика | 21–25 |

В каждом задании есть история, условие, шаблон кода, чек-лист требований и автотесты. Редактор — CodeMirror с подсветкой HTML и CSS и линтером прямо в коде.

Автопроверка (`js/task-runner.js`) открывает код студента в двух скрытых iframe шириной 1024 и 360 пикселей без права запускать скрипты и проверяет:

- **результат** — тесты из задания (`js/tasks-data.js`);
- **качество кода**, общее для всех заданий:
  - семантика: нет устаревших тегов, заголовки по порядку;
  - доступность WCAG: alt у картинок, имена у ссылок и кнопок, подписи у полей;
  - контраст текста по WCAG AA (4,5:1, для крупного 3:1);
  - чистота CSS: нет inline-стилей, `!important`, пустых и повторяющихся правил, неиспользуемых селекторов;
  - линтер без ошибок: HTMLHint для HTML и свой линтер CSS на `CSS.supports()` (знает grid, gap и переменные, ловит опечатки, неверные значения, пропущенные `;` и скобки).

Эталонные решения лежат в `tools/solutions.js`. Проверка, что шаблон каждого задания валит тесты, а эталон проходит всё:

```bash
npm start &
npm run test:tasks -- http://localhost:3000/   # нужен Playwright
```

## Проверка сервера

`npm run test:e2e` поднимает сервер с пустой временной базой и в браузере проходит путь студента и администратора: вход и регистрацию, закрытые страницы, покупку и задание с сохранением на сервере, загрузку лекций PDF и Word и доступ к ним по группам, сброс прогресса, смену роли, выход и вёрстку на телефоне. Нужен Playwright (`npm i -D playwright`).

## Уроки

Уроки — файлы Markdown в `content/lessons/` с метаданными в начале файла:

```markdown
---
id: css-grid
module: m2            # модуль
lesson: 2             # номер урока в модуле
title: Grid: сетки и области
difficulty: Средний
minutes: 30           # время прохождения
groups: [ВД-21, ВД-22, ВД-31]   # каким группам доступен
task: t05             # мини-задание с автопроверкой
---
Текст урока, примеры кода…

:::quiz
? Вопрос
- [ ] неверный вариант
- [x] верный вариант
> пояснение после ответа
:::
```

После правки уроков соберите их в `js/content.js`:

```bash
node tools/build-content.mjs
```

## Лекции в PDF и Word

В админке, в разделе «Лекции», к лекции можно прикрепить файл PDF или Word (.docx) до 20 МБ, выбрать группы, которым она доступна, сложность и время изучения. Студент видит лекцию на странице «Уроки»: PDF открывается прямо на сайте, Word превращается в страницу (библиотека mammoth), оба можно скачать.

Файлы лежат на сервере в `data/uploads`. Сервер проверяет, что это действительно PDF или Word, и отдаёт файл студенту, только если лекция опубликована и открыта его группе. Для пробы есть `samples/lekciya-flexbox.docx` и `samples/lekciya-flexbox.pdf`.

## Админ-панель

Разделы переключаются по адресу: `admin.html#users`, `#groups`, `#courses`, `#requests`, `#lessons`, `#tasks`, `#lectures`, `#achievements`, `#shop`, `#logs`. Внизу меню — «Сменить мой пароль».

- **Дашборд:** активные за 7 дней, активность по дням, прогресс по модулям, топ-5 студентов, последние покупки, ошибки автопроверки.
- **Пользователи:** поиск, фильтры по роли и группе, смена роли и группы, карточка, сброс прогресса, выдача сразу нескольких достижений, новый пароль для забывшего свой, удаление.
- **Группы:** создание, изменение, удаление, курсы и модули, дедлайн, квота, код регистрации (пустой код закрывает регистрацию в группу).
- **Курсы:** название, описание, часы, показывать ли в кабинете. Студенту курс открыт, если он есть у его группы или администратор открыл его лично (карточка пользователя → «Курсы»). Закрытый курс студент может попросить открыть.
- **Заявки:** просьбы студентов открыть курс, кнопки «Открыть курс» и «Отклонить». Новые заявки видны счётчиком в меню; пока админка открыта, она проверяет их каждые 30 секунд.
- **Уроки групп:** какие уроки видит группа и какие можно проходить; есть кнопки на весь модуль и на все уроки. Из раздела «Группы» туда ведёт кнопка «Уроки».
- **Задания, лекции, достижения, магазин:** полный CRUD с предпросмотром. В достижениях кнопка «Выдать» вручает достижение сразу нескольким студентам или всей группе. В магазине — тип товара (звание, аватар, рамка, бустер, бонус, мерч), редкость, картинка аватара или рамки, действие бустера.
- **Логи:** действия, ошибки автопроверки, транзакции.

Данные лежат в базе на сервере, каждое изменение сервер записывает в журнал. Кнопка «Сбросить демо-данные» возвращает примеры для всех: удаляет аккаунты, прогресс и загруженные лекции.

## Скорость загрузки

- Сервер сжимает ответы (gzip): скрипты, стили и данные страницы уходят в 3–5 раз меньше.
- В страницы сервер подставляет к скриптам и стилям метку версии `?v=<хеш файла>`. С ней браузер хранит файл год и не спрашивает сервер; поменяли файл — поменялась метка, и браузер скачает новый. Перезагружать кэш руками после обновления не нужно.
- Шрифты, библиотеки из `vendor/` и картинки браузер хранит неделю.
- Фон на canvas рисуется 30 кадров в секунду вместо 60, чтобы не нагружать слабые компьютеры.

## Звук

Все звуки синтезируются в браузере через Web Audio API: клики, ошибки, разбитое окно, «КОСТЁР ЗАЖЖЁН», «ВЫ ПОГИБЛИ», дверь и слизняк. Кнопка «ЗВУК ВКЛ» в шапке выключает их, выбор запоминается.

Анимации учитывают настройку «уменьшить движение» (`prefers-reduced-motion`).
